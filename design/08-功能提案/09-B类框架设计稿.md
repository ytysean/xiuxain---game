## 一、评级维度表结构（评级四维拆分）

### 1.1 现状锚点（复用现状 · 诚实标注）
- **现状**：`period_settlement.gd` 硬编码 **三维** 评分：`经营 0.30 / 收益 0.35 / 弟子 0.35`（`const 权重`），阈值 `const 评级阈值`（D~SSS），归一化期望 `const _期望` 按门派等级缩放。
- **本稿目标**：将「总成长值」按**四维**重新拆解——`底蕴 40% / 梯队 30% / 盈余 20% / 声望 10%`，权重与阈值**全部走配置**（`评级维度.csv`），雷达 UI 按四维展示。
- ⚠️ **冲突预警（待主理人裁决）**：四维是对三维的**重新分配 + 新增声望维**，非叠加。period_settlement 的 `const 权重` 将被 `评级维度.csv` 取代（单源化）。若保留三维并行，会出现「评级用三维、雷达用四维」的口径不一致——**不推荐**。推荐方案：评级维度.csv 成为唯一真源，period_settlement 改为读取配置（见 §1.5 消费者 ①）。
- ✅ 子指标可复用 period_settlement 现有 `计数`/`快照` 字段（资源产能 / 灵石增量 / 总战力增量 / 突破 / 高品质新弟子 / 稀有道具 / 首通）+ `game_state.声望`（需新增「声望增量」计数器，见 §1.5 消费者 ②）。

### 1.6 跨文档一致性 / 待主理人裁决
- ⚠️ **裁决项 A**：三维 vs 四维口径——**必须二选一单源**。推荐「四维替换三维」，period_settlement 删硬编码权重。

- 雷达 UI 四维 banding 阈值 `[数值待填]`，需与 `双周期评级体系.md` 的评级节奏一致呈现。

### 1.7 边缘情况（≥3）
- **EC-1 权重和 ≠ 100**：pre_f5 阻断；运行时若 loader 读到异常和，回退均分并纪事告警。
- **EC-2 某维度 `是否启用=0`**：该维不计入总分；雷达隐藏该维（或置灰）。
- **EC-3 声望计数器缺失（旧档/未接）**：声望维得分记 0，不崩；pre_f5 校验缺声望 key 阻断新档。
- **EC-4 评级维度.csv 缺行**：loader 容错，缺维不计分；pre_f5 校验缺四维之一阻断。

### 1.8 验收标准
- 四维权重/阈值全配置化；period_settlement 单源读取；权重和=100 闸门绿灯；声望维有数据源；旧档兼容（维度缺失降级不崩）。

### 3.5 开关逻辑草案（伪代码级 · light-code，非运行时）
```gdscript
# —— 负面影响开关.csv 读取 ——
# 负面开关表 = load_csv("负面影响开关.csv") -> Dictionary[开关ID] = row

# —— 总闸优先的生效判定（所有负面判定点先查此函数）——
func _负面效果是否生效(类别: String, 事件ID := "") -> bool:
    if int(负面开关表["neg_global"]["启用"]) == 0:
        return false                      # 一键回退纯正向：总闸关 → 全不生效
    var 分闸 = 负面开关表.get("neg_" + 类别, null)
    if 分闸 == null:
        return true                       # 无分闸定义 → 受总闸控制（默认生效）
    return int(分闸["启用"]) == 1

# —— 接入点（4 处判定点，全部先过 _负面效果是否生效）——
# ① negative_event 触发判定：命中且 _负面效果是否生效("资源建筑"/"弟子人员", 事件ID) 才应用 punish
# ② game_state 弟子流失/叛逃判定：_负面效果是否生效("弟子人员") 才降低招徒概率/触发叛逃
# ③ 坊市价差：_负面效果是否生效("声望外部") 才启用价差惩罚
# ④ period_settlement 降级/权益回收：_负面效果是否生效("品级权限") 才执行

# —— 建筑被动_负面事件减免（DORMANT → 接线）——
# 当 neg_res_build 生效时，建筑被动减免聚合参与负面惩罚结算（乘 1+减免值）
```
