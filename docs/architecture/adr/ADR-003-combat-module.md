# ADR-003 战斗系统模块边界

> 状态：决策已锁定（P0 核心，零代码；职业命名经老大 2026-07-19 拍板确认「道修」为当前职业、剑修后置为后续新增；代码重命名前置见 §2 D2 / R5）｜ 作者：eng-lead（程基岩）｜ 阶段：Phase 5 制作（Sprint-03 待发）
> 关联：太玄宗门录_核心设定总览.md §9（9.2 职业定位 / 9.5 伤害公式 / 9.6 五行克制）/ 战斗与道心细则.md、数值体系细则.md §4.1/§4.2、disciple.gd、item.gd、beast.gd
> 决策影响：战斗系统 Epic（P0）；依赖 ADR-001 战力 / ADR-002 奇遇（战斗可触发于奇遇）。

---

## 1. 背景与问题

**现状**：战斗 **零实现**。`game_state.gd` 无任何战斗循环/伤害公式调用；`disciple.属性{攻防血速}` 已备；`灵兽联动()` 仅文案提及「对战法修无敌帧 / 锁血阈值」等未接线效果；`item.gd` 极品特效（`万法可破`/`金刚不坏`/`焚身灭甲`）也只作文案。

**设计（§9 + 战斗与道心细则）**：半即时回合制（单位按攻速独立行动）；最多 5 弟子 + 2 灵兽；站位 体修前排/法修中排/道修后排；全灭判负，20 回合按剩余战力占比判定；伤害公式含 职业技能倍率 ×(1+通用)×(1+道心)× 五行克制 ×(1-防御) × 暴击。

**缺口**：无 `combat.gd`；职业克制/五行循环无代码可消费的数据接口；与弟子/装备/灵兽/奇遇的边界未定义。

---

## 2. 决策（Decisions）

### D1 — 模块边界：独立纯逻辑 `combat.gd`，经数据契约解耦
```
combat.gd  (纯逻辑, 无 UI, 无 Game 依赖)
  ├─ 输入契约：CombatantData { 战力, 属性{攻防血速}, 职业, 灵根(主+纯度), 灵兽战力, 技能列表, 极品特效 }
  ├─ 输出：BattleResult { 胜负, 回合日志, 剩余战力占比 }
  └─ 数据来源：disciple.总战力()/属性/职业/灵根；beast.战力贡献()；item 极品特效（经 disciple 暴露）
```
- **解耦方式**：战斗不直接持有 `Disciple`/`Item`/`Beast` 实例，只消费「战斗快照」`CombatantData`（由 `game_state` 或战斗入口组装）。→ 可独立单元测试（TEST_STRATEGY LOGIC 层）。
- UI（`main.gd`）仅渲染 `BattleResult` 日志 + 占位血条；art-lead 后续出真实战斗界面规格（灰模先行）。

### D2 — 职业克制数据来源（§9.2 / 战斗细则）✅ 已拍板
- **老大 2026-07-19 拍板**：当前游戏职业定位为 `道修(辅助)/体修(坦克)/法修(输出)`；**剑修不进入当前版本**，作为后续版本新增职业单独设计（新数值/技能，非简单回滚）。
- 克制关系（§9.2 / lore.职业效果）：**道修克法修、体修克道修、法修克体修**（闭环）。
- **决策**：`combat.gd` 内建 `职业克制表`（显式映射，避免解析文案），以「道修」为权威命名。
- **⚠️ 代码重命名前置（R5）**：`disciple.gd` / `lore.gd` 当前仍为 `剑修`（裁决④未落地代码），Sprint-03 前须完成：
  1. `disciple.gd`：职业名 / 解锁职业池 / 职业属性权重 / 判定职业 / 职业堂口 中 `剑修`→`道修`（保留原数值侧重：攻0.40/防0.15/血0.20/速0.25）；
  2. `lore.gd`：职业效果 / 职业堂口 中 `剑修`→`道修`；
  3. `disciple.gd` 灵兽联动「万法可破」判定由 `关联 == "剑修"` 改为 `关联 == "道修"`；
  4. `剑修` 从 `解锁职业池` 与 `职业名` 移除（后置后续版本，届时以新职业重新接入，不复用旧 `剑修` 槽位）。

### D3 — 五行循环数据来源（§9.6）
- 基础克制链 `金→木→土→水→火→金`：克制 +20% / 被克 -15% / 同属 0（§9.6.1）。
- 灵根纯度修正（§9.6.2）：单灵根 克制×1.25/被克×1.2；双灵根 ×1.0/×1.0；三灵根 ×0.75/×0.67；四+ ×0.5/×0.33。
- 极端边界：最高 1.25 / 最低 0.82（§9.6.3）。
- **决策**：`combat.gd` 提供纯函数 `wuxing_multiplier(atk_attr, def_attr, root_purity)`：
  - `atk_attr`/`def_attr` 取自弟子**主灵根**（无属性普攻/技能以主灵根判定，多段每段独立，真实/固定伤害乘率恒 1.0）。
  - `root_purity` 由 `灵根` 推导（天灵根=单/变异=单/双/三/四+）。
  - 该函数为 TEST_STRATEGY §2.3 的断言目标（可全自动化）。

### D4 — 伤害公式（§9.5 / 战斗细则 §一.4）
```
最终伤害 = 攻击方基础攻击
         × 职业技能倍率
         × (1 + 通用增益总和)        # ≤25%/硬30%（同 ADR-001 聚合器）
         × (1 + 道心增益)            # ≤10%
         × wuxing_multiplier(...)    # 独立乘区，不占其他额度（§9.6.3）
         × (1 - 防守方防御减伤率)
         × 暴击系数（暴击时）
```
- 通用增益聚合器**复用 ADR-001 的 `聚合通用增益()`**，保证战斗内外乘区口径一致（同源单帽+池总帽）。

### D5 — P0 最小可玩范围（✅ 老大确认采纳 D5 最小范围 + 3 项必纳基础能力）
| 包含（核心范围，老大确认） | 不包含（后续 Sprint / S1） |
| --- | --- |
| 1v1 或 3v3 占位战斗（灰模日志） | 完整 5 弟子+2 灵兽站位 AI |
| 伤害公式（含职业克制 + 五行循环） | 完整灵力系统（§9.3 灵力回复/技能层级解锁） |
| 胜负判定（全灭 / 20 回合超时判防守方胜） | 敌方 AI 策略（§9.8）、心魔失控（§二.3） |
| 极品特效钩子（万法可破等）占位 | 道心成长实时影响、控制命中五行修正 |

**老大确认须补充纳入 P0 的 3 项基础能力（对接刚需，低成本）：**
1. **弟子属性快照读取**：战斗单位属性直接对接 `disciple.gd` 最终属性接口（攻/防/血/速、职业、灵根），禁止写死测试值；与装备/养成体系联动的基础。
2. **快速结算 / 离线速算接口**：历练扫荡、奇遇战斗事件、离线推演共用纯数值速算，与核心结算器同实现；返回统一 BattleResult。
3. **战斗结果统一输出结构**：固定 `{is_win, round_count, remaining_hp, drop_reward, battle_log}`，奇遇/历练/后续 PVP 复用。

- **为什么最小**：P0 目标是「可玩战斗闭环 + 数值红线验证 + 主流程对接」，先把 §9.6 五行与职业克制跑通，UI 用灰模；完整灵力/技能树/AI 是 S1+。

### D6 — 触发入口（与奇遇/月度事件）
- 战斗可由：① 奇遇「征伐类」分支（ADR-002）触发；② 章节式大比/秘境（后续）；③ 调试入口（main 按钮，灰模）。
- 战斗结果影响：弟子 履历（ADR-002）、声望、潜在伤亡（境界跌落/心魔，属后续）。

### D7 — 验证策略（✅ 老大确认：Python 断言 + 本地 Godot 3 验收 + 调试日志）
- **Python 单元测试（数值正确性，无引擎可跑）**：
  - 五行 5 关系 × 4 纯度档（单/双/三/四+）系数断言（§9.6.1/§9.6.2）；
  - 职业克制闭环断言（道修→法修→体修→道修）；
  - **边界断言（新增）**：① 伤害下限=1 兜底（防御极高）、攻击=0 不出负伤；② 暴击率>70% 封顶、闪避率>40% 封顶；③ 浮动伤害严格∈[0.9,1.1]；④ 快速结算 vs 完整战斗 胜负偏差≤10%。
- **本地 Godot 验收（3 核心用例，引擎内跑通）**：
  1. 基础 1v1：单弟子 vs 同境界怪物，预期伤害与日志误差在浮动内，五行/暴击生效；
  2. 3v3 车轮战：行动顺序/车轮规则/胜负/气血继承正确；
  3. 跨系统调用：奇遇「征伐类」触发战斗→结算奖励发放→奇遇收尾，打通链路。
- **配套调试工具（P0 同做）**：战斗强制输出**结构化日志**（每回合：行动单位、伤害值、是否暴击、是否克制、双方剩余血量）至控制台，长期提效。

## 5. 验收标准（P0）

- **AC1 战斗闭环**：可由入口发起 1v1/3v3，按攻速行动至一方全灭或满 20 回合（超时判防守方胜），输出 BattleResult。
- **AC2 五行克制**：`wuxing_multiplier` 对 5 种克制关系 + 4 档纯度返回 §9.6 规定系数；边界（单灵根克制 1.25 / 被克 0.82）正确；真实伤害恒 1.0。
- **AC3 职业克制**：道修/体修/法修 闭环克制生效（D2 拍板：道修克法修、体修克道修、法修克体修）。
- **AC4 乘区合规**：战斗内通用增益复用 ADR-001 聚合器，≤30% 硬上限；五行为独立乘区不占位。
- **AC5 可单测**：`combat.gd` 纯函数可在无引擎下以断言验证（TEST_STRATEGY LOGIC 层）。
- **AC6 属性对接**：战斗单位属性 100% 取自 `disciple.gd` 最终接口（攻/防/血/速/职业/灵根），无硬编码测试值；快速结算接口与完整战斗共用同一结算器。
- **AC7 边界红线**：① 伤害下限=1（防御极高）、攻击=0 不负伤；② 暴击率>70%/闪避率>40% 强制封顶；③ 浮动伤害∈[0.9,1.1]；④ 快速结算 vs 完整战斗 胜负偏差≤10%。
- **AC8 统一输出**：所有战斗入口返回 `{is_win, round_count, remaining_hp, drop_reward, battle_log}`；3 个 Godot 验收用例（1v1 / 3v3 车轮 / 奇遇征伐联动）全部通过。

## 6. 风险

- **R1（H4，✅ 已解除）**：职业命名经老大 2026-07-19 拍板为「道修」（裁决④落地），战斗克制表与装备口径统一；剑修后置后续版本新增，不复用旧槽位。
- **R5（新，代码重命名前置）**：`disciple.gd`/`lore.gd` 当前仍为 `剑修`，Sprint-03 前须完成 `剑修`→`道修` 重命名 + 移除当前池（见 D2）。未落地前战斗克制表无法对齐真实数据。
- **R2（H5）**：灵兽战力按弟子折算，战斗内灵兽贡献口径需先修正（Beast 自持战力）。
- **R3**：P0 不含灵力系统，技能倍率若依赖灵力消耗梯度（§9.3）需简化（如 P0 技能倍率取基础值，灵力作为 S1 扩展）。
- **R4**：战斗为无引擎下最难验证的系统，发布前须主理人 solo 走查 + 本地 Godot 3 验收用例兜底。
