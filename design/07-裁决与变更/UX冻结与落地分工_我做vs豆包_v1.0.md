## 1. 分工总原则（为什么这样切）

| 线 | 谁 | 只做什么 | 绝不做什么 |
| --- | --- | --- | --- |
| **工程线** | 我（当前 GameDesigner 会话） | 所有 `.gd` 改动 · 系统改造 · 文档 · **验证收口** | 不做美术出图 |
| **美术线** | 豆包 | AI 出图（立绘/图标/背景）· 大批量纯文案 | **不碰 `.gd` 代码** |

**为什么豆包不碰代码**：上一批豆包改动在 `game_state.gd` / `disciple.gd` / `fishing_system.gd` 引入 **3 处编译错误（`PRIO_LOW` 未定义 / `下一境界()` 不存在 / `超出次数` 跨作用域），致整个游戏无法启动**，而 `gate_all` 门0/门1 全部放行。**代码是"易错且不能错"的，必须由能跑实机验证的一方收口。**

**为什么我需要收口**：`gate_all` 只查语法，不查标识符/函数存在性——**门禁通过 ≠ 能跑**。每批代码或美术产出后，我都必须跑 `headless_smoke` 实机确认。

### 9.4 新增踩坑（血泪，第 6–7 条）

6. **heredoc 会吞掉 Python 源码里的转义序列**：`python - <<'PY'` 经 Git Bash 转换后，源码中的 `'\n'` / `'\t'` 字面量会被**提前解释或吞掉** —— 逐字符比对时字符串"看起来完全一致"却 `count==0`，本轮连续 7 处补丁断言失败。**正解：补丁脚本一律用 `Write` 落盘再执行**（项目既有惯例），脚本内用 `chr(10)` / `chr(9)` 更稳。
7. **「先写盘、后断言」会让失败的补丁留下半截改动**：`wr()` 先落盘再断言 → `unlock_order.csv` 自带 BOM（属原状态非注入）被断言拦下时**内容其实已写入**，随后手工重写造成 `atlas` 行出现 2 次。**判据：写盘类脚本必须「先全部断言、后统一写盘」**（本轮 UX 总纲脚本已改用该范式）。
