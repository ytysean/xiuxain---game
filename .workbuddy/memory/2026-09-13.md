## P0-1 UI 材质试样 4 张（程序化 9-patch）· 生成完成待验收

**生成器（唯一真源，复跑调参入口）**：`.workbuddy/gen_ui_patch.py`

**★ 内置机器校验（不靠肉眼）**：

**★ 踩坑 1：验证方法自身的假 FAIL（重要）**
首轮"角部守恒"报 FAIL —— 根因是**我的验证写错了**：crop 了 110×110，而 `margin` 只有 48，crop 区混进了被拉伸的边区。**角部守恒只能比较 `margin×margin` 纯角区**（九宫格唯一不被拉伸的区域）。修正后 3/3 PASS。
→ 教训：**校验逻辑本身也要先自证**，否则会把工具 bug 误判为产物缺陷（差点改坏正确的贴图）。

**★ 踩坑 2：`.import` 手工写 uid → UID duplicate（本项目级铁律）**

**★ 四条沉淀（已写入方案 §3.2.1）**：
1. **小尺寸元素（≤256px 源图）不做复杂纹样** —— 螺旋/宝珠在 `L<30px` 一律糊成噪点
2. **角饰应与「描边」同构**（平行/同色系/更细更淡）→ 同构产生层次，异构产生拼贴感
3. **「无角饰」也是合格选项** —— 角饰是点缀非信息，形态拿不准宁可留白
4. **选型必须看 1× 真实尺寸** —— 7× 特写会放大设计差异，玩家只看得到 1×；探针专门输出 1× 并排排

**★ 一度误判（留痕）**：曾怀疑生成器「半透明绘制在 RGBA 主画布上是覆盖而非混合 → 所有 alpha 参数失效」。**核实为误判** —— 生成器早已用独立图层 `ov` + `apply_mask` + `alpha_composite`（主渲染 L350–375），alpha 是生效的。**未做任何"修复"**，避免改坏正确代码。教训：怀疑引擎/PIL 语义前先读全流程，不要凭一个 API 印象下结论。

- 落在**左/右区**的装饰只被**垂直**拉伸 ⇒ **竖向贯通的细条横向厚度守恒**，安全 → F 左侧书脊即此原理。
- 由此推论：**「完整内框线」在 9-patch 下是安全的**（圆角全在角区，直段是纯色线拉伸只变长不变粗）→ D 候选成立。
- **切角(octagon)也 9-patch 安全**：四角斜边全在角区，边区仍是直边。

## ★ P0-5.3 场景归位（2026-09-13 · 老大质疑「背景图失去意义了？幻形也没意义了？其他游戏怎么处理的？」）

### 定性：这是**设计错误**，不是调参问题；且是我 P0-5.2 自己埋的坑

被架空的项目既有系统：
- **背景图**（`_build_base_and_bg()`）：84% 面积被墨罩盖住；
- **幻形·洞天换肤（6 套皮肤）**：`sect_home_page.gd:143` `SKIN_BG` = 云海/春/夏/秋/冬/仙，`_apply_equipped_skin()` 切 `Game.当前皮肤` —— 只在 137 逻辑像素的窗里、被压到 74% 亮度 → **肉眼几乎分辨不出**。

### ★ 本轮最值钱的证据（推翻了我上一版的前提）

`panel_bg` / `card_bg` / `card_row_bg` 九宫格**填充区 alpha = 255（完全不透明）**：
`panel_bg` 中心 `rgba(28,41,47,255)`、`card_bg` 中心 `rgba(37,53,61,255)`、`card_row_bg` `rgba(33,47,55,255)`。

| **和平精英 UI 2.0** | **「全景化动态背景」**——"背景动起来极大提高沉浸感，**仿佛每个界面都活起来了**"；按赛季切换 |
| **梦幻西游三维版** | **「保证最大化的展示场景和角色本身」** + **「半开放式界面」**（功能信息用小界面承载，其它空间展示主界面） |

### ★ AI 出图路线打通 —— 「弟子简陋」的解法（2026-09-13 第二轮）
**结论：精致度换 AI 出图，动作用部件化。PIL 几何绘制已到天花板（无五官/平铺色块/无层次），继续调参＝在 Tesseract 上调参。**

**三个工程坑（实测，必照抄）**
1. **ImageGen 的 `background:"transparent"` 是假的** → 返回的是「画上去的棋盘格图案」（不透明像素），`getbbox()` = 全画布 → 直贴进去就是灰底方块。
2. **抠底必须用连通域，不能用颜色阈值**：棋盘格两色交替 ⇒ `floodfill(thresh=30)` 只抠掉 **0.1%**。有效法 = **HSV 判据（S<14 且 V>70）+ 二值连通域取「与四边连通」** ⇒ 抠掉 **64.1%**，且角色内部白领（低饱和但不与边缘连通）完整保留。
3. **抠底前别做局部清除**：曾粗暴清「右下角矩形」去水印 ⇒ 切掉角色下半身。棋盘格整体抠除后水印自动消失，**无需额外处理**。

**形变 vs 部件化**：待机/走位用「整图 `rotate`（**绕足底**）+ 位移 + 起伏」够用（已实测）；**挥臂扇火等关节动作必须部件化**（头/躯干/上臂×2/前臂×2/腿×2 ≈ 6–8 件 + `Skeleton2D`，一套动作 6 型复用）。**形变会绕错中心 ⇒ 人物像"翻跟头"，务必绕足底。**

**场景侧（"整页死气"的解法）**：单靠角色动不够，场景至少 3 层 —— ① 光照呼吸（整帧亮度随主光源 ±2%，最省最有效）② 主光源多频脉动 ③ 粒子（烟/火星/尘埃）。局部微动幅度 **≥4px**（实测 2.6px 肉眼不可见）。
⚠ **烟柱禁止用「整块像素滚动」**：曾把烟区选成 `(556,34)-(812,374)` **正好罩住匾额** ⇒ 匾额跟着漂（明显穿帮）；改**粒子叠加（不动像素）**才安全。

**成本**：ImageGen 约 **5–10 积分/张**（1 正视图/型，透明底）。

+「你也可以全网深度学习下教程和技术方法，我要求的是结果，至于过程和方法你来定。」

### 决策：A 位移场 → B 模块化 cutout
- **A 位移场**：对**整张位图**逐像素非线性形变 ⇒ 手臂等部位**无法隔离**，关节处必然拉扯 ⇒ 撕裂是**原理性**的，调参救不回来。
- **B 模块化**：拆成**独立部件精灵**，各自绕**关节锚点**旋转+平移 ⇒ **像素永不被拉伸** ⇒ 原理上不可能撕裂，且手臂可独立抬起（真扇火/真投料）。
- **路线判据**：要"整体气息/衣袂飘举" → A 够用；要"某人正在做某事" → **必须 B**。
- WebSearch 验证「关节圆盘 + 重叠切片」= **Spine 官方标准做法**（非土办法），可放心工程化。

### 三条铁律（本轮确立）
1. **关节圆盘**：部件根部以旋转中心为圆心做圆盘，**圆绕自身圆心旋转不变** ⇒ 根部永远严丝合缝。
2. **重叠切片**：切片边界故意放宽 2~5px 互相重叠，上层盖下层，**重叠区像素相同** ⇒ 拼回与原图逐像素一致。
3. **数据标定**：关节坐标/站位/人物高度一律由**剖面数据**推出，**禁止手填**。

### ★ 分段袖（本轮最关键教训）
宽袖**整条绕肩转** ⇒ 转走露出大片内衬侧壁（横向色带/黑块）⇒ 读作撕裂。

## 22:15 ★ 路线级裁决：人物动画改走「AI 图生视频 → 序列帧」（老大质问方法论）

**老大反馈 3 点 + 1 个方法论质疑**（丹房 v2 交付后）：
1. 右侧弟子穿模；2. 弟子动作僵硬「像鬼屋假人」；3. 药柜左右方向不对且穿模

**调研结论（Holopix 动画板块）**：它根本不做「拆件 + 骨骼」。走的是
`基础动作生成器 / 图转动画生成器 / 首尾帧动画生成器`（AI 视频）→ `普通·特效视频抠图`（纯色底 → 透明 WebM + 序列帧 ZIP，Unity 可直接用）→ `视频转序列帧`（8 fps）。
**关键**：输出物本身就是给引擎用的透明序列帧 ⇒ 我此前「游戏不能用 AI 视频」的判断**作废**。

**★ 裁决：人物动作改走路线 C（AI 图生视频）**；模块化 cutout 退为「场景陈设」用途。
- **僵硬根因**：我给每个部件手写 `A·sin(2πt)` —— **正弦 = 匀速往复，没有加速/减速/停顿/回弹** ⇒ 必然木偶感；
  且右臂只绕一个支点硬转（无肩→肘→腕逐级传递），袖摆/飘带无延迟跟随。
- **穿模根因**：扇子 pivot 是**肉眼读网格**标的（偏几像素即错开）+ 扇子转开后**下方原图无像素**露出破口。
- **药柜根因**：**3/4 视角道具被 `flip` 镜像复用** ⇒ 透视反转（硬 bug，非参数问题）。

**AI 路线的三关工程兜底**（业界实测坑）：
① **帧基线对齐**（AI 逐帧脚不在同一水平线 ⇒ 播放上下浮）；
② **首尾缝合**（模型不自动闭合循环 ⇒ 必跳）；
③ **多底色清边**（发丝/袖口/道具尖，棋盘格上看不见，亮场景里原形毕露）。

**分工（融合方案）**：场景（静态）→ 路线 B 模块化独立贴图；人物（要活的）→ 路线 C 序列帧。
