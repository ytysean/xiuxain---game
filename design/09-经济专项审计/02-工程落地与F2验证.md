## 三、(a) F2 全局调节阀门 —— 设计 / 实现 / 接线

### 3.1 架构定位
`economy_balance.gd` 是**纯计算中间件**，不持有任何游戏状态、不读 `game_state`、无副作用。唯一职责：对结算最终输出节点的原始数值做「系数纠偏 + 熔断」后输出最终值。

### 3.2 三大能力（对应 ECON-01 §4.8）
1. **全局系数纠偏**：总产出 `global_income_rate`、总消耗 `global_cost_rate`，各自 ±15% 硬范围；越界配置 `push_error` 并拒绝（clamp 但不放行危险值）。
2. **单模块独立管控**：坊市 `trade_profit_rate`、运维 `global_cost_rate`（同源）、负面影响 `event_damage_rate`，各带独立开关 + 系数。
3. **极端阈值熔断**：单周期阀门总效应使最终值相对本周期基准（= 原始值）波动 > ±15% 时，强制拉回基准（零跳变保证）。

### 3.3 唯一接线点
`period_settlement.gd` 结算 `结算()` 返回 `卡` 前，对 `卡["明细"]["灵石增量"]` 套一次阀门：
```gdscript
# === F2 全局调节阀门（ECON-02 跨功能强约束 · S1-P0 · IMPL-ENG-01）===
var _平衡器 := EconomyBalance.new()
卡["明细"]["灵石增量"] = int(_平衡器.平衡(float(快照.get("灵石增量", 0))))
return 卡
```
> 注：因类型推断要求，此行 `:=` 实为 `EconomyBalance.new()`（构造函数，属扫描器已知安全调用），不触发类型推断闸。

### 3.4 参数（全 CSV 驱动 · 零硬编码）
`config/经济阀门.csv` 表头 `阀门,系数,开关,说明`：

| 阀门 | 系数 | 开关 | 说明 |
|------|------|------|------|
| global_income_rate | 1.0 | 1 | 全局产出纠偏（±15% 硬范围） |
| global_cost_rate | 1.0 | 1 | 全局消耗纠偏 / 运维同源 |
| trade_profit_rate | 1.0 | 0 | 坊市增益（默认关，待 D 类接入） |
| event_damage_rate | 1.0 | 0 | 负面影响（默认关，待 D 类接入） |
| 熔断阈值 | 0.15 | 1 | 单周期振幅熔断线 |
| 基准值 | 366 | 1 | 标准局月产（ECON-01 §三，参考/测试用） |

> **表头独立设计说明**：项目内 `评级节奏.csv` / `节奏校准.csv` 使用 `参数,值,说明` 表头，`validate_all.py` 的 `identify_table` 按首列值匹配预期字段。若 `经济阀门` 复用该表头会被误识别为 KV 表，故采用独立表头 `阀门,系数,开关,说明`，并在 `csv_validator.gd` 与 `validate_all.py` 的 `TABLE_RULES` 中单独注册（`required_fields=["阀门","系数","开关","说明"]`、`primary_key="阀门"`、系数 float≥0、开关 float∈[0,1]）。

## 五、(b) pre_f5 产耗±15%红线闸门 —— 四层设计

`check_resource_redline.py` 作为 `pre_f5_check.py` 第 11 道子进程闸（接在「七载奖励零通胀校验」之后），复用 `run_check` + `CHECKS` 编排。四层如下：

- **A) 系数基线偏差层**：从 `game_state.gd` 抽取关键系数（建筑保底津贴、升级消耗基数/指数、任务奖励系数上限、随机事件奖励系数、招徒基础概率/上限、气运产出加成=0.02、等级/建筑等级乘区步进）及 `经营基数` 和（解析 Dictionary 累加），逐项对比 `config/经济基线.csv` 中系数基线，偏差 > ±15% 即 `fail()`。
- **B) 公式镜像层**：镜像 `预估月产出()`（标准局 L=4、N=48、n_per=4、BL=2、经营加成=0.10、产出buff=0.01）复算月产，对比标准局月产（366）偏差 > ±15% 即 `fail()`；附带条件式盈余率红线（仅当 `F2_阀门_接线==1 AND F3_经营加成_封顶==0.30` 才阻断，否则 WARN）与特征影响卡位（读取 `config/新功能冲击声明.csv`，缺失则 WARN 跳过）。
- **C) 静态护栏 + F2 接线层**：校验 `economy_balance.gd` 引用 `经济阀门.csv`、含三个阀门键、含 `push_error`/0.15/红线硬范围；校验 `period_settlement.gd` 调用 `EconomyBalance.平衡()`；F3 经营加成封顶（单建筑≤0.20/全≤0.30）仅当 `F3_经营加成_封顶==0.30` 才阻断，否则 WARN（符合 ECON-01 §4.6 门控：F2/F3 未同时接线时仅 WARN 不阻断）。
- **D) 事件渠道占比层**：`事件渠道月均产 / 全月均产 ≥ 5%` 即 `fail()`（ECON-01 安全线：事件渠道 <5%）。

任一层失败 → `sys.exit(1)`；全过 → 打印 `ALL ASSERTIONS PASSED · 产耗红线 OK ...` 并 `sys.exit(0)`。

1. ECON-02 跨功能强约束明确：坊市 / 运维 / 负面影响进 S1 的**前置条件**是 F2 阀门已接线且通过可行性验证。

因此，D 类具体功能逻辑（宗门运维成本、坊市行情、负面影响经济侧）的实现可启动——但实现时须：
- 通过 `config/经济阀门.csv` 的 `trade_profit_rate` / `global_cost_rate` / `event_damage_rate` 三个旋钮接入，不得绕过 `economy_balance.gd` 直接改结算；

> **建筑产业链（全链路）仍按 ECON-02 结论递延至 S2**，S1 仅承接 T≤55 净零汇子集，本任务未涉及。
