## 四、核心循环与节奏

**登录 → 离线推演**（`现实秒每游戏日 = 240`）→ 折算流失天数（上限 3650）→ 每 30 日一批 `推演一月()`：弟子修炼突破 → 藏经阁悟道点 → 复检成就 → 殿阁被动 → 宗门事件 → 招徒 → 灵兽孵化 → 历练结算 → 差事推进 → 年结/七载大考。

**手动操作**：宗务领日常 → 弟子页招徒/试炼/装备 → 殿阁任命升级 → 历练派弟子 → 坊市买卖 → 库藏合成开箱 → 日供领 30 绑定仙玉。

### ⚠️ 节奏风险（核心问题）

| 周期 | 游戏日 | 真实时间 |
|---|---|---|
| 日常 / 周常 / 月结 | 1 / 7 / 30 | **4 分钟 / 28 分钟 / 2 小时** |
| 年结 / 七载大典 | 365 / 2555 | 24.3 小时 / **7.1 天** |

**1 游戏日 = 4 真实分钟**导致日常任务每 4 分钟刷新一次，「一天」被压缩到分钟级——短期反馈极快，但**长期目标严重错配**：练气圆满需 3 真实天、**仙阶圆满累计 381 真实天（≈1.04 年）**，而道阶层 99999 日/层实际不可推进。

## 五、数值与经济诊断（重点问题）

### 5.1 殿阁升级「高阶不回本」（结构性缺陷）
- 成本：`_升级消耗_灵石() = ceil(200 × 1.5^(L-1))` —— **指数增长**
- 收益：增益约线性（+10.4/月 → +5.4/月 → …）
- 回本周期：**L1→2 约 19 月、L2→3 约 56 月、L3→4 约 83 月**
- 结论：**高阶殿阁升级是负收益陷阱**，玩家升到 2-3 级后升级动力归零。且该函数标注 `[PLACEHOLDER] 待数值 GDD`，成本曲线从未校准。

### 5.2 仙玉体系失衡（付费设计缺陷）
- 免费日供 **30 绑定仙玉/游戏日 = 450/真实小时**
- `消耗仙玉()`(`game_state:6769`) **优先扣绑定**，而皮肤/抽奖走此接口
- 后果：**免费币可完整顶替付费币**；至尊礼包（98 元给 1000 绑定仙玉）≈ 仅值 **2.3 小时的免费日供**，付费价值感几乎归零

### 5.3 死资源（产出无消耗）
- **灵草 / 矿石**：`resource_flow.csv` 标记 `suspended_s1`，代码中**无任何消耗点**
- **香火 / 信徒**：`_结算香火_S1()` 是 `pass` 空桩，恒为 0，但 UI 顶栏有展示胶囊
- **体力**：上限 `50+(门派等级-1)*5`，**无日恢复**（代码注释明写「体力系统暂未实现」）

### 5.4 红线只锁住 0.94% 的产出盘子
`经济基线.csv` 全月均产 39066（日常 34600 + 周常 3090 + 机缘 1010 + 自动 366），而 ±15% 红线**只锚定自动产出 366** —— 占 96.5% 的活跃产出完全无约束，通胀风险敞口极大。

### 5.5 其他数值问题
- 道阶 `每层所需日 = 99999`（哨兵值）→ 顶层境界实际不可推进
- `disciple.gd:99` 硬编码稳固期（元婴730/化神1460…）与 `节奏校准.csv`（1800/3000…）**严重背离**
- `game_state.gd:14` 注释「1 现实分钟 ≈ 1 游戏年」与 240s=1日 **矛盾**（实为 24.3 小时/年）
- 年结用 365 日、月内用 `% 30`，**年/月不整除**（365 ≠ 12×30）

## 六、工程健康度

### 6.1 架构
- **`game_state.gd` = 上帝对象**：11492 行、549 函数，同时承担状态/存档/推演/战斗/经济/文案/成就，`preload` 硬依赖 8 个模块
- **循环依赖**：`game_state.gd` preload `Disciple/Item/Beast/Lore/Quest`，而 `disciple.gd` 反向引用 `Game.` 22 处
- **47/99（47%）的 `.gd` 直接引用 `Game.`**，`main.gd` 330 处、`page_building.gd` 122 处——无接口层隔离
- **18 个 Autoload 全部常驻**，无按需加载

### 6.2 质量保障（薄弱）
- **无单测框架**：`tests/` 下 5 个 `.gd` 全是运行时模拟器/手动工具，非断言套件；93 条战斗断言由 Python 脚本在 pre_f5 里跑，**游戏内自动化覆盖率 ≈ 0**
- **无 CI**；`.git/hooks/pre-commit` 调用 pre_f5 且明令「禁止 --no-verify」，但当前 8 项 FAIL 而最近 10 次提交照常入库 → **钩子实际已失效**
- **门禁信噪比低**：29 闸 8 红，其中「1606 处裸中文方法调用」经核实 **KNOWN_BAD=0，全为误报**（扫描范围含 `.scratch_backup` 备份目录）

### 6.3 技术债
- 硬编码中文字符串 **10424 处**（`game_state.gd` 6973、`main.gd` 1138）——此前「长叙事抽表」仅抽 56 条，**比例 1:186，未解决根本问题**
- **11 张孤儿 CSV**（`sect_ship_config` / `teleport_array_config` / `flying_beast_config` / `caravan_*` / `title_config` 等）——「飞船/传送/飞行/商队」只建了表、没实现
- 根目录 **356 个一次性 `.py`** 脚本坟场，无归档
- 配置表 schema 漂移：44 表 / **70 错误 / 29 警告**（`achievement_config.csv` 条件枚举大面积非法）
- `main.gd:2328` 访问 `d.命格`，但 `disciple.gd` 只声明 `destiny_id` → 命中即 `Invalid get index`
- 离线推演性能热点：流失日上限 3650，按 30 天一批循环 **122 次**，每次至少 2 遍遍历弟子列表 → **O(122×2N)**，主线程无进度条，长时间离线后冷启动卡顿

| 「战斗引擎仅旧 UI 可达 / 不可用」 | `BattleCalculator` 在 `.gd` 中被引用 **39 次**、`BattleManager` 17 次 | 结论方向成立（新 UI 无入口）但引用量描述失准，已修正 |
