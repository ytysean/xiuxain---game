# 双周期评级体系（岁末考评 + 七载宗门大考）

> 阶段：Phase 5 · S0 收口后增量（2026-07-23 落地）
> 关联：`game_state.gd`（`_年结评分` / `_发放周期奖励` / `更新门派` / `_七载大考`）、`period_settlement.gd`、`config/评级节奏.csv`、`config/节奏校准.csv`
> 设计基线：`design/04-数值体系/数值体系细则.md`、`design/04-数值体系/修炼周期与境界膨胀治理方案.md`

---

## 0. 一句话定义

把「年度评级奖励」拆成 **年度 70% 即时发放 + 七载 30% 递延至七载大典集中结算**，并把「宗门等级晋升」的生效时机从「年度实时」改为「七载大典生效」。**全程零新增资源**——7 年总奖励 = 7 × 原年度奖励。

---

## 1. ⚠️ 事实偏差声明（务必先读）

**早期讨论曾隐含一个错误前提：「评级原本是按月结算，现在要拆成年度 + 七年。」这是错的。**

- 实际代码：`周期评分.结算()`（`period_settlement.gd`）产出的是**年度评级**；`game_state._年结评分()` 由 `推演一月` 跨 **365 日** 边界触发（游戏年 = 365 日），**从未有过月度评级**。
- 因此本特性**不是「把月度评级拆成两段」**，而是：**评级频率本来就是年度，本特性只改变了「年度奖励的发放节奏」与「宗门等级的生效时机」**。
- 拆分对象是 **奖励的发放时点与量级分布**（70% 当下 / 30% 七年一度），**不是评级本身的频率**。任何后续维护者不要误以为需要再去「改评级为月度」——那会把设计带偏。

> 这个偏差已记入本文件，避免后人顺着错误前提二次开发。

## 2. 设计裁决（用户 q-0 / q-1）

| 项 | 裁决 |
|---|---|
| 三档范围 | 全部落地：年度 70% / 七载 30%×7 / 宗门等级七载生效 |
| 七载大考形态 | **零新增奖励版**：只重排发放节奏，不引入任何新奖励类型/数量 |
| 量级铁律 | 单位时间总奖励 = 当前等级原值；仅拆分分布节奏，**零新增资源** |
| 招徒概率 | 校准为 **75%**（按季度触发） |
| 随机事件 | 半年触发一次 + 单次奖励 ×**1.8** |
| 奇遇 | 保留日上限 5 |
| 配置化 | 全部数值走 CSV（`评级节奏.csv` / `节奏校准.csv`），不硬编码 |

| 通胀锁死 | `pre_f5_check.py` 新增「七载奖励零通胀校验」闸门：占比和≠1 或 7 年总奖励偏差 > ±5% 即阻断 |

## 3. 零通胀不变量（数学）

设某年评级得奖 `奖`，年度占比 `a=0.70`、七载占比 `s=0.30`（`a+s=1`）：

- 年度即时发放：`a·奖`
- 递延入池：`s·奖`（累积 7 年 → 池 = `7·s·奖_avg`）
- 七载大典一次性结算池

7 年总发放 = `Σ(a·奖_i) + Σ(s·奖_i) = Σ(奖_i)` = **7 × 原年度总奖励**。偏差严格为 0。

> 高阶掉落（S 及以上上品法宝）同样平移至七载大典一次性赐下，7 年赐下数量 = 原 7 年 S+ 次数，**无数量通胀**，仅改为集中发放。

## 5. 代码落点

| 函数 | 职责 |
|---|---|
| `game_state._年结评分()` | 跨 365 日触发；调用 `_发放周期奖励`；跨 2555 日（7×365）触发 `_七载大考` |
| `game_state._发放周期奖励(评级) -> Dictionary` | 双周期：年度 `a·奖` 即时 + `s·奖` 入池；S+ 法宝入 `七载待发掉落`；回退：全额即时。返回 `{年度发, 入池, 平移法宝}` 供 UI |
| `game_state.更新门派()` | 双周期：成长值写入 `门派等级目标`（递延）；回退：直接 `门派等级 = 新等级` |
| `game_state._七载大考()` | 发放 `七载奖励池` + `七载待发掉落` 法宝 + `门派等级 = 门派等级目标`；置 `七载大典待展示` + `七载大典摘要` |
| `main._构建离山内容()` | 岁末考评卡片（三栏：评级 / 当年论功 / 七载积存 + 双倒计时）；读取 `七载大典待展示` 弹七载大典 |
| `main._弹七载大典()` | 七载大典仪式弹窗（纯展示，零数值） |

**新增/改动字段（存档兼容，不 bump SAVE_VERSION）**：`七载奖励池` / `七载待发掉落` / `门派等级目标` / `上次七载日`，均 `data.get(..., 默认)` 读回，老档自动兜底。

## 6. 测试与护栏

- `pre_f5_check.py` → 「七载奖励零通胀校验」闸门（纯 stdlib，`check_rating_inflation.py`）：
  1. 配置层：`年度奖励占比 + 七载奖励占比 ≈ 1.0`（偏差 > 0.001 阻断）
  2. 公式镜像层：代表性 7 年序列复算，7 年总奖励偏差 ≤ 5%
  3. GDScript 守恒层：静态校验 `game_state.gd` 比例读配置、`入池 = 奖 - 年度发`、`_七载大考` 消费池
  4. 年度产耗校验：招徒/随机事件系数在合规区间
- 现有断言（战斗/命格/灵兽/弟子终局/资源/增益）不受影响，全量 16 闸门绿灯。
