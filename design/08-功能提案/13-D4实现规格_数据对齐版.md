## 1. 声望外部类激活规格（交付物 1）

### 1.1 缺口与落点
- **缺口（D3 留浅接线）**：`game_state.gd` L1394-1396 `_负面事件结算` 的 `卖价` 分支：`if _neg_reputation: _坊市负面卖价下限 = min(_坊市负面卖价下限, pv)` —— 已在写入 `_坊市负面卖价下限`，但 `坊市实价(原价, 类别)`（L392-399）**未消费**该下限 → 即便 neg_reputation=1 触发 ne_011/012，售价不降。
- **D4 落点**：在 `坊市实价()` 的 D2 浮动乘子**之后**叠加 `_坊市负面卖价下限` 乘子。

### 1.2 改动后 `坊市实价()` 伪代码（仅加 2 行，不重写）
```gdscript
func 坊市实价(原价: int, 类别: String = "") -> int:
    var 价 = ceil(原价 * 坊市折扣率())            # 现有声望折扣
    var 行 = _坊市行情表().get(类别, {})
    var 下限 = float(行.get("浮动下限", 0.90))
    var 上限 = float(行.get("浮动上限", 1.10))
    var 浮动 = randf_range(下限, 上限)             # D2 买价浮动（±10% 摆动，每调用随机）
    价 = int(round(价 * 浮动))
    价 = int(round(价 * _坊市负面卖价下限))        # 【D4 新增】声望外部类卖价下限一次性下调（0.92，不摆动）
    return 价
```
- **公式（带单位）**：
  `成交价 = ceil(原价 × 声望折扣率()) × randf_range(D2浮动下限, D2浮动上限) × _坊市负面卖价下限`
  - 单位：灵石/件；`_坊市负面卖价下限` 默认 `1.0`（无效果），ne_011/012 触发 + neg_reputation=1 时置 `0.92`。
- **月度重置（D4 必加，修正 D3 遗漏）**：`_坊市负面卖价下限` 在 D3 `_结算负面事件_S1`（L1356-1357）中**未重置**，会导致卖价下限永久滞留 0.92。D4 须在 `_结算负面事件_S1` 开头补：`_坊市负面卖价下限 = 1.0`（与 `_本月灵石冲击 = 0.0` 同位置重置），保证每月重新评估。

### 1.3 neg_reputation 0 → 1
- `config/经济阀门.csv` 行 `neg_reputation,1.0,0,...` → 翻为 `neg_reputation,1.0,1,...`（确切行见 §4）。
- 翻转后：`_负面事件结算` 的 `卖价` 分支（L1394-1396）开始执行 → `_坊市负面卖价下限 = min(1.0, 0.92) = 0.92` → `坊市实价()` 消费 → 成交价 −8%。

### 1.4 ne_011 / ne_012 生效验证
- 触发条件：randf() < base_prob（ne_011 0.03 / ne_012 0.02）且 monthly_limit（3 / 2）未耗尽。
- 生效后：`_坊市负面卖价下限 = 0.92`（min 取最严，多次触发仍为 0.92）。
- 验证点：玩家当月购买 `坊市实价(原价)` 返回值 = `原价 × 折扣 × 浮动 × 0.92`，较无事件时低 ~8%（浮动为随机项，下限方向确定性成立）。

### 1.5 与 D2 边界表（显式区分，防冲突误判）
| 维度 | D2 坊市行情（买价浮动） | D4 声望外部类（卖价下限） |
|---|---|---|
| 作用函数 | `坊市实价()` 内 `randf_range(下限,上限)` 步 | `坊市实价()` 末尾 `× _坊市负面卖价下限` 步 |
| 数据来源 | `坊市行情.csv`（浮动下限/上限） | `negative_event.csv` ne_011/012 `punish_value=0.92` |
| 摆动性 | **每调用随机摆动**（±10%） | **一次性下限**，事件触发后整月固定（不摆动） |
| 数值 | [0.90, 1.10]（±10%） | [0.85, 1.0]（0.92，−8%） |
| 经济侧 | 玩家买价（宗门中性，不触 Σ，ECON-02 §2.1） | 玩家交易价/售灵收益 −8%（社计口径，非宗门直接损失，0 Σ 占用） |
| pre_f5 | Layer A 浮动∈[0.85,1.15] | Layer A 卖价∈[0.85,1.0] |
| 冲突 | **无**：二者为 `坊市实价()` 内独立乘子，乘法可交换；均作用于玩家侧，不触宗门 Σ/±15% 红线（坊市中性）。运行时乘积最低 ≈0.90×0.92=0.828（玩家更便宜），属体验范畴，非宗门红线问题。 | |

## 3. 品级权限类最小可交付定义（交付物 3）

### 3.1 经济化要求与核查结论
- **要求**：品级权限类作为「负面影响经济侧」，必须产出可量化经济后果（非纯叙事/摆设）。
- **用户首选路径**：`权益回收` = 触发 `罢免阶位(d)` 褫夺某弟子堂口职位，经济后果 = 该堂口当期资源产出/收入 ×(1 − 惩罚%)。
- **堂口产出锚点核查（结论：不存在）**：
  1. `_资源建筑产出()`（L2016-2063）把产出**直接累加进全局 `灵石/矿石/灵草` 池**（`灵石 += 产`、`灵草 += 产`、`矿石 += 产`），**无任何按堂口留存「当期资源产出/收入」字段**可供扣减。
  2. 堂口系统 dict 的 `产出` 字段（L229）为**展示文本**（架构复盘 REVIEW-104 明确：堂口「产出」字段仅为文本，不实算）。
  3. 负责人产出 buff（P0-BUILD-2 L2023-2024）= 全局 +1%/座，且 `罢免阶位`（L2676-2686）**仅改 `d.阶位`，不解除/不触碰 `堂口列表[key]["负责人"]`** → 罢免对产出 buff **零自动影响**。
  - **结论**：首选「堂口产出 ×(1−惩罚%)」路径**无锚点、需新建按堂口结算追踪系统 = 重写底层框架 / 造摆设** → **否决**。
- **采用用户授权备选**：`权益回收` 惩罚折算为 `_本月灵石冲击` 派生的**「治理失序罚金」固定值**（须在 Σ≤62 内）。真实可量化、复用既有 Σ 卡位、零摆设。

### 3.2 `权益回收` punish_type 定义（本批做）
| 项 | 定义 |
|---|---|
| punish_type | `权益回收` |
| 归属类别 | 品级权限（`_punish类别` 映射 → `"品级权限"`，由 neg_grade_perm 分闸控制） |
| 动作（真实，非摆设） | 取一名 `阶位 != "无"` 的弟子 d，调用既有 `罢免阶位(d)`（L2676）—— 降阶位一级 + 写宗门纪事。若无可降弟子，动作跳过（不影响罚金）。 |
| 经济后果（真实，可量化） | `治理失序罚金 = punish_value`（固定值，单位：灵石）累入 `_本月灵石冲击`，经既有 `_负面总冲击卡位()`（L1405）受 Σ≤62 卡位后扣公库。 |
| 数值 | `punish_value = 20`（= 5.46% × 366，落入 D3 Layer A [5%,17%] 红线带，无 warn；Σ 占用 20/62=32.3%）。 |
| 忠诚（best-effort，非阻断） | 罢免阶位当前**无**忠诚惩罚接线（与 D3 §5「已有覆盖」表述不符，已核实代码 L2676-2686 不含忠诚逻辑）→ 规格建议工程在 `罢免阶位()` 或管理器内对 d 施加 `忠诚 −15`（复用 `_施加弟子属性惩罚("忠诚", 15, d)` 若支持定向）；**若本期不接，不影响经济交付（罚金已保证惩罚>0）**，列为待工程核对项 O2。 |

### 3.3 `降级` 为何不做独立枚举（取舍论证）
- 降级语义 = 弟子身份/阶位下降（调 setter）。但「降级省俸禄」是**省支出（宗门少付）非受损（宗门多扣）**，经济语义矛盾 → 若作为经济扣减源则数值造假。
- 故 `降级` **不作为经济扣减源**，仅作叙事 +（若接）忠诚惩罚 —— 其叙事/忠诚效果已通过 `权益回收` 的 `罢免阶位(d)` 动作承载。
- **决策**：不新建 `降级` punish_type，避免「纯叙事枚举占用四分类 + 无经济后果 = 摆设」。**若主理人坚持要纯叙事降级事件**，见待拍板项 O3（届时为 narrative-only，明确不占 Σ）。

**声望类论证（不破红线）**：
