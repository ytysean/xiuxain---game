## 3. 信息架构

1. **顶部栏**：统一与其他二级页一致（深青底 `#11212A`）。
2. **殿阁总览**：司职数、总等级，两个核心经营指标。
3. **司职列表**：每行展示名称/职能/等级、产出/主事/成员、被动/政绩；右下「修葺」升级入口。真实共 12 行，超出部分滚动。
4. **御兽堂分区**：已契约灵兽、引育计划队列、新增引育计划。
5. **底部被动条**：展示殿阁被动对负面事件的减免百分比，固定于屏底，不参与滚动。

## 4. 交互规则

| 区域 | 操作 | 响应 |
|---|---|---|
| 司职卡片 | 点击卡片 | 进入殿阁详情二级子视图（`page_building.gd::DetailRoot`，复用 `page_disciple` 范式） |
| 司职卡片 · 修葺按钮 | 点击 | emit `殿阁升级请求(key)`，由宿主 / Game 处理升级 |
| 御兽堂 · 卸下主宠 | 点击 | emit `灵兽_卸下_request(弟子, 槽)`，灵兽退回库存 |
| 御兽堂 · ＋新增引育计划 | 点击 | 展开内联预设选择器（`page_building.gd::_yushou_新增选择器`），2 列网格选偏好/经费 |
| 底部被动条 | 纯展示 | 无点击 |
