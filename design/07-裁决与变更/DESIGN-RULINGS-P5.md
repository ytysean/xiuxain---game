## 裁决① §4.2 弟子面板战力系数表

公式（§4.2 第 236–247 行）：

```
弟子最终战力 =
    境界基础战力
  × 资质系数            -- 基础属性乘区，无封顶
  × 灵根系数            -- 基础属性乘区，无封顶
  × 职业综合系数        -- 基础属性乘区，无封顶（主1.0+辅0.7+三0.4）
  × (1 + 通用增益总和) -- 软上限≤0.25，硬上限≤0.30（溢出 20% 衰减）
  × (1 + 道心增益)    -- 道心独立乘区，总增益≤0.10
  + 灵兽契约战力加成    -- 主战×1.0 + 助战×0.2（助战仅被动 20%）
```

### A. 资质系数（基础属性乘区，无封顶）

权威来源 §6.4 七档「初始属性总系数」（第 607–615 行）：

| 资质档位 | 系数 |
| --- | --- |
| 凡俗 | 0.9 |
| 平庸 | 1.0 |
| 优良 | 1.1 |
| 天才 | 1.25 |
| 妖孽 | 1.4 |
| 旷世 | 1.6 |
| 道胎 | 1.8 |

MVP 简化（§6.4 五·MVP，第 665–668 行）：三档合并 → 普通(凡俗/平庸)=1.0、优秀(优良/天才)=1.15、顶级(妖孽/旷世/道胎)=1.6。

> ⚠️ **与 eng 临时口径的对齐 TODO（非阻断 E4）**：ADR-001 D3 用 `资质系数 := 资质表[资质]["速度"] / 4.8`。本裁决的权威系数是上表 0.9–1.8 区间，与「速度/4.8」并非同一标度。请 eng 将 `disciple.资质` 的速度属性归一化到 0.9–1.8 区间（或改用本表的 资质档→系数 查表），保证 `计算战力()` 产出落在设计量级。该对齐不影响 E4（E4 只卡通用增益 25%/30%），标非阻断。

### C. 职业综合系数（基础属性乘区，无封顶）

权威来源 §4.2 第 242 行 + §4.1 定案第 227 行：

```
职业综合系数 = 主职业×1.0 + 辅修职业×0.7 + 三修职业×0.4   （按激活职业数量计算）
```
- 单职业：1.0
- 主+辅：1.7
- 主+辅+三：2.1

> 注：此系数是对**整体战力**的乘子（§4.2）。它与 §6.1.1 三职业铁三角「初始属性分配结构」（体修血防高/法修攻速高/道修均衡，第 634–638 行）是正交的两层——分配结构只改基础值构成，不改变总属性量；职业综合系数是多职业激活的额外乘子。两者都要落，不要二选一。

### D. 道心增益（道心独立乘区，总增益≤0.10）

权威来源 §4.1 红线第 208 行 + §4.2 第 244 行：道心增益独立乘区，**总增益硬上限 10%**，不占通用 25% 额度。

- 当前无道心系统 → 弟子道心增益 = **0.0**（占位正确）。
- 道心系统落地后：`道心增益 = Σ(道心标签 BUFF)`，单弟子总封顶 0.10（§6.9.1，圣品 50%/真品 80%/道品满效果，第 1953/1962 行）。

## 裁决② 装备单源子帽数值基线（§4.1 v2.19 口径）

### 口径铁则（§4.1 第 233 行 + §4.2 v2.20 第 247 行）

所有「来源子类」先各自**边际乘算衰减**收敛到**单源子帽**，收敛值再**加算**汇入「通用增益总和」feeding `(1 + 总和)`，最终强制卡软上限 25% / 绝对硬上限 30%（溢出 20% 衰减）。跨乘区（通用/道心/产出效率/减耗/临时战斗）独立乘算，永不加算合并。**禁止任何来源「裸线性加算到上限」绕过子帽**。

### 文档已钉死的子帽（§4.1 v2.19）

| 来源子类 | 单源子帽（全局等效） |
| --- | --- |
| 功法类 | ≤ 2% |
| 血脉类 | ≤ 1.5% |
| 大阵 / 聚灵 / 先贤堂 / 常规养成 | 各有上限（见 §11.x，文档未在此处给单值，下同「各有上限」） |
| 自创功法 | 单功法≤3% 单属性、主修1+辅修2、等效全局约 2% |
| 家族气运 | 单家族≤1% 全局属性、多家族边际衰减、全局合计≤2% |
| 血脉共鸣 | 组队等效全局约 1%~1.5% |
| 灵兽辅助修炼 | 单只≤3%（通用池） |

文档明示：叠加现有大阵/聚灵/先贤/常规养成后，**总等效约 23%~24.5%，卡 25% 软上限不击穿**（第 233 行）。

### ⚙️ 装备单源子帽 · design 裁决基线（文档未给单值，由 design 设定）

文档 §4.1 v2.19 列举的子帽中**未显式给出装备的独立数值**，仅在第 247 行将「装备」列为来源子类之一、要求「收敛到单源子帽」。为解除 E4 阻塞，design 设定：

> **装备单源子帽（全局等效）基线 = ≤ 8%**
> 理由：装备词缀是玩家**主动养成的主要放大器**，应占最大单源份额；8% 与其他已钉子帽汇总（功法2% + 血脉1.5% + 家族2% + 自创2% + 灵兽~3% + 大阵/聚灵/先贤/常规≈6%）≈ 24.5%，精准贴合文档自述的 23%~24.5% 总预算，留出边际余量不击穿 25%。

**装备子帽收敛公式（落地建议，供 eng 实现 `聚合通用增益()` 的装备分支）**：

```
装备词缀池 =
  for 每个已穿戴槽位的 item:
    槽位内词缀% 先加算 → 槽位内边际衰减（同槽多条词缀收益递减）
  跨槽位再边际乘算收敛（槽位 n 贡献率 ×0.5^(n-1) 衰减）
装备子帽 = clamp(收敛值, 0, 0.08)        -- 单源子帽 ≤8%
通用增益总和 += 装备子帽                     -- 再进 25%/30% 池总帽
```

> ⚠️ 此 8% 为 **design 基线**，按文档自身 [PLACEHOLDER] 惯例标记 `[DESIGN_BASELINE, 待实测校准]`。E4 的 PASS 条件（任意装备组合下 `聚合通用增益()` ≤ 硬上限 30%、软 25% 溢出按 20% 衰减）现已可判定；若实测发现 8% 偏松/偏紧，回调装备子帽即可，不影响机制正确性。最终数值待老大/实测拍板。

## 奇遇 CSV 结构确认（eng 问询：quest_random.csv / random_entry_pool.csv 是否已是 §10 规范结构）

**结论：两者均不是 §10 奇遇核心池（8 类×25=200 则 / 四档稀有度权重 10000）。当前 config/ 下 §10 核心池缺失，奇遇引擎将退 `Lore.取奇遇` 兜底（与 ADR-002 R1 预警一致）。**

### 逐表判定

**`quest_random.csv`（9 行 = 8 数据 + 表头）**
- 列：`quest_id, quest_name, quest_type, trigger_type, trigger_prob, valid_time, unlock_sect_level, difficulty, reward_pool_id, reward_lingjing, reward_lingqi, quest_npc_id, is_auto_complete`
- 内容样本：`random_001 云游修士委托 / 访客委托 / 登录 / 0.15`；`random_002 妖兽悬赏 / 访客委托 / 历练归来 / 0.1`
- 判定：❌ **非 §10 奇遇**。实为「访客委托 / 妖兽悬赏」随机任务表（trigger=登录/历练归来，reward 引用外部 pool）。结构不对口，奇遇引擎**不应**读它作正文源。

**`random_entry_pool.csv`（21 行 = 20 数据 + 表头）**
- 列：`entry_id, entry_name, entry_category, value_type, tier_grade, base_value, value_grow_per_lv, apply_slots, rarity, weight_common, weight_rare, weight_epic`
- 内容样本：`ent_001 攻击力提升 / 攻击类 / 百分比 / T1灵品 / 3% / 0.5% / 武器,饰品 / 普通 / 80,20,5`
- 判定：❌ **非 §10 奇遇正文**。实为「词条/属性 entry 池」（含 rarity + `weight_common/rare/epic` + `apply_slots`），**仅 3 档稀有度（普通/稀有/史诗），缺第 4 档「传说/金」**；且是「属性加成词条」而非「奇遇正文+四维分支」。→ 可复用为**奇遇奖励词条层**，但非正文源。

**`event_quest.csv`（11 行 = 10 数据 + 表头）**
