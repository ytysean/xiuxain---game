## 二、B-03 可利用路径（重点条目）

**缺陷**：`game_state.gd:25606` 载入后 `主线已完成` 恒被清空 ⇒ 已完成主线可**重复领取奖励**。

### 1. 涉及的两个按钮
- **「尽数收取 / 一键领取」**（任务页）：`ui/page_quest.gd:1381-1386` —— 遍历 `取主线任务列表()`，对 `state == "claimable"` 的每条调 `Game.领取主线(id)`。
- **单条「领取」**：`ui/page_quest.gd:1268-1270` —— 直接调 `Game.领取主线(quest_id)`。

### 2. 为什么能重复领（缺陷机理）
1. `Game.领取主线(qid)`（`game_state.gd:9737`）首行闸门：`if 主线已完成.has(qid): return {"ok": false, "msg": "已完成"}`（`:9739`）；通过后发 灵石/灵气/声望/灵草 并 `主线已完成.append(qid)`（`:9763`）。
2. 状态判定 `取主线任务列表()`（`:9683+`）用 `主线已完成.has(qid)`（`:9694`）决定是否 `claimable`。
3. **根因**：load 时 `主线已完成 = data.get("main_done") if "main_done" in wjson else []` —— 键 `main_done` 实际写在**存档 root**（`save_game` `:24906`），而代码查的是 `wjson`（weekly 子字典，`:25600`）⇒ 条件恒 false ⇒ **每次载入清空为 `[]`**。
4. 清空后：`取主线任务列表()` 把已领任务重新判为 `claimable` ⇒ 按钮再次调用 `领取主线` ⇒ 闸门 `has()` 为假 ⇒ **再发一次奖励**。
5. **可利用性**：单机离线；每重启一次会话即可重领一次 ⇒ 数值膨胀（灵石/灵气/声望/灵草）。无网络/无其它前置，纯 UI 操作可达。

### 3. 修复后为何不可重复
- Batch 1D 改读 root：`data.get("main_done") if "main_done" in data`（`:25606`）⇒ 载入**正确恢复** `主线已完成`。
- 于是 `has(qid)` 为真 ⇒ `领取主线` 首行 **立即 return** `{"ok": false, "msg": "已完成"}`（**VERIFY-3 §3 V3.5 实证**：`领取主线(main_001)={"ok":false,"msg":"已完成"}`）。
- 且 `取主线任务列表()` 不再把已领任务标为 `claimable` ⇒ 一键领取遍历时不会触碰。

### 4. 副作用独立复核（不采信工程结论，QA 自验）
- **load 本身不发奖**：VERIFY-3 §3 V3.4 —— 载入前后 `灵石 1000→1000 / 灵气 460→460 / 声望 33→33`（load 恢复存档值，未凭空增加）⇒ **无发奖副作用**。
- **重领被拒且不改状态**：V3.5 返回「已完成」；V3.6 重领后 `主线已完成` 仍 `["main_001"]`、资源未变 ⇒ 无一次性弹窗/无二次发奖。
- **静态佐证**：全仓 `领取主线` 的调用点仅在 UI 页（`page_quest.gd:1270/1385`），**load 路径及其 deferred（`离线结算`/`_迁移宗主实体`）均无调用** ⇒ 载入不可能发奖。
