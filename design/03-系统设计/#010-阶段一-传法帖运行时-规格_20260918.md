## 2. 链引擎数据模型

### 2.1 `chain_id` 构造规则

**决定**：采纳现表口径，**不新造规则**——`chain_id = "T_" + 系统key`。

- 依据（实测）：`quest_teach.csv` 的 19 个 `chain_id` 与 `绑定系统key` **一一对应**（`T_alchemy↔alchemy`、`T_forge↔forge`…），构造即 `"T_"+系统key`。
- `newbie` 链：把现有 `newbie_001~007` 视为 `chain_id="newbie"` 的首条链（GDD §2.1：`is_newbie` 标志扩展为 `chain_id`）。⇒ 通用引擎里 `newbie` 与 `T_*` **同构**，天然兼容。
- 落到文件：`game_state.gd` 的链配置装配函数（新增，取名如 `_传法_配置()`；与既有 `_新手_配置()` 平行）。

### 2.2 链 / 步 的运行时结构

**复用 `quest_daily.csv` 18 字段的哪些列（同名直取，不改名）**：

| 运行时字段 | 来源列 | 说明 |
|---|---|---|

| `chain_id` | `chain_id` | 链键 |
| `name` | `名称` | 步名（如「炼丹·初识」） |
| `desc` | `描述` | 步描述 |
| `condition_type` | `condition_type` | 条件类型（8 枚举，见 §2.4） |

**需新增列 / 缺失列**：

- ❌ **本表无 `prev_quest_id` 等价列**（对比 `quest_daily.csv` 有 `prev_quest_id`）。⇒ **链内串联只能靠 `(chain_id, int(步序))` 升序**。
  - **决定**：运行时按 `(chain_id, 步序)` 排序推导「下一步」；**不改 CSV**。
  - 若未来要在 CSV 层显式串联，再增 `prev_teach_id` 列——但**增列须同步 `csv_validator.gd` + `validate_all.py` 两处镜像表**（GDD §3.1）。**本阶段不增。**
- ❌ **本表无 `target_num`**：阈值语义现由 `condition_param` 承载（如 `recruit_count,1`）。**决定**：运行期统一读 `condition_param`，`target_num` 缺省视为 `1`。

**链/步的运行时容器（建议结构，供 engineer 落地）**：

```
传法链表: Dictionary   # chain_id -> Array[步字典]，按 int(步序) 升序
当前激活链: String      # "" = 无
传法进度: Dictionary    # chain_id -> { "已完成步": Array[teach_id], "链完成": bool, "激活日": int }  （存档键，增量+默认兜底）
传法计数: Dictionary    # 持久计数器：condition_type[:param] -> int（★ 见 §8-R5，禁复用会每日清空的 日常计数）
```

### 2.3 多链并行时的「当前链选取算法」

**决定：同日只激活 1 条；排队判据 = `unlock_order.csv` 的 `(阶段, 顺序)`，非优先级列。**

- 依据：`quest_teach.csv` 与 `system_meta.csv` **均无「优先级」列**；唯一既有顺序源是 `unlock_order.csv` 的 `(阶段, 顺序)`（GDD §2.1 原文：「按 `unlock_order.csv` 顺序入队」）。
- 算法（纯函数，建议置于 `game_state.gd`，取名如 `传法帖_放行一条()`）：

```
候选 = { 系统key : SystemUnlock.已解锁系统列表() 含该 key
                  AND quest_teach 有该 key 的步
                  AND 该 chain_id 未激活 AND 未完成 }
若 当前激活链 非空 且 该链未完成 → 保持不动（不抢档，当日不再放行）
否则 → 按 unlock_order 的 (阶段序号, 顺序) 升序取候选第一 → 激活；当日不再激活第二条
```

- 「同日」口径：**按真实日切换**（对齐 `game_state.gd::_推进差事系统` 的 `86400s` 真实秒差分支），**不按游戏日**——因 `_推进差事系统` 已是全项目唯一真实时钟刷新点。
- 「链步之间不强制等待」：当前步完成即推进同链下一步（**不做每日 1 步限制**）；末步完成 → 链完成 → **次日**放行下一条。
- `newbie` 链优先：`newbie` 未完成时先走 `newbie`（它不在 `unlock_order` P0–P7 表内，作为**独立前置链**，优先级高于所有 `T_*`）。

## 4. 红点口径（★ 设计评审重点）

### 4.1 结论

**传法帖红点 = 「待裁决队列型（进度/待办驱动）」，不属于「未读内容型」；禁 seen（不因"看一眼面板"即消）。**

### 4.2 论证（为什么"它不是待裁决队列"这一反命题被推翻）

铁律原文判据：「**这件事宗主不做，弟子 AI 会不会替自己做？**」——会自决的一律不亮红点。

| 当前步形态（`is_auto_trigger`） | 弟子 AI 会替宗主做吗？ | 红点结论 |
|---|---|---|
| 主动型（`"false"`，如实测的 `open_page` 初识步） | **不会**——"打开该页面/前往"是宗主本人的行为，弟子 AI 无此职责 | ✅ **亮**（判据成立，是合法待办） |
| 自动型（`"true"`，如 `realm_first_enter` 修炼突破） | **会**——`disciple.gd::AI决定是否突破` 证明弟子**自决突破** | ❌ **不亮**（面板显示「（自动达成中，静候机缘）」） |

⇒ 传法帖**确为待裁决队列**：主动型当前步「宗主不做，没人替他做」。

**为什么它不是"未读内容型"（关键区分）**：

- **未读内容型**（纪事 `纪事_未读` / 灵讯 `宗门_灵讯`）：消除条件是「**看过**」（`进页即消` / seen 驱动）。
- **待裁决队列型**（弟子请示 / 执法 / **本传法帖**）：消除条件是「**做过**」（条件满足 / 队列驱动）。
- 传法帖步的消除 = 该步 `condition_type` 满足（**状态驱动**），**与"是否看过面板无关"** ⇒ **必须禁 seen**——否则"点开看一眼红点就灭、玩家反而没学会"，正是铁律要防的事。
- 同族既有先例：`宗门_宗务`（新手目标链）即"当前进行一项 + 完成即回落"的状态驱动点，`red_dot_init.gd::_刷新宗门红点()` 直接取 `Game.新手_有红点()`。**传法帖照此范式**。

### 4.3 与 `red_dot_init.gd` 的接入方式

落到 `red_dot_init.gd`：

1. `红点ID` 常量表**新增** `"宗门_传法帖": "宗门_传法帖"`。
   - **不复用** `宗门_宗务`——理由同 `宗门_执法` 的既有裁决（`red_dot_init.gd` 注释：「一 ID 一语义，塞两源会让数字与语义一起错」）。
2. `_注册层级关系()`：按 §5 的入口落点，`_管理器.注册父子(红点ID.TAB_宗门 或 首页入口聚合, 红点ID.宗门_传法帖)`。
3. 新增 `_刷新传法帖红点()`（在 `刷新所有红点()` 里调用）：
   - `待办 = 1 if (当前激活链存在 且 当前步为主动型 且 未完成) else 0`
   - `_管理器.设置红点数量(红点ID.宗门_传法帖, 待办)`
4. 形态：**一级红点（朱砂）= 仅状态 → 圆点**（`UITheme.make_red_dot(12.0)` 实心点），与既有 `宗门_执法`/`殿阁_升级`「仅状态 → 圆点」分档一致（`_注册层级关系()` 注释：父级仅状态 → 圆点）。

### 4.4 「未激活的链不亮红点」如何实现

**机制**：红点**只在「当前激活链的当前步」上求值**——排队链、未激活链、已完成的或未激活的链**一律不进入 `_刷新传法帖红点()` 的计算**。

- 因「同日只激活 1 条」（§2.3），红点源**至多 1 个** ⇒ **天然治「一次给太多」**（GDD §2.1 的核心一刀）。
- 与自动型当前步叠加 ⇒ 可能出现"有激活链但**零红点**"（当前步为自动型、静候机缘）——这是**正确行为**，不是 bug。

- **决定**：传法帖「前往」**不走 `main.gd::_跳转`**，改走 **`ui/game_ui.gd::_on_首页入口(jp)`**。依据：该函数天然支持四种落点——`ENTRY_SUB_PAGES` 开二级页、`PAGE_IDS` 切 Tab、`ENTRY_ALIAS` 别名、以及 `SystemUnlock.入口可显示()` 的 fail-open gating（`ui/game_ui.gd::_on_首页入口` 注释：未开启仅提示不进入）。
- **接线**：面板持 `game_ui` 引用（经 `Game.注册主UI()` 已可拿到，`game_state.gd` 有该注册口）→ 按钮 `pressed` → `主UI._on_首页入口(jp)`。
- **边界**：`jp` 不在路由 → 依 GDD §6.5 **静默跳过该步**（不报错、不弹窗、不卡流程），并 `_toast("此路暂未开")`。
- **可达性已实测通过**：19 链的 `jump_path` 全部落在 `PAGE_IDS`（弟子/殿阁/历练）或 `ENTRY_SUB_PAGES`（丹方/装备图纸/商道/拍卖行/毒道/闲情雅趣/灵兽/药园/论道棋弈/灵酿/音律/风水堪舆）内 ⇒ `audit_teach_chain.py` [I] 现值应为 0 越界。
