## 一、为什么必须放弃位移场（warp）路线

前一版用「柔性位移场」让整张立绘扭动。**撕裂不是调参问题，是数学必然**：

| 维度 | 位移场（旧） | 模块化（新） |
|---|---|---|
| 操作对象 | **一整张位图** | 独立部件 |
| 变换方式 | 逐像素非线性重映射 | 部件整体**旋转/平移** |
| 关节 | 像素被拉扯 → 糊、裂 | 两部件绕同一圆心转，**像素永不被拉伸** |
| 能否做出「关节运动」 | ❌ 只能得到「呼吸/蠕动」 | ✅ 真实的转动 |
| 换角色 | 重出图 | **换部件包**，动作库复用 |
| 加动作 | 改场函数 | **加一条角度曲线** |

**结论**：warp 只能产生「整体形变感」，与「有人真的在动」是两种不同的东西。

## 二、模块化三条铁律（不撕裂的数学保证）

> 与 **Spine 官方文档**一致，非自定义土办法：
> 「*When drawing limbs, **aim to leave an area as close to a circle as possible where the joints overlap**. Ending overlapping parts in a round way ensures no gaps are shown and maximizes the usable rotation.*」
> 「*相邻部件之间需要留出少量重叠像素（通常 2-5 像素），防止动作拉伸时出现缝隙*」

### 1. 关节圆盘（Joint Disc）
部件根部**以旋转中心为圆心**做一个圆盘并纳入该部件。
圆绕自身圆心旋转是**不变的** ⇒ 根部永远严丝合缝，**绝不露缺口**。
实测验证：`arm_r` 绕肩转 −10°/−20°/−30°/−40°，质心位移 50.0 / 100 / 148.5 / 195 px，
与理论值 `2R·sin(θ/2)` = 50.0 / 99.7 / 148.7 / 196.5 **完全吻合**。

### 2. 重叠切片（Overlap）
躯干/袍摆/袖的切片边界**故意放宽互相重叠**，合成时上层盖住下层。
重叠区像素完全相同 ⇒ 拼回去与原图**逐像素一致**。
实测：**还原校验 0.000%**（0 / 547932 像素差），即「切了等于没切」。

### 3. 内衬同源（Lining）
被遮挡的区域原图里没有像素（美术没画）。
用「切缝内侧列的颜色」水平延伸生成内衬 ⇒ 部件移开后看到的是**袍子侧壁**而非背景。
⚠ **内衬形状必须跟随原部件轮廓**，严禁铺成矩形（实测会变成一块黑方块暴露在背景上）。

**层级（自下而上）**：`foot → skirt → torso → sleeve → cuff → head`
（袖必须在躯干**上层**，否则躯干会把整条袖子盖死；袖根无缝由**关节圆盘**保证，不靠遮挡）

## 三、关键教训：宽袖必须「分段」

**v1 的致命错误**：把整条宽袖当一块绕肩旋转。
结果：袖子一转走，原地露出**一整片内衬侧壁**，且内衬逐行取色产生**横向色带** → 视觉撕裂。

**正解（v2）**：袖子拆两段

| 层 | 范围 | 关节 | 摆幅 | 作用 |
|---|---|---|---|---|
| `sleeve` | 整条袖 | 肩 | **±3°** | 底衬：袖摆转开后露出的是**同色整袖**，天然无缝 |
| `cuff` | 肘以下袖摆 | 肘 | **±15°** | 动的主体：真正的大幅摆动 |

整袖只微摆 ⇒ 露出的躯干侧壁仅十余像素 ⇒ 内衬只需极窄一条。

## 五、场景模块化 & 比例标定

### 5.1 模块清单（各自动各自的）

| 层 | 内容 | 动法 |
|---|---|---|
| `base` | 墙 / 药柜 / 丹炉 / 地面 | 静止（**不该动的不动**） |
| `glow` | 炉火照亮 | 径向渐变，**上下不对称**，随火势脉动 |
| `fire` | 炉膛火焰 | 亮度 × 高度脉动 |
| `ember` | 火星 | 26 粒子，独立上升+摆动+衰减 |
| `smoke` | 丹烟 | 9 团半透明，上升+横向摆动 |
| `role` | 弟子 | 烘焙序列帧 |

### 5.2 比例标定（老大红线：不能比例失调）

```
丹炉：原图 y 461..901  ⇒ 高 440px
弟子：身高 = 炉高 × 1.45 = 550px（原图尺度）⇒ 丹炉齐胸口 = 大型八卦炉
转换：crop x[240,1808] → 1080x707   scale ≈ 0.689
结果：丹炉 303px / 弟子 440px（输出尺度）
```

### 5.3 两处「贴纸感」根因（都已修）

1. **光照不匹配**：白底立绘是中性冷白光，场景是暖橙火光 ⇒ 读作贴纸。
   → `lit()`：染暖色（strength 0.42~0.72）+ 压暗（dim 0.84~0.88）。近火的弟子更暖更亮。
2. **没接地影**：脚下悬空 ⇒ 读作贴纸。→ 椭圆接地阴影（径向衰减 × 0.55）。

### 5.4 炼丹过程叙事（48 帧 / 8s）

```
t 0.00-0.20  投料（pour）        火势 0.45→0.80
t 0.20-0.62  扇火（fan）+ 文火    火势 ~0.80 稳定
t 0.62-0.85  武火                火势 →1.25
t 0.84-1.00  开炉取丹            向上光柱 + 扩散光环
```

## 七、落到 Godot 的映射（符合任务书 §4.1/§4.2）

| 模块 | Godot 节点 | 依据 |
|---|---|---|
| 场景底图 | `TextureRect` | 静止图 |
| 弟子 | `AnimatedSprite2D`（16~24 帧） | 任务书明确推荐帧切换 |
| 炉膛火焰 | `AnimatedSprite2D`（8 帧，仅覆盖炉膛小区域） | 同上 |
| 丹烟 | `GPUParticles2D` | 任务书 §4.2 明确要求 |
| 炉火光晕 | 1 张径向渐变 PNG + `modulate` 动画 | 零 shader |
| 火星 | `GPUParticles2D`（≤26） | 粒子总数 ≤50 ✔ |

> **为什么烘焙成帧而不是运行时骨骼**：任务书 §4.4「禁止骨骼动画」指的是**逐帧解算的运行时骨骼**。
> 烘焙序列帧 = 纯贴图播放，**运行时零骨骼开销**，且每帧是完整位图 ⇒ 原理上不可能撕裂。
> 上限参考：`Skeleton2D` 几十根骨在移动端可行，但本项目**不需要**为它引入复杂度。
