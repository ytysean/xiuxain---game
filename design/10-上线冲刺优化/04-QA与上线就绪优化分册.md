## 一、上线测试总体策略（分阶段）

按"内测→删档测试→不删档（软启动）→公测"四级递进，每级目标、准入线、退出线、必须真人项不同。原则：**自动化守"程序没坏"，真人守"玩家愿玩"**；自动化通过是进真人的前提，真人是进下一阶段的门槛。

### 1.1 阶段定义与准入/退出线

| 阶段 | 目标 | 范围/样本 | 准入线（进本阶段前） | 退出线（可进下一阶段） | 必须真人 |
|---|---|---|---|---|---|
| **内测（Closed Beta）** | 验证"新玩家能不懵地跑通核心循环" | 50–200 名核心玩家；白名单 | 门0–5 全绿 + 67 页真实渲染 ACCEPT + 核心循环探针全通 + **P0-1 FTUE 已处置** | R2 真人 30min 脚本"五时刻"全出现；无 P0；P1 有处置计划 | ✅ R2 |
| **删档测试（Wipe Test）** | 验证"系统全开、运营活动跑得通、承载可接受" | 全量开放（限时），数据可清 | 内测退出线达成 + 兼容矩阵最低配置机型实测通过 | 全 8 大系统"入口可达/有正反馈/无死循环/无死资源"签收；无 P0/P1；崩溃率阈值内 | ✅ R3（60–90min 老手） |
| **不删档（Soft Launch / 付费不删档）** | 验证"留存与付费体感、长时稳定、存档向后兼容" | 开放注册，存档永久保留 | 删档退出线 + **存档迁移机制验证通过** + 合规四件套到位 | D1/D7 留存达基线、崩溃率达标、无存档损坏反馈、监控/埋点出数 | ✅ 日常 Monitoring |
| **公测（Public / GA）** | 全量、买量、规模化 | 全渠道 | 不删档退出线 + Go/No-Go 全绿 + 放量预案 | 持续监控，按版本节奏迭代 | 持续 |

### 1.2 测试轮次（复用 PLAYTEST R1/R2/R3，扩为可持续）
- **R1 自动冒烟（常态跑，每次提交/每日）**：门0–5 + headless 链 + 67 页真实渲染 + 死键扫描 + `_probe_perf` 基线不劣化。**连续 2 次无 flaky 才算过**（治门3 假 FAIL）。
- **R2 真人首 30min（新开档，录屏+秒表）**：验证"新玩家能玩"。五个该出现时刻（序章/目标条/气泡/灰锁引导/新手红点）必须全出现；脚本见 PLAYTEST 报告 §1.1。
- **R3 真人中期 60–90min（老手视角）**：验证"中盘系统值得玩"；8 大系统逐项签收；记录最强正反馈时刻与想关游戏时刻。

### 1.3 新增"R4 长时稳定性轮"（补齐 PLAYTEST 覆盖空白 #7）
- 关服模拟 30 天 → 冷启动实测（治离线推演 O(122×2N) 卡顿）；
- 长会话内存/对象采样（治退出泄漏与 `.godot` 缓存增长）；
- 后台切回（pause/resume）不崩、不丢状态。

## 二、测试用例体系设计

### 2.1 分类与覆盖目标
| 类别 | 定义 | 覆盖目标（上线前） | 主载体 |
|---|---|---|---|
| **功能** | 核心循环与系统可达性/正确性 | 核心循环（招徒→修炼→历练→殿阁→坊市→纪事→灵钓→灵兽）100%；8 大系统入口可达/无死资源 100% | `_probe_features` + R2/R3 真人 |
| **性能** | 启动/FPS/内存/DrawCall/对象增长 | 启动（移动端）≤ 目标值；FPS≥目标；内存稳定无泄漏；超重页全虚拟化 | `_probe_perf` + R4 |
| **兼容** | 机型/OS/分辨率/芯片 | 兼容矩阵每档 ≥1 真机实测通过 | 真机矩阵（§六） |
| **回归** | 已修 Bug 不回潮 | P0-1/P1-1~3/P2-1~4 全有对应回归用例；门0–5 每次必跑 | 门控 + 探针 + 存档迁移 |
| **边界** | 空档/越界/极限/异常输入 | 空列表/缺失字段/越界 ID/超长文本/弱网(单机不适用)/极端数值 | 边界用例集（§2.4） |

### 2.2 用例编写规范（统一模板，沿用 P1-QA 报告 §3 形式）
每条用例含：`用例ID / 前置条件 / 操作步骤 / 预期 / 通过标准 / 类型(功能·性能·兼容·回归·边界) / 优先级(P0–P3) / 执行方式(自动·真人·真机) / 关联风险`。
- ID 命名：`[模块]-[序号]`（如 BD-建筑详情、DP-弟子详情、FTUE-引导、SAVE-存档、COMP-兼容）。
- 通过标准必须**可观测、可断言**（截图/日志关键字/`ACCEPT_ALL_DONE`/数值阈值），杜绝"看起来对"。
- 自动用例须产出**确定性退出码**（PASS/FAIL/DEAD），禁止"无报错即过"的弱判据。

### 2.3 覆盖缺口补全（针对 PLAYTEST 覆盖空白 #1–#8，逐条补用例）
1. **引导可达且讲清**：新增静态门"断言 FTUE 初始化入口在启用路径被调用"（`main.gd:_进入主界面` 新 UI 分支须触发 `_入门指引_初始化`）+ R2 五时刻真人用例。
2. **数值节奏是否好玩**：R2/R3 秒表+录屏 + 埋点"正反馈事件时间戳"（非自动化，属观测数据）。
3. **弟子 AI 行为可感知**：R3 真人"能否复述弟子刚干了什么" + 纪事/传讯披露校验。
4. **红点/传讯/纪事三通道可信**：给红点补"三态"自动断言（点开前/点开后/刷新后）；缩小死键扫描"选中态只改样式"盲区（补 `button_pressed`/主题态数值通道）。
5. **竖屏单手可达/遮挡/裁切**：引用 `accept_shots_full/` 真实渲染截图人工走查 + 真机触摸热区（safe area 适配）。
6. **付费价值感/仙玉体系**：R3 真人 + 经济专项审计文档对照（不删档阶段重点）。
7. **长时稳定性**：R4（关服 30 天冷启动 + 长会话采样 + 后台切回）。
8. **"像半成品"死资源/死入口体感**：R2/R3 每个可见入口点一遍，记录"点了有没有内容"（治 19 入口按钮墙 P1-1、顶栏胶囊恒为 0 等）。

### 2.4 边界用例集（建议最小集，描述级）
- 空档：新档首月散修池/药园/纪事为空时不崩（P2-1 已修，须回归）。
- 越界：药园地块 ID 越界被拒（P1-1）；历练关卡极端时长。
- 缺失字段：建筑/弟子 entry 缺字段回落"—"不 Invalid access（P1-QA R8 重定向风险）。
- 超长文本：功绩堂奖赏长串折行（P2-4）；纪事模板括号残缺（P2-3）。
- 极端数值：`[PLACEHOLDER]` 34 处未校准值（PLAYTEST P2-3，须标注"不回本"并限期收敛）。

## 三、验收门控强化方案

### 3.1 现有闸门可持续化（把"能跑"变"可信"）
- **门禁运行姿势固化**：`gate_all.py` / `run_headless_chain.py` 必须以 `PYTHONUTF8=1` + PortableGit 进 PATH 运行（否则门3 编码假 FAIL，已实证）。建议：将正确 env 写进 `.workbuddy/_run_gates.py` 封装，**禁止手写裸跑**；CI/定时任务只调用封装入口。
- **门3 flaky 治理（PLAYTEST P2-1）**：死函数闸改为"仅连续 N 次扫描均无引用才判死"的宽限；门禁在**冻结点单线程**跑，规避并行编辑 game_state.gd 的中间态假 FAIL；"结论翻转"记入 flaky 台账。
- **门5 重复字典键**：确认 CSV 重复键扫描覆盖全部 config/*.csv（解锁表/元数据/传法帖/经济表），并纳入每次提交门。
- **战斗红线守护口径统一（PLAYTEST P2-2）**：文档统一为"93 条（`tests/combat/test_combat.py`）"，`pre_f5` 第 30 道文案改 72→93；红线**零改动**，但"数得清自己守几条"以防重构误动。

### 3.2 覆盖率缺口与门控补强
| 缺口 | 补强方案（描述级） |
|---|---|
| FTUE 初始化是否可达 | 新增静态门：断言 `_入门指引_初始化()` 在"启用新UI"路径被调用；`Game.激活新手目标链()` 首日可被触发 |
| 红点三态可信 | 新增自动断言探针：红点点开→消失→刷新不复发 |
| 配置表 schema 漂移 | 门2 validate_all 扩"字段改名护栏"：业务层改 key/字段名时，UI 静默回落"—"须转运行时告警（治 R7 重定向风险） |
| 资源/纹理红线 | 门2/独立门扩：`mode=0` 未压缩、非 4 倍数、超 2048 的纹理纳入**告警级**门（不阻断日常，但删档前须清零） |
| 存档键对称 | 门3 闸门22（存档键名对称）扩为"读档迁移前后键一致"校验 |

### 3.3 headless 探针扩展建议（描述级，不落地）
- **`_probe_save_migration`**：旧档→新档迁移探针（加载历史版本 save.json，验证字段兜底/不崩/数据不丢）——支撑不删档阶段。
- **`_probe_compat`**：分辨率/异形屏 safe area 探针（不同视口尺寸下无裁切/无溢出），替代 headless 不可离屏截图的盲区（治覆盖空白 #5）。
- **`_probe_reddot`**：红点三态探针（点开前后/刷新后）。
- **`_probe_longrun`**：长会话/后台切回探针（治 R4 / 覆盖空白 #7）。
- **探针纪律**：72 条战斗断言红线零触碰；每个新探针须有确定性退出码；flaky 探针必须隔离（单跑+重试上限），不污染 CI 信号。

### 3.4 真实渲染巡检自动化（headless 不可离屏，须独占窗口）
- **瓶颈**：`ui_full_accept.tscn` 必须真实渲染（窗口移屏外），与另一会话的 Godot 编辑器争抢 `.godot` 缓存与显示资源，无法进常规 CI 并发。
- **方案**：① 真实渲染巡检设为**排它任务**（串行，单 Godot 实例），避免在编辑器占用期跑；② 引入"指纹 diff"：每轮 `accept_shots_full/` 截图与基线逐页结构 diff（非像素全比，比布局断言 BK/OF/OFF 计数），新页/回归自动标红；③ 截图产物入版本管理外的独立目录（如 `E:\Xiuxian\_taixuan_offload\`，治 `.workbuddy` 红线 P3-4）；④ 真机 touch 热区用独立 safe area 用例覆盖（见 §2.3 #5）。

## 四、分级发布与数据策略

### 4.1 四级发布的切换与清档开关
- **清档开关**：由**启动参数/后端配置**控制"是否清档"，不写死在 Game 单例。内测/删档期可一键清；不删档期**永久关闭清档**。
- **配置与代码解耦**：CSV（解锁表/经济/引导/道具）与 `.gd` 分离，配置热更不需清档；代码版本与配置版本独立编号。
- **灰度放量**：公测按渠道/机型档位分批（先中端机、后全量），每批观察崩溃率/留存 24h 再扩。

### 4.2 存档兼容（不删档阶段生命线，当前缺失→必须新建）
- **save schema 版本化**：存档写入 `schema_version` 字段；读档时按版本执行**迁移函数**（vN→vN+1），缺失字段给默认兜底，禁止删除旧字段（防旧档读崩）。
- **迁移验证**：`_probe_save_migration`（§3.3）加载各历史版本 save.json，验证迁移后字段完整、不崩、不丢核心进度（宗门/弟子/资源）。
- **删档→不删档切割点**：切割前冻结 schema，切割后存档永久保留；切割当日全量备份 + 回滚预案。
- **单人项目无后端**：存档落 `user://save.json`；跨设备/云存档为可选增强（不删档阶段非必须，但须保证本地存档不被版本升级破坏）。

## 五、崩溃监控与埋点接入方案（大厂级）

> 原则：单人开发、无后端，采用**轻量但完整**方案——崩溃/ANR 用免费第三方 SDK（如 Crashlytics/Bugly/TAPM 之一），行为埋点用"本地事件队列 + 定期上报/或同 SDK 自定义事件"。本分册只定义**接入点与上报字段规范**，不落地代码。

### 5.1 必须接入的信号
| 信号 | 定义 | 上线阈值（建议） | 上报方式 |
|---|---|---|---|
| **崩溃率** | crash-free users / sessions | 内测 ≤2%；不删档 ≤1%；公测 ≤0.5% | native crash handler（Android/iOS）+ GDScript `push_error` 钩子转发 |
| **ANR** | 主线程卡顿 >5s（移动端） | ≤0.5% | 主线程 watchdog |
| **留存** | D1 / D7 / D30 | 对照同类修仙手游基线 | 启动事件 + 日期归因 |
| **关键漏斗** | 创建宗门→首徒→首历练→首殿阁产出→首笔坊市交易→（首充） | 每步转化率监控，掉点告警 | 自定义事件埋点 |
| **性能采样** | 启动耗时/首屏 FPS/内存峰值 | 移动端启动 ≤ 目标；FPS≥目标 | 启动时 + 定时采样 |

### 5.2 接入点规范（描述级）
- **崩溃钩子**：Godot `OS` 错误回调 + `push_error` 重定向到上报队列；捕获未处理异常与脚本 SCRIPT ERROR（含文件名:行，对齐 `_probe_* >>>FAIL` 格式）。
- **埋点事件字典**：统一事件名（`ftue_step_done` / `disciple_recruited` / `expedition_settled` / `shop_trade` / `building_output` / `reddot_cleared` / `session_start` / `session_end`），字段含 `ts / uid(匿名) / stage / device_tier / os_ver / resolution`。
- **隐私合规**：埋点默认匿名；含个人数据须先过隐私同意（§七）；上报走 HTTPS，敏感字段不上报。
- **GDScript 红线**：埋点/监控代码**零 GameState 写入**、零战斗触碰（与现有 UI 层红线一致）。

### 5.3 上线后"失明"风险（无监控 = 大厂级不可接受）
- 当前**完全无崩溃率/留存数据**，上线即"盲飞"。列为本分册 **Top 风险**（见 §九）。
- 缓解：不删档前必须完成 §5.1 全信号接入并出数；内测期即可开始采集（即使样本小）。
