## ① 目标与范围

本批是 **S1 赛季核心三 P0 子系统**：凡世香火体系、辈分礼制体系、正邪路线抉择（规划 §4.4 / §4.6 优先级6）。三者均为**纯经营/叙事/数值层**，与战斗结算解耦，全部以**加法**进入 `game_state.gd`（新 `var` + 月循环空桩 + `save_game`/`load_game` 键）与 `main.gd`（挂在现有 5 Tab 内的新面板/弹窗）。

| 子系统 | 本批落地范围 | 回归风险 |
|---|---|---|
| A. 凡人香火体系 | 香火值、信徒、凡世城镇、月度结算桩、凡人事件端口、宗门页香火面板 | 低 |
| B. 辈分礼制体系 | 字派序列、弟子辈分序/道号、门规严格度、谱系树、排序、弟子 to_dict 扩展 | 低 |
| C. 正邪路线抉择 | 正邪路线标记、解锁桩、二次确认弹窗、路线徽记、风味事件端口 | 低 |
| 宗门大比/赛季冲榜/奇遇扩容100+/气运功德全链路 | **本批不设计**（P1），GDD 仅标注后置端口 | — |

**铁律（本批不可逾越）**：严禁写任何 `.gd` 代码、严禁改 `BattleCalculator.gd`/`BattleManager.gd`/`game_state.gd`/`main.gd`；不增删 Tab；不引入裸 `#xxxxxx`；不改动背景三常量；正邪不可逆须含存档标记 + 二次确认；数据层新增须 `.get` 默认兼容旧档。

**sub-batch 拆分与执行顺序**（每 sub-batch 独立 F5、独立落地，详见 §⑦）：
- **A → B → C**（推荐顺序，A/B 可并行，C 为宗门里程碑）；三者均独立可落，无强制先后依赖（仅 C 的视觉入口建议排在 A/B 之后以免宗门页过挤）。

## ③ 落地决策 D1..D11

### D1 · 赛季核心整体落地形态
- **决策点**：三子系统以何种形态接入，避免触碰铁律。
- **推荐默认**：纯经营/叙事/数值层，**全加法**进入 `game_state.gd`（新 `var` + 月循环空桩 + `save/load` 键）与 `main.gd`（现有 Tab 内新面板/弹窗）。
- **替代方案**：新开「香火/礼制」Tab 或新堂口（需改 `Lore.堂口`）。
- **采纳默认理由**：契合铁律1/2/5 + 规划 §4.6 优先级6；与现役 S1 空桩（`_结算俸禄_S1` 等同区）零冲突。

### D2 · 凡人香火落地形态（A）
- **决策点**：香火是宗门级子系统还是新建筑？
- **推荐默认**：**宗门级子系统**，不新开堂口；以 `香火值` 标量 + `信徒数` + `凡人城镇[]` 数据驱动，月结算桩 `_结算香火_S1()` 挂 `推演一月` L884 区。
- **替代方案**：新开「香火庙」堂口（需改 `Lore.堂口`，重型）。
- **采纳默认理由**：批5 轻量、零 `Lore` 改动、低回归；建筑端口留 P1 后置（设定 §5077「复用 §11.2 建筑框架」标注为远期）。

### D3 · 香火产出与信徒增益管线
- **决策点**：香火产出公式与信徒增益如何接入，避免通胀/越红线。
- **推荐默认**：月产 = 基值 × 城镇数 × (1 + 门派等级系数) × 阵营声望修正（全 `[PLACEHOLDER]`，真机校准）；产出来源计入 §11.9 财政（灵石/粮草），不独立通胀。**信徒增益**作月度重算加法项并入 `宗门加成pct`（现有 cap +100%，`推演一月` L795）或 `汇总负责人全局buff` 同管线，不新建战斗数值、不破 25% 通用软帽/10% 道心独立乘区（设定 §4.1）。
- **替代方案**：信徒增益走独立 buff 乘区。
- **采纳默认理由**：并入现有产出/增益管线，守数值红线，零新机制。

### D4 · 辈分/字派落点（B）
- **决策点**：字派序列与弟子辈分存哪。
- **推荐默认**：`辈分字派: Array`（宗门级）存 `game_state.gd`（新档自动生成 5–10 古风字，旧档首次进入生成并持久化）；弟子 `辈分序: int` + `道号: String` 存 `Disciple`（扩展 `to_dict`/`from_dict`，旧档缺键默认 `0`/`""`，零回归）。
- **替代方案**：辈分全存 `game_state` 并行字典（keyed by 姓名）。
- **采纳默认理由**：跟随弟子对象生命周期、随 `to_dict` 自动存档；与现有 `阶位` 字段同范式（L152/L1056），最省心。

### D5 · 辈分排序与谱系 UI 挂点（B）
- **决策点**：谱系树挂哪。
- **推荐默认**：弟子列表按「辈分序→境界→入门序」排序；**谱系树 UI 挂「宗门」页**（新增 `_宗门谱系面板()`，或「纪事」页二级）。师徒传承链（`disciple.gd` 若无 `师父` 字段）**本批仅落字派序+道号**；师徒关系 UI 标注后置 P1（设定 §6.11.6），不在批5。
- **替代方案**：挂「弟子」页。
- **采纳默认理由**：辈分属宗门礼制，归属宗门页沉浸感强，且不与弟子页现有二级 Tab 冲突。

### D6 · 门规严格度（B）
- **决策点**：门规如何量化。
- **推荐默认**：`门规严格度: String = "中庸"`（宽松/中庸/严格三档）；影响以下犯上概率与忠诚增长（幅度 `[PLACEHOLDER]`）。单字段 + 三枚举，低回归。
- **替代方案**：数值滑杆（0–100）。
- **采纳默认理由**：三档枚举对齐设定 §5586「门规预设（宽松/中庸/严格）」，UI 最简。

### D7 · 正邪路线枚举条数（C · 已拍板）
- **决策点**：路线枚举该几条？
- **最终决策（主理人采纳用户定夺）**：**3 条，命名 玄门正道 / 逍遥中立 / 九幽邪道**（世界观命名升级，对齐设定 §2.1/§11.18 三·2「正道宗 / 邪修路线」与 §78「正道/魔道/中立三条玩法路线」；用户定夺理由：区分度足够、开发量可控、认知成本低、S2 可平滑扩展细分分支）。
- **替代方案（未采纳）**：(a) 2 条（正/邪字面二元，缺中立缓冲）；(b) 5 条（五大阵营，S1 开发量翻倍、内容稀释）。
- **铁律冲突注（视觉色）**：用户视觉建议为 正-金 / 中-青 / 邪-紫，但 **pre_f5 闸门18 禁止引入新裸 hex / 新色常量，调色板无紫色**。故 C 批路线徽记色须映射已定义常量：玄门正道→`暗金`、逍遥中立→`青玉`(或`青黛`/`青灰`)、九幽邪道→`朱砂`（**禁用紫色**，守铁律）。详细见 §⑥.5。

### D8 · 正邪解锁阈值（C · 已拍板）
- **决策点**：何时解锁抉择。
- **最终决策（主理人采纳用户定夺）**：**双重条件 —— 门派等级 >= 3 且 已完成首次七载大考**（「七载大考」见 §4.3 修炼模型/七载大典）。仅当双条件满足且 `正邪路线 == ""` 开放抉择入口；未达 UI 灰态显「门派 Lv.3 且 七载大考后解锁」。
- **检测桩**：`_检查正邪解锁_S1()` 挂 `推演一月` L884 区（`更新门派()` L883 之后），读 `门派等级` + 七载大考完成标记（落地时确认 game_state 现有字段名，如 `_七载大典已完成` 类状态）。
- **替代方案（未采纳）**：仅绑声望阈值 / 仅门派Lv.5。
- **采纳理由**：与「晋升七品 / 首次七载大考」节点深度对齐，玩家认知节奏匹配、差异化体验前置、风险与仪式感平衡；`门派等级` 已是权威成长量（L2085 公式），无需新量。

### D9 · 正邪不可逆机制（C · 铁律6）
- **决策点**：如何保证不可逆。
- **推荐默认**：`正邪路线: String = ""`（空=未选）；抉择仅当 `门派等级>=阈值 且 正邪路线==""` 开放；选定经**二次确认弹窗（confirm 式，非误触即选）**写入并存档；选定后 UI 显当前路线徽记 + 不可重选（除非新游戏）。批5 仅设标记 + 路线风味事件/文案 + 阵营声望倾向（轻量）；重代价（功德/功法权限/黑市/围剿）后置 P1 气运功德全链路，本批仅标注端口不实现。
- **替代方案**：可逆 + 冷却。
- **采纳默认理由**：铁律6 不可逆 + 设定「正邪选择」不可逆心智（§5067）。

### D10 · 新 UI 颜色与字号（铁律3 / pre_f5 18）
- **决策点**：新面板/按钮用什么色。
- **推荐默认**：标题 `暗金`、数值 `次墨`、增益/正道 `玉石绿`、魔道 `朱砂`、中立 `次墨`/`青灰`、面板底 `面板底`/`暗墨面板()`；按钮用 `BTN_主*`/`BTN_次*`/`BTN_标签*`/`BTN_危险*`；字号仅 `{22,17,18,16,15,13}`。**禁止任何裸 `#xxxxxx` / 新色常量**。
- **替代方案**：引入新裸色。
- **采纳默认理由**：pre_f5 闸门18 只认顶部 const + 四类锁定 hex；全用 const 即零风险。

### D11 · 存档兼容策略（铁律5）
- **决策点**：旧档如何不崩。
- **推荐默认**：新字段全部 `var ... := 默认`；`save_game` 增键、`load_game` 用 `.get(key,默认)`；**不升 `SAVE_VERSION`**（沿用 S0 任务系统/P0 目标链先例）。`正邪路线` 旧档空串→保持未选；`辈分字派` 旧档空→首次进入生成并持久化；弟子 `辈分序` 旧档→默认 0（开山第1字），`道号` 旧档→默认空（按规则生成）。
- **替代方案**：升 `SAVE_VERSION` + 迁移脚本。
- **采纳默认理由**：与现役 `.get` 默认兼容范式一致，旧档零崩溃、零迁移成本。

### 5.2 辈分计算与字派
- **字派生成**：新档自动从候选池（如 `玄清道明悟真常寂虚静渊徽…`）随机取 5–10 字；开山掌门 = 第 1 字（索引 0）。旧档 `辈分字派` 空→首次进入生成并持久化（D11）。

- **道号自动生成**（设定 §5083）：外门 = 辈分字+单字（如「玄尘」）；内门可保留本名道号「xx子」；金丹+「xx真人」；元婴+长老「xx真君」。玩家可手动改任意弟子道号。
- **全场景称谓**：事件/对话/禀报文案按辈分关系自动替换称谓（师兄/师叔/师祖），复用 §6.18 社交关系文案框架（本批标端口，文案替换后置）。
