# 《太玄宗门录》渐进式引导与每日节奏体系

> 定位：**不改任何既有玩法数值**，只在既有系统之上加一层「什么时候教、今天做什么、长期走哪条」的调度层。
> 设计铁律：好玩 / 修真世界观 / 玩家操作习惯 / 仿真修仙宗门 / 文案修真化 / 手机端流畅。

---

## 1. 概述

### 1.1 问题诊断

现有 `config/unlock_order.csv`（洋葱体系，P0–P7 共 38 项）只解决了 **「什么时候给」**，但三件事无人负责：

| 缺口 | 具体表现 | 后果 |
|---|---|---|
| **给了不会玩** | P5_三周 一次性开放 8 个休闲玩法（灵钓/探秘/饲灵/卜算/药圃/论道/灵酿/音律） | 玩家打开一堆入口，不知道先点哪个、点了有什么用 |
| **今天该干嘛** | 日常差事 16 条 + 各系统红点同时亮 | 顾此失彼，哪个都没做完，上线即焦虑 |
| **长期走哪条** | 所有玩家被同一套日常推着走 | 玩到第四周失去目标，不知道「我在经营一个什么样的宗门」 |

既有 `newbie_001~007`（新手目标链）只覆盖**开局前 30 分钟**，之后玩家即陷入无引导状态。

### 1.2 目标

1. **每天有事做**——每日 08:00 有明确的 3 件事，做完有收工感。
2. **逐步学会**——每个系统解锁时配 3 步微教学，同日只教一件。
3. **形成自己的玩法**——三周后由玩家自己的行为凝结出「仙途」，后续内容围绕它展开。

### 1.3 四层模型（与洋葱体系的关系）

| 层 | 职责 | 状态 |
|---|---|---|
| **洋葱体系** | **何时给**——门派等级达标即开入口 | 已有，保留不动 |
| **传法帖** | **怎么教**——每系统 3 步微教学 | 新增 |
| **晨课三事** | **今天做哪件**——每日焦点 + 红点收敛 | 新增 |
| **仙途** | **长期走哪条**——玩家自选择的玩法流派 | 新增 |

> 关键约束：**本体系不新增任何玩法内容**，只做调度与呈现。所有奖励均从既有池（灵石/灵气/`pool_newbie` 等）出，不新增货币。

## 2. 核心规则

### 2.1 传法帖（解决「给了不会玩」）

**定义**：每个洋葱系统解锁时，自动挂载一条 **3 步** 传法链。

| 步序 | 名称 | 目的 | 类型 |
|---|---|---|---|
| 1 | **初识** | 打开该系统页面（建立「在哪」的认知） | 主动型，配「前往」跳转 |
| 2 | **实践** | 在该系统内完成 1 次核心操作（建立「怎么用」） | 自动型，事件命中即完成 |
| 3 | **小成** | 拿到 1 次该系统的可见产出（建立「有什么用」） | 自动型 |

**铁则：同日只激活 1 条传法链。**
- 解锁多个系统时（如 P5 的 8 个），按 `unlock_order.csv` 顺序入队，每日放行 1 条。
- 未激活的链**不显示、不亮红点**——这是治「一次给太多」的核心一刀。
- 链步之间不强制等待：玩家一天做完 3 步，次日放行下一条。

**复用既有机制（降低实现成本）**：
- 数据结构沿用 `config/quest_daily.csv` 的 18 字段结构（`jump_path`/`condition_type`/`is_auto_trigger`/`prev_quest_id`）。
- 逻辑复用 `game_state.gd` 新手函数族（`_新手_检测`/`_新手_评估后续`/`_新手_完成`，L428–545），改造为支持**多链并行**的通用链。
- `is_newbie` 标志扩展为 `chain_id`（链标识），`newbie_001~007` 视为 `chain_id=newbie` 的首条链，天然兼容。

**示例（炼丹 alchemy）**：

| teach_id | 步序 | 名称 | condition_type | jump_path |
|---|---|---|---|---|
| `T_ALC_1` | 初识 | 丹房初启 | `open_page` | 丹方 |
| `T_ALC_2` | 实践 | 首炉开炼 | `alchemy_craft_count` ≥1 | 丹方 |
| `T_ALC_3` | 小成 | 丹成济用 | `pill_obtain_grade` ≥凡品中品 | 库藏 |

### 2.2 晨课三事（解决「顾此失彼」+「每日新鲜感」）

**定义**：每日 08:00（对齐既有真实时间刷新口径）生成 **3 件事**，构成当日焦点。

三事的**固定构成规则**（保证节奏与新鲜度）：

| 槽位 | 来源 | 作用 |
|---|---|---|
| **一 · 保底** | 稳定简单池：收日供 / 巡视殿阁 / 授业讲道 | 保证上线 30 秒内有正反馈，永不做不完 |
| **二 · 进阶** | 当前激活的传法帖当前步 ＞ 主线/门派等级目标 | 推玩家往前走，是「逐步学会」的落点 |
| **三 · 机缘** | 随机池：秘境 / 机缘 / 商队 / 奇遇 / 灵钓 | **新鲜感的唯一来源**，每日不同 |

- **圆满奖励**：三事全部完成 → 额外发「晨课圆满」一份（灵石 + 当日气运微量），写入纪事。
- **未做完不惩罚**：次日正常刷新，不做累积负债（避免焦虑）。
- **仙途影响权重**：仙途相关的事，在二/三槽抽取时权重 ×3（见 §2.4）。

### 2.3 红点收敛（配套铁律，不可省）

> **只给「晨课三事」+「传法帖当前步」亮一级红点（朱砂）；其余系统红点降级为不亮。**

- 其余系统内部仍可正常提示（页面内角标），但**首页入口与底部 Tab 不亮红点**。
- 提供「老手模式」开关（设置内，默认关）：开启后恢复全红点。仙途确定后自动询问一次是否开启。
- 依据：既有 `red_dot_init.gd` 已集中管理红点，改造点单一。

### 2.4 仙途（解决「形成自己的玩法」）

**仙途七条**：丹道 · 符道 · 器道 · 御兽道 · 商道 · 战道 · 逍遥。

> **命名分界（2026-09-16 终定）**：流派体系名已定为「仙途」，与正邪路线的「道统」（`main.gd` 旧 UI 的「宗门道统 · 正邪路线」，一字未动）不再冲突；二者非同物，勿混用。
> 命名历程：`道途`（原名）→ `道统`（2026-09-16 初改，因与 `Disciple.道途` 代码字段撞名而废）→ **`仙途`（2026-09-16 终定）**。详见 `design/06-角色与UI/FTE-首次30分钟体验审查_2026-09-16.md` §8。

**不强制、不预设**——三阶段推进：

| 阶段 | 时机 | 行为 |
|---|---|---|
| **观察** | 第 1–21 天 | 系统暗中统计行为倾向（炼丹/制符/炼器/饲灵/交易额/出战/休闲次数），玩家无感 |
| **初定** | 第 22 天（或门派等级 ≥5 时触发） | 弹「仙途初定」：据统计推荐 1 条，玩家可**确认或改选** |
| **践行** | 初定之后 | 晨课权重倾斜 + 仙途专属周常 + 专属成就 |

**切换规则**：
- 可改，但有冷却：**每月 1 次**（对齐游戏内月结）。
- 初定前不计冷却，随意改（鼓励试错）。
- **不锁死内容**：非本仙途的系统照常开放，只是不做推荐。

**仙途 → 权重映射**（示例，`daoTu.csv` 配置）：

| 仙途 | 主要统计行为 | 晨课倾斜方向 |
|---|---|---|
| 丹道 | 炼丹次数 | 丹方/药圃/丹纹相关事 ×3 |
| 符道 | 制符次数（S45） | 符箓相关事 ×3 |
| 器道 | 炼器次数 | 装备图纸/灵矿相关事 ×3 |
| 御兽道 | 饲灵/灵兽互动 | 灵兽/饲灵相关事 ×3 |
| 商道 | 坊市交易额 | 商队/拍卖相关事 ×3 |
| 战道 | 出战/征伐次数 | 历练/宗门战相关事 ×3 |
| 逍遥 | 休闲玩法次数 | 灵钓/论道/音律/灵酿相关事 ×3 |

### 2.5 本周宗务主题（周级新鲜感，P1）

- 每周一 08:00 刷新 1 个主题（如「丹道大兴」「商路通达」「厉兵秣马」），从主题池按门派等级过滤。
- 效果：该主题相关的日常/晨课抽取权重 ×3，相关系统产出 **+20%**（**具体数值待经济专项确认**）。
- 作用：让玩家**每周的重心不同**，避免每天都做同一套。

## 3. 数值与配置

### 3.1 新增/扩展 CSV

| 表 | 用途 | 关键字段 |
|---|---|---|
| **`tools/config/system_meta.csv`（新增 · 单一事实源 · 仅被 .py 工具链消费，按治理迁 tools/config 脱离运行时闸门）** | **系统元数据，一表养活整个引导层** | `系统key, 核心操作计数键, 核心产出物id, 道途tag, 晨课权重, 传法帖版本` |
| `tools/config/quest_teach.csv`（新增 · 由 system_meta 派生 · 仅手写例外覆盖） | 传法帖链 | `teach_id, chain_id, 步序, 绑定系统key, 名称, 描述, condition_type, condition_param, is_auto_trigger, jump_path, reward_lingjing, reward_lingqi` |
| `config/quest_daily.csv`（扩展 1 列） | 晨课与仙途 | 追加 `daoTu_tag`（该日常归属哪条仙途，可空） |
| `config/morning_topic.csv`（新增，P1） | 周主题 | `topic_id, 名称, 描述, 门派等级下限, daoTu_tag, 产出加成` |
| `config/daoTu.csv`（新增，P1） | 仙途定义 | `daoTu_id, 名称, 描述, 统计行为键, 权重倍率` |

> **列名沿用 `道途tag`（2026-09-16 已裁 · 数据层红线）**：`tools/config/system_meta.csv` 的列名就是 **`道途tag`**（实文件表头）。本轮「UI / 体系文案 → 仙途」**不改列名**——`道途tag` 属**数据层标识（字段名 / CSV 列名）**，受铁律「不动字段名 / CSV 列名 / 代码标识符 / 存档键」保护，**不随 UI 文案改名而变**。
> 理由：该列是 `build_teach_chain.py` / `audit_teach_chain.py` 的消费键，改名须连带改工具链、并扰动既有数据层；而「仙途」是**玩家可见文案层**的体系名 —— **文案层改、数据层不改**，是本项目一贯口径。
> ⇒ 上表「关键字段」里的 `道途tag` 即实列名，以实文件为准。若未来真要改列名，须**单独立任务 + 同步两个 `.py`**，勿夹带在文案改名里。

> **ID 跳号说明（2026-09-16）**：`config/quest_daily.csv` 的新手目标链实为 `newbie_001 → 002 → 004 → 005 → 006 → 007`，**不含 `newbie_003`**。
> 此**非漏配**：链由 `prev_quest_id` 显式串联（`newbie_002` 的下一环直接是 `newbie_004`），无死链；`newbie_003` 系预留跳号。
> 请勿据此判定「漏配」，亦勿补 `003` 打断现链。（详见 `design/06-角色与UI/FTE-首次30分钟体验审查_2026-09-16.md` §7.4）

**配置纪律**：新增表须同步 `csv_validator.gd` 白名单（既有门 2 铁律）；`condition_type` 新增须同步该白名单与消费分支（既有成就系统同款铁律）。

### 3.2 奖励口径

- 传法帖：**低于**日常任务（教学不该是收益主渠道），建议日常 ×0.6。
- 晨课圆满：日常单条 ×1.5，且**每日仅一次**。
- 全部走既有池，不新增货币、不新增 Item 类型。

## 6. 可持续维护：防漂移机制

> **前提**：玩法与系统在上线前会持续修改。**引导层必须自动跟上，不能靠人记着同步。**
> **本章优先级高于引导内容本身**——引导最难的不是写对，是玩法改了之后**悄悄失效而无人发现**。

### 6.1 引导失效的四种漂移

| 漂移 | 触发 | 症状 |
|---|---|---|
| **入口漂移** | 页面路由改名 / 删除 | 点「前往」跳空或跳错页 |
| **条件漂移** | 事件 / 计数字段改名 | 目标永远检测不到 → **死目标** |
| **内容漂移** | 玩法流程改了，传法帖仍教旧流程 | 教错，玩家照着做做不出来 |
| **解锁漂移** | 洋葱表新增系统但没配引导 | 新系统裸奔 |

**解锁漂移最危险**：不报错、不崩溃、闸门不红，只是新玩家永远学不会新玩法。

### 6.2 单一事实源：`system_meta.csv`

**铁则：同一事实只存一份。** 引导层不重复存储任何别处已有的信息：

| 信息 | 唯一来源 | 引导层怎么用 |
|---|---|---|
| 系统名 / UI 入口 | `unlock_order.csv` | **按 `系统key` 外键引用** |
| 仙途定义 | `daoTu.csv` | 引用 |
| **核心操作 / 核心产出** | **`system_meta.csv`（唯一新增）** | 派生传法帖 |

⇒ 每个系统在 `system_meta.csv` **只需维护 1 行**：系统 key、核心操作计数键、核心产出物 id、`道途tag`（列名 · 数据层标识，不随文案改名）、晨课权重、传法帖版本。

### 6.3 传法帖模板生成（维护成本降一个数量级）

三步传法**高度模板化** ⇒ **默认自动生成，不手写**：

| 步序 | 模板 | 数据来源 |
|---|---|---|
| 初识 | 「打开{系统名}」+ 前往 | 洋葱表 `UI入口`（外键取） |
| 实践 | 「完成 1 次{核心操作}」 | `system_meta.核心操作计数键` |
| 小成 | 「获得 1 份{核心产出物}」 | `system_meta.核心产出物id` |

- **手写逃生舱**：`quest_teach.csv` 中存在该系统的手写行时**优先用手写**，未覆盖的系统才走模板。模板教得明白的用模板，教不明白的（如论道棋弈）才手写。
- ⇒ 玩法改动时，**绝大多数情况只需改 `system_meta.csv` 一行**，传法帖自动跟随。

### 6.4 启动期自检（挂进 `gate_all.py`）

新增 `audit_teach_chain.py` 作为常驻闸门（纯 CSV 校验，毫秒级）：

| 校验 | 断言 | 治哪种漂移 |
|---|---|---|
| **覆盖率** | 洋葱表「已接入」的系统，每个都有可达传法帖 | 解锁漂移 |
| **可达性** | `jump_path` 存在于 `game_ui.gd::ENTRY_SUB_PAGES` 路由 | 入口漂移 |
| **条件白名单** | `condition_type` 全在白名单内（复用成就系统同款机制） | 条件漂移 |
| **死链检测** | `prev_quest_id` 无环、无悬空 id、无条件永不可满足项 | 死目标 |
| **孤儿检测** | 传法帖绑定的 `系统key` 在洋葱表中存在 | 内容漂移 |

**输出形态**：不只报「失败」，必须报**影响面**——
「本次改动影响 3 条传法帖：T_ALC_2 / T_FORGE_1 / T_FISH_3，请确认」。

### 6.5 运行时容错：引导永不阻断游戏

即使配置失效，**绝不能卡住玩家**：

- 跳转目标不存在 → **静默跳过该步**（不报错、不弹窗、不卡流程）。
- 条件永不可满足 → **超时自动放行**（如 3 天未完成自动标记完成并推进下一条）。
- 引导系统自身异常 → 降级为「无引导」，**游戏照常可玩**。

> 依据：既有 `_引导_跳过()` 的兜底思路（跳过玩家也不落入无目标死局）应扩展到整条引导链。

### 6.6 版本化与老档兼容

- 传法帖带 `传法帖版本`：玩法改动后，**已完成的步骤保留、未完成的重新评估**，不整体重置（避免老玩家被迫重做）。
- **不追溯补引导**：新系统上线后，老玩家只收到「新增系统」的传法帖，同样受「同日 1 条」约束。
- 存档键走增量 + 旧档默认值兜底（沿用 `newbie_active` 同款写法）。

### 6.8 UI 位置漂移：引导只绑语义，不绑坐标

> **当前 UI 布局仍在调整中。引导绝不能以任何形式写死坐标**——否则改一次布局就产生一批指错位置的 bug，**这比没有引导更糟**。

**铁则一：三种引导形态，只允许前两种。**

| 形态 | 绑定对象 | 抗漂移 | 说明 |
|---|---|---|---|
| **目标型**（默认，推荐） | 页面路由 + 语义目标 | ✅ 完全抗漂移 | 「前往丹房炼一炉丹」——只跳转页面，不指具体按钮 |
| **锚点型**（需指位置时） | **Node.name**，运行时 `get_global_rect()` | ✅ 抗漂移 | UI 挪位置，高亮框自动跟随 |
| **坐标型**（**禁用**） | 硬编码 `(x, y)` | ❌ 一改就错 | **明令禁止写入任何坐标** |

**铁则二：锚点用 Node.name —— 这是项目既有惯例，不是新发明。**
既有 `main.gd::_刷新_新手UI()` 已用 `Named("新手红点")` 定位 Tab 角标。沿用此惯例：关键控件统一钉 `name`，引导按名查找。
⇒ **顺带收益**：UI 验收（`ui_full_accept` 等）同样可按 name 断言，**钉 name 对 UI 重构本身就有复用价值**，不是纯为引导服务。

**铁则三：锚点丢失时降级，绝不指错。**

| 情况 | 行为 |
|---|---|
| 锚点存在 | 画高亮框（**运行时**求 rect，非写死） |
| 锚点不存在 | **只做页面跳转，不画高亮**——退化但不误导 |
| 页面都不存在 | 静默跳过该步（同 §6.5） |

> **核心原则：不画一个错位的箭头。错位比缺失更糟。**

**铁则四：锚点纳入自检。**
`audit_teach_chain.py` 增一项——传法帖引用的 `锚点控件名` 必须在目标页面脚本中存在（Grep 断言）。改 UI 误删控件 ⇒ **闸门报错**，而非等玩家发现。

**铁则五：晨课「今日」区做成组件，不占死坐标。**
首页是纯代码 UI（坐标手算），故晨课区必须实现为独立函数（如 `_建_今日区()`）**返回节点**，由首页布局决定挂载位置与高度。布局调整时只动一个调用点，晨课内部零改动。

**UI 布局调整 ≠ 阻塞项。真正依赖布局的只有两处：**

| 依赖 UI 布局（最后插） | 不依赖布局（随时可做） |
|---|---|
| ① 高亮框落位（锚点型引导的指向位置） | `system_meta.csv` 元数据（纯数据） |
| ② 晨课「今日」区在首页的具体坐标 | 传法帖模板生成逻辑 |
| | 通用链改造（`game_state.gd`） |
| | 晨课三事生成逻辑、仙途行为统计 |
| | 自检脚本扩展、CSV 配置 |

⇒ **结论：不必等 UI 定死。**
理由一：锚点钉的是**语义 name 而非坐标**——调布局（挪位置、改尺寸）不会冲掉 name；真被误删，门4 当场报错，是可立即修复的小事，不是灾难。
理由二：钉 name 对 **UI 验收脚本本身就有复用价值**，早钉早受益。

⇒ **唯一的顺序约束是「并行写者」，与 UI 无关**：当另一路任务正在改同一个 `.gd`（如 `game_state.gd`）时才需避让，避免互相覆盖。

### 6.9 给玩法开发者的约定

**改玩法的人只需做一件事**：若改了某系统的**核心操作或产出**，同步 `system_meta.csv` 那一行。
**其余全部自动派生**——传法帖文案、跳转、晨课池、仙途统计。
**忘了改也没关系**：`audit_teach_chain.py` 会在闸门里报出来。

## 7. 未做项与风险

1. **不改动任何玩法数值**——本体系只调度与呈现，产出加成等数值待经济专项确认后回填。
2. **不动 `unlock_order.csv` 本体**——传法帖通过 `绑定系统key` 外挂，洋葱体系保持单一职责。
3. **风险：通用链改造触碰 `game_state.gd` L428–545**——属关键函数，须 read-before-write + 备份 + 逐项探针断言，且 F5 前零战斗触碰审计。
4. **风险：红点收敛可能引发老玩家不适**——故提供「老手模式」开关，默认关、可随时开。
5. **风险：仙途统计字段新增存档键**——须走增量键 + 旧档默认值兜底（沿用 `newbie_active` 同款兼容写法）。
