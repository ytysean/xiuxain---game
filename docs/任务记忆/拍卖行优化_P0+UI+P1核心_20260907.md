## 三、核心功能实现细节

### 3.1 私库物品自动使用（disciple.gd）
- `私库自动使用()`：总入口，月度推演调用
- `私库自动穿戴()`：遍历私库可穿戴物，按战力加成贪心替换，旧装备留私库
- `私库自动服用丹药()`：心魔高→清心丹、受伤→疗伤丹、瓶颈→突破丹、正常→修炼丹
- 安全实现：先收集候选，再统一处理，避免遍历中修改数组

### 3.2 声望等级系统（game_state.gd）
- 5级：普通客人(0)→熟客(500)→贵宾(2000)→黑金贵宾(8000)→至尊贵宾(30000)
- 佣金率：5%→4.5%→4%→3.5%→3%
- 声望获取：成交价×1%，大拍×2
- `_拍卖当前等级()` / `_拍卖当前佣金率()` / `_拍卖增加声望()` / `_拍卖等级名称()`

### 3.3 委托竞拍系统（game_state.gd）
- `设置委托竞拍_S34()`：冻结灵石，记录委托
- `取消委托竞拍_S34()` / `_取消委托竞拍内部_S34()`：解冻灵石
- `_处理委托出价_S34()`：其他玩家出价后系统代委托出价
- `_查找拍品_S34()`：常驻+大拍统一查找
- 委托价内自动出价，超过则失效，灵石冻结/解冻机制完整

### 3.4 延时结算与通知（game_state.gd）
- `_延时结算检查_S34()`：最后10秒出价延长10秒，最多延长4分钟
- `_添加结算通知_S34()` / `获取结算通知_S34()` / `清除结算通知_S34()`
- 结算时自动生成通知：竞得/未竞得/流拍
- 物品自动入库，不需要手动领取

### 3.5 时间轴优化（auction_config.csv + game_state.gd）
- 常驻：持续开放8件，单件30游戏日（2真实小时），到期即补
- 大拍：每365游戏日（约24真实小时）一次，12件，持续30游戏日
- `_推进拍卖会_S34()`改为单件到期即补模式，取消批量刷新

### 3.6 弟子灵石系统（disciple.gd + game_state.gd）
- `私库灵石`变量，序列化/反序列化完整
- `_发放弟子月例_S34()`：按境界发放（练气10→渡劫8000），职位+50%
- 月度推演中调用，宗门灵石扣除入弟子私库

### 3.7 弟子AI竞拍决策（game_state.gd）
- `_弟子AI竞拍决策_S34()`：月度推演调用，遍历拍品计算兴趣
- `_计算弟子拍品兴趣_S34()`：道途匹配+30、品阶适配+20/+10/-50、稀缺性+20/+30/+50、性格±10
- 兴趣≥60则设置委托，复用委托竞拍系统
- `_设置弟子委托_S34()`：心理估值=基准×(0.8+兴趣/200)×性格修正，委托价不超过私库灵石80%

### 3.8 弟子委托拍卖（简化版）
- `_弟子委托拍卖_S34()`：遍历背包，找重复装备或用不上的物品
- 简化实现：直接给弟子灵石（战力×2），不实际上架拍卖行
- 后续P1完善：实际上架，显示"匿名道友寄售"

## 四、设计决策与经验教训

### 4.1 私库自动使用的安全实现
- 问题：遍历私库时同时修改私库可能导致数组遍历异常
- 解决：先收集候选列表，再统一处理，最后统一移除
- 经验：GDScript的Array遍历中修改数组是常见bug来源

### 4.2 委托竞拍的灵石冻结机制
- 问题：委托竞拍需要冻结灵石，防止出价后灵石不足
- 解决：设置委托时立即扣除，代出价时调整冻结金额，结算时扣款或解冻
- 经验：经济系统必须有明确的资金流向，每一步都要有对应的扣减/返还

### 4.3 弟子AI竞拍的兴趣值设计
- 问题：弟子竞拍决策需要综合考虑多种因素
- 解决：0-100兴趣值系统，道途/品阶/稀缺性/性格各有加权，兴趣≥60则参与
- 经验：AI决策用数值化的兴趣值比硬编码条件更灵活可扩展

### 4.4 Edit工具匹配问题
- 问题：Edit工具在匹配含特殊缩进的行时频繁失败
- 解决：改用PowerShell直接修改文件，更可靠
- 经验：对于复杂缩进的文件，PowerShell的字符串替换比Edit工具更稳定
