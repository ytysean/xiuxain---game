## 一、结论先行

**「弟子动起来格格不入」不是画得好不好的问题，是五项渲染口径没对齐。** 全部可量化、可修正：

| # | 口径 | 现状（实测） | 对齐做法 |
|---|---|---|---|
| 1 | **亮度** | 立绘 L=113 ／ 场景 L=55 → **ΔL=+58** | 按**所站地面亮度**归一化 |
| 2 | **色调** | 立绘 R−B=−38 ／ 场景 R−B=−25 | 向所处地面色混合约 14% |
| 3 | **朝向** | 正视镜头 | **背身／侧身**（俯视空间不做正视） |
| 4 | **细节密度** | 512 厚涂胸像缩到 250px → 糊成噪点 | 剪影化＋低明度固有色 |
| 5 | **接地** | 无阴影 → 悬浮 | 脚下椭圆软阴影 |

> 参照阈值：ΔL > 15 即肉眼可辨「贴纸感」。当前 **+58，超标 4 倍**——所以之前那种"直接把立绘贴上去"必然翻车。
> 实测图见 `.workbuddy/_scene_preview/align_test.png`：左右两个角色用的是**同一素材**，只差这五项处理。

## 二、为什么现有弟子立绘不能直接用作场景精灵

三条硬实证（非推测）：

1. **它是方形胸像，没有透明人形轮廓。**
   实测 `avatar_0.png` / `depth_huo2_男_stand.png`：`alpha bbox = (0,0,512,512)`，**内容占画布 100%**——整张图不透明。贴进场景就是一块方形色块，连"人形"都不是。
2. **它是正视镜头的半身／胸像。**
   立绘的设计目的是"给玩家看清脸、做头像"。而场景是**一点透视的俯视空间**，正视立绘放进去会出现"脚浮、身位失重"。
3. **它自带独立打光，且比场景亮一倍。**
   实测 ΔL=+58。立绘是为了在深色 UI 面板上"跳出来"而打的顶光／正面柔光；场景是**炉火暖侧光＋青绿漫射**。两套光照拼在一起，物理上不可能协调。

> **⇒ 立绘与场景精灵是两种完全不同的资产，不能互相替代。**
> 这与项目既有口径一致：`disciple.gd` 头部的「气质＝对外视觉基准（立绘变体）」用于**人物界面**；场景精灵是新增的**第四类资产**。

## 三、型号方案：2 套骨架 × 3 色板 → 6 型

老大提的「男女各做几种模型样板」方向正确。**关键是用骨架复用把美术量压到最低**：

```
男骨架 ×1 ──┬─ 色板/配饰 变体 A → 杂役弟子（清瘦·文）
            ├─ 色板/配饰 变体 B → 负薪力士（壮硕·暴）
            └─ 色板/配饰 变体 C → 执事长老（端方·沉）
女骨架 ×1 ──┬─ 色板/配饰 变体 A → 药童师妹（纤秀·文）
            ├─ 色板/配饰 变体 B → 飒爽女修（英挺·娇）
            └─ 色板/配饰 变体 C → 端方执事（端方·沉）
```

**只画 2 套骨架动画，长出 6 个视觉型号。** 色板变体与项目既有机制同构（`弟子立绘变体槽位 _v{n}` 同样是"同底模换色"）。

**气质映射**沿用 `disciple.gd` 已有的气质六型（chen/gu/wen/bao/jiao/huo2），不新增体系——保证"看到哪个型号，就能读出什么气质"，与立绘口径一致。

**动作只做 3 种**（每种 2–4 帧）：待机 · 行走 · 劳作。
⇒ 美术总量 ≈ 2 骨架 × 3 动作 × 3 帧 ≈ **18 张图**（同朝向可复用），远小于"6 型号各做一套"的 54 张。

## 四、融入技术参数（可直接落代码）

### 4.1 亮度归一化（最有效的一条）

```
目标亮度 = 所处地面亮度 × 0.90      # 人物是背光实体，应略暗于地面，而非更亮
k        = clamp(目标亮度 / 精灵原始亮度, 0.10, 1.30)
```

实测依据：丹房场景地面**光照极不均匀**——左地砖 L=22.5、右地砖 L=69.1（**系数差 3 倍**）。
⇒ **同一张精灵图，站左边和站右边必须用不同的 k**。这是"看起来很假"的头号成因。

> 踩坑记录：首版取 `地面亮度 × 1.16`（提亮），结果小人在暗场景里**过亮**、像幽灵。修正为 `× 0.90` 后才正常。

### 4.2 色调偏置

```
结果RGB = blend(精灵RGB, 所处地面色, 0.14)   # 只混 RGB，alpha 原样保留
```
> 踩坑记录：混合比例 0.22 会把衣色洗成灰度；且**必须保留 alpha**，否则透明区被染色。

### 4.3 朝光源的边缘光（暗场景角色的"存在感"来源）

暗场景里人物**不靠固有色被看见，靠轮廓＋边缘光**。做法：叠加一层乘性方向渐变——
朝主光源一侧暖亮（`#FFD098`）、背光远端冷暗（`#3A3730`）。
丹房主光＝炉火（中心偏下），故**左侧角色右缘亮、右侧角色左缘亮**。

### 4.4 接地阴影

```
椭圆  rx = 0.44 × 角色高   ry = 0.085 × 角色高
高斯模糊 ≈ ry     alpha ≈ 192     色 #090805
位置：脚底线上方 3px
```
这是**性价比最高的融入手段**，一次实现全局复用。

### 4.5 精灵尺寸按景深分档

| 站位 | 显示高度 | 说明 |
|---|---|---|
| 近景（前景地砖） | ≈ 300px | 可带 4 帧行走 |
| 中景（柜台／台面前） | ≈ 210px | 以站桩＋小幅位移为主 |
| 远景（靠墙） | ≈ 150px | 只做站桩，零位移 |

源图建议 **256px 高导出**（覆盖近景 300px 的放大需求 + 手机端缩放余量）。

## 五、动效方案：怎么动才不假

直接引用项目**既有设计**（《UX体验·宗主复兴主线》§3.3）：

> 「世界活着 ≠ 屏幕在动」——**呼吸原则：4–6s 周期、<0.8Hz、退到潜意识层**；人事「**不必多，3–5 个活跃像素即够**」。

| 动作 | 帧数 | 帧率 | 附加 | 备注 |
|---|---|---|---|---|
| 待机 | 2 帧 | 8fps | ±1–2px 上下浮动 | **零序列帧也可做**（单帧＋Tween 浮动） |
| 行走 | 4 帧 | 10fps | Tween 匀速位移 | **必须有位移** |
| 劳作 | 2 帧 | 6fps | 固定锚点 | 扇火／捣药等 |

**红线：绝不做"原地踏步"**——那是廉价感的头号来源。要么有位移，要么干脆站桩。

**同屏上限 5 个角色**（对齐既有"3–5 个活跃像素"设计），避免性能与视觉噪音。

### 5.1 实测验证（2026-09-13 · 已做出可播放动画）

`.workbuddy/_scene_preview/minion_anim.gif`（24 帧 / 10fps / 场景带 1080×710＋说明条）：

| 角色 | 动作 | 表现 |
|---|---|---|
| 杂役弟子 | **行走** | 4 帧腿交替＋身体起伏＋手臂反摆；走到端点**自动转向**（左右镜像） |
| 药童 | **扇火** | 2 帧手臂上下＋蒲扇随动，面向丹炉（背身/侧身） |
| 执事师姐 | **待机** | 2 帧呼吸＋±1px 浮动 |
| 场景本身 | **炉火跳动** | 亮度脉动 3Hz——让场景也"活" |

关键帧检查图：`.workbuddy/_scene_preview/check_walk.png`、`check_fan.png`。

### 5.2 两条实测踩坑

1. **Q版比例必须是 1:3.5 头身**。首版按 1:5（头半径 0.10H）画 → 像"踩高跷的火柴人"；改为头半径 **0.145H** ＋ 短粗腿（腿只占 18–20% 高）才出 Q版观感。
2. **暗场景里"脸"必须压暗**。首版用常规肤色 `(188,156,118)`，归一化后脸变成一块"发光的白饼"，最抢眼也最假。改成暗肤色 `(150,124,94)` ＋ **脸偏朝向侧、后脑偏背侧**——既压住亮度，又能一眼读出朝向。

### 5.3 Godot 落地

| 方案 | 做法 | 适用 |
|---|---|---|
| A 序列帧 | `SpriteFrames` + `AnimatedSprite2D`（项目目前零使用，需新建） | 行走／劳作 |

**建议**：待机走 B（最省），行走/劳作走 A。角色节点统一挂在场景页的 `_角色层` 容器下，锚点坐标取自场景模板库。

## 八、实测补充：角色美术的两条路（2026-09-13 第二轮）

> 起因：老大反馈「弟子样子还是很简陋」「只有炉火在动，其他都没动」。本节是对这两个问题的实测结论。

### 8.1 结论表

| 环节 | 手段 | 实测结果 |
|---|---|---|
| 精致度 | PIL 几何图元拼装（椭圆 + 多边形） | ❌ **已到天花板**——无五官、平铺色块、无层次 |
| 精致度 | **AI 出图（透明底直出）** | ✅ **质变**——五官 / 发髻 / 衣褶 / 轮廓光俱全 |
| 融入 | 五步归一化 | ✅ 直贴 = 贴纸 → 归一化后与场景同一光照体系 |
| 动作 | 整体形变（位移 / 摆动 / 前倾） | ⚠️ 能看出"走"和"扇"，但**无关节动作** |
| 动作 | **部件化（cutout animation）** | ⭕ 待做——每型号约 6 部件即可做出真实关节动作 |

**一句话**：**精致度换 AI 出图，动作用部件化。** 继续在几何绘制上调参＝在 Tesseract 上调参。

### 8.2 AI 出图的三个工程坑（实测，务必照抄结论）

1. **"透明底"是假的。** 参数传 `background: transparent`，实际返回的是**画上去的棋盘格图案**（不透明像素）。
   `getbbox()` 返回 `(0,0,W,H)` 全画布 → 直接贴进场景就是三个灰底方块。
2. **抠底必须用「连通域」，不能用颜色阈值。** 棋盘格是两色交替，`floodfill(thresh=30)` 跨不过格子边界
   （实测只抠掉 **0.1%**）。有效做法：
   - 判据 = **HSV 中 S < 14 且 V > 70**（棋盘格 S≈0；角色脸 S≈32）
   - 再取「**与图像四边连通**」的候选为真背景
   - ⇒ 实测抠掉 **64.1%**，且角色内部白领（低饱和但与边缘不连通）**完整保留**
3. **不要在抠底前做局部清除。** 曾为去水印粗暴清除「右下角矩形」→ 把角色**下半身切掉**。
   棋盘格背景整体抠除后水印随之消失，**无需额外处理**。

### 8.3 形变驱动 vs 部件化驱动

| | 形变（当前已实现） | 部件化（推荐下一步） |
|---|---|---|
| 资产量 | AI 单图 × 1 | 头 / 躯干 / 上臂×2 / 前臂×2 / 腿×2 ≈ **6–8 件** |
| 待机呼吸 | ✅ | ✅ |
| 走位 / 转身 | ✅ | ✅ |
| **抬腿走路** | ❌ | ✅ |
| **挥臂扇火 / 劳作** | ❌ | ✅ |
| 实现 | 整图 `rotate` + 位移（绕足底） | `Skeleton2D` + `Bone2D`，或节点层级 rotate |
| 成本 | 零（AI 图直接可用） | 需拆分 + 骨骼绑定一次 |

**判断**：**待机 / 走位**用形变足够（已实测）；**要"扇火""捣药"这类手上动作，必须部件化。**

### 8.4 生产路径（5 步）

1. **AI 出图**：每型 1 张正视图，`background: transparent`（拿到手先按 8.2 抠底）
2. **归一化为标准画布**：角色净高 **256px** + 四周 **20% 安全边**（供旋转/位移不裁切）
3. **拆件**：头（含发髻）/ 躯干 / 上臂 / 前臂 / 大腿 / 小腿 ≈ 6–8 件 → 独立 PNG
4. **Godot**：每型一个 `Skeleton2D` 场景；动作 = 骨骼关键帧；一套动作 **6 型复用**
5. **型号**：男 3 型 + 女 3 型，沿用项目既有六型气质（chen / gu / wen / bao / jiao / huo2）

### 8.5 场景侧必做（否则"整页死气"）

单靠角色动不够——**场景本身至少要 3 层动效**才算"活"：

| 层 | 做法 | 实测效果 |
|---|---|---|
| 光照呼吸 | 整帧亮度随主光源（炉火）±2% | 最省、最有效 |
| 主光源脉动 | 炉火区多频叠加（3Hz + 7Hz）＋ 色温变化 | 一眼可见 |
| 粒子 | 烟柱翻腾 / 飞溅火星 / 灵光尘埃 | 补足"空气感" |
| 局部微动 | 垂挂物摆动、挂画微动（**幅度 ≥4px**，否则看不出） | 实测 2.6px 肉眼不可见 |

⚠ **烟柱不要用"整块像素滚动"**：曾把烟区选成 `(556,34)-(812,374)`，**正好罩住匾额**，
滚动时匾额跟着漂 → 明显穿帮。**改用粒子叠加（不动像素）** 才安全。

## 九、v3 实测：写实比例 + 接地 + 关节动作（2026-09-13 第三轮）

老大看完 v2 提三条：**① 太 Q 版（脸也卡通）② 左右两个弟子没站在地面上 ③ 要关节动作**。逐条落地结果：

### 9.1 三条问题的根因与修法

| 问题 | 根因（实测） | 修法 | 结果 |
|---|---|---|---|
| 太 Q 版 | v2 的 prompt 里写了「可爱 3.5 头身」——**关键词直接把模型带偏** | prompt 改为「写实正常人体比例、约六头身、绝对不要 Q 版 / 不要大头娃娃」 | 6.5 头身、写实五官 ✅ |
| 没站地上 | 三个角色脚底 y 各不相同（664/694/650），且左、右两人正落在**前景罐子堆上方** | 站位统一到前景地面带（690/704/696），加**双层接地影**（实心核心影 + 外扩柔影） | 脚踩实 ✅ |
| 无关节 | v2 是**整体形变**（绕脚底摆动），腿之间没有相对运动 | **柔性位移场**：腿分侧反相摆动 + 交替抬脚 | 迈步清晰 ✅ |

### 9.2 ★ 关键洞察：长袍角色做不出迈步，角色必须露腿

第一版沿用长袍角色做「腿部刚性旋转」→ **把袍摆切出裂缝**；改柔性位移场后裂缝消失，但**腿被袍子遮住，动作依然看不出来**。

⇒ 结论：**要做"迈步"，角色必须露腿**。男弟子改为**劲装短打 + 束脚长裤**（修真题材里外门杂役本就该如此），腿部可见后位移场立刻做出清晰迈步。
**这不是美术偏好问题，是"能不能做出动画"的技术前置**——定为弟子场景精灵的素材规格。

### 9.3 关节实现（可直接移植 Godot）

**柔性位移场**（逐像素反向映射 + 双线性插值，numpy 向量化）：

```
腿区（髋→脚）：env = t^0.9                              # 髋部 0 → 脚部最大（绕髋摆腿；线性包络，避免裤腿鼓胀）
                dx  = tanh((x-cx)/kx) * env * s * 40px   # 左右分侧反相
垂直抬脚：      dy  = -lift包络 * (左半·max(0,s) + 右半·max(0,-s)) * 0.055h
上身：          env = sin(πt) * (-0.42) * s             # 与腿反相轻摆
扇火：          dy  = sin(2πφ) * 20px * (1-t)^0.9       # 手部最大 → 肩部归零
```

- **连续位移场 ⇒ 长袍 / 裤腿只弯曲不撕裂**（对比：刚性切块旋转会撕）
- 参数：身高 h=300px（中景角色）、maxdx=40px、抬脚 0.055h≈16px、步频 **2 步/半程**（步幅≈132px）

### 9.4 ★ 四条实测踩坑（做同类动画直接照抄）

1. **`np.mgrid` 返回顺序是 (行=y, 列=x)** —— 写成 `xs, ys = np.mgrid[...]` 会把 x/y 对调（症状：位移场全乱但**不报错**）。
2. **float32 下 `sin(π·1.0)` 会算出 -8e-8** → 负底数取分数次幂 = NaN → 索引崩。凡 `sin(...)**k` 一律先 `np.clip(...,0,1)`。
3. **`Image.MESH` 的 quad 语义反复踩空**（本工程两次撕裂）→ **直接改用 numpy 逐像素反向映射**更可控。
4. **抽帧检查要避开相位零点**：v2 检查图取 0/3/6/9 帧，恰巧每帧相位都是 0 ⇒ 看起来"完全没动"，实际动画是好的。**抽帧前先算相位**。

## 十、v4 实测：修真道袍 + 衣袂飘举（2026-09-13 第四轮）

老大第四轮反馈五条，逐条闭环。**这一轮最重要的不是某个参数，而是一次方向性纠偏。**

### 10.1 五条反馈的根因与改法

| 反馈 | 根因（实证） | 改法 |
|---|---|---|
| 左边弟子悬空没踩地 | 我把左弟子放在 `x=210` —— 那里是**前景葫芦堆**，根本不是地面 | 见 10.3「可站立地面带」标定 |
| 风格古代但不合修真界 | 为做出「迈步」，v3 把男弟子改成**短打劲装**（武术/江湖味） | 换回广袖道袍 + 披帛飘带 + 发髻玉簪 + 灵气微光 |
| 女弟子原地、上下把人拉长 | v3 的 `fan_warp` 是**整段垂直平移**（位移场不区分部位）⇒ 读作拉伸 | 废弃。改**多频叠加衣袂飘举 + 绕脚底重心微旋** |
| 走动的弟子速度太快 | 半程 2 步 / 24 帧 2.4 秒走完 500px | **取消来回走动** |
| 特效有点假 | 白袍在暗场景里即使做完全局亮度匹配仍过亮，像**自发光体** | 见 10.4「高光压缩」 |

### 10.2 ★ 核心取舍：不追求高难度动作（方向性结论）

v3 走了一条弯路：**为了让「迈步」可见，把角色改成短打露腿 —— 等于拿世界观去迁就技术难点。**
换赛道后结论明确：

> **长袍 + 单张整图 + 位移场 ⇒ 做不出可信的迈步，也做不出可信的「只动手臂扇火」。**
> 位移场在 x/y 上连续，作用到「袖子」必然带动上半身；作用到「腿」必然搅动袍摆。

而修真审美里，**「飘」比「走」更贴题** —— 衣袂飘举、披帛拂动、吐纳呼吸，既是世
界观自带的动感，又是位移场最擅长、最不可能崩的效果。丹房弟子本就各守其位，不必
来回走动。**降难度不是妥协，是选对了题。**

### 10.3 ★ 站位必须量化：可站立地面带

`scene_ground_probe.py` 逐列扫描「前景遮挡」后得到硬结论：

- **可站立区 = 火塘前方 `x ∈ [396, 862]`**，`y ≈ 680–706`
- 左侧 `x < 390` 是**葫芦/坛堆**（前景物）→ 站上去必然「悬空」
- 右侧 `x > 862` 是**瓶罐堆 + 药架** → 同理
- 火塘本体占 `x ∈ [576, 782]` → 人站这里会遮住炉火中心，故**三人只能分居炉体两侧**

⇒ 站位代码：`ground_y_at(x) = 700 - |x-630|/630 × 22`（近景更低，向两侧微抬）。
**铁律：脚底 y 必须由场景实测得出，不能手填。**

### 10.4 ★ 暗场景白袍必须先压高光（否则必发飘）

**实测：** 纯白裙摆 `V≈230`，即使按 `k = 地面亮度×0.94 / 角色亮度` 做全局匹配，
结果仍然比场景亮约 40% ⇒ 在暗绿场景里读作**一块自发光体**（v4 首版实测踩到）。

**正解：先压高光，再匹配亮度。**

```python
def align(spr, gl, gc, tint=0.20, lit_left=True, hi_knee=140, hi_gain=0.46):
    base = spr.convert("RGB").point(
        lambda v: v if v <= hi_knee else hi_knee + int((v - hi_knee) * hi_gain))
    k = max(0.10, min(1.30, (gl * 0.94) / max(1.0, lum(base))))
    ...
```

`V>140` 的部分按 `0.46` 压下来（230 → 181），再做亮度匹配；同时色调偏置从 `0.12`
提到 `0.20`，让角色吃到更多场景色。⇒ 白袍融入暗部，与深色执事同处一个光照体系。

### 10.5 三档「衣袂飘举」参数（可直接复用）

| 档位 | 角色 | `ax`（横向） | `ay`（纵向） | 说明 |
|---|---|---|---|---|
| 大幅 | 女弟子（浅青仙裙） | 0.062 | 0.017 | 裙摆/披帛明显飘动 |
| 中幅 | 月白弟子 | 0.048 | 0.013 | 衣带拂动 |
| 小幅 | 墨青执事 | 0.026 | 0.008 | 沉稳人设，几乎静立 |

位移场关键点（三条都是实测出来的）：

1. **多频叠加**：主频 `0.72` + 泛音 `0.28`（`1.63×` 频率）。**单频正弦会读成「钟摆」**，
   叠加泛音后才有布料的不规则感。
2. **沿高度带相位差** `+ (foot-ys) * 0.017` ⇒ 下摆滞后于腰部 ⇒ 波动而非整体平移。
3. **包络 `sin(πs)^0.85` 在脚底归零** ⇒ 脚钉在原地，不滑步。
4. 额外一层**绕脚底的重心微旋**（`±1.15°`，`rotate(center=(w/2, foot))`）——
   脚不动、上身微摆，读作「人在微微动」而非纸片平移。
