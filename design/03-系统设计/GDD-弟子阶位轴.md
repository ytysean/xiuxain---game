# 《太玄宗门录》弟子阶位轴（双轴·阶位轴）系统设计

> 版本：v1.0 ｜ S1 批1（机制补全第一块地基）｜ 定位：在**完全不动现役身份轴**前提下，新增独立 4 级阶位轴（执事→堂主→长老→供奉）。
> 铁律红线：零底层破坏、旧档无缝兼容；所有新增字段用 `.get(...,默认)`；数值加成为辅不冲击已验证战斗基线；任何战力加成须折算攻防血速（MEMORY 铁律）。

---

## 〇、已裁决·不可推翻（权威基线，本 GDD 全部决策依从）

1. 保留现有 5 级 `身份` 轴（外门→内门弟子→核心弟子→亲传弟子→长老，境界驱动、只升不降）**完全不动**。
2. 新增独立 4 级 `阶位` 轴（执事→堂主→长老→供奉，功绩/考核驱动、玩家手动任命、考核通过后晋升）。
3. 双轴同名「长老」消歧：身份轴长老 = 化神修为层级（最高）；阶位轴长老 = 第三阶管理职位。UI/存档须加轴前缀区分（`身份·长老` / `阶位·长老`）。
4. **至少内门弟子才可授阶；境界不足无法任高阶**。

> 代码侧佐证（已 Read 核对，2026-07-25 在场）：
> - `disciple.gd` L149 `const 身份层级序: Array[String] = ["外门","内门弟子","核心弟子","亲传弟子","长老"]`（⚠️ 任务原称 L131，实际落点为 **L149**，engineering-lead 以 L149 为准）。
> - `disciple.gd` `_刷新身份()` L637：仅由境界映射驱动、只升不降，未引用任何阶位字段 → 身份轴逻辑与本 GDD 零耦合。
> - `game_state.gd` `任命负责人(key, d)` L1705、`举办测灵根()` L1781（L1818 留「制式装备/入职包」hook）。本 GDD 复用此二函数，不新增并行任命链路。

## 一、系统概述与目标（MDA 映射）

### 1.1 设计支柱（S1 批1 内）
- **P1 自主（Autonomy）**：玩家手动发起考核、任免阶位、决定谁掌何堂——把「宗门管理权」交还玩家。
- **P2 胜任（Competence）**：阶位晋升有明确可达成条件（境界+贡献+考核掷骰），晋升即时反馈（纪事永录+全宗士气加成），形成「我能经营好一座宗门」的正循环。
- **P3 关联（Relatedness）**：弟子因阶位获得明确宗门角色（谁管丹堂、谁接引新徒），强化玩家与弟子的「宗门共同体」情感锚点（呼应 `GDD-弟子养成.md` 情感代入目标）。

### 1.2 MDA 三层
| 层 | 本系统落点 |
|---|---|
| **Mechanics（机制）** | 阶位字段 + 授阶边界 + 考核掷骰 + 名额上限 + 降级淘汰 + 破格晋升 |
| **Dynamics（动态）** | 玩家在「培养境界（身份轴）」与「功绩考核（阶位轴）」两条线间分配资源；高阶阶位抢手、名额稀缺形成博弈 |
| **Aesthetics（美学）** | 体验目标 = *Discovery（经营宗门格局）* + *Submission（安稳推演的制度感）*；晋升仪式感提供 *Expression/Spectacle* 微高潮 |

### 1.3 玩家心理映射（自我决定论 + Bartle）
- **成就型（Achiever）**：冲阶位满编、攒贡献刷考核成功率。
- **社交型（Socializer）**：任命亲传弟子掌核心堂口、接引执事带新人。
- **探索型（Explorer）**：解锁高阶阶位权限（如供奉的全局加成）。
- **杀戮型（Killer）**：通过「降级淘汰」行使管理权威（轻量、低风险出口）。
- **心流**：名额随宗门等级平滑放开 + 考核成功率 60%~90% 区间，避免「必成」无聊或「死卡」焦虑。

### 1.4 与身份轴的关系（一句话）
身份轴回答「这弟子修为多高」，阶位轴回答「这弟子在宗门管多大事」——双轴正交、互补、互不写对方字段。

## 二、阶位字段数据结构（新增·向后兼容）

### 2.1 新增字段（`disciple.gd`，全部 additive，不触碰现役字段）

```gdscript
# === S1 批1：阶位轴（方案 B 双轴并行，独立于身份轴）===
const 阶位层级序: Array[String] = ["执事", "堂主", "长老", "供奉"]   # 阶位轴 4 级，与 身份层级序 并列
var 阶位: String = "无"            # 当前阶位：无/执事/堂主/长老/供奉（默认无 = 未授阶）
var 考核冷却剩余: int = 0          # 考核失败后的冷却（游戏日），>0 时不可再对其发起考核
var 考核心得: bool = false         # 失败后获得，下次考核 +10%，一次性消耗（消耗后清零）
# var 功绩: int = 0                # 【S1 MVP 不启用】预留 per-disciple 功绩字段；当前功绩复用全局 贡献点（见 §4.1 / §7.4）
```

> **Engineering 注意（typed-array 重置陷阱）**：引用常量时沿用现役 `_刷新身份()` L643 范式——用**无类型** `var 序: Array = 阶位层级序`，**禁** `Array[String]()` 或 `x = []` 重赋（MEMORY 铁律：Godot 4.7 严格模式会崩，gdtoolkit 报 Unexpected token）。
>
> **命名冲突声明**：阶位 4 名（执事/堂主/长老/供奉）属「宗门职位」，与 `item.gd` 七阶品阶（凡/灵/宝/王/圣/仙/道）及掉落展示四档（凡/良/上/极）**无任何重叠**，不触发 MEMORY「品阶三层映射唯一基准」铁律。

### 2.2 存档读写（`to_dict` / `from_dict`，旧档无缝）

**`to_dict()`（L959-968 区块）追加三键：**
```gdscript
"阶位": 阶位, "考核冷却剩余": 考核冷却剩余, "考核心得": 考核心得,
```

**`from_dict()`（L970 起）追加三行（全部 `.get(...,默认)`）：**
```gdscript
阶位 = d.get("阶位", _默认阶位(身份))          # 旧档缺键 → 按身份推导 legacy 阶位（见 §2.3）
考核冷却剩余 = int(d.get("考核冷却剩余", 0))
考核心得 = bool(d.get("考核心得", false))
```
> 关键：`.get` 的**默认值是动态函数 `_默认阶位(身份)`**，而非固定 `"无"`——这实现了「旧档默认认内门对应阶位」（见 §2.3）。新档（已写 `"阶位":"无"`）直读存储值，不受影响。

### 2.3 旧档兼容映射 `_默认阶位(身份)`（新增函数，仿 `_默认身份` L657）
旧档弟子（存档无 `阶位` 键）按身份轴层级推导 legacy 阶位，避免「化神长老(身份) 却阶位无」的违和：

| 身份轴值 | legacy 阶位（旧档缺键时） |
|---|---|
| 外门 | 无 |
| 内门弟子 | 执事 |
| 核心弟子 | 堂主 |
| 亲传弟子 | 长老（阶位） |
| 长老（身份） | 供奉 |

```gdscript
func _默认阶位(身份值: String) -> String:
    match 身份值:
        "内门弟子": return "执事"
        "核心弟子": return "堂主"
        "亲传弟子": return "长老"
        "长老": return "供奉"
        _: return "无"
```

> **【决策点 D1 · 名额溢出豁免】** legacy 阶位为「祖父条款」，加载时**豁免名额上限**（名额上限仅约束 S1 之后的手动考核晋升）。理由：不得因新系统降级 veteran 弟子。若主理人认为应硬卡名额，则 legacy 超额部分按「身份高者优先保阶、低者回落无」裁剪——默认采用豁免方案，待主理人确认。

### 2.4 边缘情况（≥3 类）
- **EC-1 旧档缺键**：`d.get("阶位", _默认阶位(身份))` → 无 null/空，全部落在合法枚举。
- **EC-2 新档写 `"阶位":"无"` 后又读**：`.get` 命中存储键，返回 `"无"`，不会被 `_默认阶位` 误升。
- **EC-3 `_默认阶位` 收到未知身份串**（如未来扩展）：`match` 落到 `_: return "无"`，不崩。
- **EC-4 存档损坏/类型错乱**：`int(d.get(...))` / `bool(d.get(...))` 强转，避免 String→int 解析异常触发 pre_f5 第10门之外的真机崩。

## 三、授阶边界判定（精确阈值 + 与身份轴绑定）

### 3.1 核心判定函数（供 §4 考核 / §7 联动复用）

```gdscript
# 身份轴索引：外门=0, 内门弟子=1, 核心弟子=2, 亲传弟子=3, 长老(身份)=4
func 可授阶(d: Disciple) -> bool:
    return 身份层级序.find(d.身份) >= 1          # 至少内门弟子

func 阶位索引(d: Disciple) -> int:
    return 阶位层级序.find(d.阶位)               # "无" → -1

func 阶位上限索引(d: Disciple, 破格: bool) -> int:
    var i: int = 身份层级序.find(d.身份)
    var cap: int = clamp(i - 1, -1, 3)           # 非破格：内门→0执事 / 核心→1堂主 / 亲传→2长老阶位 / 长老身份→3供奉
    if 破格:
        cap = clamp(i, -1, 3)                     # 破格：上限 +1 阶（仍须 ≥ 内门）
    return cap
```

### 3.2 边界决策表（不可推翻裁决的精确化）
| 弟子身份 | 可授阶？ | 非破格可任最高阶位 | 破格可任最高阶位 |
|---|---|---|---|
| 外门 | ❌ 否 | — | — |
| 内门弟子（筑基） | ✅ | 执事 | 堂主 |
| 核心弟子（金丹） | ✅ | 堂主 | 长老（阶位） |
| 亲传弟子（元婴） | ✅ | 长老（阶位） | 供奉 |
| 长老（身份，化神） | ✅ | 供奉 | 供奉（已顶） |

> **【决策点 D2】** 「境界不足无法任高阶」= 阶位上限由身份轴索引减 1 决定（封顶 3=供奉）。任何任命/考核目标阶位索引 **不得超过 `阶位上限索引`**，否则拒绝并提示「境界不足，需先提升修为/身份」。

### 3.3 降级/罢免的独立路径
阶位轴「只升不降」**不适用**（与身份轴相反）。降级走独立手动操作（见 §4.6），不走 `阶位上限索引` 正向校验。

### 3.4 边缘情况
- **EC-5 外门弟子被误纳入考核候选**：`可授阶()` 前置过滤，候选列表根本不含外门。
- **EC-6 破格后身份下降**：身份轴只升不降，此情形不会发生；若未来放开，应在每次阶位读取时 `clamp(阶位索引, -1, 阶位上限索引)` 防御（当前可省略）。
- **EC-7 高阶阶位弟子被任命时身份恰好临界**（如内门刚达标即破格任堂主）：`阶位上限索引(破格=true)` 以调用瞬间身份为准，任命成功即落定，不随后续回滚。

## 四、晋升考核机制

> 驱动：玩家**手动发起**（非自动）。资源：复用全局 `贡献点`（`game_state.gd` L29，非 per-disciple）。掷骰：基础 60% / 满配 90%。

### 4.1 发起条件与消耗
- **候选资格**：`可授阶(d) == true` 且 `d.考核冷却剩余 <= 0` 且 `阶位索引(d) < 阶位上限索引(d, 破格)` 且 `目标阶位名额未满`（见 §4.4）。
- **行政成本**：发起单次考核消耗全局 `贡献点 -= 考核成本`（默认 **50**，调参待校准 `[PLACEHOLDER]`）。成本在「发起」时扣除（无论成败），体现举办考核的行政开销。
- **【决策点 D3 · 功绩来源】** S1 MVP **复用全局 `贡献点`** 作为唯一功绩/资源闸门（不新增 per-disciple 功绩系统）。理由：零新增底层、与「宗门贡献攒条件」(§7.4) 直接对齐。`var 功绩` 字段预留但**本批不启用**，待 S1 后半/ S2 宗门贡献 per-disciple 体系落地后再接。

### 4.2 成功率公式（clamp 0.60~0.90）
```gdscript
func 考核成功率(d: Disciple) -> float:
    var P: float = 0.60                                  # 基础
    P += clamp(float(贡献点) / 贡献阈值, 0.0, 1.0) * 0.20  # 功绩充足度 +0~0.20（贡献阈值默认 300 [PLACEHOLDER]）
    if d.灵根品阶 in ["极品", "天品"]: P += 0.05          # 灵根加成
    if 有特殊命格(d): P += 0.05                          # 命格加成（命格数据见 DestinyDataLoader）
    if d.考核心得: P += 0.10                             # 考核心得 buff（一次性）
    return clamp(P, 0.0, 0.90)                           # 满配封顶 90%
```
> 满配 = 贡献达标 + 极品灵根 + 特殊命格 + 考核心得 = 0.60+0.20+0.05+0.05+0.10 = 1.00 → clamp 0.90 ✅ 符合裁决。

### 4.3 结果与惩罚
- **成功**：`阶位 = 阶位层级序[阶位索引(d)+1]`；`考核心得 = false`（消耗）；触发 §4.7 仪式感。
- **失败**：
  - 全局 `贡献点 -= 失败扣减`（默认 **50** `[PLACEHOLDER]`，与行政成本叠加即单次失败共 -100）；
  - `d.考核冷却剩余 = 7`（游戏日，期间不可再对其发起考核）；
  - `d.考核心得 = true`（下次 +10%）；
  - 写轻量纪事（非庆典级）。

### 4.4 名额限制（与宗门等级绑定）
名额 = `f(门派等级)`，跨全宗各阶位**总数**上限：

| 阶位 | 名额公式（门派等级 L） | L1 | L3 | L5 | L10 |
|---|---|---|---|---|---|
| 执事 | 2 + L | 3 | 5 | 7 | 12 |
| 堂主 | 1 + floor(L/2) | 1 | 2 | 3 | 6 |
| 长老（阶位） | floor(L/3) | 0 | 1 | 1 | 3 |
| 供奉 | floor(L/5) | 0 | 0 | 1 | 2 |

> **【决策点 D4】** 名额公式与默认值为**推荐起点**，`[PLACEHOLDER]` 待数值实测校准。早期（L1）玩家可拥 1 堂主 + 3 执事 = 4 阶位holder，与弟子规模匹配，不溢出。
> 名额查询函数 `阶位名额占用(阶位名) -> int` 遍历 `弟子列表` 统计；发起考核前 `占用 < 上限` 才放行。

### 4.5 批量考核
- 弟子页多选模式勾选多名候选 → 一次性发起；逐人独立掷骰（`randf() < 考核成功率(d)`）；结果汇总弹窗（成功/失败分列 + 总消耗贡献点）。
- 批量时每人独立判定冷却与名额；若中途名额满，后续候选跳过并提示「名额已满」。

### 4.6 破格晋升 / 降级淘汰
- **破格晋升**：满足 `破格条件` 时 `阶位上限索引(破格=true)`（上限 +1 阶）。破格条件候选（**【决策点 D5 · 待主理人终裁具体阈值】**）：
  - 弟子 `灵根品阶 ∈ {极品, 天品}`，或
  - 持有「经营/宗门」类特殊命格（`DestinyDataLoader` 维度判定），或
  - 宗门声望 ≥ `破格声望阈值`（默认 **5000** `[PLACEHOLDER]`）且刚立大功（纪事标记）。
  - 破格仍须 `可授阶()`（≥内门），不可让外门越级。
- **降级淘汰**：玩家手动「罢免阶位」→ 阶位降一级（供奉→长老→堂主→执事→无）；释放名额；弟子忠诚度小幅下降（沿用 `GDD-宗门经营.md` §五.1「罢免职位忠诚下降」口径，具体值 `[PLACEHOLDER]`）。降级**不走考核掷骰、不消耗贡献点**。

### 4.7 晋升仪式感 / 纪事永录 / 全宗士气
- **纪事永录**：成功晋升写 `宗门纪事.append({"日":累计游戏日,"弟子":d.姓名,"稀有度":"宗门","名称":"阶位晋升","文案":"【晋升】%s 晋升为 阶位·%s" % [d.姓名, d.阶位]})`（复用 `任命负责人` L1710 范式，persistent）。
- **推演条目**：`_加推演条目("【晋升】%s 任 阶位·%s。" % [d.姓名, d.阶位], ET_APPOINT, PRIO_NORMAL, {"弟子":d.姓名,"阶位":d.阶位})`。
- **全宗士气临时加成**：复用 `设置气运buff(修炼加, 产出加, 天数)`（`game_state.gd` L758，与天品弟子同机制）：
  - 堂主 / 长老（阶位）晋升：`设置气运buff(0.02, 0.01, 3)`（调参待校准）
  - 供奉晋升：`设置气运buff(0.03, 0.02, 7)`（同天品弟子 L1829 口径）
  - 执事晋升：仅纪事 + 推演条目，不触发全局 buff（轻量）。

### 4.8 边缘情况
- **EC-8 考核中名额被他人占满**：发起前二次校验 `占用 < 上限`；掷骰成功落定前再校验一次（防并发/批量竞态）。
- **EC-9 考核心得未消耗即再次失败**：失败分支 `考核心得 = true` 幂等，重复失败不叠加 >+10%。
- **EC-10 7 天冷却期间玩家强发**：`考核冷却剩余 > 0` 前置拦截，UI 禁用按钮并显示剩余天数。
- **EC-11 贡献点不足支付行政成本**：发起前 `贡献点 >= 考核成本` 校验，不足则禁用并提示「贡献点不足」。

## 五、数值平衡

### 5.1 总原则：权限差异为主，数值加成为辅
阶位的**核心价值 = 权限**（负责人资格 / 俸禄倍率【待俸禄 GDD】/ 历练全队加成资格 / 仪式感）。数值加成仅作「甜头」，严格封顶。

### 5.2 阶位战力加成（须折算攻防血速，MEMORY 铁律）
在 `disciple.gd::get_final_combat_attr()`（L864）中，**紧接境界倍率（L916）之后**新增阶位系数块（乘性，小数）：

| 阶位 | 累计攻防血速系数 | 单步增量 |
|---|---|---|
| 无 | ×1.00 | — |
| 执事 | ×1.025 | +2.5% |
| 堂主 | ×1.05 | +2.5% |
| 长老（阶位） | ×1.075 | +2.5% |
| 供奉 | ×1.10 | +2.5% |

```gdscript
# 在 get_final_combat_attr() 境界倍率块之后插入（与装备/命格/境界同口径折算攻防血速）
var 阶位系数: float = { "无":0.0, "执事":0.025, "堂主":0.05, "长老":0.075, "供奉":0.10 }.get(阶位, 0.0)
if 阶位系数 > 0.0:
    for _st in ["攻","防","血","速"]:
        战斗属性[_st] = int(战斗属性[_st] * (1.0 + 阶位系数))
```
> **【决策点 D6】** 满阶（供奉）总加成 **≤10%**，每条晋升 +2.5%，落在裁决「5%~10% 内」区间（堂主起已 ≥5%，供奉封顶 10%）。具体系数 `[PLACEHOLDER]` 待 `tests/` 战斗基线回归校验。必须满足 MEMORY 战力映射铁律：加成**只经 `get_final_combat_attr` 折算攻防血速**，不得只堆 `总战力()` 虚高。

### 5.3 新手前 3 名默认内门（防卡进度，跨轴兼容）
- **问题**：接引堂新徒默认外门（`举办测灵根` L1797 `d.堂口="yuying"` + `身份` 默认 `"外门"`），而 `上阵历练` 须内门+、`授阶` 须内门+。全外门开局会卡核心玩法。
- **决策**：在 `举办测灵根()` 创建循环（L1795-1814）内，按**全局招募序**判定：若 `弟子列表.size() + i < 3` 且当前推导身份为外门，则置 `d.身份 = "内门弟子"`（仅改初始值，**不触碰 `_刷新身份` / to_dict / from_dict 逻辑**）。
```gdscript
# 在 L1807（极品→内门弟子）之后、L1808（测灵buff）之前插入：
if 弟子列表.size() + i < 3 and d.身份 == "外门":
    d.身份 = "内门弟子"   # 前3名防卡进度；仅初始值，不改身份轴逻辑
```
> **兼容性声明**：此改仅设置 `身份` 字段**创建时初始值**，未改 `var 身份` 定义、`_刷新身份()`、`to_dict`/`from_dict`——符合「不改动现役身份轴字段/逻辑/存档」。
> **【决策点 D7】** 取「全局前 3 名」而非「每批前 3 名」。若主理人希望改为「仅首测灵事件前 3 名」，调整为 `if i < 3 and 上次测灵日 == 0` 判定。默认全局前 3。

### 5.4 边缘情况
- **EC-12 前3名中恰有天品/极品**：其身份已被 L1800/L1804 抬至核心/内门，跳过前3覆盖（不降级）。
- **EC-13 阶位加成与装备/灵兽加成叠加**：均为乘性独立因子，叠加后单弟子总战力仍受 `get_final_combat_attr` 统一口径约束，不破基线。

## 七、系统联动接口

### 7.1 接引堂（新徒默认外门 → 前3内门）
- 新徒默认外门候补（`举办测灵根` L1797），遵循接引堂外门体系；前 3 名按 §5.3 默认内门防卡。
- **接引执事复用 `任命负责人("yuying", d)`**（`game_state.gd` L1705）：yuying 主事即接引执事，**不新建岗位体系**。接引执事资格 = `阶位 >= 执事` 且 `可授阶(d)`（见 §7.2）。S1 接引品质判定（魅力/命格）挂 `_接引堂测灵加()`（L234）链路，本 GDD 不重复。

### 7.2 建筑驻守 / 负责人权限（阶位门槛映射，新增，不改堂口结构）

```gdscript
# game_state.gd 新增 const（阶位门槛：0=执事,1=堂主,2=长老阶位,3=供奉；-1=不可任）
const 堂口阶位门槛: Dictionary = {
    "yuying":0, "lingtian":0, "kuangmai":0,          # 基础资源/接引：执事起
    "cangjing":1, "dantang":1, "qitang":1, "zhifa":1, # 功能堂口：堂主起
    "zhenfa":2, "yushou":2, "xixi":2, "wudao":2,     # 核心堂口：长老阶位起
    "shanzhen":3, "hushan":3, "baoku":3, "yanwu":3,  # 战略堂口：供奉起（按 Lore.堂口定义 key 对齐）
}
```
- **`任命负责人(key, d)` 加阶位闸（additive，不改现有负责人锁定/纪事逻辑）**：在 L1708 `_设负责人` 之前插入：
```gdscript
if 阶位索引(d) < int(堂口阶位门槛.get(key, 0)):
    # 拒绝：提示「{d.姓名} 阶位不足，无法任 {堂口列表[key]['名称']} 主事」
    return false
```
> 旧档 legacy 阶位（§2.3）已按身份给到对应阶位，故 veteran 弟子接任主事不被误拦。

### 7.3 历练上阵权限（阶位全队加成）
- **上阵资格**：仍由身份轴决定（内门+ 可上阵，沿用 §5.4 现役规则），阶位**不卡上阵**。
- **全队加成（权限特征）**：阶位 ≥ 长老（阶位）（index 2）的弟子上阵历练时，提供全队小幅 buff（攻防血速 +5% `[PLACEHOLDER]`），须在 `BattleManager` 新增 ally-buff 钩子。
  > **【决策点 D8 · 需程基岩对齐】** 此加成触达战斗层，须与战斗 owner（程基岩）经主理人中转对齐实现点，且必须满足 MEMORY 战力映射铁律（折算攻防血速）。若本批工期紧，可后置为 S1 批1 的 follow-up 子任务，不阻塞阶位轴主体落地。

### 7.4 宗门贡献（全局 `贡献点` 闸门）
- 考核行政成本 + 失败扣减均走全局 `贡献点`（`game_state.gd` L29）。
- 「宗门贡献攒条件」= 玩家需先积累 `贡献点` 才能发起考核/破格——贡献来源（驻守/历练/任务/事件）沿用现役经济，本 GDD 不新增获取渠道。

### 7.5 命格 / 灵根（降门槛 / 加成）
- **降门槛**：极品/天品灵根、经营类特殊命格 → 破格晋升资格（§4.6）。
- **加成**：极品/天品灵根 → 考核成功率 +0.05（§4.2）；经营类命格 → 接引执事品质（§7.1，既有）。

## 八、验收标准（pre_f5 友好 · 可测判定点 + 伪代码）

> 全部判定须可被 `pre_f5_check.py` 19 道闸门覆盖或现有 `tests/` 断言回归验证；任何新增 `.gd` 改动须保证 19 门全绿（EXIT 0）方可提交（MEMORY 铁律）。

### 8.1 可测验收点
1. **旧档兼容**：加载无 `阶位` 键旧档 → 所有弟子 `阶位` 由 `_默认阶位(身份)` 推导，无 null/空串；pre_f5 无报错。
2. **边界正确**：外门 `可授阶()==false`；内门 `可授阶()==true` 且 `阶位上限索引(破格=false)==0`（执事）。
3. **双轴消歧**：存档/UI 中 `身份·长老` ≠ `阶位·长老`（字符串带轴前缀，检索不混）。
4. **考核闭环**：发起扣 `贡献点`；`考核成功率` ∈ [0.60, 0.90]；失败 → `考核冷却剩余==7` & `考核心得==true` & `贡献点` 扣减；成功 → `阶位` +1 且不超 `阶位上限索引`。
5. **战力红线**：任意阶位对攻防血速总乘区 ≤ 1.10，且仅经 `get_final_combat_attr` 生效（非 `总战力()` 虚高）。
6. **名额闸**：`阶位名额占用(阶位名) >= 上限` 时拒绝新考核（返回 false + 提示）。
7. **降级独立**：罢免阶位使 `阶位索引` -1（最低至 -1=无），释放名额，不走掷骰。

### 8.2 伪代码级判定边界（供 engineering-lead 直接落地）
```gdscript
# 边界1：可授阶（至少内门）
func 可授阶(d: Disciple) -> bool:
    return 身份层级序.find(d.身份) >= 1            # 内门弟子(index1)起

# 边界2：阶位上限（破格 +1 阶，仍须 ≥ 内门）
func 阶位上限索引(d: Disciple, 破格: bool) -> int:
    var i: int = 身份层级序.find(d.身份)
    var cap: int = clamp(i - 1, -1, 3)
    if 破格:
        cap = clamp(i, -1, 3)
    return cap

# 边界3：考核成功率 clamp（基础60% / 满配90%）
func 考核成功率(d: Disciple) -> float:
    var P: float = 0.60
    P += clamp(float(贡献点) / 贡献阈值, 0.0, 1.0) * 0.20
    if d.灵根品阶 in ["极品", "天品"]: P += 0.05
    if 有特殊命格(d): P += 0.05
    if d.考核心得: P += 0.10
    return clamp(P, 0.0, 0.90)
```

### 8.3 边缘情况（回归覆盖建议）
- 旧档缺键（EC-1~4）、外门误纳入候选（EC-5）、名额竞态（EC-8）、冷却期强发（EC-10）、贡献不足（EC-11）、前3名天品（EC-12）——均须有断言或手动验收步骤。
