## 一、背景与目标

评测结论：系统纵深已摸到《了不起的修仙模拟器》门槛，但**前 30 分钟玩家看不到内容**——
76 个 UI 入口、26 个系统对新人同时可见，认知负荷远超竞品。P0-1 的目标是**把系统的暴露顺序变成可配置的架构约束**，而非上线前的补丁。

本轮同时收口一条遗留 lint（老大拍板）：

- `world_map_system.gd:288`「剑修」——秘境「剑冢」世界观文案（"为上古剑修陨落之地"），**加白名单**而非改文案。

## 三、设计要点

### 3.1 解锁条件（全部可派生，**零新增存档字段**）

| 条件类型 | 判定依据 | 落地字段 |
|---|---|---|
| 开局 | 恒真 | — |
| 门派等级 N | `Game.门派等级 >= N` | game_state.gd:3368 |
| 首次突破后 | `Game.累计弟子突破次数 >= 1` | game_state.gd:3618 |
| 第二世代开始 | `Game.当前辈分序 >= 2` | game_state.gd:16902 |

> **实测纠错**：`当前辈分序` 初值 = 1 且**永不归 0**（`_辈分月度推进` = `int(累计游戏日/36000)`）。
> 故实际语义为 **1 = 第一代（开山辈）、2 = 第二代**；源码注释「0=开山」有误。阈值据此定为 `>= 2`。

### 3.2 三条安全原则

1. **单一来源**：所有解锁条件只在 `unlock_order.csv` 一处定义（吸取本项目「枚举双写漂移」教训）。
2. **fail-open**：任何「无配置 / 条件类型不认识 / 取不到 Game」的查询一律返回**可见**——宁可多显示一个入口，绝不错藏一个功能。
3. **只读分层**：`sect_home_page.gd` 红线是「仅展示 + 入口，不写玩法」，本引擎只被**只读调用**（与既有 `Game.日供_今日可领()` 同性质）。

### 3.3 入口判定规则

某入口若被任一系统引用 → 取「**最先可解锁者**」的结果；未被任何系统引用 → 直接显示。
例：「弟子」被 `disciple_recruit`（开局）引用 → 恒开；「闲情雅趣」被 6 个休闲玩法（等级 5）引用 → 等级 5 开。

### 3.4 回退开关

`Game.系统解锁.强制全解锁 = true` → 一切系统与入口视为已解锁，出问题可一键回到「全可见」旧行为。

## 四、验证

**引擎自检**（`tests/headless_unlock_check.tscn`，EXIT=0）：

- 开局恰解锁 **4** 系统：`disciple_recruit` / `hall_assign` / `cultivate_breakthrough` / `topbar_generation`
- 等级 6 + 突破 1 后：库藏 / 丹方 / 拍卖行 / 宗门战 → 全开
- 辈分序 2 → 祖师堂开；辈分序 1 → 关
- 未知系统 / 山门入口 → fail-open 为 true
- 强制全解锁开关 → 生效且可复原

**回归**：`headless_smoke10.log` 四阶段（推演 100 月 / 15 系统 / 存读档 / 死亡路径）全执行、**零 SCRIPT ERROR**。

**门禁**：门0 PASS ｜ 门1 gdtoolkit PASS（186 files，含新引擎）｜ 门2 validate_all **PASS（剑修 lint 清零）** ｜ 门3 pre_f5 预存基线（死函数 393/380，**与改动前一致，零引入**）。

## 五、待办（本轮范围外）

1. **一级 Tab 未接 gating**：底部导航（弟子/殿阁/历练/纪事）本轮**未动**——动 bottom_bar 布局风险较高，且历练(P3)/纪事(P4) 隐藏会显著改变主界面结构，留作下一轮单独评估。
2. **休闲玩法入口缺位**：`fishing` / `relic` / `divine` 无独立首页入口（`page_leisure.gd` 仍是「完善中」占位页），故这三项入口列**留空 fail-open**——待休闲页真正落地后补映射。
3. **经济 sink 配套（P0 之一）**：六个休闲玩法仍是纯 source，每上线一个须补一个 sink。
