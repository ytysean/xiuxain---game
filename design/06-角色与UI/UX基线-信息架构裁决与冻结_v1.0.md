# 《太玄宗门录》UX 基线 · 信息架构裁决与冻结

> **一句话定位**：本文档不新设计一套 UX，而是把项目内**四套互相冲突的既有 UX 定义收敛为一份**，与 1080×1920 代码事实对齐并冻结。它是 UI 布局重构与美术页面级资产的**唯一前置依据**。
>
> **铁律**：本文档冻结前，UI 布局重构不得开工；页面级美术资产（页面专用图标 / 页面背景 / 页面级动效）不得产出。与本文档冲突的任何旧文档、旧实现、AI 自由发挥，一律以本文档为准。

## 0. 问题陈述：为什么必须先做这一步

### 0.1 当前并存的四套 UX 定义

| # | 来源 | 日期 | 分辨率 | 底部导航 | 首页形态 | 自述状态 |
| --- | --- | --- | --- | --- | --- | --- |
| 1 | `信息架构与导航硬性约束.md` v1.0 | 2026-07-25 | 480×854 | 无 Tab（9 页扁平森林） | 仅状态带 + 主导航 | **自陈「已作废」** |
| 2 | `UI硬性约束规范.md` v2.0 §1 | 2026-07-24 | 480×854 | 宗门/弟子/**御兽**/历练/纪事 | 快捷网格（≤4 受控） | 自称「唯一验收基准」 |
| 3 | `首页UI布局规格.md` v1.2 | 2026-07-30 | 480×854 | **经营**/弟子/**建设**/历练/纪事 | 背景图 + 悬浮节点 + 动态面板 | 「待主理人审批」 |

### 0.2 三处硬冲突

1. **分辨率基线**：三份文档均按 480×854 撰写，代码已全面切换到 1080×1920（`UI_SCALE = 2.25`）。文档中的高度预算（内容区 ≈694px）、触摸目标、字号阶梯**全部需要按 2.25 倍重新标定**。
2. **一级 Tab 命名**：同一位置出现四种说法（御兽 / 建设 / 经营 / 殿阁）。**代码与 `pre_f5_check.py` 闸门17 一致取「殿阁」**，文档全部滞后。
3. **首页形态**：三份文档给出三种互不相同的首页，且**没有任何一种**与代码实现的「侧边 6 入口 + 快捷栏 + 更多面板 36」一致。

### 0.3 代码中暴露的真问题（本任务的实际工作对象）

| # | 问题 | 事实 | 后果 |
| --- | --- | --- | --- |
| P1 | **首页入口失控** | 侧边 3+3 + 快捷 5 + 更多面板 **36** ≈ 46 个入口 | 违反 `UI硬性约束规范 §1.2 B7`「禁止超 4 个无分组入口 / 禁止退化为滚动按钮墙」——36 个平铺即标准按钮墙 |
| P2 | **解锁节奏覆盖不全** | `unlock_order.csv` 中「首页入口id」仅 18 个非空 | 洋葱解锁只覆盖约 40% 入口，其余 28 个永久常开，渐进披露失效 |
| P3 | **无权威可依** | 四套定义并存且互相矛盾 | UI 布局重构无验收基准；美术无法确定页面清单 |
| P4 | **底部 Tab 未接 gating** | 5 Tab 中「殿阁/历练/纪事」未纳入解锁判定 | 与新玩家体验节奏脱节（此项为既定待办，非本文档范围） |

> **结论**：当前 UX 的问题不是「不够好」，而是「**没有唯一事实**」。因此本阶段的任务是**裁决 + 冻结**，不是从零设计。

## 0.4 UX 规划铁则（系统基数大前提）

> **前提事实**：本作系统基数极大——`ui/page_*.gd` 二级页 40+、「更多面板」现挂 36 个入口、`unlock_order.csv` 29 条解锁项、`MORE_ENTRIES` 36 项。
> **核心判断**：**系统多 ≠ 入口多**。系统数量的增长必须由「分层 + 分组 + 分批」消化，**绝不允许**转化为入口平铺。以下八条为 UX 规划不可违背的铁则，与项目「绝对设计铁则」一一对应。

| # | 铁则 | 对应项目铁则 | 可执行约束 | 违反后果 |
| --- | --- | --- | --- | --- |
| **U1** | **入口密度** | 真人操作习惯（手游友好） | 任一屏**可见入口 ≤ 8**（7±2 认知上限）。首页侧边 6 + 快捷 5 已达上限，新增入口必须**进组或置换**，不得追加 | 首屏认知过载，新手劝退 |
| **U2** | **渐进披露** | 好玩（成长反馈） | 系统按 P0–P7 分批开放，开局**绝不全量放开**；全部经 `SystemUnlock.入口可显示` 单一判定 | 核心循环被淹没，玩家无从下手 |
| **U3** | **主题聚类** | 好玩（策略深度） | 长尾系统按**功能主题**分组，组 ≤6、组内 ≤8（见 §5） | 退化为按钮墙（违反 §1.2 B7） |
| **U4** | **频次分层** | 真人操作习惯 | 层级由**触碰频次**决定，不由「图方便」决定：高频→侧边/快捷，中低→更多面板，触发式→弹窗 | 高频功能被埋、低频功能占主位 |
| **U5** | **单页单目标** | 好玩 + 性能 | 一页只服务一件事，**禁止**多系统塞一页；跨系统联动走弹窗或跳转 | 页面职责模糊，系统无处扩展 |
| **U6** | **命名修真化** | 修真世界观 | 入口名严格用修真词汇：殿阁/宗务/丹方/灵讯/日供/山门/玄榜/宗门典藏；**禁**「建筑/任务/配方/邮件/签到/排行榜」 | 破坏世界观沉浸（违反文案铁则） |
| **U7** | **性能轻量** | 手机端流畅 | 系统多 → 列表长 → 滚动列表**必须分页/懒加载**，禁每帧重算、禁全量一次实例化 | 手机端卡顿 |
| **U8** | **新增必归位** | 执行要求 | 任何新系统上线前，**必须先在本文档定义其 IA 位置**，再写代码 | 系统持续膨胀且无归属 |

> **U8 的工程含义**：沿用「先补规范再写代码」纪律（对齐 `UI硬性约束规范 §3.1`）——先改本文档 → 再改 `unlock_order.csv` → 最后写页面。顺序不可颠倒。

## 2. 冻结基线 A：一级导航（5 Tab）

**权威定义（与代码、闸门17 一致）**：

```
宗门 / 弟子 / 殿阁 / 历练 / 纪事
```

| 序 | Tab | 全名 | 职责（单页单目标） | 缺省进入态 | gating |
| --- | --- | --- | --- | --- | --- |
| T0 | 宗门 | 宗门主权展示页 | 展示宗门全景 + 全部功能入口；**不承载任何玩法操作** | 默认选中 | 常开 |
| T1 | 弟子 | 弟子录 | 全宗弟子名录 / 接引决策；点弟子进详情弹窗 | 名录 | 常开 |
| T2 | 殿阁 | 殿阁营造 | 建筑总览 / 建造 / 升级 / 堂口派遣 | 总览 | 门派等级 ≥ 2 |
| T3 | 历练 | 历练征途 | 历练地图 / 派遣 / 战斗结算 | 地图 | 门派等级 ≥ 3 |
| T4 | 纪事 | 纪事阁 | 宗门纪事分类浏览（大事件/岁纪/庶务/异闻） | 大事件 | 常开 |

**导航机制硬约束**：
- **必须** 常驻底部、跨页不释放，复用 `ui/bottom_tab_bar.gd`（`TABS` 数组为唯一数据源）。
- **必须** 分页 = **整页切换**（`queue_free()` 旧页 → 重建新页），**禁止**同滚内 `visible` 切面板、**禁止**嵌套 `ScrollContainer`。
- **必须** 受锁 Tab 置灰可显（`disabled` + 🔒 + tooltip），**禁止隐藏**。
- **禁止** 一级 Tab 数量变动（恒为 5）。增删一级 Tab 必须先改本文档 + 闸门17。

## 3. 冻结基线 B：首页（宗门页）信息架构

首页 = **展示 + 导航**，不含任何玩法操作。三容器职责边界正式定义如下（此前为隐式约定，UI 布局重构的唯一依据）：

| 容器 | 职责 | 容量上限 | 当前位置锚点 |
| --- | --- | --- | --- |
| **侧边入口** | 最高频直达，视觉主位（金边大图标） | 左 3 + 右 3 = **6** | `ENTRIES_LEFT` / `ENTRIES_RIGHT`，`ENTRY_YS = [150,222,294,366]` |
| **快捷栏** | 日常操作与系统入口 | 可见 **≤5** | `QUICK_ENTRIES`，`QUICK_XS`（5 槽） |
| **更多面板** | 长尾入口，**必须分组收纳** | 组 ≤6，组内 ≤8 | `MORE_ENTRIES`（当前 36 平铺，待整改） |

**容器语义一致性铁律**：
- 三个容器**共用同一个解锁过滤来源**（`SystemUnlock.入口可显示` + `sect_home_page.gd::_过滤已解锁`）；**禁止**任何容器绕过过滤自行判断。
- 隐藏后**一律按「可见序号」紧凑排布**，不留空洞（侧边/快捷/更多三者语义必须一致）。
- 布局坐标与 gating 逻辑**保持解耦**：重构布局只替换坐标算法，不得改动解锁判定。

## 5. 首页「更多面板」分组治理（核心整改项）

**现状**：36 个入口平铺于「更多」面板 → 违反 `UI硬性约束规范 §1.2 B7`，且无解锁节奏。

**整改原则**：按**功能主题分组**（而非按解锁阶段），每组默认折叠，组标题常显，组内入口受 gating 过滤。**分组数量 ≤6，单组入口 ≤8**。

**建议分组（待主理人确认）**：

| 组 | 建议组名 | 归入入口（当前 36 项重分配） |
| --- | --- | --- |
| G1 | 宗门经营 | 宗门气运、凡人王朝、传送阵、风水堪舆、灵酿、科技 |
| G2 | 弟子养成 | 家族、护道人、身外化身、毒道、宗主管理、宗主、幻形 |

## 10. MUST / MUST NOT 验收清单

**【一级导航】**
- [ ] **MUST** 底部 Tab 恒为 5 项：宗门 / 弟子 / 殿阁 / 历练 / 纪事（与闸门17 一致）。
- [ ] **MUST** 整页切换（queue_free + 重建）；**MUST NOT** `visible` 同滚切页、嵌套滚动。
- [ ] **MUST** 锁定 Tab 置灰可显（disabled + 🔒 + tooltip）；**MUST NOT** 隐藏。

**【首页信息架构】**
- [ ] **MUST** 首页仅含：状态带 + 侧边入口(≤6) + 快捷栏(≤5) + 更多按钮 + 底部 Tab。
- [ ] **MUST** 更多面板按主题分组（≤6 组，组内 ≤8），**MUST NOT** 平铺超过 8 个入口。
- [ ] **MUST** 三容器共用同一解锁过滤来源与「可见序号紧凑排布」语义。
- [ ] **MUST** 布局坐标与 gating 解耦（改布局不动判定）。

**【解锁节奏】**
- [ ] **MUST** 所有首页入口在 `unlock_order.csv` 有对应解锁条件或显式标注「常开」。
- [ ] **MUST** 已解锁玩法必有可达入口（**MUST NOT** 出现「解锁了但找不到」）。

**【UX 铁则符合性（§0.4）】**
- [ ] **MUST** 任一屏可见入口 ≤ 8（U1）；超限必须分组或置换，**MUST NOT** 追加平铺。
- [ ] **MUST** 所有系统入口经 `SystemUnlock.入口可显示` 单一判定（U2）。
- [ ] **MUST** 更多面板按主题分组（U3：组 ≤6、组内 ≤8）。
- [ ] **MUST** 层级由频次决定（U4）；**MUST NOT** 低频功能占主位。
- [ ] **MUST** 入口命名修真化（U6）：出现「建筑 / 任务 / 配方 / 邮件 / 签到 / 排行榜」等现代词即 FAIL。
- [ ] **MUST** 长列表分页或懒加载（U7）。
- [ ] **MUST** 新系统先在本文档定 IA 位置再写代码（U8）。

**【完整性】**
- [ ] **MUST** `§4.5(2)` 的「有入口无落点」项全部归零（点击必有响应）。
- [ ] **MUST** `§4.5(3)` 的孤儿页全部核实完毕（保留者归位 / 废弃者归档）。

**【文档一致性】**
- [ ] **MUST** 任何架构变更先改本文档再改代码。
- [ ] **MUST** 旧文档（§0.1 表 1–3）中与本文档冲突的架构结论不再被引用。
