# 洋葱解锁 × UI 布局解耦 + Item 对象取值 bug 修复

**日期**：2026-09-11
**触发**：老大问「刚做的洋葱解锁对后续重构 UI 布局有影响吗」→ 核查后直接做解耦收敛
**结论**：引擎层零影响；接线层已收敛为单点，重构 UI 只需换坐标算法。

---

## 一、回答「有没有影响」：分两层

| 层 | 文件 | 对 UI 重构的影响 |
|---|---|---|
| **引擎层** | `system_unlock.gd`（`Game.系统解锁`） | **零影响**。纯数据层单例，只暴露只读查询，不持有任何 Control 引用、不关心布局。推倒重写 UI 一行不用动。 |
| **接线层** | `ui/sect_home_page.gd`（3 处）+ `ui/game_ui.gd`（1 处路由兜底） | **随 UI 走**。本轮已收敛成单点，见下。 |

---

## 二、发现的隐患：同一套 gating 有**三种行为**

| 容器 | 改前行为 | 问题 |
|---|---|---|
| 侧边入口 | 位置用 `ENTRY_YS[全量索引]`，未解锁 `continue` | **固定槽位留空洞**，后续项不位移 |
| 快捷栏 | 位置用 `QUICK_XS[全量索引]`，且 `_apply_quick_fold` 只切 `visible` | **中间项隐藏即永久空洞** |
| 「更多」面板 | 先收集可见项再按新索引排网格 | 紧凑重排（唯一正确者） |

同一张 `unlock_order.csv` → 三种视觉行为。前期入口都在末尾看不出来，一旦锁掉靠前入口就暴露空洞。

---

## 三、本轮改动

### 1. `system_unlock.gd` — 新增 UI 统一入口（静态）
```gdscript
static func 入口可显示(入口id: String) -> bool
```
内含 fail-open + `Game.系统解锁` 判空。**fail-open 策略收敛到唯一来源**，UI 侧原各写一份的包装（`sect_home_page._入口可见`、`game_ui._入口已开启`）已删除。
> 命名说明：`SystemUnlock` 已有实例方法 `已解锁(系统key)`，GDScript 不支持同名重载，故静态入口取名 `入口可显示`。

### 2. `ui/sect_home_page.gd` — 过滤与定位单一来源
```gdscript
func _过滤已解锁(配置表: Array) -> Array   # 三容器共用的唯一过滤（fold 恒保留）
func _可见序号(全量表: Array, id: String) -> int  # 红点据此跟随宿主
```
三容器 + 红点全部改用「**可见序号 → 坐标**」：`ENTRY_YS[可见序号]` / `QUICK_XS[可见序号]`。

### 3. `ui/game_ui.gd` — 路由兜底直调静态入口
`if not SystemUnlock.入口可显示(entry_id)` → toast「尚未开启」并拦截。

## 四、实机证据（新 harness `tests/headless_ui_decouple_check.tscn`）

**该 harness 补上了 smoke 的盲区**：`game_ui.gd` 不是 autoload，`headless_smoke` 从不加载 `ui/*.gd`，所以这两个 UI 文件此前**没有编译验证**。本 harness 用 `load()` 强制编译 + 真实例化首页。

| 场景 | 实测坐标 | 判定 |
|---|---|---|
| 全条件成立 | 左列 Y=[150,222,294]；快捷 X=[106,173,240,307,374] | 与改前全解锁布局**完全一致（零可见变化）** |
| 锁「宗务」 | 左列 Y 收缩为 **[150,222]** | **坊市从槽位2(294) 上移到槽位1(222)** —— 紧凑无空洞 |

自检 **FAIL=0**（A 段证静态入口可访问 autoload `Game`；B 段证两个 UI 脚本可编译；C/D 段证过滤与紧凑排布）。

## 五、顺带修掉的既有 bug：Item 对象两参 `.get()`

复跑冒烟暴露（`推演一月` 热路径，30+ 次/月）：
```
SCRIPT ERROR: Invalid call to function 'get' in base 'RefCounted (Item)'. Expected 1 argument(s).
  at: _找丹药 (game_state.gd:10182) / _消耗宗门库房丹药 (game_state.gd:10241)
```
**属既有 bug**（非本轮引入；上一轮 smoke10 未命中，因那个月库房恰好无丹）。

修复清单（全部改为属性直取 + `is Item` 判空）：

| 文件 | 函数 | 处数 |
|---|---|---|
| `game_state.gd` | `_找丹药` | 3 |
| `game_state.gd` | `_消耗宗门库房丹药` | 6 |
| `caravan_system.gd` | `_库房灵材数量` / `_扣灵材` / 商铺日耗 | 3 |

**根因**：库房/背包囤的是 **Item 对象**，代码却按 Dictionary 取值——与 `.has()` 对象误用同一家族。已并入 `MEMORY.md` 红线第 5 条。

## 七、给 UI 重构的两条约束

1. **布局只换坐标算法，gating 一律走 `_过滤已解锁`**；隐藏语义保持「紧凑重排、无空洞」。
2. **入口 id 是中文串，与 `config/unlock_order.csv`「首页入口id」列硬绑定**——改名须同步两处，无编译期保护（唯一会静默失效的点）。
