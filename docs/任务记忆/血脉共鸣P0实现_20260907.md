## 二、设计方案（P0调整版）

### 2.1 调整原因
当前S1阶段没有组队系统，原设计的"组队修炼+5%/战力+3%"无法直接生效。参考"结义道友修炼速度+1%"的实现方式，调整为：

**有血缘关系的弟子同时在宗时，提供微弱的全局修炼加成和个人战力加成**

### 2.2 血脉关系识别
支持的血缘关系类型：
- 父子/母子（父母ID互链）
- 兄弟/姐妹（有共同的父母）
- 祖孙（通过父母的父母ID识别）

### 2.3 加成数值（遵守§6.16红线）
| 加成项 | 数值 | 上限 |
|---|---|---|
| 单亲属修炼加成 | 0.3% | - |
| 单弟子修炼加成上限 | - | 1.2%（4个亲属） |
| 全宗血脉共鸣修炼加成上限 | - | 1.5%（全局等效） |
| 单亲属战力加成 | 0.3% | - |
| 单弟子战力加成上限 | - | 1.2%（4个亲属） |

### 2.4 S2预留
- 组队系统解锁后，组队时血脉共鸣效果翻倍
- 当前代码中已预留注释位置，S2接入时只需修改倍率

### 3.2 disciple.gd 新增函数

#### `是否有血缘关系(其他弟子ID: int) -> bool`
判断两个弟子是否有血缘关系，检查：
1. 对方是我的父母（其他弟子ID in 父母ID）
2. 我是对方的父母（其他弟子ID in 子嗣列表）
3. 有共同的父母（兄弟姐妹）
4. 祖孙关系（通过父母的父母ID识别）

#### `获取血缘关系类型(其他弟子ID: int) -> String`
返回血缘关系类型描述："父母"、"子女"、"兄弟姐妹"、"祖孙"、"远亲"

#### `获取血脉关系列表() -> Array`
返回所有有血缘关系的弟子ID列表，每项包含：id、名、关系

#### `获取在宗血脉亲属数() -> int`
返回在宗的有血缘关系弟子数量（用于计算血脉共鸣加成）

### 3.3 game_state.gd 新增函数

#### `血脉共鸣修炼乘区() -> float`
计算全宗血脉共鸣修炼乘区：
1. 遍历所有在宗弟子
2. 每个弟子的在宗亲属数 × 0.3% = 该弟子的修炼加成
3. 单弟子加成上限1.2%
4. 全宗总加成上限1.5%（遵守§6.16红线）
5. 返回 1.0 + 总加成

#### `血脉共鸣战力加成(弟子: Disciple) -> float`
计算指定弟子的血脉共鸣战力加成：
1. 检查弟子是否在宗
2. 计算在宗亲属数
3. 加成 = min(0.3% × 亲属数, 1.2%)
4. S2预留：组队时效果翻倍（当前未实现）

### 3.4 接入点

#### 修炼系统接入
`game_state.gd` 推演一月中的宗门加成pct计算：
```
var 血脉共鸣pct: float = max(0.0, 血脉共鸣修炼乘区() - 1.0)
var 宗门加成pct: float = clamp(灵脉加成pct + 负责人修炼pct + 藏经阁pct + 彩蛋修炼加成() + 大阵pct + 血脉共鸣pct, 0.0, 1.0)
```

#### 战力系统接入
`disciple.gd` 计算战力()函数：
```
var 血脉共鸣增益: float = 0.0
if Game != null and Game.has_method("血脉共鸣战力加成"):
    血脉共鸣增益 = Game.血脉共鸣战力加成(self)
var 主体: int = int(base * 资质系数 * 灵根系数 * 道途系数 * (1.0 + 通用增益) * (1.0 + 道心增益) * (1.0 + 血脉共鸣增益) * (1.0 + 套装增益()))
```

#### UI显示接入
`ui/disciple_detail_page.gd` 社交关系网格：

- 新增"🔗 血脉共鸣"卡片：显示在宗亲属数 + 修炼/战力加成
- 新增"👨‍👩‍👧 家庭"卡片：显示父母/子女/兄弟姐妹数量

## 六、后续规划（P1/P2/P3）

### P1：宗门家族基础
- 家族识别：以老祖为核心的师徒+子嗣+姻亲网络
- 家族族谱：记录家族世系、老祖、杰出子弟
- 家族气运：家族整体实力带来的全局属性加成（单家族≤1%，全局≤2%）
- 家族先贤祠：家族坐化/飞升弟子入家族先贤祠，提供家族内部加成

### P2：凡间家族融入王朝沙盒
- 凡间家族势力值：家族在郡县的势力，受弟子办差/成就影响
- 凡间家族声望：家族在当地的声望，影响朝廷册封（乡绅→士族→望族→修仙世家）
- 凡间家族产业：家族在郡县的田产/商铺/矿场，每月给弟子提供资源
- 凡间家族人脉：家族在当地的人脉，弟子办差成功率+、朝廷关系+
- 凡间家族苗子输送：家族优秀子弟推荐入宗门，灵根资质更好
- 凡间家族竞争/联姻/仇杀：融入王朝派系系统

### P3：两层联动 + 家族传承功法
- 宗门→凡间：宗门弟子的凡间家族受到宗门庇护
- 凡间→宗门：凡间家族给宗门弟子提供资源/人脉/苗子
- 血脉联动：凡间家族的子弟入宗门后，与宗门已有弟子形成血缘关系
- 传承联动：宗门家族的功法可以传承给凡间家族的优秀子弟
- 家族传承功法：家族专属功法，家族成员参悟速度+30%

## 七、经验教训

### 7.1 设计与实现的差距
- 原设计的"组队修炼+5%/战力+3%"依赖组队系统，但S1阶段没有组队系统
- 调整方案：改为"在宗亲属提供微弱加成"，参考"结义道友"的实现方式
- 教训：实现前必须先确认依赖系统是否已存在，不能盲目按设计文档实现

### 7.2 数值红线的重要性
- §6.16明确规定血脉类单源子帽≤1.5%（全局等效）
- 实现时严格遵守：单弟子上限1.2%，全宗上限1.5%
- 教训：所有新增加成系统都必须先查数值红线，不能凭感觉设数值

### 7.3 假数据的清理
- 弟子详情页原有的"🤝 道友（0人）"和"🏛 家族（散修）"都是假数据
- 本次替换为真实的血脉共鸣/家庭显示
- 教训：UI中的假数据要及时清理或替换为真实数据，避免误导玩家

### 7.4 S2预留的重要性
- 组队系统S2才解锁，但血脉共鸣系统P0就实现了
- 在代码中预留了S2接入位置（组队时效果翻倍）
- 教训：实现系统时要考虑后续扩展，预留接口和注释位置

### 7.5 Edit工具的局限性
- Edit工具在匹配含特殊缩进/中文的行时频繁失败
- 改用PowerShell直接修改文件更可靠
- 教训：对于大文件的复杂修改，优先用PowerShell，Edit工具只用于简单的小修改
