# 28 屏确认奖励交互规格

## 页面定位

通用奖励领取弹窗：在战斗结算、历练完成、事件触发后弹出，展示玩家获得的可消耗资源与物品，并提供一键领取入口。

> 设计意向声明：本屏为通用组件，无特定现成 `page_*.gd` 对应；奖励内容、领取方式与动效按通用手游结算弹窗合理假设。

## 信息架构

1. **顶部标题区**：标题 + 关闭
2. **奖励来源说明**：本次击破奖励
3. **奖励列表区**：每项含图标占位 + 名称/数量，按配置顺序纵向排列
4. **底部操作**：一键领取

---

## 交互规则

| 元素 | 交互 | 状态/反馈 |
|---|---|---|
| 关闭 ✕ | 点按 | 关闭弹窗；奖励是否后台保留取决于业务规则（建议默认已领取或提示未领取） |
| 点蒙层 | 点按 | 同关闭 |
| 一键领取 | 点按 | 将所有奖励写入对应库存/弟子经验，播放获得动效，完成后关闭弹窗 |
| 单个奖励 | 长按（S2） | 显示该物品/资源详情提示 |
| 弹窗打开 | 自动 | 若奖励含未获得过的新物品，可加「新」角标（S2 可选） |

## 代码映射

- 入口：战斗结算、历练完成、奇遇完成、邮件附件领取、任务奖励等所有需要展示奖励的地方。
- 建议封装为通用组件：`ui/popup_reward.gd`。
- 调用方式：`show_reward_popup(reward_dict: Dictionary)`，其中 `reward_dict` 形如：
  ```gdscript
  {
    "灵石": 2000,
    "灵气": 500,
    "玄铁": 3,
    "item_uid": "青锋剑·灵"
  }
  ```
- 数据写入：由 `game_state.gd` 提供 `add_reward(reward_dict)`，自动分发到货币、库存、弟子经验等模块。
- 动效：S1 可做简单数字跳动；S2 做物品飞入顶部资源栏动画。

## 后续待明确

1. 奖励弹窗是否允许关闭不领取（建议 S1 统一为「一键领取」必填）。
2. 多段奖励（如战斗奖励 + 首通奖励 + 成就奖励）是分多个弹窗还是合并一个。
3. 新物品/高稀有度物品是否需要额外高亮或全屏特效。
4. 奖励数量超过一屏时是否启用滚动（S1 建议最多 6 项）。
5. 是否显示「再看一次」或「分享获得双倍」等运营入口（S1 不做）。
