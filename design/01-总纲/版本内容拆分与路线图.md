# 首发版本（v1.0）与 S1 赛季内容拆分清单

## 拆分总原则

1. **MVP 优先，风险前置**：首发仅保留支撑核心经营循环的必做内容，所有沉浸向、非强增益系统全部移入 S1，降低首发开发与测试压力。
2. **梯度解锁，控制密度**：首发内容按宗门等级分层释放，避免新手信息过载，保证前 2 周有持续的新内容反馈。
3. **主题明确，承接成长**：S1 作为首个主题大版本，承接首发玩家的成长平台期，补全策略深度、沉浸感与长线目标。
4. **新人友好，差距可控**：所有赛季核心内容全服同起点，配合段位隔离与追赶机制，弱化进服时间差的影响。

---

## 一、首发版本（v1.0・宗门奠基）

**定位**：跑通「建设 - 培养 - 产出 - 扩张」核心玩法闭环，支撑玩家前 3 周的成长体验，验证核心留存数据。
**上线节点**：公测首发
**内容解锁规则**：全部内容绑定宗门等级，随玩家成长逐步解锁，无全服统一时间锁。

### 1. 核心经营系统（P0 必做）

| 系统模块 | 首发包含内容 | 解锁条件 | 备注说明 |
| --- | --- | --- | --- |
| 宗门建设 | 大殿、灵田、丹房、功法阁、演武场、库房 6 类基础建筑；建筑升级、产能提升 | 宗门 1 级开放大殿 / 灵田，2 级开丹房 / 演武场，3 级开功法阁 / 库房 | 砍掉装饰性、沉浸类建筑，保留纯功能型 |
| 弟子体系 | 招募、灵根判定、境界修炼、突破、基础功法装备穿戴 | 宗门 1 级开放招募，境界随建筑等级逐步解锁上限 | 首发仅开放炼气 - 筑基 - 金丹三个大境界 |
| 资源体系 | 灵石、灵气、草药、矿石 4 类基础资源；产出 / 消耗 / 存储规则 | 宗门 1 级即开放 | 气运、功德等拓展属性仅预留接口，暂不生效 |
| 历练探索 | 节点式地图、基础关卡挑战、资源 / 道具掉落 | 宗门 2 级开放 | 采用 2D 节点关卡制，不做开放世界大地图 |
| 交易商店 | 基础商店、高阶商店、周限购 | 宗门 1 级开基础商店，3 级开高阶商店 | 统一解锁条件为宗门等级，解决此前文档规则不一致的冲突 |

### 2. 基础玩法模块（P0 必做）

- **日常任务**：每日固定刷新，引导核心操作，奖励基础资源，塑造用户使用习惯
- **随机事件**：绑定收资源、历练等操作被动触发，仅做小幅增益 / 减益，无大额奖励
- **基础奇遇**：投放 50 个左右低门槛单事件奇遇，保留传统双选项结构，暂不做连锁型内容

> 首发即明确三类内容的独立入口与定位差异，从根源解决体验重叠、玩家认知混淆的问题。

### 3. 数值体系（P0 必做）

- 完成核心循环数值校准：行动力（体力）、基础资源产耗、弟子境界成长曲线，所有核心占位符全部替换为实测值。
- 丹药、功法、装备数值采用保守保底值，做成可配置参数，预留调优空间。
- 气运、功德、PVP 平衡等非核心数值仅设基础区间，不做全链路生效测算。

### 4. UI 与性能（P0 必做）

- 设计基准升级为 1080×1920 竖屏，兼容主流全面屏，保留最低分辨率适配。
- 核心功能页面扁平化改造，砍掉冗余三级页面，高频操作增加快捷入口。
- 完成核心场景性能压测：同屏 50 单位稳定 30 帧，离线 100 天推演耗时≤2 秒。
- 复杂信息看板（经济、谱系、战斗）先用结构化列表呈现，不做深度可视化。

### 5. 叙事与商业化（P1 精简）

- 叙事：仅打磨 3 个核心里程碑剧情（创宗、首徒筑基、宗门 3 级），基础世界观植入典籍与奇遇文本。
- 商业化：开放月卡、基础资源礼包、新手礼包，保障基础付费渗透率。
- 社交：单服排行榜、好友宗门拜访，满足轻度互动需求。

## 二、S1 赛季版本（v1.1・凡世香火）

**定位**：首发后第 4-6 周推送的大版本更新，补全沉浸向系统、深化策略玩法、提升付费厚度与长线留存。
**上线节点**：全服统一时间更新，所有玩家同步开启新内容，新老玩家同起点。
**核心主题**：凡人世界交互 + 宗门礼制体系。

### 1. 赛季新增核心系统

- **凡人香火体系**：凡世城镇交互、香火值获取、信徒增益、凡人事件，承接宗门 3 级后的成长溢出。
- **辈分礼制体系**：弟子辈分排序、宗门礼法、传承谱系、门规设定，强化宗门沉浸感。
- **正邪路线抉择**：宗门达到对应等级后可选择发展路线，不可逆，对应不同的资源获取、事件与阵营关系，解决策略深度不足的问题。

### 2. 玩法内容升级

- **奇遇体系扩容**：新增连锁奇遇、条件专属奇遇共 100+，打破固定双选项结构，提升重复体验的新鲜感。
- **赛季冲榜玩法**：以「宗门声望」为赛季积分，分境界段位排行，结算专属限定奖励。
- **宗门大比**：弟子竞技玩法，同段位匹配，补充 PVP 玩法内容。

### 3. 数值与表现补全

- 气运、功德系统全链路数值落地，明确生效维度、换算公式与上下限，解决数值表层化问题。
- 丹药、功法、装备新增专属机制与特殊词条，跳出纯数值堆砌，降低内容同质化。
- 经济看板、传承谱系、战斗详情完成可视化升级，用图表替代纯文字列表，解决纯代码 UI 表现力不足的问题。
- 阵营人设灰度改造，补充核心 NPC 背景故事，新增赛季专属剧情线。

### 4. 商业化与社交升级

- 上线赛季战令（宗门令），分免费 / 付费两档，覆盖外观、资源、专属道具，提升付费厚度。
- 新增外观类付费：弟子皮肤、建筑主题、宗门铭牌，抬升付费天花板。
- 开放好友互助加速、赛季段位共享，强化社交留存抓手。
- 新增回归专属福利与追赶 buff，降低流失用户召回门槛。

### 5. 技术与性能优化

- 完成弟子、建筑数量扩容后的性能二次优化，放开部分数量上限。
- 验证异步多人交互方案，为后续跨服玩法做技术铺垫。

## 三、版本节奏与新玩家适配规则

### 1. 内部解锁节奏（首发版本内）

- 宗门 1 级（0-10 分钟）：仅开放核心建设、招募、基础资源，完成新手引导
- 宗门 2 级（30 分钟 - 2 小时）：开放历练、丹房，新增核心玩法
- 宗门 3 级（1-3 天）：开放高阶商店、功法阁，解锁首发全部核心内容
- 后续等级仅提升数值上限与建筑等级，不新增系统，保证信息密度可控

### 2. S1 赛季开启规则

- 全服统一时间开启，无论玩家当前宗门等级，均可参与赛季内容。
- 低等级玩家参与赛季可获得额外经验与资源加成，加速追赶主体进度。
- 赛季积分按境界分段排行，新老玩家互不干扰，均有冲奖机会。

### 3. 晚进服新玩家适配

- 新手 7 天加速 buff：资源产出、修炼速度加成，快速追平同阶段平均水平。
- 历史赛季内容永久保留：错过 S1 的新玩家，后续可通过回溯玩法体验核心内容，不损失永久成长。
- 新赛季全员清零：每次新赛季开启，赛季积分、任务全部重置，新老玩家同起点竞争。

# 开发优先级与工时占比

以下基于**单人独立开发、首发版本总工作量为 100%** 的基准测算，优先级从 P0 到 P2 递减：P0 为缺项无法上线的核心刚性内容，P1 为可简化、可延后的体验优化项，P2 为首发完全不做、移入 S1 的内容。

## 一、首发版本（v1.0 宗门奠基）

### P0 核心必做（占首发总工时 70%，上线刚性要求）

1. 核心经营系统 | 占比 35%
   - 宗门建筑（建设、升级、产能逻辑）：12%
   - 弟子体系（招募、修炼、突破、属性计算）：12%
   - 资源与交易（产耗规则、存储、商店配置）：6%
   - 历练关卡（节点地图、结算逻辑）：5%
   说明：这是游戏核心循环的骨架，必须优先跑通闭环，所有后续内容都基于此扩展。
2. 基础玩法与数值框架 | 占比 15%
   - 日常任务、随机事件基础框架：5%
   - 核心循环数值校准（资源产耗、成长曲线）：7%
   - 基础单事件奇遇（50 个）：3%
   说明：数值直接决定核心体验，必须保证无明显崩坏；奇遇用标准化模板快速填充，保证基础内容量。
3. UI 与基础性能 | 占比 20%
   - 5 个核心一级页面（宗门 / 弟子 / 历练 / 背包 / 商店）：10%
   - 主流分辨率自适应与基础交互：5%
   - 核心场景性能压测与基础优化：5%
   说明：优先保证功能可用、操作顺畅，视觉美观度后置到 S1 优化。

### P1 首发优化项（占首发总工时 20%，可简化、可延后上线）

1. 新手引导与基础叙事 | 占比 8%
   - 3 个核心里程碑剧情文案：3%
   - 新手分步引导流程：5%
   说明：引导可简化为弹窗提示，剧情可用精简文案替代，不影响核心玩法闭环。
2. 基础社交与付费框架 | 占比 7%
   - 单服排行榜、好友拜访：4%
   - 月卡、新手礼包内购框架：3%
   说明：付费功能首发可先不上，只预留框架；社交也可延后到 S1，优先级可再下调。
3. 存档与数据安全 | 占比 5%
   - 本地存档 + 基础云存档：5%
   说明：刚性需求，但实现难度低，保证不丢档即可。

### P2 完全移入 S1（占首发规划量 10%，首发零投入）

辈分礼制、凡人香火、正邪路线、连锁奇遇、可视化看板、多结局框架等，全部移出首发排期，集中资源做核心闭环。

> 整体节奏参考：按每日投入 5 小时测算，P0 核心内容预计 6-8 周可跑通可玩原型，叠加 P1 内容后总首发开发周期约 8-11 周，符合小步快跑的验证节奏。

# 后续玩法预告方案

## 一、核心结论

非常有必要做**分层、控粒度的预告**，但绝对不能给精确死线，也不能透未落地的细节。核心逻辑是：用确定的方向拉长期期待，用模糊的时间留容错空间，用可控的进度建立玩家信任。

### 1. 预告的核心价值

- 降低流失：玩家明确知道后续有新内容，不会因 “玩透了” 直接卸载，能撑到 S1 更新。
- 管理预期：提前划清首发和后续的内容边界，避免玩家上线后吐槽 “内容太少”，把 “内容精简” 转化为 “持续更新” 的优势。
- 提升粘性：预告内容能引发社区讨论，比如正邪路线的选择，提前攒起话题热度。
- 适配独立开发身份：个人开发者同步开发进度，更容易拉近和玩家的距离，用户包容度远高于商业团队。

### 2. 必须遵守的预告原则（避坑关键）

- **已开工的说明确，没开工的说方向**
进入开发、80% 概率上线的内容，可讲清核心玩法，比如 “S1 会开放凡人香火系统，管理凡间信徒获取增益”；仅在构思、未排期的内容，只提大方向，比如 “远期会考虑跨服宗门玩法”，绝不承诺 “一定会做”。
- **只给时间区间，不给精确日期**
大版本说 “开服后 1-2 个月”，小更新说 “2 周左右”，永远留足缓冲期。独立开发变数多，精确日期跳票极伤信任。
- **只说核心卖点，不说实现细节**
只告诉玩家 “能玩到什么”，不说 “怎么做的”，比如只说 “丹药新增特殊效果”，不说具体数值和公式，避免玩家提前挑细节，也防止设计变更后出现落差。
- **坏消息提前说，惊喜藏着放**
首发没有的功能（跨服、多结局），提前划入后续规划，降低初始预期；隐藏彩蛋、专属剧情不要预告，留给玩家自行挖掘，提升口碑传播。

### 3. 分阶段预告落地方式

- **首发预热期（上线前）**
做一份「首发内容 + 后续规划」的清晰说明，明确拆分：
  - 首发可玩：核心经营、弟子培养、基础历练、基础奇遇
  - 第一波更新（S1）：凡人香火、宗门礼制、正邪路线
  - 远期规划：多结局、跨服对战、大地图探索
  目的是让玩家对首发内容量有准确预期，清楚这是持续更新的游戏。
- **首发运营期（上线后）**
开服第 7 天左右发布第一篇开发日志，同步 S1 大节点进度，比如 “凡人香火核心框架已完成，进入事件填充阶段”，配 1-2 张开发中截图；每 2 周发一次短进度播报，几句话 + 一张图即可，保持存在感。
S1 上线前 1 周，放出正式更新预告，讲清核心内容、上线区间和版本福利，拉动回流。
- **游戏内入口**
在宗门大殿加一个低存在感的「宗门规划」入口，存放更新预告，想了解的玩家主动查看，不干扰普通玩家的游戏体验。禁止主界面强弹公告推预告，避免引发 “画饼” 反感。

### 4. 开发进度同步规则

要同步，但只同步**大节点进度**，不报流水账。

- 可以说：“S1 核心功能开发完成约 70%，进入内容填充阶段”
- 不要说：“今天改了 3 个 bug，写完了 2 个奇遇”
- 进度数字保守报：实际完成 80% 就说 70%，提前完成是惊喜，延期了也有缓冲空间。
- 若确定延期，提前告知并说明原因（比如遇到技术坑），独立开发者的身份下，玩家包容度很高，诚实比硬撑跳票更拉好感。

### 5. 风险规避

- 所有远期规划都标注 “规划中，以实际上线为准”，避免后续内容调整被指责 “画饼”。
- 一次只预告 1-2 个版本的内容，预告太多既记不住，也容易给自己挖坑。
- 核心玩法的具体数值、隐藏分支不要提前泄露，保留玩家上线后的探索新鲜感。
