# 26 屏降级开关交互规格

## 页面定位

对高阶装备执行「降级」操作时的二次确认弹窗。降级通常用于回收培养材料，但会导致装备属性清空，属于高风险操作，因此需要显式开关确认。

> 设计意向声明：本屏无现成 `page_*.gd` 或 GDD 可对照，「降级」作为装备养成反向操作按通用游戏设计合理假设；实装前需策划确认是否开放降级、返还比例、是否不可逆等规则。

## 信息架构

1. **顶部标题区**：危险色标题 + 关闭
2. **风险提示区**：说明降级不可逆
3. **目标物品区**：物品名 + 品阶 + 返还材料预览
4. **确认开关区**：开关默认 off，必须打开才可点击确认
5. **底部操作**：取消 / 确认降级

---

## 交互规则

| 元素 | 交互 | 状态/反馈 |
|---|---|---|
| 关闭 ✕ | 点按 | 关闭弹窗，不执行降级 |
| 取消 | 点按 | 关闭弹窗，不执行降级 |
| 确认降级开关 | 点按 | off → on：开关钮右移、底色变为金 `#C8A86A`；on → off：开关钮左移、底色恢复 `#182D37` |
| 确认降级按钮 | 默认禁用 | 开关 off 时按钮透明度 0.5 且不可点击；开关 on 后启用 |
| 确认降级按钮 | 点击 | 执行降级：清空该装备属性 / 等级，返还材料写入宗门库房，关闭弹窗并提示「已降级」 |

## 代码映射

- 入口：建议从装备详情弹窗、强化/升星界面的「降级」入口触发。
- 新增脚本建议：`ui/popup_downgrade.gd`。
- 数据接口建议：由 `game_state.gd` 提供 `downgrade_item(item_uid)`，内部执行：
  1. 校验物品是否已穿戴（已穿戴需先卸下）。
  2. 按配置表计算返还材料并写入库存。
  3. 重置装备等级/精炼/觉醒属性（不可逆）。
  4. 记录日志，供纪事与调试追踪。
- 开关状态建议作为弹窗内部状态，不持久化到存档。

## 后续待明确

1. 是否允许已穿戴装备直接降级（还是先强制卸下）。
2. 返还材料比例：固定值 / 百分比 / 随机区间。
3. 降级是否有冷却、次数限制或 VIP 限制。
4. 不可逆是否可以二次弹窗确认（S1 建议保留开关即可）。
5. 装备品阶、强化等级对返还数量的影响公式。
