## ① 目标与范围

本批是 **S1 阵法体系 Phase-1**：把投稿三层阵法中的 **Layer1 宗门大阵（批6-A）** 与 **Layer2 单人法阵的「常驻属性部分」（批6-B）** 一起正式化落地。两者均**零战斗触碰**——所有战斗效果经「战前属性聚合（`disciple.gd` `get_final_combat_attr` + `_聚合未来战力来源`）+ 战斗结算后回调（仅标端口）」等效实现，严守铁律。

| 层级 | 阵法类型 | 本批落地范围 | 回归风险 |
|---|---|---|---|
| Layer1（批6-A） | 宗门大阵（护山/聚灵/镇煞） | 全域经营 + 防御兜底；单主阵切换 + 耐久；品级解锁；修炼/产出/入侵概率/声望 经营层生效；防御类经属性等效进战斗属性 | 中（新系统，但全加法/属性等效） |
| Layer2（批6-B） | 单人法阵（常驻属性部分） | 弟子单槽装备 + 身份阶别锁 + 灵根匹配 + 升级/拆解；常驻攻防血速/修炼/暴击/闪避 经属性聚合；护盾→最大生命等效 | 中（聚合接入点明确，子帽待校准） |
| Layer2 触发类（护盾已做/回血/回蓝） | 触发类 | 护盾→最大生命+X%（本批属性等效）；回血→结算后回血、回蓝→灵气（**真实触发标 [PLACEHOLDER] 端口，S2 补**） | 高（体感缺失，仅存意图） |
| Layer3（S1 不做） | 组队结阵 | **本批不做**（需 BattleManager 深度对接，铁律禁止）；仅记录设计，S2 视铁律豁免再补 | — |
| 赠送物品（阵图） | 独立 feature | **不并入批6**（另立 GDD，仅做 `unlock_array_id` ID 关联解耦） | — |

## ③ 落地决策 D1..D11

### D1 · 宗门大阵数据结构（game_state 新增）
- **决策点**：`宗门大阵` 用一个 `Dictionary` 统包，还是拆成多个 `var` 字段？
- **推荐默认**：**单个 `var 宗门大阵: Dictionary = {}`**，内含：
  - `"当前主阵": String`（启用阵的 `array_id`，`""`=未启用）
  - `"等级": Dictionary`（keyed `array_id → int`，各阵等级，0=未启用/1=初始）
  - `"耐久": Dictionary`（keyed `array_id → int`，各阵当前耐久）
  - `"已解锁": Dictionary`（keyed `array_id → bool`；或运行时由 `门派等级` 推导，存表免每帧算）
- **替代方案**：拆成 `var 当前主阵`、`var 大阵等级表`、`var 大阵耐久表` 等多个独立 `var`。
- **采纳默认理由**：与 game_state 既有「宗门级状态分组」范式一致（如 `七载奖励池`/`七载待发掉落` 同组），`save_game` 增一个键即可（L2441 区）、`load_game` 一处 `.get(默认={})`；旧档缺键→默认 `{}`，零回归。
- **解锁规则**：`已解锁[array_id] = (门派等级 >= array_config.unlock_sect_rank)`（护山/聚灵/镇煞按投稿 §2 品级门槛）；不消耗阵图（阵图仅用于单人法阵解锁，见 D5）。

### D2 · 单人法阵存储（disciple 新增）
- **决策点**：法阵存 `装备` Dictionary 的新「法阵」穿戴位 key，还是 disciple 独立字段？
- **推荐默认**：**独立字段 `var 当前法阵: Dictionary = {}`**（存 `{"array_id": String, "等级": int}`，空 `{}`=未装备）。**强约束理由**：① `装备` 的 key 必须是 `item.穿戴位`，而 `穿戴位名`（`item.gd` L26）仅 9 值、无「法阵」，且 `get_final_combat_attr` L959-969 遍历 `槽位名列表[9]` 并按 `槽位映射[9]` 索引——注入「法阵」会**越界崩溃**；② 法阵是「已布阵状态」而非 gear（无 `装备基础战力`、无穿戴位），阵图是 consumable 解锁物、消耗即消失，不应以 `Item` 实例常驻；③ `自动穿戴`/`一键最优`/`_修复装备一致性`（L298-383）均假设 gear 语义，法阵入内会污染。故**独立字段 + 平行 `to_dict`/`from_dict` 键**，与 ADR-001 装备体系「同层不同槽」，最省心。
- **替代方案（未采纳）**：在 `装备` Dictionary 增 `"法阵"` key。→ 会触发上述越界与一致性 bug，否决。
- **存档兼容**：`to_dict` 增 `"当前法阵": 当前法阵`；`from_dict` 增 `当前法阵 = d.get("当前法阵", {})`（旧档缺键→`{}`，零回归，照 L1062 范式）。
- **✅ 主理人已采纳（独立字段）**：代码侧强约束已指向独立字段，投稿「装备 Dictionary 新 key」因越界崩溃风险否决。落地用 `var 当前法阵: Dictionary = {}`。

### D3 · 法阵属性聚合接入点
- **决策点**：法阵战斗属性走 `聚合通用增益()`（L207，单浮点乘区）还是 `_聚合未来战力来源()`（L1146 TODO）？
- **推荐默认**：**常驻攻防血速 / 护盾→最大生命 → 全部走 `_聚合未来战战来源()` 的 L1146 `TODO(S1): 阵法加成` 接入点**（与批3 功法 L1141-1145 同路径、同铁律「战力映射铁律」L979-982「禁止只堆 总战力()」）。**不并入 `聚合通用增益()`**——L207 注释「大阵并入同池」已滞后（功法实走 L1143 路径），且该池是 `(1.0+通用增益)` 单浮点乘区，会重蹈「虚高战力」覆辙。
- **修炼速度（经营）**：
  - 单人法阵·修炼辅助 → disciple `总修炼速度倍率()`（L423）乘性并入（per-disciple）。
  - 宗门大阵·聚灵大阵 → game_state 新增 `_宗门大阵修炼乘区()`（仿 `_藏经阁修炼乘区()` L273），在 `推演一月` L812-813 并入 `宗门加成pct`（clamp 0~1）。
- **暴击/闪避（概率属性）**：法阵暴击率/闪避率%+N% → 扩展 `get_final_combat_attr` L937-942 的 暴击率/闪避率 推导（合约：在此处累加 `当前法阵` + `宗门大阵` 的暴击/闪避贡献）。
- **单源子帽 / 叠加上限**：单法阵满级总增益 ≤15%（投稿 §3 基线）；宗门大阵(全域%) × 个人法阵(个人%) 乘法叠加须锁总上限（建议 ≤25%，[PLACEHOLDER] 真机校准，见 §⑦/R9）。L1146 接入时对本源（宗门大阵 + 当前法阵）分别 clamp 后再叠加。
- **注**：既有 `game_state.gd` L1839「阵法阁常驻防御+1%」dormant 路径**不强制复用**——宗门大阵防御类同源走 L1146，避免分散两处维护。

### D4 · 触发类属性等效（护盾 / 回血 / 回蓝）
- **决策点**：投稿 §7 的「护盾/回血/回蓝」三类触发效果，S1 如何等效？
- **推荐默认**：
  - **护盾 → 最大生命 +X%**：在 L1146 接入，将「最大生命+X%」作为 flat 加到 `战斗属性["血"]`（等效承伤，缺护盾条视觉，见 §⑨/R1）。**S1 实现。**
  - **回血 → 结算后恢复 X% 最大生命**：**S1 仅存意图、不实现回调**（实现需改 `BattleManager.gd` 结算后钩子，铁律禁止）。在 `当前法阵` 状态记录 `回血%`，文档标注「S2 经战斗结算后回调钩子应用」。
  - **回蓝 → 待定（见开放项）**：
    - 方案 A（推荐·安全）：**等效为「灵气上限 +X%」**（属性前置，零战斗触碰，S1 可落地，体感为续航上限提升而非每回合回蓝）。
    - 方案 B：**标 [PLACEHOLDER] 端口**（同回血，S2 补真实回蓝回调）。
- **✅ 主理人已采纳（方案A 灵气上限+X%）**：回蓝 S1 等效为「灵气上限 +X%」（属性前置，零铁律风险，可落地）；真实每回合回蓝标 S2 端口（同回血）。

### D5 · CSV 字段对齐（array_config / 阵图物品）

### D6 · 身份阶别锁实现
- **决策点**：投稿 §3 写「外门/内门/亲传/长老」4 级锁，但代码 `身份层级序`（L149）**实为 5 级**：外门/内门弟子/核心弟子/亲传弟子/长老（无「真传」值）。

### D7 · 灵根匹配加成
- **决策点**：弟子灵根与阵法 `match_element` 匹配 +5% 如何并入聚合？
- **推荐默认**：读 `disciple.灵根`（L138，单灵根模型）；`match_element` 映射：`earth→土 / water→水 / metal→金 / wood→木 / fire→火 / fire_water→{火,水} / all_five→恒匹配 / none→不判`。匹配判定：`match_element in {单元素}` → `灵根==该元素`；`fire_water` → `灵根 in ["火","水"]`；`all_five` → `true`。匹配成立则该法阵对弟子的**有效贡献 ×1.05**（+5%，乘法，不破单法阵≤15% 基线）。

### D8 · 升级消耗公式
- **决策点**：法阵升级消耗与现有升级体系是否兼容？
