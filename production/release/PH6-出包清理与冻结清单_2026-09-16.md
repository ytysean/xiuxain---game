## 1. 机制澄清：两案**不能**混用（本文件最重要的一节）

| | `.gdignore` | `exclude_filter`（导出预设） |
|---|---|---|
| 作用域 | **编辑器资源库**（本目录 + 整棵子树） | **仅导出列表**（打进的包） |
| 对运行时 `res://` 加载 | **致命**——文件从资源库消失，`load("res://...")` 直接失败 | 无影响（编辑器/本地运行照旧） |
| 对本项目七闸 / uifa | **会砸**——七闸与 uifa 都以 `res://tests/*.tscn` 起场景（`--scene res://tests/ui_full_accept.tscn` 等） | 安全 |
| 可否带规则 | 否（空文件即标记，**不带规则**） | 是（逗号分隔 glob，匹配 `res://` 全路径与去前缀相对路径） |
| 放根目录的后果 | **灾难**——整工程被跳过 ⇒ 空包 / 崩 | 不适用 |

> **铁则**：任何**需要被 `res://` 加载**的东西（脚本、场景、测试），**只能**用 `exclude_filter` 挡在包外，**绝不可** `.gdignore`。
> 反过来，**纯数据 / 纯文档 / 从不由 `res://` 加载**的目录，才可用 `.gdignore`。

## 4. A / B 两案最终建议

### A 案（`exclude_filter`，**推荐**）
- 位置：`export_presets.cfg` 的 `[preset.N.options]` 段各加一行（Android + Windows 各一）。
- 内容（逗号分隔 glob，**终版已复核**，证据见 §2.2 / §3.3 / §3.2）：
  ```
  exclude_filter="tests/*,美术资源/宗门首页/_gen/ui_mockups/*,design/01-总纲/concept/*,design/06-角色与UI/reference/*,Godot/*"
  ```
  - **硬规则**：**有 `.gdignore` 的目录一律不列**（已被编辑器扫描排除）——`_taixuan_offload/*`、`accept_shots*/*`、`.venv_genai/*`、`.workbuddy/*`、`.scratch_backup/*` 等 **16 个**已确认带 `.gdignore`；
  - `.cache/*` **不列**（**点目录，Godot 自动跳过**）；
  - `Godot/*` 当前可打包 = **0 B**，列入纯为**保险**（防未来 `save.json` 落进 `res://`，见 §7.6）。
  - 精确版 vs 宽版任选：上式为精确版；若想少写几项也可用 `美术资源/*,design/*,tests/*,Godot/*`（等价，因为 `美术资源/` 整棵树只有 mockups、`design/` 的可识别资源只有那两个 image 子目录）。
- 优点：**不动编辑器资源库** ⇒ 七闸 / uifa / 探针全部照常；一次改完 Android+Windows 通用。
- 代价：需**解冻 `export_presets.cfg`**（现冻结于 5536 B / 4 sections）。**建议并入 §6 的「预设写入窗口」一次做**（与 Android 两键同窗口，避免反复动预设）。

### B 案（`.gdignore`，**兜底**）
- 可行范围：**仅 C1/C2/C3 三个图目录**（外部引用 = 0，且从不由 `res://` 加载图片）。
  - `美术资源/.gdignore`、`design/.gdignore`（或精确到 `design/01-总纲/concept/.gdignore` + `design/06-角色与UI/reference/.gdignore`）。
- **禁止**用于 `tests/`（会砸七闸/uifa）。
- 优点：**不动预设**（绕过冻结）。
- 代价：这些图从编辑器资源库消失（但 0 引用 ⇒ 无副作用）；若日后有工具想引用它们需先删 `.gdignore`。
- 注：`design/` 还有 300+ `.md` 文档，`.gdignore` 会把它们一并移出扫描面——文档非资源、无影响，但若团队希望编辑器内可见这些 md，就改用精确到两个 image 子目录。

### 组合建议（我的最终意见）
**优先 A 案（统一 `exclude_filter`，含 `tests/*`）**；若 team-lead 决定 preset 不动，则 **B 案只处理 C1/C2/C3，C4 暂留包内**（0.75 MB，可接受，`tests/` 脚本随包发布属可容忍的次优）。

## 7. 已知风险与红线

### 7.1 `.gdignore` 语义坑（P0）
`.gdignore` = 忽略**本目录 + 整棵子树**、**不带规则**。放进根目录 ⇒ **整工程被跳过 ⇒ 空包 / 崩**。
**任何人不得在 `res://` 根放 `.gdignore`。** 只允许放在确需排除的**子目录**内。

### 7.2 绝不能 `.gdignore` 的目录
见 §3.2 白名单（`ui/`、`config/`、`components/`、`addons/`、`art/` 非 `_` 子目录、`theme/`、`vfx/`、`assets/`）。
`tests/` 属「能排除但不能 gdignore」的特殊类（见 §1 / C4）。

### 7.3 探针脚本污染 `res://` 根（遗留）
`tests/` 与 `.workbuddy/` 的探针脚本把产物写到 `res://` **根目录**（如 `_probe_*.png`），
⇒ **下次跑探针会重新污染根**（本轮已搬到 `_taixuan_offload/`，但**机制未修**）。
建议二选一（B 轮后处理，待 team-lead 裁决）：
- **根治**：探针输出改到 `user://`（不再污染 res 树）；
- **围栏**：探针产物目录补空 `.gdignore`（与 A/B 同批做）。

### 7.4 `compress/high_quality` —— 采纳 team-lead 纠正
**更正本仓早期说法**：`high_quality=true` **不是**「同量级小幅」。实测（读源图色型）：
