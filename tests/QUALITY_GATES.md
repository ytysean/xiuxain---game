# 质量门定义（QUALITY_GATES）

> 版本：v1.0 ｜ 适用阶段：Phase 4 收口 ｜ 模式：solo 评审（无 Godot 运行器，无法真机 playtest）
> 作者：quality-lead（严守真）｜ 对齐文档：太玄宗门录_核心设定总览.md §4 / §9.6 / §11.21 / §11.24、csv_validator.gd、奇遇系统落地规范.md

## 0. 文档定位与适用范围

本文件定义项目从设计到发布的**质量门（Quality Gates）**。质量门是**建议性门控（advisory）**：
qa-lead 给出判定，但最终放行由主理人（游承峰）决定；高影响动作（发布签字）须人工审批。

本环境**无 Godot 运行器**，因此真机 playtest、真实烟雾跑测均不可行。所有门控在 solo 模式下
用以下**四种可执行手段替代**真机验证：

| 手段 | 代号 | 说明 |
| --- | --- | --- |
| 代码评审 | CR | 人读 .gd 源码，按清单核对（命名/存档兼容/数值红线/无硬编码） |
| CSV 校验 | CV | 复用 `csv_validator.gd` + 跨表关系校验（drop 权重和=100、event 权重和=100 等） |
| 逻辑自查 | LS | 把纯函数（战力聚合/奇遇权重/五行克制/增益乘区）抽成镜像实现，跑断言 |
| 存档兼容验证 | SC | 构造旧档/新档，比对双层结构与字段三原则，确认不丢不崩 |

> ⚠️ 缺口提示：`csv_validator.gd` 头部注释多次引用「调用方（validate_all.py 镜像）」承载跨表关系校验，
> 但仓库内**不存在 validate_all.py**（仅见 docx_extract.py）。本门控中凡标注「依赖 validate_all 镜像」的检查项，
> 在 eng-lead 落地测试框架前视为 **CONCERNS**，不记 FAIL（属框架缺口，非实现缺陷）。

## 1. 质量门总览（阶段切换门控）

| 门 # | 门名称 | 触发时机 | 替代真机的核心手段 | 放行硬条件 |
| --- | --- | --- | --- | --- |
| G1 | 设计评审门 | Story 进开发前 | CR + CV | 验收标准可测、数值出处置 [PLACEHOLDER] 或基线值 |
| G2 | 架构评审门 | 代码可合入前 | CR + LS | 存档兼容 §11.21 已设计、乘区归属 §4.6 已占坑 |
| G3 | 烟雾测试门 | 冲刺出口 / 提测前 | LS + SC + CR | 关键路径 smoke 全绿（见 §4 装备穿戴定义） |
| G4 | 发布检查门 | 版本发布前 | CR + CV + SC | 存档兼容三项用例通过、四件套齐全 |

判定语义统一：**PASS**（可放行）/ **CONCERNS**（可放行但需跟踪，附风险单）/ **FAIL**（阻塞，不得放行）。

## 2. G1 设计评审门（Design Review Gate）

**目标**：确认一个 Story 的验收标准可被测试、数值不出现裸数「拍脑袋」、配置表 schema 已就位。

### 2.1 可执行检查项
- **[CR] 验收标准可测性**：每个 Story 至少含 1 条可量化验收点（数值 / 阈值 / 状态切换），禁止「体验良好」类模糊描述。
- **[CV] 配置表就位**：涉及的新表已在 `csv_validator.gd` 的 `TABLE_RULES` 注册（字段、主键、枚举、区间）。
- **[CR] 数值出处**：所有数值要么标 `[PLACEHOLDER]`（待实测），要么引用总览具体章节（§4.x / §11.24）基线值；禁止无出处硬编码。
- **[CR] 乘区占坑**：凡新增增益源，须先在 §4.6 全局乘区归属总表占坑，标明归属乘区与软/硬上限。

### 2.2 判定标准
| 判定 | 条件 | 阻塞项示例 |
| --- | --- | --- |
| PASS | 以上 4 项全满足 | — |
| CONCERNS | 数值标 [PLACEHOLDER] 但无后续实测排期，或乘区占坑延后到实现期 | 「装备词缀增益具体数值待定，但本冲刺就要穿」→ 标 CONCERNS，附平衡测算待办 |
| FAIL | 验收标准不可测 / 新表未注册却要读 / 出现无出处裸数 | 「战力公式里直接写 ×1.3 无任何章节引用」→ FAIL，阻塞进开发 |

## 3. G2 架构评审门（Architecture Review Gate）

**目标**：确认实现不会触碰存档兼容红线、不会击穿数值红线、增益计算落在正确乘区。

### 3.1 可执行检查项
- **[CR] 命名规范**：脚本/函数/信号命名一致（蛇形或项目既定风格），无 `tmp`/`test123`/`a` 类临时命名；常量集中定义，无散落字面量。
- **[CR] 存档兼容 §11.21**：新增数据只在 `items`/`disciples` 等业务分区内扩展；遵守字段三原则（只新增+默认值／不修改／不删除）；不得改元数据头格式、不得改主键 ID 生成规则、不得改全局枚举顺序。
- **[CR] 数值红线 §4.1**：所有增益必须显式归属某一乘区；通用增益池遵守软上限 25% / 硬上限 30%（溢出 20% 衰减）；道心独立乘区 ≤10%；减耗专属 ≤40%；产出效率池单建筑 ≤20% / 全建筑 ≤30% 且不入战力。
- **[LS] 无硬编码**：增益系数、克制系数、权重阈值不得写在逻辑分支里，必须从 config/CSV 或常量读取；提供一处可读来源。
- **[CR] 乘区归属 §4.6**：实现对照总表，确认「同一乘区内部先加算再转系数，跨乘区严格相乘」；单源子帽 + 池总帽双重保险已实现。

### 3.2 判定标准
| 判定 | 条件 | 阻塞项示例 |
| --- | --- | --- |
| PASS | 命名规范 + 存档兼容零触碰 + 乘区归属正确 + 无硬编码 | — |
| CONCERNS | 乘区实现正确但缺少单源子帽收敛（仅靠池总帽兜底） | 「装备/大阵各自收敛到子帽未实现，只卡总 25%」→ CONCERNS，标数值漂移风险 |
| FAIL | 触碰存档结构/枚举/主键红线，或增益被加算混用击穿 25%/30% 硬上限 | 「把装备加成直接线性加到基础战力而非乘区」→ FAIL，阻塞合入 |

## 4. G3 烟雾测试门（Smoke Gate）—— 含「装备穿戴首个冲刺」定义

**目标**：以最低成本确认「关键路径不崩、核心数值聚合正确」。因无引擎，smoke 用 LS+SC+CR 替代真机跑测。

### 4.1 通用 smoke 检查项（每个冲刺出口都跑）
- **[LS] 关键纯函数不崩**：战力聚合、奇遇权重抽取、五行克制判定等纯函数对边界输入（满值/零值/极端组合）不抛错、不 NaN。
- **[CV] CSV 全量校验通过**：48 张表跑 `csv_validator.gd`，零错误（含权重和=100 类跨表校验，依赖 validate_all 镜像）。
- **[SC] 存档读写往返**：构造一个含典型数据的 `save.json`，经「存→读→存」往返，业务分区字段无丢失、无类型漂移。
- **[CR] 无回归**：本次变更未引入对既有分区/枚举/主键的破坏性修改（对照 G2）。

### 4.2 ★ 装备穿戴首个冲刺 —— 入口门（Entry Gate）与出口门（Exit Gate）

> 首个冲刺目标 = 装备穿戴。以下为专属门控，其余系统（战斗/奇遇/引导）本轮不强制过此门。

#### 4.2.1 入口门（进开发前必须 PASS）
- **[CV] 装备表就绪**：`equip_main.csv`（7 槽位字段齐全：base_atk/def/hp/durability 等）、`equip_set.csv`、`equip_blueprint.csv` 已在 `TABLE_RULES` 注册且校验通过。
- **[CR] 数据模型就位**：`game_state.gd` 的 `items` 业务分区已含「装备槽位→equip_id」「仓库持有」结构；槽位枚举对齐 `EQUIP_SLOTS`（武器/法袍/头盔/护腕/腰带/靴子/饰品）。
- **[CR] 存档兼容**：装备相关字段属 `items` 分区扩展，遵守字段三原则；若在旧档上新增，须有默认值补全逻辑（§11.21.2）。
- **[CR] 乘区占坑**：装备词缀增益已在 §4.6 占坑为「装备乘区」，汇入通用增益池，单源子帽已定（参考 v2.19 单源子帽口径）。

入口门 FAIL 示例：equip_main 缺 base_hp 字段仍要穿 → 阻塞进开发；`items` 分区直接改旧字段名 → 触碰 §11.21 红线 → FAIL。

#### 4.2.2 出口门（smoke 级别，提测前必须 PASS）
以下四条为**出口门硬条件**，任一 FAIL 即阻塞提测：

| # | 检查项 | 验证手段 | PASS 标准 | FAIL 阻塞示例 |
| --- | --- | --- | --- | --- |
| E1 | 穿戴后战力正确聚合 | LS（战力公式镜像） | 穿戴装备后战力 = 基础 × 资质 × 灵根 × 职业综合 ×(1+通用增益[含装备词缀]) ×(1+道心) + 灵兽；装备词缀计入通用增益乘区 | 穿戴后战力未变化（说明「不穿不算战力」缺口未修）→ FAIL |
| E2 | 卸载后战力回退 | LS | 卸下装备后战力等于穿戴前原值，无残留加成、无浮点漂移 | 卸载后战力仍偏高 → FAIL（加成未清除） |
| E3 | 存档读档不丢装备 | SC（存→读 diff） | 穿戴状态经 save→load 后，槽位绑定与仓库持有一致；items 分区字段三原则兼容，无空指针/悬空 equip_id | 读档后装备消失或指向不存在物品 → FAIL（对照 §11.21.5 自修复应卸下归还，但正常路径不应丢） |
| E4 | 乘区不破红线 | LS（乘区聚合镜像） | 任意装备组合下，通用增益总和 ≤ 硬上限 30%（软 25% 溢出按 20% 衰减）；装备单源子帽生效 | 满配 7 件传说装备使通用增益 >30% → FAIL（击穿红线） |

> 出口门偏差处理：若 E4 触发但仅为「数值偏高需调参」而非「机制错误」，可降级为 **CONCERNS** 并附 §11.24 平衡测算需求；
> 若 E1/E2/E3 任一 FAIL，则**必须 FAIL**，属功能性缺陷，不得放行。

### 4.3 判定标准（G3）
| 判定 | 条件 |
| --- | --- |
| PASS | 4.1 通用项全绿 + 4.2 装备冲刺入口门已 PASS + 出口门 E1~E4 全 PASS |
| CONCERNS | 通用项绿，但装备出口门 E4 仅数值偏高（机制正确）或依赖 validate_all 镜像的检查项暂缺 |
| FAIL | 出口门 E1/E2/E3 任一 FAIL，或通用项 CSV 校验报错，或触碰存档红线 |

## 5. G4 发布检查门（Release Gate）

**目标**：版本发布前，确保存档兼容铁则与四件套齐备，兼容问题优先保数据可用。

### 5.1 可执行检查项（对齐 §11.21.6 开发侧强制约束）
- **[SC] 三项用例通过**：① 旧存档兼容测试 ② 数据迁移测试（仅主版本）③ 回退还原测试 —— 三项不通过不得发布。
- **[CR] 四件套齐全**：更新包 + 回退包 + 迁移脚本 + 回退脚本（主版本强制；次/修订版免迁移但需兼容校验）。
- **[CV] 全量 CSV 校验**：48 表零错误，权重和校验全绿。
- **[SC] 加载流程合规**：更新加载走 §11.21.4 六步（备份前置→版本校验→完整性校验→增量加载→二次校验→结果处理），失败可自动回滚。
- **[CR] 最终红线**：核心进度数据（宗门等级/弟子/资源/建筑）绝不因更新丢失/清零/错乱。

### 5.2 判定标准
| 判定 | 条件 | 阻塞项示例 |
| --- | --- | --- |
| PASS | 三项用例通过 + 四件套齐全 + CSV 零错 + 加载流程合规 | — |
| CONCERNS | 三项用例通过，但回退脚本仅覆盖正向主路径、极端中断场景未测 | 「迁移中途退出未验证可重试」→ CONCERNS，附容错测试待办 |
| FAIL | 三项用例任一不通过，或四件套缺失，或核心数据有丢失风险 | 「无回退脚本就发主版本」→ FAIL，硬阻塞发布 |

## 6. 跨门依赖与跟踪

| 门 | 依赖（需其他成员交付） | 状态 |
| --- | --- | --- |
| G1/G2 | eng-lead 的 ADR（存档结构/乘区实现决策）与测试框架提案（validate_all 镜像落地） | 待对齐 |
| G3 出口 E4 | design-lead 的装备单源子帽数值基线（§4.1 v2.19 口径） | 待提供 |
| G4 | art-lead 的降级开关（异常兜底/轻量模式 UI 降级） | 待提供 |
| 全局 | design-lead 的 UX 验收点（竖屏/单手/降级走查）用于人工层 | 待提供 |

> 任一依赖缺失时，对应检查项按上文明规记为 CONCERNS 而非 FAIL，避免把「框架/资料缺口」误判为「实现缺陷」。

## 7. 质量门快速判定速查

```
G1 设计评审 ──PASS──▶ G2 架构评审 ──PASS──▶ G3 烟雾(含装备入口/出口) ──PASS──▶ G4 发布检查 ──PASS──▶ 放行
   │CONCERNS          │CONCERNS            │CONCERNS                         │CONCERNS
   └─可放行+跟踪       └─可放行+跟踪         └─可放行+跟踪                      └─可放行+跟踪
   FAIL               FAIL                 FAIL(出口E1/E2/E3 任一)            FAIL(三项用例/四件套)
   └─阻塞              └─阻塞                └─阻塞提测                         └─阻塞发布
```
