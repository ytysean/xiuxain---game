## 1. 概述与红线重申

**目标**：建筑详情页从零实现，弟子详情页在现有 6 section 基础上做 P1 品质升级，两页对齐 P1 标准（组件化、进度可视化、统一动效与红点）。

**范围（已拍板，不可更改）**
- 全量 P1：建筑详情页从零实现 + 弟子详情页 P1 品质升级，两页对齐。
- 建筑详情页深度：标准字段（名称/职能/等级/产出/主事/成员数/被动加成/修葺进度）+ 进度条可视化（修葺进度条 + 升级入口强调态）。升级/任免仅发占位信号。

**硬红线（绝不可破）**
1. **UI 层零 GameState 写入**：所有操作（升级/任免/开关）仅 `emit` 占位信号，由业务层后续接线。
2. **数据只读**：弟子详情读 `Game.弟子列表`/弟子对象；建筑详情只读 `Game.堂口列表[key]`。读数一律 `is_instance_valid(Game)` + `.get()` 守卫，缺失即 `"—"` 不崩。
3. **动态色一律走 `UIThemeConfig`**（品级/境界/状态），静态色走 `main_theme.tres` + `ui_theme.gd` getter；禁止散落硬编码 `Color(#...)`。
4. **组件复用优先**：已有 `ListItem`/`BasePanel`/`ItemSlot` 直接复用，不新建重复组件。

**字段核实结论（关键）**
- 堂口 entry **确认存在**：`key, 名称, 职能, 产出, 加成维度, 负责人(Disciple|null), 成员(Array[Disciple]), 负责人锁定(bool), 等级(int,默认1), 政绩(int), 里程碑(int), 高政绩事件(bool)`。
- 堂口 entry **不存在（待业务层确认）**：`修葺进度, 修葺等级, 描述, 状态`。（核实 `重建堂口()` L2693 与全量引用均无此四字段；`升级建筑()` 为瞬时写、`等级+1`，无进度值。）
- 弟子对象 **确认存在**：`姓名, 道号, 身份, 阶位, 来源, 备注, 资质, 灵根, 灵根品阶, destiny_id, 性格, 职业, 境界, 层数, 修炼进度(0~1), 寿元, 年龄, 突破冷却剩余, 瓶颈打磨值(0~1), 稳固期剩余, 丹毒(0~1), 堂口, 考核冷却剩余, 考核心得, 属性{攻,防,血,速}, 战力, 装备(Dict 穿戴位→Item), 当前法阵, 道心增益(=0.0 占位), 资质显示(Dict), 总战力()`。
- 弟子对象 **不存在**：`心魔值, 心境`。（`道心`仅 `道心增益` 占位，无独立系统。）
- 装备 `Item.品阶` 取值域 = `凡品/良品/上品/极品/天品`，与 `UIThemeConfig.QUALITY_COLOR` 键（`fan/liang/ling/bao/wang/sheng/xian/dao`，含灵/宝/王/圣/仙/道）**不一致**，需确认映射。
- **项目暂无全局红点管理器**：仅 main.gd 内 `玉牌红点`/`新手红点` 与 `Game.新手_有红点()` 散布实现（见 §3.4）。

### 2.3 交互

- **进/出二级视图**：新增 `page_building._detail_root`（`VBox`，`visible=false`），与 `page_disciple` 同构。`_on_hall_gui_input` → `建筑详情请求.emit(key)` → `_show_building_detail(key)`：隐藏 ListRoot、显示 `_detail_root`、调用 `UITween.fade_in(_detail_root)`（见 §2.4）。返回按钮 `_on_back_pressed` → `建筑详情返回.emit()`（新增 signal）→ 隐藏 `_detail_root`、显示 ListRoot。
- **升级按钮**：`pressed` → 先 `UITween.button_press(btn)` 再 `建筑升级请求.emit(key)`（复用既有 signal，占位）。
- **任免入口（新增 signal）**：`page_building` 新增 `signal 建筑任免请求(key: String)`；按钮 `pressed` → `UITween.button_press` + `建筑任免请求.emit(key)`（占位，业务层后续接 `任命负责人/解除负责人锁定`）。
- **功能开关（新增 signal）**：`page_building` 新增 `signal 建筑开关请求(key: String, 开启: bool)`（单开关场景两参数，多开关后续扩展）；`负责人锁定` Toggle `toggled` → `建筑开关请求.emit(key, val)`（占位）。

### 2.4 进度条可视化 + 升级入口强调态

**修葺进度条（自绘，P1 不新建组件）**
- 结构：`Panel`(track, `make_panel_stylebox(false)` 或 `color.bg.content` 圆角 `RADIUS_BUTTON=6`) 内嵌 `ColorRect`(fill)。
- 取值：`ratio = clamp(等级 / Game._建筑等级上限(), 0, 1)`（派生，待真实 `修葺进度` 字段替换）。fill 宽 = track 宽 × ratio。
- 配色：track=`COLOR_BG_CONTENT`；fill=`COLOR_TEXT_GOLD`（`color.text.accent`）。数值文本 `Lv.等级 / 上限` 用 `apply_value_font`。
- 入场：fill 宽从 0 → ratio 用 `UITween` 自补间（或 `tween_number` 驱动 label，bar 宽随 label 更新）。

**升级入口强调态（仍占位）**
- 可升级（`等级 < Game._建筑等级上限()`）：`apply_primary_button_style` 基础上 `border_color=COLOR_TEXT_GOLD` + `border_width=BORDER_W2(2)`（金边强调），文案"修葺升级"，右上角加 **金点/可升级红点角标**（见 §3.4；**C1 缺口：当前实现未渲染该红点角标，P1 放行，P2 接 RedDotManager 统一补齐**）。
- 达上限（`等级 >= 上限`）：置 `disabled` 态（`COLOR_BTN_DISABLED` 底），文案"已达上限"，不 emit。
- 按压：所有态均先 `UITween.button_press(btn)` 再判定 emit。

## 3. 弟子详情页 P1 升级映射

### 3.1 现有 6 section 组件化收口方案

现有 `_populate_detail` 6 section（基本信息/资质灵根/修炼状态/任职/四维/个人纪事）均为「`PanelContainer` + 直接 `Label`」手搓。P1 收口：**区块外层统一用 `BasePanel`**（取其标题栏+进出动效基础），区块内 KV 行改用 `ListItem`（`title=caption, value=字段值, value_abnormal=异常`）；装备槽用 `ItemSlot`；所有动态色走 `UIThemeConfig`。

| 现有 section | P1 收口 | 组件/动态色 |
|---|---|---|
| 基本信息 | `BasePanel` 包裹 | 6 行 `ListItem`(title=姓名/道号/…,value=文本)；无异常 |
| 资质灵根 | `BasePanel` 包裹 | `ListItem`；`资质`经 `DiscipleData.资质显示` 解析；`命格`经 `DestinyDataLoader.get_destiny(destiny_id)` 解析（沿用现有逻辑）；`灵根品阶` 走 `UIThemeConfig.set_quality_color`（映射灵根品阶→stem，待确认） |
| 修炼状态 | `BasePanel` 包裹 | `ListItem`；`境界` 走 `UIThemeConfig.set_realm_color`；`突破冷却剩余>0`/`丹毒`超阈 → `value_abnormal=true`（danger 红） |
| 任职 | `BasePanel` 包裹 | `ListItem`；堂口/阶位/考核冷却/考核心得 |
| 四维 | `BasePanel` 包裹 | 4 行 `ListItem`；`攻/防/血/速` 取 `属性` Dict；数值 `apply_value_font` |
| 个人纪事 | `BasePanel` 包裹 | `ListItem`（"第N日"/事件名），空→"暂无个人纪事" |
| **装备**（新增 section） | `BasePanel` 包裹 | 遍历 `装备` Dict，每槽一个 `ItemSlot.set_item(名称,1,品阶→stem映射)`；空槽 `ItemSlot` 灰显占位；`clicked` → emit 弟子装备查看请求(占位) |

> 动态色统一：`境界→UIThemeConfig.set_realm_color(realm_stem)`；`资质/灵根品阶/装备品阶→UIThemeConfig.set_quality_color(stem)`；异常数值→`UITheme.apply_value_font(v,true)`（danger）。**品阶映射已确认（R5 修正）**：`Item.品阶` 实为七品阶（凡阶/灵阶/宝阶/王阶/圣阶/仙阶/道阶，见 `item.gd`），与 `QUALITY_COLOR` 键精确匹配（凡阶→fan…道阶→dao）；实现 `_ITEM_QUALITY_STEM` 已对齐，无需回落默认。规格原 §1 五品阶描述属文档漂移，已修正。

### 3.2 进度可视化（真实字段核实）

| 进度条 | 数据字段（核实） | 取值/范围 | 配色（UIThemeConfig/token） |
|---|---|---|---|
| 修为进度条 | `修炼进度` | 0~1（层内进度） | fill=`color.text.accent`(金)；满→提示可升层 |
| 突破打磨条 | `瓶颈打磨值` | 0~1（仅 `层数>=10` 大圆满后生效） | fill=`color.status.success`(绿)；满→可突破 |
| 道心条 | `道心增益` | 0.0（占位，无系统） | fill=`color.text.title1`(金)；当前恒空 |
| 心魔/丹毒条 | `丹毒` | 0~1（代理"走火入魔风险"） | fill 随值分色：`<=0.5` 正常 / `>0.5` `color.status.danger`(红) |
| 心境条 | **字段不存在** | 待业务层确认 | P1 灰态占位，不绑数据 |

> 横向条统一组件形态（自绘，复用 §2.4 进度条规范）：track=`color.bg.content`、圆角 `RADIUS_BUTTON`；数值文本 `tween_number` 滚动。标注：**`心魔值`/`心境` 字段在弟子对象中不存在（核实 disciple.gd），`道心`仅 `道心增益=0` 占位**——P1 以"丹毒代理心魔风险 + 道心占位空条 + 心境灰态"呈现，待业务层补字段后替换。

### 3.3 动效接入点（统一 `UITween`）

| 动效 | 调用位置 | 说明 |
|---|---|---|
| `UITween.fade_in(node)` | `_show_detail` / `_show_building_detail` 入口 | 对整个 `_detail_root` 调用，替代直接 `visible=true`（弹入 0→1，dur 0.2） |
| `UITween.button_press(btn)` | 所有 `Button.pressed` 回调首行 | 返回/升级/任免/开关/排序按钮；`ListItem` 自带缩放不动此；升级/任免按钮为原生 Button 须手动接 |
| `UITween.tween_number(label, target)` | 战力 `_power_value` 刷新、`建筑详情`Σ产出/总等级入场、弟子 `总战力()` | 数值滚动；进度条 fill 同步补间 |
| `UITween.fade_out` | `_on_back_pressed` 离场 | 可选：`_detail_root` 淡出后再 `visible=false`（与 fade_in 对称） |

### 3.4 红点接入点

**现状**：项目**无全局红点管理器**；仅 main.gd `玉牌红点`/`新手红点`（`朱砂`色 `ColorRect`）+ `Game.新手_有红点()` 散布实现。

**P1 方案**：先用**本地标记位**（各 page 内判定 + 复用 `Game.新手目标更新` / `弟子变动` signal 刷新时机），**建议立项新增 `RedDotManager` Autoload（P2 收口）**。样式遵循《UI交互规范_古风经营A版》§弱状态提示：可升级/可招募用**暗金小圆点**（非强红点）；突破完成/异常警示用 `color.status.danger`(#E07878)。

| 红点 | 数据判定条件（基于真实字段） | 显示位置 |
|---|---|---|
| 突破红点 | `(修炼进度>=1.0 且 层数<10)` **或** `(层数>=10 且 瓶颈打磨值>=1.0 且 突破冷却剩余<=0)` | 修炼状态 section 顶部 / 突破行左；强提醒用 danger |
| 互动红点 | `Game.待抉择.size() > 0`（全局有接引抉择即亮；按弟子精确匹配待 `Game` 提供映射） | 弟子详情顶部 / 任职区互动入口；暗金点 |
| 状态警示 | `丹毒 >= 阈值(建议0.5,待定)` **或** `突破冷却剩余 > 0`(闭关养伤)（心魔字段缺失，以丹毒代理） | 修炼状态 section 字段值；danger 红 |
| 装备红点 | `装备.size() < 槽位数(9)`（存在空槽）→ 提示；P1 简化 `装备.size()==0` 全未装备 | 装备 section 标题 / 空 `ItemSlot` 角标；暗金点 |
| *(建筑)*升级红点 | `等级 < Game._建筑等级上限()` | 建筑详情 升级按钮右上角；暗金点（强调态联动 §2.4）【**C1 缺口：P1 未实现，P2 收口**】 |

> 判定辅助：弟子 `总战力()`、`修炼进度`、`瓶颈打磨值`、`丹毒`、`突破冷却剩余` 均为只读真实字段；`待抉择` 为 `Game` 全局 Array（含 `弟子`/`物品`/`文本`）。所有红点**仅展示，不写 GameState**。

### 3.5 不做边界（P1 明确排除）
- 3D 头像 / 立绘渲染（用 `icon="弟子"` 线稿占位）。
- 命格刷新 / 命格重抽（仅展示 `destiny_id` 解析名）。
- 装备强化 / 穿戴操作（仅 `ItemSlot` 只读展示 + 占位 `clicked`）。
- 分享皮肤 / 截图导出。
- 真实 `修葺进度`/`心魔值`/`心境` 字段驱动（待业务层确认后替换派生/代理方案）。

## 4. 两页统一规范

1. **主题源**：复用 `main_theme.tres`（原生控件基础样式）+ `UIThemeConfig` 常量（品级/境界/状态色）；静态色经 `ui_theme.gd` getter，动态色经 `UIThemeConfig`。
2. **动效统一**：全部走 `UITween`（fade_in / button_press / tween_number），禁止页面内手搓 Tween 重复实现。
3. **红点统一**：接全局 `RedDotManager`（建议 P2 新增）；P1 先用本地标记位，样式按 §3.4（弱提示暗金点 / 强提醒 danger 红）。
4. **组件复用优先**：`ListItem`（KV 行）、`BasePanel`（区块包裹+标题栏）、`ItemSlot`（装备/资源槽）直接复用；进度条自绘一套规范（§2.4）两页共用。
5. **布局基线**：竖屏 480×854；外边距 `MARGIN=16`、栅格 `GRID=8`、区块间距 `GRID*2`、面板圆角 `RADIUS_PANEL=8`、按钮圆角 `RADIUS_BUTTON=6`、字号走 `FONT_H2`(区块标题)/`FONT_BODY`(正文)/`FONT_AUX`(辅助)/`FONT_VALUE`(数值)。
6. **红线铁律**：UI 层零 GameState 写入，所有操作仅 emit 占位信号；数据只读 + `.get()` 守卫；缺失即 `"—"`。
