# 《太玄宗门录》结局系统设计（GDD）

> 本批次定位：搭建**判定框架**（维度定义 / 判定节点 / 结算逻辑 / 触发流程 / 奖励发放 / 数据接口预留）。不填充完整分支路径与结局文案（属 P2 远期内容）。所有数值阈值、文案、分支判定条件一律标 `[PLACEHOLDER]`，待实测校准，禁止写入魔法数字。
> 本 GDD 直接闭环 `REPORT-方案评审.md` #5 指出的「多结局 GDD 缺口（缺口⑥）」，是后续所有长线系统（正邪路线、气运功德、宗门声望、弟子传承）的统一接入底座。

## 1. 概述

### 1.1 系统定位
- **长线终极承接层**：正邪路线抉择、气运/功德、宗门声望、弟子传承等模块的最终判定出口。先定统一框架，后续所有系统设计都有明确接入标准，从根源避免规则脱节（呼应 `REPORT-方案评审.md` #3「杜绝文档孤岛」）。
- **沙盒式经营心智承载**：对应 `核心设定总览 §80`「军事扩张 / 丹道致富 / 隐逸修仙 / 商业世家等路线皆可顺利玩通（对应不同宗门结局）」，对标《环世界》《矮人要塞》经营心智。

### 1.2 设计目标
- 强宿命感与话题性：终局有「选 A 即失去 B」的不可逆重量（`问题解决方案总览` 玩法深度模块核心亮点）。
- 多路线公平可玩通：无单一最优解，每条路线都有清晰终局反馈。

### 1.3 范围（与《版本内容拆分与路线图》对齐）
- **首发 v1.0**：仅落地判定框架 + 维度累计 + 数据接口预留；**不触发实际结局演出**，不占用首发核心工期。
- **S1 及以后**：填充分支路径、判定阈值、结局文案与专属演出（属 P2 远期规划）。

## 2. 结局总览与分类

### 2.1 四大主结局（开发路线型 · 判定框架主口径）
> 源自《版本内容拆分与路线图》四.3，本 GDD 以这四结局为**统一判定框架**。

| 结局 | 核心判定维度（主） | 辅助维度 | 路线气质 | 终局反馈 |
| :--- | :--- | :--- | :--- | :--- |
| **正道结局** | 功德值 + 宗门声望 | 正邪路线=正 | 守正济世、门庭若市 | 正道共主 / 飞升资质 |
| **邪道结局** | 势力值 + 杀戮值 | 正邪路线=邪 | 以武犯禁、一统玄洲 | 魔道共主 / 亦正亦邪 |
| **隐世结局** | 传承代数 + 弟子总数 | 灵脉/隐逸权重 | 薪火相传、与世无争 | 万代传承 / 归隐山林 |
| **覆灭结局** | 宗门崩坏值（阈值触发） | 弟子团灭/建筑焚毁 | 中道崩殂 | 遗迹留存供后人探索 |

### 2.2 剧情包变体（终局浩劫型 · 挂在同维度上）
> 源自 `核心设定总览 §16.7`（面对幽魔族终局浩劫时的剧情包）。本质是同套维度判定的「剧情皮肤」，映射到 2.1 的主结局，具体映射与文案标 `[PLACEHOLDER]`。

| §16.7 剧情包 | 映射主结局 | 核心意象 |
| :--- | :--- | :--- |
| 守序结局 | 正道 | 联合正道修复九天玄极封印，太玄宗成玄洲新领袖 |
| 霸道结局 | 邪道 | 吸收魔族力量以魔制魔，一统玄洲成魔道共主 |
| 逍遥结局 | 隐世 | 另辟蹊径封闭幽渊，代价灵脉衰退、再无飞升但永世和平 |
| 飞升结局 | 正道/传承变体 | 以玄极令破开飞升通道，率核心弟子飞升留传承 |

> ⚠ **待裁**：§16.7 四结局与路线图四结局是「剧情包」与「判定框架」的上下级关系，还是各自独立触发（浩劫线 vs 普通长线条线）？建议：普通长线走 2.1 四结局，触发终局浩劫事件后走 2.2 剧情包覆盖演出；判定维度共用。具体触发优先级标 `[PLACEHOLDER]`。

## 3. 判定维度体系（统一维度定义）

> 所有维度走 `核心设定总览 §11.19 三·1~5` 的**全局变量入口**，本系统只读不写，避免跨系统直接改底层（单一数据源铁律）。维度取值区间、累计速率一律 `[PLACEHOLDER]`。

### 3.1 功德值（merit）
- **定义源**：`§11.18 三·2` / `§11.20.4`（特殊属性类货币）。
- **获取**：降妖、救治、剿邪、庇护、归还天材。
- **负向（消耗）**：修邪功、劫掠、滥杀（对应 §5223 恶名值逻辑）。
- **作用链**：影响雷劫难度（§11.16）、心魔概率、正邪外交（§6.18）、正邪功法权限。
- **接入接口**：`global_vars.merit`（写方：事件系统 / 奇遇 / 宗门行为）。

### 3.2 宗门声望（reputation）
- **定义源**：`§11.1`（连锁分铺解锁绑宗门等级与声望）。
- **获取**：宗门大比胜场、奇遇扬名、阵营贡献、S1 赛季积分。
- **接入接口**：`global_vars.sect_reputation`（写方：经营/战斗/赛季系统）。

### 3.3 势力值（power）
- **定义源**：`GDD-阵营系统.md`（正邪路线抉择产出）。
- **获取**：占领灵脉、吞并敌对宗门、商路垄断、弟子战力总和加权。
- **接入接口**：`global_vars.power`（写方：阵营系统 / 宗门扩张）。

### 3.4 杀戮值（slaughter）
- **定义源**：`§5223` 恶名值（频繁劫掠/劫镖累计）。
- **获取**：滥杀、劫掠、邪修行为；正道围剿事件的反向增益。
- **接入接口**：`global_vars.slaughter`（写方：战斗/事件系统）。

### 3.5 传承代数（generation）
- **定义源**：弟子传承体系（`§10` 先贤传承 / `GDD-弟子养成.md`）。
- **获取**：核心弟子闭关传承、收徒链累计代数。
- **接入接口**：`global_vars.generation`（写方：弟子养成系统）。

### 3.6 弟子总数（disciple_total）
- **定义**：当前在册弟子数（含休退/坐化前的累计峰值标 `[PLACEHOLDER]`）。
- **接入接口**：`global_vars.disciple_total`（写方：弟子系统）。

### 3.7 宗门崩坏值（collapse）
- **定义**：`[PLACEHOLDER]` 负向累计值。建议来源：弟子团灭率、建筑焚毁、灵脉枯竭、国库清零时长。
- **触发**：达阈值即锁定「覆灭结局」，优先级最高（兜底防卡死）。
- **接入接口**：`global_vars.collapse`（写方：战斗/灾难事件）。

## 4. 判定节点与累计逻辑

> 源自《版本内容拆分与路线图》四.3：三个关键判定节点，玩家选择累计对应维度数值，最终按最高值判定结局。

| 节点 | 触发条件 | 累计动作 |
| :--- | :--- | :--- |
| 节点一 | 宗门达 3 级 | 快照维度初值，开启正邪路线抉择入口（`GDD-阵营系统.md`） |
| 节点二 | 宗门达 5 级 | 维度二次快照，锁定不可逆路线分支 |
| 节点三 | 任一弟子达渡劫期 | 终局倒计时开启，进入结算候选 |

- **累计方式**：线性累加（引 `核心设定总览 §4557 八、落地自动计算公式`：线性累加 + 统一结算，避免乘算叠加导致数值崩坏）。
- **衰减规则**：杀戮值/恶名值是否随时间衰减标 `[PLACEHOLDER]`；功德值是否随邪行回退标 `[PLACEHOLDER]`。

## 5. 结算流程

### 5.1 触发条件
- 终局事件触发（节点三达成 **或** 宗门崩坏值达阈值 **或** 主动触发「飞升/退隐」仪式 `[PLACEHOLDER]`）。

### 5.2 判定算法（伪代码）
```
dim_正道 = w1*merit + w2*sect_reputation          // 权重 [PLACEHOLDER]
dim_邪道 = w3*power  + w4*slaughter               // 权重 [PLACEHOLDER]
dim_隐世 = w5*generation + w6*disciple_total      // 权重 [PLACEHOLDER]
if collapse >= collapse_threshold: return 覆灭结局   // 最高优先级兜底
return argmax(dim_正道, dim_邪道, dim_隐世)          // 取最高维度对应结局
```

### 5.3 平局 / 兜底规则
- 双维度相等时优先级标 `[PLACEHOLDER]`（建议 正道 > 隐世 > 邪道，或触发特殊「中庸结局」`[PLACEHOLDER]`）。
- 所有维度均低于最低激活阈值：默认「隐世结局（平庸退场）」`[PLACEHOLDER]`。

## 6. 奖励发放规则

- **终局奖励**：专属称号（`GDD-成就.md` 终极成就）、传承印记、专属剧情演出、世界线记录（`核心设定总览 §3713` 全服编年史）。
- **关联**：终极成就写入 `achievement_config.csv` 的 `reward_id`，须先在 `config/item_id_registry.csv` 注册，避免悬空引用（见 `DESIGN-RULINGS.md` 六、数据治理待办）。
- **发放时机**：结算动画后统一发放，失败可重试 `[PLACEHOLDER]`。
