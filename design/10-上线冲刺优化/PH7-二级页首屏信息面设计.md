### §1.2 方案总览

- **块数 = 4**（满足「≤4 块」）；**每块 ≤2 行**。
- **形制词汇（本文件统一）**：`数` = 阿拉伯数字 + 单位（`FONT_VALUE 27` viewport ｜ 12 逻辑）；`条` = 进度条 + 右侧数值；`文` = 纯文字（`FONT_BODY 27` viewport）；`标` = 字符图标（白名单内）+ 文字。
- **每块建议包 `PanelContainer`（实心面板）**，调用 `UITheme.apply_panel_style` —— 与同页既有先例同族（`ui/page_fishing.gd:679-680` 图录详情面板）；目的：满足铁律「**数据＝实心面板**」，并为块提供视觉收边（同时吃掉一部分 void）。

**块间顺序（推荐）**：

```
[现有 9 段]  →  块A「下一步」  →  块B「今日机缘」  →  块C「灵渊探索」  →  块D「图录收录」
```

- **推荐理由**：本页是「待玩家决策」页 ⇒ 首屏第一眼应是「现在该做什么」（**块A 置首**），其后三个状态块作为**支撑证据**解释为什么。
- **★ 待用户拍板（顺序二选一）**：若倾向「先状态、后动作」（更传统的仪表→引导节奏），则改为 `块B → 块C → 块D → 块A`。两种顺序**字段与形制完全一致**，只换序。

### §1.4 块A「下一步」判定规则（文字描述，不写代码）

**按优先级逐条判，命中即止（取第一条成立）：**

1. 若 `获取剩余机缘次数()`（`fishing_system.gd:1958`）≤ 0 ⇒ 「今日机缘已尽，宜静候明日」
2. 若 `可钓灵渊().size()`（`fishing_system.gd:242`）< `灵渊表.size()`（`fishing_system.gd:13`） ⇒ 「钓道尚浅，宜精进修为以探更深灵渊」
3. 若 `本周大赛参与`（`fishing_system.gd:195 var`）< 3（上限见 `fishing_system.gd:2077`） ⇒ 「本周灵钓大赛尚可参与」
4. 若 `获取鱼获分类统计()`（`fishing_system.gd:1631`）中「鱼获图鉴」`已收录 < 总数` ⇒ 「图录尚缺，宜续竿」
5. 否则 ⇒ 「机缘充足，宜抛竿入水」

> 括号内数值由块B/块C字段同源填充（例：`今宜·继续抛竿（尚余机缘 7 次）`）。
> **不判**「钓具可否晋阶」—— 该判定需「库房灵材计数」，现无公开口子（见 §3 N1）；设计上**不臆测可行性**（避免出现「可晋阶」却材料不足的误导）。

### §2.4 块A「下一步」判定规则（文字描述，不写代码）

**按优先级逐条判，命中即止：**

1. 若 可进化灵兽数 ＞ 0（遍历 `beast_management_system.gd:4 var 灵兽库存` × `beast_management_system.gd:241 获取灵兽进化消耗()` 的 `["是否可进化"]`）⇒ 「苑中 N 只灵兽可进化，可往『灵兽库』」
2. 若 `获取灵兽统计()`（`beast_management_system.gd:75`）`["库存数"]` − `["出战数"]` ＞ 0 ⇒ 「苑中 N 只灵兽待出战，可往『出战绑定』」
3. 若 `灵兽兑换队列`（`beast_management_system.gd:5 var`）中 `启用 == false` 项 ＞ 0 ⇒ 「有 N 项引育计划停用，宜启用」
4. 若 `获取灵兽统计()` `["孵化中数"]` ＞ 0 ⇒ 「N 只灵兽孵化中，静候破壳」
5. 若 `繁殖中灵兽`（`game_state.gd:6357 var`）非空 ⇒ 「N 对灵兽繁殖中」
6. 否则 ⇒ 「苑中无事，可往『引育计划』补一条」

> 顺序理由：**「可进化 / 待出战」是玩家当场可完成的动作**（优先级最高）；「引育停用」次之（需一步启用）；「孵化 / 繁殖」是**等待型**，只作状态告知；兜底引导到引育。
