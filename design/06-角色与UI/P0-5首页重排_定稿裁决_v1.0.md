## 一、裁决结论（一句话）

**A「宗门中枢」为定稿骨架**：
`顶栏 → 时令横幅 → 匾额主视觉 → 气象带 → 传讯栏 → 运转快照(4 卡) → 常用(4 按钮, 拇指热区) → 快捷条 → 底部 5 Tab`

**B / C 的核心增量「司职产出双栏」砍掉**——因为它不是"更仿真"，而是**把殿阁 Tab 已有的内容搬上首页**（重复页），且 10 行双栏超出移动端密度上限。

### 判据 1 的纵深（为什么这条是决定性的）

老大上轮的纠偏是「宗主＝管理者，不该点收」——方向对。但 **B/C 走过了头**：把"不点收"理解成"把产出明细摊到首页"。而按 **X12 一义一名一页**，司职明细的**唯一页面就是殿阁 Tab**；首页再放=同一信息两处展示，玩家反而要判断"以哪个为准"。

**正确解法**：首页只给「**谁在管 + 缺几个**」的**概览数字 + 跳转**（A 的快照卡 2），细节进殿阁页。这既满足"管理视角"，又不破坏一义一名一页。

## 十、★ P0-5.3 场景归位（2026-09-13 · 老大反馈「背景图失去意义了？幻形也没意义了？」）

### 10.1 问题的定性：这是设计错误，不是调参问题

老大问得准。**我上一版（P0-5.2）把背景压死了**，直接后果是项目已有系统被架空：

| 被架空的东西 | 代码位置 | 后果 |
|---|---|---|
| 背景图 | `_build_base_and_bg()` → `bg.texture` | 84% 面积被墨罩盖住 |
| **幻形 · 洞天换肤（6 套皮肤）** | `sect_home_page.gd:143` `SKIN_BG`（云海/春/夏/秋/冬/仙）｜`_apply_equipped_skin()` 切 `Game.当前皮肤` | 6 套皮肤只在 137 逻辑像素的窗里、且被压到 74% 亮度 → **肉眼几乎分辨不出** |

### 10.2 根因（两条，全部可量化）

1. `获取背景压暗系数()` = `Color(0.74,0.76,0.82)` —— 全页压到 74~82%；
2. `建背景晕影渐变()` 在**全屏**叠 62%~95% 不透明深墨，只在 `0.60–0.76` 留一扇 **137 逻辑像素**（占屏 **16%**）的窗。

**但最关键的一条是「白压」的证据**：

> 面板底九宫格 `panel_bg` / `card_bg` / `card_row_bg` 的填充区 **alpha = 255（完全不透明）**
> —— 实测：`panel_bg` 中心 `rgba(28,41,47,255)`、`card_bg` 中心 `rgba(37,53,61,255)`。
> **面板读字根本不依赖背景压暗**。那 84% 的墨，换来的对比度一点没用上，纯粹牺牲了背景与皮肤。

### 10.3 行业做法（调研结论）

背景不是用来"压暗当底"的，**背景就是主角，UI 是画框**：

| 案例 | 做法（原文/实证） |
|---|---|
| **明日方舟** | 主界面两侧 UI **微妙倾斜**以突出看板角色；有「背景模糊 + 飞舞粒子 + 顶部渗透光效」；**「丰富的背景与 UI 皮肤满足了不同玩家的审美需求」**——皮肤是核心卖点 |
| **原神** | 简约幻想风，**中央留白**给场景/角色，四周图标；持续加入「快捷地图 / 可自定义快捷菜单」 |
| **和平精英 UI 2.0** | **「全景化动态背景」**——「通用背景动起来的时候会极大程度提高沉浸感，**仿佛每个界面都活起来了**」；按赛季切换动态背景 |
| **梦幻西游三维版** | **「保证最大化的展示场景和角色本身」** + 「**半开放式界面**」：功能信息用小界面承载，其它空间继续展示主界面 |
| **绝区零** | 毛玻璃 + 霓虹光效做 UI 层，背景场景透出 |

**共同点（这就是我们要抄的）**：中部留**全亮的主视觉窗**（占屏 40–60%），UI 收在边缘；面板靠**自身不透明**保证可读性，不靠压暗背景。

### 10.7 补修：快捷条底座「中心错位」（像素实测发现）

|---|---|---|---|
