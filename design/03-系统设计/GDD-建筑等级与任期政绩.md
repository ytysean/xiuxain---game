## 一、系统概述与目标（MDA 映射）

### 1.1 设计支柱（S1 批2 内）
- **P1 自主（Autonomy）**：玩家手动触发建筑升级、手动任命/撤换主事（续任保留手动，不自动到期）——「宗门经营决策权」交还玩家。
- **P2 胜任（Competence）**：升级有清晰成本/收益（每级产出 +2%），政绩里程碑给即时反馈（气运产出 buff + 纪事），形成「我把这座堂口经营好了」的正循环。
- **P3 关联（Relatedness）**：政绩挂在「你任命的主事」任期内，强化玩家与该弟子的「宗门共同体」情感锚点（呼应批1 §1.1）。

### 1.2 MDA 三层
| 层 | 本系统落点 |
|---|---|
| **Mechanics** | 建筑等级字段 + 升级消耗校验 + 产出乘区 + 政绩月度累积 + 里程碑奖励 + 特殊事件 + 持久化 |
| **Dynamics** | 玩家在「灵石投入哪座建筑升级」与「谁任主事攒政绩」间分配资源；高政绩主事形成「续任惯性」，撤换有心理成本 |
| **Aesthetics** | 体验目标 = *Submission（安稳推演的经营感）* + *Discovery（解锁层级）*；升级跳字/政绩里程碑提供 *Spectacle* 微高潮 |

### 1.3 玩家心理映射（自我决定论 + Bartle）
- **成就型（Achiever）**：冲建筑满级、刷主事政绩至里程碑/特殊事件。
- **社交型（Socializer）**：任命亲传/核心弟子掌核心堂口，看其政绩积累。
- **探索型（Explorer）**：解锁升级层级（L2 保底津贴 / L4 主事增效）与隐藏的政绩事件。
- **杀戮型（Killer）**：通过「撤换低政绩主事」行使管理权威（轻量出口，不触战斗）。
- **心流**：升级成本指数平滑（200→300→450…），每级稳定 +2% 产出，无死卡也无无聊必成；政绩每月可见增长。

### 1.4 与门派等级乘区的关系（一句话）
门派等级乘区（`1.0+0.02*max(0,门派等级-1)`，现役 L1494/L1529）是**宗门整体**产出因子；建筑等级乘区（`_建筑等级_乘区(key)`）是**单体建筑投资**因子。二者为**独立乘因子、同处一个乘积式**，互不替换、不重复相加、不冲突——见 §二.4。

## 二、建筑等级体系（机制）

### 2.1 字段与持久化（additive，仿 `堂口负责人存档` 范式）

现役 `堂口列表[key]` 已有 `"等级":1`、`"政绩":0`（L1682）。新增**独立持久化 dict**（不动现役 `堂口列表` 重建逻辑）：

```gdscript
# === S1 批2：堂口等级/政绩持久化（仿 堂口负责人存档 L204）===
var 堂口状态存档: Dictionary = {}   # {key: {"等级":int, "政绩":int, "里程碑":int, "高政绩事件":bool}}
```

- **写入**：升级成功 / 政绩累积后，`堂口状态存档[key] = {...}`（见 §二.2 / §三.1）。
- **存档（L2279 区，跟随 `堂口负责人` 同行）**：`"堂口状态": 堂口状态存档,`
- **读档（L2339 区）**：`堂口状态存档 = data.get("堂口状态", {})`
- **回填（在 `应用负责人存档()` L1733 之后新增 `应用堂口状态存档()`）**：
```gdscript
func 应用堂口状态存档():
    for key in 堂口状态存档.keys():
        if 堂口列表.has(key):
            var s: Dictionary = 堂口状态存档.get(key, {})
            堂口列表[key]["等级"] = int(s.get("等级", 1))
            堂口列表[key]["政绩"] = int(s.get("政绩", 0))
            # 里程碑/高政绩事件仅用于防重复发奖，运行时重建亦可，但持久化更稳（防重启刷奖励）
```

> **兼容性声明**：新档 `堂口状态存档` 为空 → `应用堂口状态存档` 跳过 → 所有建筑 `等级=1/政绩=0`（与现役一致）。旧档缺 `"堂口状态"` 键 → `data.get("堂口状态", {})` 默认空 → 零回归。

### 2.2 升级机制（`升级建筑(key)` 函数 · UI 调用）

```gdscript
# 返回 {ok:bool, msg:String}
func 升级建筑(key: String) -> Dictionary:
    if not 堂口列表.has(key):
        return {"ok": false, "msg": "建筑不存在"}
    var 等级: int = int(堂口列表[key].get("等级", 1))
    var 上限: int = _建筑等级上限()                      # §二.3：min(门派等级,7)
    if 等级 >= 上限:
        return {"ok": false, "msg": "已达等级上限（需更高宗门品级）"}
    if 门派等级 < 2:                                     # §二.3：凡阶不可升
        return {"ok": false, "msg": "需灵阶及以上宗门解锁建筑升级"}
    var 耗: int = _升级消耗_灵石(等级)                   # §四.1：ceil(200*1.5^(等级-1))
    if 灵石 < 耗:
        return {"ok": false, "msg": "灵石不足（需 %d）" % 耗}
    灵石 -= 耗
    堂口列表[key]["等级"] = 等级 + 1
    _存堂口状态(key)                                     # 写 堂口状态存档 + 回填
    宗门纪事.append({"日": 累计游戏日, "弟子": "", "稀有度": "宗门", "名称": "建筑升级",
        "文案": "【营建】%s 修缮至 Lv.%d，产出增益。" % [堂口列表[key]["名称"], 等级 + 1]})
    _加推演条目("【营建】%s 升至 Lv.%d。" % [堂口列表[key]["名称"], 等级 + 1], ET_SECT, PRIO_NORMAL, {"建筑": key})
    return {"ok": true, "msg": "%s 升至 Lv.%d（-%d灵石）" % [堂口列表[key]["名称"], 等级 + 1, 耗]}

func _存堂口状态(key: String):
    var s: Dictionary = 堂口状态存档.get(key, {})
    s["等级"] = int(堂口列表[key].get("等级", 1))
    s["政绩"] = int(堂口列表[key].get("政绩", 0))
    s["里程碑"] = int(s.get("里程碑", 0))
    s["高政绩事件"] = bool(s.get("高政绩事件", false))
    堂口状态存档[key] = s
```

> **升级时机**：手动（UI 按钮），**不进 `推演一月`**——即时扣灵石、即时生效（乘区在下次 `_资源建筑产出` 自然生效）。反馈靠纪事 + UI 跳字（§五.2）。

### 2.3 等级上限（门派品级 gate · 沿用 GDD-宗门经营 §一）

沿用 §一「建筑等级上限」列（凡1→道7），映射 `门派等级`（1~10，L1975）：

```gdscript
# 建筑等级上限 = min(门派等级, 7)；门派等级 8~10（§一未定义更高阶）封顶 7
func _建筑等级上限() -> int:
    return clamp(门派等级, 1, 7)
```

- **凡阶（门派等级=1）**：上限=1 → **不可升级**（升级按钮禁用 + 提示「需灵阶宗门解锁」）。
- **解锁节奏**：灵阶(2)→上限2、宝阶(3)→3、…、道阶(7)→7。早期（凡阶）锁定升级，防 trivial 战力/产出膨胀。
- **【决策点 D4/D5】** 默认沿用 §一（`min(门派等级,7)`、凡阶不可升）。备选：① 上限 `min(门派等级,10)` 放宽头；② 凡阶即允许 L1→L2（cap=`门派等级+1`）。推荐默认（尊重权威文档、防过早膨胀）。

### 2.4 产出乘区接入（🔴 本批工程核心点）

**(a) 创建函数**（清单公式；`.get` 默认 1 → 旧档/缺键零回归）：

```gdscript
# === S1 批2：建筑等级乘区（清单公式；清单误称"已落"，实际须创建）===
func _建筑等级_乘区(key: String) -> float:
    var 等级: int = int(堂口列表.get(key, {}).get("等级", 1))
    return 1.0 + 0.02 * max(0, 等级 - 1)     # 等级=1 → 1.0（零回归）；每级 +2%
```

**(b) 接入现役产出公式**（两处必须同步，否则 UI 预览与实际不符）：

- **实际产出** `game_state.gd` **L1495** —— 在 `产` 的乘式中追加 `* _建筑等级_乘区(key)`：
```gdscript
# 原 L1495：
var 产: int = int(n * base * (1.0 + 经营加成) * 气运乘 * (1.0 + 产出buff + 彩蛋产出加成()) * 等级乘区)
# 改为（仅在末尾乘入建筑等级乘区，与门派等级乘区并列独立因子）：
var 产: int = int(n * base * (1.0 + 经营加成) * 气运乘 * (1.0 + 产出buff + 彩蛋产出加成()) * 等级乘区 * _建筑等级_乘区(key))
```
- **UI 预览** `game_state.gd` **L1538** `预估建筑产出()` —— 同样末尾乘入 `* _建筑等级_乘区(key)`（保持预览==实际）。

**(c) 乘区作用域（明确判定）**：乘入 `产`（统一产出值），**作用于该建筑的全部产出**——
- 灵石（`灵石 += 产`，L1496）
- 灵草 / 灵气（`lingtian`：L1502/L1503，灵气=`ceil(产*0.5)`）
- 矿石（`kuangmai`：L1506）
- 丹堂/器堂记录（`_本月丹堂产出`/`_本月器堂产出`：L1507/L1508，供 `_建筑被动结算` 翻倍）

> **【决策点 D3 · 作用域判定】推荐：乘区作用于 `产`（全产出），非仅灵石。** 理由：升级一座灵田应同步提升其灵草/灵气（直觉一致），且为单乘点、改动最小；`_建筑被动结算` 的「当月产出翻倍」会自然翻倍已缩放值（一致、无需额外改）。若主理人要求「仅灵石、专属材料不变」，则改为只对 `灵石 += 产` 用缩放值、专属材料用未缩放值——默认不采用（割裂且不直觉）。

> **与门派等级乘区独立**：`等级乘区`（门派）与 `_建筑等级_乘区(key)`（单体）是两独立因子，同处乘积式，互不影响、不冲突、不重复相加。

### 2.5 升级解锁功能（S1 轻量 · 重玩法留 P2）

每级产出 +2%（乘区，核心）。S1 仅做 **1~2 个轻量解锁**（不碰战斗、复用现役管线）：

- **解锁①（Lv.2）· 保底津贴**（推荐，轻量结构性产出）：
  - 等级 ≥ 2 时，该建筑每月获得与成员无关的保底灵石：`保底 = 等级 * 基础津贴`，`基础津贴` 默认 **5** `[PLACEHOLDER]`。
  - 接入点：在 `_资源建筑产出()` 循环内、`match key` 之后，对 `等级>=2` 的建筑 `灵石 += int(等级 * 基础津贴)`（与成员产出叠加，写入预览 `预估建筑产出` 一致）。
- **解锁②（Lv.4）· 主事增效**（可选轻量，复用 `汇总负责人全局buff`）：
  - 等级 ≥ 4 且 该建筑有负责人时，其 global buff 贡献由 `+0.01` 升为 `+0.02`。
  - 接入点：`汇总负责人全局buff()` L1758 改为：`buff[维] += (0.02 if int(堂.get("等级",1)) >= 4 else 0.01)`（仅该 key，其他建筑不受影响）。
  - ⚠️ 此改动触达 P0 负责人 buff 管线，须随数值 GDD/CSV 校准；若工期紧可后置为 follow-up，不阻塞建筑等级主体。

> **【决策点 D7】** 默认两项都做（② 标 `轻量可选`）；若求最小落地面，可只做 ①（保底津贴），② 留 P2。

### 2.6 边缘情况（建筑等级）
- **EC-B1 旧档缺 `等级` 键**：`_建筑等级_乘区` 用 `.get("等级",1)` → 1.0，零回归。
- **EC-B2 堂口列表缺 key**（未来扩展）：`堂口列表.get(key,{}).get("等级",1)` → 不崩。
- **EC-B3 门派等级=1（凡阶）**：上限=1，升级按钮禁用 + 提示。
- **EC-B4 已达上限再点升级**：`等级>=上限` 拦截，返回失败 msg。
- **EC-B5 灵石不足**：`灵石<耗` 拦截，UI 禁用并显示缺口。

## 三、任期政绩（机制）

### 3.1 累积逻辑（`_累计任期政绩()` · 在 `推演一月` L841 之后调用）

```gdscript
# 在 推演一月 内、_资源建筑产出() 之后调用（L841 后）：
#   _累计任期政绩()
func _累计任期政绩():
    # 建筑政绩基数（每月固定月增，按建筑类型；[PLACEHOLDER] 待数值 GDD 校准）
    const 政绩基数: Dictionary = {   # 基础/功能/核心 三档
        "lingtian":1, "kuangmai":1, "yuying":1,          # 基础类 +1
        "cangjing":2, "dantang":2, "qitang":2, "zhifa":2, "gongxun":2, "tanwei":2,  # 功能类 +2
        "zhenfa":3, "yushou":3, "xichi":3, "wudao":3,    # 核心类 +3
    }
    for key in 堂口列表.keys():
        var 堂: Dictionary = 堂口列表[key]
        var 负责: Variant = 堂.get("负责人", null)
        if 负责 == null:
            continue                              # 无主事 → 不累积（任期空窗）
        var 月增: int = int(政绩基数.get(key, 1))
        # （可选）事件加成：当月若触发该建筑相关正向事件，月增 += 事件加成[PLACEHOLDER]
        堂["政绩"] = int(堂.get("政绩", 0)) + 月增
        _累计政绩奖励(key)                         # §三.2 里程碑/事件判定
        _存堂口状态(key)                           # 持久化
```

> **累积频率**：与 `_资源建筑产出` 同节奏——每次 `推演一月` 调用累加一次（=每月一次）。快进多月单次调用仅累一次（与现役产出行为一致，见 EC-P6）。
> **事件加成**：S1 先定「固定月增」，事件加成留 `[PLACEHOLDER]`（后续接事件系统再挂）。

### 3.2 影响维度（S1：展示 + 续任偏向 + 1 轻量奖励 + 1 轻量事件）

- **(1) 政绩展示**（必做）：建筑详情展示「主事名 · 政绩 N（任期 M 月）」；M = 自任命以来的月数（可在 `_设负责人` 时记 `任期起始日`，或用累计游戏日差推算）。
- **(2) 续任偏向**（保留手动，不自动到期）：
  - S1 **不引入自动任期到期**（维持 P0 手动任命 + 锁定机制，尊重自主/Autonomy）。
  - 「偏向」由**经济激励**实现：高政绩主事持续触发里程碑奖励（见下），撤换即失去后续里程碑潜力 → 玩家自然倾向续任。UI 在撤换高政绩主事时弹确认「该主事政绩卓著，确定更换？」。
- **(3) 轻量奖励 · 里程碑**：政绩每跨 **12** 点（`里程碑阈值` `[PLACEHOLDER]`），触发一次全宗 `设置气运buff(0.0, 0.01, 3)`（产出 +1%、持续 3 游戏日，复用现役气运管线）。可重复触发（每跨一档刷新一次）。
```gdscript
func _累计政绩奖励(key: String):
    var 政绩: int = int(堂口列表[key].get("政绩", 0))
    var s: Dictionary = 堂口状态存档.get(key, {})
    var 里程碑: int = int(s.get("里程碑", 0))
    var 阈值: int = 12                              # [PLACEHOLDER]
    while 政绩 >= (里程碑 + 1) * 阈值 and 里程碑 < 100:
        里程碑 += 1
        设置气运buff(0.0, 0.01, 3)                  # 产出+1% ×3日（复用 L774）
        _加推演条目("【政绩】%s 主事治业有成，全宗产出微增。" % 堂口列表[key]["名称"], ET_SECT, PRIO_TRIVIAL, {"建筑": key})
    s["里程碑"] = 里程碑
    # 高政绩特殊事件（一次性，防重启刷奖须持久化标记）
    if not bool(s.get("高政绩事件", false)) and 政绩 >= 36:   # 高阈值 [PLACEHOLDER]
        s["高政绩事件"] = true
        声望 += 50                                  # [PLACEHOLDER]
        宗门纪事.append({"日": 累计游戏日, "弟子": "", "稀有度": "宗门", "名称": "政绩卓著",
            "文案": "【政绩】%s 主事任期政绩卓著，宗门上下称颂（声望+%d）。" % [堂口列表[key]["名称"], 50]})
        _加推演条目("【政绩】%s 主事政绩卓著，誉满宗门！" % 堂口列表[key]["名称"], ET_SECT, PRIO_HIGH, {"建筑": key})

```
- **(4) 轻量事件 · 高政绩**：政绩首次达 **36**（`高政绩阈值` `[PLACEHOLDER]`）→ 纪事「政绩卓著」+ 一次性声望 +50（标记持久化，防重启重复领取）。

> **与战斗层零耦合**：里程碑奖励走 `设置气运buff(产出+, 0)`（仅产出），高政绩事件加声望（非战力）。本批不触 `get_final_combat_attr` / `BattleManager`，满足 MEMORY 战力映射铁律。

### 3.3 与负责人锁定机制复用点（汇总）

| 现役机制 | 任期政绩复用方式 |
|---|---|
| `任命负责人(key, d)` L1721 | **新主事上任 → 政绩清零、里程碑重置**（新任期）：在 L1727 `_设负责人` 之后加 `堂口列表[key]["政绩"]=0` + 重置 `堂口状态存档[key]` 的里程碑/高政绩事件标记 |
| `解除负责人锁定(key)` L1765 | **仅解锁、不换人** → 政绩**不重置**（主事仍在任） |
| `_设负责人(key, d)` L1716 | 政绩重置钩子挂此处（覆盖手动任命 + 自动顶替两条路径）；但 `应用负责人存档()` L1738 调用时**不重置**（那是读档，非新任期） |
| `汇总负责人全局buff()` L1743 | 本批**不改动**其 +1% 基线（L4 主事增效为可选叠加，见 §二.5） |
| `_加推演条目` / `宗门纪事` | 政绩里程碑 / 高政绩事件 / 升级 纪事直接复用 |

> **重置边界（关键）**：政绩清零**仅当主事实际变更**（新 disciple 接任）。`解除负责人锁定` 与 `应用负责人存档`（读档）**不触发清零**——否则重启/解锁即丢政绩。

### 3.4 边缘情况（任期政绩）
- **EC-P1 无主事建筑**：`负责==null` → 不累积（任期空窗）。
- **EC-P2 新任命替换主事**：旧主事政绩清零、里程碑/事件标记重置，新主事从 0 计。
- **EC-P3 解除锁定未换人**：政绩不重置（主事仍在任）。
- **EC-P4 读档加载**：从 `堂口状态存档` 还原政绩/里程碑/事件标记，不重置。
- **EC-P5 高政绩事件防刷**：`高政绩事件` 标记持久化，重启不重复发奖。
- **EC-P6 快进多月单次推演**：政绩/产出均按月单次累加（与现役 `_资源建筑产出` 同节奏），不重复不遗漏。

## 六、系统联动接口

### 6.1 门派等级（乘区独立 + 上限 gate）
- **乘区独立**：门派等级乘区（现役 L1494/L1529）与建筑等级乘区（`_建筑等级_乘区`）为乘积式内两个独立因子，互不替换/相加。
- **上限 gate**：建筑可升上限 = `min(门派等级,7)`（§二.3），凡阶锁定。门派等级提升→解锁更高建筑等级空间（不自动升级，需玩家手动投入灵石）。

### 6.2 批1 阶位轴（边界清晰）
- 负责人 = 主事，其**阶位**决定能否任该堂口（`堂口阶位门槛`，批1 §7.2）：阶位不足 → `任命负责人` 拒绝（L1725）。
- **边界**：主事**阶位不影响建筑产出/政绩**（阶位只卡任命资格 + 弟子自身战力加成，不进 `_资源建筑产出` 公式）。政绩是「任期」维度，与阶位正交。
- 撤换主事触发政绩清零（§三.3），与阶位罢免（批1 §4.6）是两条独立路径。

### 6.3 资源体系
- 升级消耗 = **灵石**（S1 独立资源 P2 才做，见 S1-S2 §一「独立资源」）。
- 产出仍走现役四资源（灵石/灵草/灵气/矿石），乘区作用域覆盖全部（§二.4c）。
- 政绩里程碑奖励走气运产出 buff（临时、全局），不新增资源账本。

### 6.4 负责人锁定（P0 复用）
- 政绩挂主事任期内（§三）；新任命清零、解除锁定不清零、读档不清零（§三.3/§三.4）。
- `汇总负责人全局buff` 本批不改基线；L4 主事增效为可选叠加（§二.5）。

## 八、验收标准（pre_f5 友好 · 可测判定点 + 伪代码）

```gdscript
func _建筑等级_乘区(key: String) -> float:

    return 1.0 + 0.02 * max(0, 等级 - 1)          # 等级=1 → 1.0

# 边界2：升级校验（灵石 / 上限 / 门派等级）
func 升级建筑(key: String) -> Dictionary:
    if not 堂口列表.has(key): return {"ok": false, "msg": "建筑不存在"}
    var 等级: int = int(堂口列表[key].get("等级", 1))
    if 等级 >= clamp(门派等级, 1, 7): return {"ok": false, "msg": "已达等级上限"}
    if 门派等级 < 2: return {"ok": false, "msg": "需灵阶及以上宗门解锁"}
    var 耗: int = int(ceil(200 * pow(1.5, 等级 - 1)))   # [PLACEHOLDER]
    if 灵石 < 耗: return {"ok": false, "msg": "灵石不足（需 %d）" % 耗}
    灵石 -= 耗; 堂口列表[key]["等级"] = 等级 + 1; _存堂口状态(key)
    return {"ok": true, "msg": "升级成功"}

# 边界3：政绩月度累积（仅在有主事时）
func _累计任期政绩():
    for key in 堂口列表.keys():
        if 堂口列表[key].get("负责人", null) == null: continue
        堂口列表[key]["政绩"] = int(堂口列表[key].get("政绩", 0)) + int(政绩基数.get(key, 1))
        _累计政绩奖励(key); _存堂口状态(key)

# 边界4：政绩清零仅在主事实际变更（挂 _设负责人，非 解除/读档）
#   在 _设负责人(key, d) 内（覆盖手动任命+自动顶替）：
#   堂口列表[key]["政绩"] = 0; 重置 堂口状态存档[key] 的 里程碑/高政绩事件
```
