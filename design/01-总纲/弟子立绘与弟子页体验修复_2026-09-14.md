## 二、「万仙大誓」与「山门气象」究竟是什么

两者都是**宗门级**系统，不是弟子个人功能 —— 这正是它们不该压在「弟子」名册首屏的理由。

### 万仙大誓 ＝ 全宗共誓（宗门级限时全局修炼 buff）

| 项 | 说明 |
|---|---|
| 状态字段 | `Game.万仙大誓` = `{名称, 剩余日, 期限, buff_cult}`（空字典＝当前无誓） |
| 配置来源 | `Game._读表_万仙大誓()` → 列 `name / duration_days / desc` |
| 玩法 | 宗主择一道誓 → `Game.发起万仙大誓(so_id)` → **期限内全宗弟子修炼倍率 ×`buff_cult`** |
| 决策性质 | 「以誓约换短期增益」的宗门级拍板，属**宗主定方向**一类，与弟子个人养成无关 |

### 山门气象 ＝ 宗门级望气（灵石买宗门气运）＋ 突破方针

| 项 | 说明 |
|---|---|
| 望宗门气运 | `Karma.宗门气象(弟子列表)` 给出全宗整体气运读数；需花 `Karma.望宗门价` 灵石，有效 `Karma.望气有效期` 游戏日（会话内缓存，过期需重设坛再望） |
| 突破方针（C3 宗主干预接口③） | 宗主定方向 → **整体平移弟子 AI 的冲关阈值**（不逐个操作） |
| 决策性质 | 同样是宗门级：一个是「花钱看全宗气数」，一个是「给全宗弟子定冲关基调」 |

### 为什么是「搬走」而不是「删掉」

宗门级内容已有的归口是**宗门气象抽屉**（UX §4.13）：入口＝**首页气象带** ＋ **首页快照卡「裁决」**。该抽屉本就承载写操作（传讯批复），分层上正好接得住（页面只读、交互层写），符合 S1 首页红线同构。

## 三、「弟子脸都一样」的根因：三个真 bug

> **结论先行**：脸一样与「旧存档」无关 —— 是**代码把 6 个弟子算成了同一张脸并写进档**，旧档只是把这批脏值一直带到现在。修完**旧档自动自愈**，无需删档重开、无需升 `SAVE_VERSION`。（实测老档脏值：`立绘类型 = {huo2: 6}`、`立绘变体 = {0: 6}` ⇒ 6/6 同一张脸。）

### Bug A —— `气质底模列表` 与 `气质列表` 错序（4/6 性格的脸对不上）

```gdscript
# 旧（错）：["chen","gu","wen","bao","jiao","huo2"]
# 新（对）：["chen","huo2","gu","bao","wen","jiao"]   ← 与 气质列表 严格同序
```

`气质列表` = 沉稳 / 活泼 / 孤傲 / 暴躁 / 温润 / 狡黠。旧表只有 **沉稳→chen、暴躁→bao** 两档碰巧对上，其余 4 档全错位（活泼→gu、孤傲→wen、温润→jiao、狡黠→huo2）⇒ 表现就是「弟子的脸对不上他的性格」。

**修**：重排为严格同序，并在源码处写明「本数组必须与 气质列表 严格同序（不可拆）」。
**实测**：12 性格 → 底模映射 **12/12 全对**（`_face_probe.log` §A）。

### Bug B —— `随机生成()` 把立绘三维算在掷骰之前

```gdscript
# 旧：块位置在 性格 之后，但 灵根(2576) / 年龄(2607) 都还没掷
立绘变体 = 获取灵根序()        # 灵根 尚未赋值 ⇒ 恒 5
年龄段   = 获取外观年龄段()    # 年龄 尚未赋值 ⇒ 恒「少年」
```

**修**：整块「立绘三维」挪到 `性格 / 灵根 / 年龄` 全部掷定之后。
**实测**：12 次随机生成，`立绘变体 == 灵根序` 与 `年龄段 == 按真实年龄` **12/12 全对**（`_face_probe.log` §B）。

### Bug C —— 旧档不回炉（脏值永久传播）

`from_dict()` 原本把 `立绘类型 / 立绘变体` **径直从存档读回**。**修**：二者改为**派生值** —— 读档即按 `性格 → 气质 → 底模` / `灵根 → 变体槽位` 重算：

```gdscript
立绘类型 = 获取立绘底模()   # 派生：性格→气质→底模
立绘变体 = 获取灵根序()     # 派生：灵根→变体槽位
```

⇒ **旧档自愈**；`to_dict()` 仍写这两项（无害，读档时被覆盖），故不必升 `SAVE_VERSION`、不必清档。
**实测**：灌入实测脏值（`huo2` / `0`）后过一遍 `from_dict(to_dict())`，5 名弟子底模从 1 种恢复为 **3 种**且各自正确（`_face_probe.log` §C）。

### 附：立绘三维口径（对齐美术《弟子批量生产规范》90 原型）

```
depth_{气质底模}_{性别}_{姿势}[_v{灵根序}][_年龄段][_资质档].jpg
```

| 维度 | 取值 | 来源 | 视觉表现 |
|---|---|---|---|
| **底模**（文件名第 2 段） | chen / huo2 / gu / bao / wen / jiao（6） | **气质**（由性格派生） | 五官与气质 → 「外观可读出性格」 |
| **变体槽位 `_v{n}`** | 0–4 五行，5＝变异/天灵根 | **灵根** | 服装主色 |
| **后缀** | `""` / `_elite` / `_top` | **资质** | 服饰档次 |

★ 分工铁则：**性格（12）＝ 内部玩法轴**（相冲／行为偏好／突破倾向）；**气质（6）＝ 对外视觉基准**。性格不入文件名，气质不参与玩法结算。

### 5.1 「信息出屏」的真实根因（探针实测定位，第一轮误判）

第一轮把责任都算给了右对齐的 `_power_summary`。**探针实测推翻了初判**：

```
详情页内容链（修复前）：
  DetailPage  VBoxContainer  size=(1207,3265)  min=(1207,3265)   ← 整页最小宽 1207
  PageScroll  ScrollContainer size=(1215,956)                    ← 被撑到 1215 > 屏宽 1080
  ContentArea Control         size=(1080,956)
```

逐层扫描 `detail_vb` 直系子的 minimum 宽度，锁定唯一元凶：

```
@PanelContainer@1779 = 1207   ← 「命格重铸」面板
   └ chongzhu_desc：「前往洗池·灵泉重铸命格/性格，改变弟子天赋与修行方向。」
     27 字 @ FONT_TITLE(45px) 且**未换行** ⇒ 单行最小宽 ≈1207
```

**机制**：`page_scroll` 虽已设 `SCROLL_MODE_DISABLED`，但 HBox/VBox 的**最小宽度和**仍会把内容撑开；`detail_vb` 是整个「详情」Tab 的父 VBox，它一宽，**同容器内所有右对齐元素（含「⚔战力」）都被推到 1207**。

**修**：`chongzhu_desc.autowrap_mode = AUTOWRAP_WORD_SMART` ⇒ 最小宽归零 ⇒ 整页最小宽 **1207 → 901**，战力右缘 **1207 → 1072**（屏内）。

> **顺带**：`_power_realm`（`境界 · 身份 · 资质 · 年龄`）与 `_power_summary` 也统一加了换行 + 降号，属「文字太大」的正面收益，且让整行**恒不溢出**（不依赖数据长度）。
