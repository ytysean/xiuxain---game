# 无缝大地图技术方案

> 项目：太玄宗门录（Godot 4.7 竖屏修真宗门游戏）
> 现状：`page_world_map_visual.gd` 纯Control架构，固定2000×2000，所有节点一次性创建
> 目标：支持超大/无限地图、分块加载、流畅拖动、与现有系统兼容

---

## 一、方案选型

### 三种路径对比

| 方案 | 架构 | 改动量 | 性能 | 无限地图 | 推荐度 |
|---|---|---|---|---|---|
| **A. Control分块加载** | 保持Control，Chunk动态创建/销毁 | 中 | 良 | 逻辑无限（足够大） | ★★★★★ |
| B. Node2D+TileMapLayer | 迁移到底层Node2D，SubViewport包裹 | 大 | 优 | 原生支持 | ★★★ |
| C. 混合架构 | 底层Node2D地形+上层Control UI | 很大 | 最优 | 原生支持 | ★★（长期） |

### 推荐：方案A（Control分块加载）

**理由：**
1. **零架构迁移** — 不改动现有Control体系，workbuddy可直接接入
2. **复用现有逻辑** — 地点标记、事件、行军、迷雾、资源采集全部保留
3. **性能可控** — 视口外节点销毁，内存恒定（约15-20个Chunk）
4. **风险最低** — 可灰度上线，先扩到8000²验证，再逐步放大
5. **手游足够** — 竖屏大地图视口约400×700px，不需要百万级节点

## 二、核心设计

### 2.1 坐标系与Chunk划分

```
逻辑地图：无限（或固定 100000×100000，对玩家感知=无限）
Chunk大小：500×500 逻辑单位
Chunk坐标：(cx, cy) = (floor(x/500), floor(y/500))
视口覆盖：约 2×3 = 6个Chunk（竖屏400×700px @ 0.5缩放）
加载范围：视口周围 1层缓冲 = 约 4×5 = 20个Chunk常驻
```

### 2.2 数据层（与渲染分离）

```gdscript
# world_map_data.gd（新建，纯数据，不依赖Control）
const CHUNK_SIZE := 500

# 地形数据：按chunk存储，key="cx,cy"
var _地形缓存: Dictionary = {}
# 地点数据：全局列表，按位置索引
var _地点列表: Array = []
# 资源点：按chunk存储

# 迷雾：按chunk存储已探索网格
var _迷雾缓存: Dictionary = {}

# 程序化生成地形（确定性噪声，同一坐标永远生成同样结果）
func 获取_chunk地形(cx: int, cy: int) -> Dictionary:
    var key := "%d,%d" % [cx, cy]
    if not _地形缓存.has(key):
        _地形缓存[key] = _生成地形(cx, cy)
    return _地形缓存[key]

func _生成地形(cx: int, cy: int) -> Dictionary:
    # 用FastNoiseLite生成地形类型（平原/森林/山脉/河流/沙漠/冰原）
    # 基于chunk坐标的噪声，确定性，无需存储全图
    pass
```

**关键：地形用噪声程序化生成，不预生成全图数据。** 同一坐标永远生成同样结果，玩家探索过的区域缓存，未探索的按需生成。

### 2.3 渲染层（Chunk动态加载）

```gdscript
# page_world_map_seamless.gd（新页面，替代visual版）
extends Control

const CHUNK_SIZE := 500
const 加载半径 := 1  # 视口外多加载1层chunk

var _当前chunks: Dictionary = {}  # key="cx,cy" -> Control节点
var _视口中心: Vector2 = Vector2.ZERO

func _process(_delta: float) -> void:
    _更新chunk加载()

func _更新chunk加载() -> void:
    # 计算视口覆盖的chunk范围
    var 视口矩形 := _获取视口逻辑矩形()
    var min_cx := int(floor(视口矩形.position.x / CHUNK_SIZE)) - 加载半径
    var max_cx := int(floor(视口矩形.end.x / CHUNK_SIZE)) + 加载半径
    var min_cy := int(floor(视口矩形.position.y / CHUNK_SIZE)) - 加载半径
    var max_cy := int(floor(视口矩形.end.y / CHUNK_SIZE)) + 加载半径
    
    # 加载新chunk
    for cx in range(min_cx, max_cx + 1):
        for cy in range(min_cy, max_cy + 1):
            var key := "%d,%d" % [cx, cy]
            if not _当前chunks.has(key):
                _当前chunks[key] = _创建chunk节点(cx, cy)
    
    # 卸载远处chunk
    var 待删除: Array = []
    for key in _当前chunks:
        var parts := key.split(",")
        var cx := int(parts[0]), cy := int(parts[1])
        if cx < min_cx or cx > max_cx or cy < min_cy or cy > max_cy:
            待删除.append(key)
    for key in 待删除:
        _当前chunks[key].queue_free()
        _当前chunks.erase(key)
```

### 2.4 Chunk节点内容

每个Chunk是一个Control，包含：
```
Chunk (Control, position=cx*500, cy*500, size=500x500)
├── 地形底色 (ColorRect, 500x500, 该chunk主地形色)
├── 地形装饰 (数个ColorRect/TextureRect, 森林/山脉/河流细节)
├── 地点标记 (TextureButton, 该chunk内的城镇/宗门/秘境)
├── 资源点标记 (TextureButton, 矿脉/灵草/钓点)
└── 迷雾覆盖 (数个ColorRect, 未探索区域)
```

**单Chunk节点数控制在10-20个**，20个Chunk常驻 = 200-400节点，远低于当前400迷雾+地形+地点的总量。

### 2.5 视口与拖动（复用现有逻辑）

现有拖动逻辑（_偏移/_缩放/_地图层.position）完全保留，只需：
- 地图层不再设固定custom_minimum_size（或设极大值）
- `_更新chunk加载()`在_process中根据_偏移/_缩放计算视口范围
- 地点标记的position改为逻辑坐标，由Chunk管理

## 三、地形生成方案

### 3.1 噪声地形（FastNoiseLite）

```gdscript
var _噪声: FastNoiseLite

func _初始化噪声() -> void:
    _噪声 = FastNoiseLite.new()
    _噪声.seed = 12345  # 固定种子，保证同一世界
    _噪声.frequency = 0.002
    _噪声.noise_type = FastNoiseLite.TYPE_PERLIN

func _获取地形类型(x: float, y: float) -> String:
    var 海拔 := _噪声.get_noise_2d(x, y)
    var 湿度 := _噪声.get_noise_2d(x + 10000, y + 10000)
    # 海拔+湿度决定地形
    if 海拔 > 0.5: return "山脉"
    if 海拔 < -0.3 and 湿度 > 0: return "河流"
    if 湿度 > 0.3: return "森林"
    if 湿度 < -0.3: return "沙漠"
    if 海拔 < -0.2: return "冰原"
    return "平原"
```

### 3.2 五大区域叠加

区域（中州/东域/西域/南疆/北域）用大尺度噪声决定：
```gdscript
func _获取区域(x: float, y: float) -> String:
    var 区域噪声 := _区域噪声.get_noise_2d(x * 0.0005, y * 0.0005)
    # 中心=中州，四方=四域
    var 距中心 := Vector2(x, y).distance_to(Vector2(50000, 50000))
    if 距中心 < 15000: return "中州"
    # 根据方位决定东/西/南/北
    ...
```

### 3.3 地形渲染（Chunk内）

每个Chunk内：
- 底色 = 该chunk主地形类型的颜色
- 用子噪声在chunk内生成细节（森林簇、山脉脊线、河流曲线）
- 细节用**矢量绘制**（draw_polyline/draw_rect）或小ColorRect，不用大图

**美术资源需求：** 可选——为6种地形各做一张**可平铺纹理**（256×256），替代纯色色块。纹理在Chunk内用TextureRect平铺。

## 四、迷雾系统改造

### 现状：400个ColorRect网格（2000/100 × 2000/100）

### 改造：按Chunk管理迷雾

```gdscript
# 每个Chunk内 5×5 = 25个迷雾格（500/100=5）
# 已探索的格子不创建节点，未探索的创建半透明黑色ColorRect
func _创建chunk迷雾(cx: int, cy: int) -> Control:
    var 迷雾层 := Control.new()
    for i in range(5):
        for j in range(5):
            var 网格x := cx * CHUNK_SIZE + i * 100
            var 网格y := cy * CHUNK_SIZE + j * 100
            if not _已探索(网格x, 网格y):
                var 格 := ColorRect.new()
                格.color = Color(0, 0, 0, 0.7)
                格.position = Vector2(i * 100, j * 100)
                格.size = Vector2(100, 100)
                迷雾层.add_child(格)
    return 迷雾层
```

**效果：** 已探索区域零节点，未探索区域按需创建。常驻迷雾节点从400降到约50-80。

## 五、地点与资源管理

### 5.1 地点生成

```gdscript
# 地点不随chunk销毁，全局存储，按chunk索引
var _地点按chunk: Dictionary = {}  # key="cx,cy" -> Array[地点数据]

func _生成地点(cx: int, cy: int) -> Array:
    # 用chunk坐标做种子，确定性生成地点
    # 每个chunk 0-3个地点（城镇/宗门/秘境/灵脉）
    var rng := RandomNumberGenerator.new()
    rng.seed = hash("地点_%d_%d" % [cx, cy])
    ...
```

### 5.2 资源点

资源点（矿脉/灵草/钓点/妖兽领）同样按chunk确定性生成，采集后标记冷却，不随chunk销毁丢失。

## 六、性能预算

| 指标 | 当前（2000²） | 无缝方案（常驻20Chunk） |
|---|---|---|
| 地图大小 | 2000×2000 | 逻辑无限 |
| 总节点数 | ~500（地形+400迷雾+地点） | ~300（20Chunk×15） |
| 内存 | 随地图线性增长 | 恒定 |
| 拖动帧率 | 大地图时下降 | 恒定 |
| 加载时间 | 一次性创建500节点 | 滚动时增量创建 |

**目标：** 中端手机稳定60fps，拖动无卡顿。

## 七、迁移路径（分3期，可灰度）

### P0：数据层抽离（1-2天）
- 新建`world_map_data.gd`，把地形/地点/资源/迷雾数据从`page_world_map_visual.gd`抽离
- 现有页面改为从data层读取，渲染逻辑不变
- **验证：** 现有功能完全正常，无视觉变化

### P1：Chunk渲染（2-3天）
- 新建`page_world_map_seamless.gd`，实现分块加载
- 地形用噪声生成，迷雾按chunk管理
- 地点/资源标记改为按chunk创建
- **验证：** 地图扩大到8000²，拖动流畅，功能正常

### P2：无限化+优化（1-2天）
- 移除地图尺寸上限，逻辑坐标无限
- 加Chunk节点对象池（避免频繁创建/销毁）
- 地形纹理可选替换
- **验证：** 向任意方向滚动无限远，内存恒定

## 十、风险与对策

| 风险 | 对策 |
|---|---|
| Chunk频繁创建/销毁导致卡顿 | 对象池复用，加载半径设1层缓冲 |
| 噪声地形不够"好看" | P2加地形纹理+细节装饰，先色块验证玩法 |
| 地点/资源在chunk边界重复 | 用chunk坐标做种子，边界地点归属明确 |
| 与workbuddy的UI优化冲突 | P0先抽离数据层，渲染层不动；P1新建页面并行开发 |
| 存档兼容 | 坐标体系不变（仍是Vector2），只是范围扩大 |
