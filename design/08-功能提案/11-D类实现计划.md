# D 类三功能落地实现计划

> **背景**：S1-P0 阶段三（F2 全局调节阀门 + 第11闸产耗±15%红线）已落地，主理人独立复跑 `pre_f5_check.py` 验证 `EXIT 0 / 25 闸全绿、零战斗触碰 PASS`。F2 实装 = `economy_balance.gd`（class_name `EconomyBalance`，extends `RefCounted`，纯计算外挂中间层，运行时±15%强制钳制）+ `config/经济阀门.csv`（表头 `阀门,系数,开关,说明`；三旋钮 `global_cost_rate`/`trade_profit_rate`/`event_damage_rate`，默认 1.0）+ `period_settlement.gd` 结算最终输出节点单次调用 `EconomyBalance.平衡()`。D 类三功能（运维成本/坊市行情/负面影响经济侧）的准入前提已满足（ECON-02 §三：三项均「直接进 S1」）。
>
> **本稿定位**：在 F2 已验证的前提下，输出 D 类三功能的**落地实现蓝图**（交付优先级、三位一体清单、叠加冲击测算、开关降级、测试用例、4 项非阻断待办清理、风险缓解）。遵循三位一体（配置表 + 运行时消费者 + pre_f5 闸门）。

## 0. 前置结论

1. **F2 已验证、D 类准入前提满足**：`pre_f5` 第11闸 `EXIT 0`、零战斗触碰 PASS；ECON-02 已给三项「直接进 S1」准入结论（运维成本=强制补闭环、坊市=低风险、负面影响=卡阈值）。
2. **本计划为落地蓝图**：明确「先出计划 → 清 4 项非阻断待办 → 再正式开发」的节奏，本稿不落实际代码/配置。
3. **三位一体对齐**：每项均交付 ① 配置表（CSV schema）② 运行时消费者（接入节点 + 伪代码，锚定 `game_state.gd`/`period_settlement.gd` 真实函数）③ pre_f5 校验（第11闸 A/B/C/D 层落点）。

## 1. 交付优先级与落地顺序

| 批次 | 功能 | 优先级 | 价值 | 风险 | 理由 |
|---|---|---|---|---|---|
| **批次一** | 宗门运维成本（D1） | 最高 | 补 ECON-01 **F1 缺口**（刚性消耗全 STUB）+ 对冲 **F6**（弟子津贴 N×2 无对冲），使 总产/总耗 比值从 ≈∞ 收敛到 1.20，建立零通胀闭环。是 ECON-02 唯一能补消耗闭环的功能。 | 中（数值已锚定，风险可控） | 最刚需：不进则零通胀永远不成立；同 PR 须补 **F3 经营加成 clamp**（见 §6.2）以抵消闭环被无封顶放大。 |
| **批次二** | 坊市动态行情（D2） | 次高 | 纯体验优化（价格浮动 + 限购反抑通胀），**不触碰自动 366 基底**（ECON-02 §2.1：±10% 系数 < ±15% 红线，对闭环中性）。 | 低（±10% 天然在红线内） | 风险最低、无闭环依赖；可独立上线。 |
| **批次三** | 负面影响经济侧（D3） | 第三 | 配合评级体系、卡阈值、吃冗余防囤积；总灵石冲击 ≤62（17%×366）。 | 中（须卡阈值，否则 −35% 单档会破产） | 须先有 **D1 闭环**作缓冲基座，再叠加动态消耗阀门；配合 `负面影响开关.csv` + `负面影响经济参数.csv` + 激活 `negative_event.csv`。 |

**顺序说明**：价值维度——D1 是闭环钥匙（无它则零通胀不成立）；D2 是纯体验增益、零闭环风险；D3 是动态阀门，须建在 D1 闭环缓冲之上才安全。风险维度——D2（±10%<±15%）天然合规最低；D1 数值已由 ECON-02 §2.2 锁死 [293,318]；D3 须严格卡 Σ≤62 防破产。故顺序为 **D1 → D2 → D3**，且 **F3 clamp 与 D1 同 PR**（ECON-02 §五强约束）。

## 2. 每功能「三位一体」标准化交付清单

> 通用注：所有「运行时消费者」伪代码均基于**实际 F2 方案B API**（`period_settlement.gd` 结算() L128-129 单次调用 `EconomyBalance.平衡(灵石增量)`；`平衡()` 内部按 `raw>=0` 走产出侧公式、`<0` 走消耗侧公式，并对单周期振幅 >±15% 拉回 `raw`）。GDD §1.5/2.5/3.5 的 `取系数(...)` 写法已废弃，落地时改写（见 §7-R1）。

### 2.1 宗门运维成本（D1 · 补刚性耗 C4-C7 STUB 缺口）

#### 2.1.1 配置表结构：`宗门运维成本.csv`
> 仅呈 schema，不落实际文件。主键 `耗项ID`，单价与倍率来源引用 GDD §1.3 / ECON-02 §六。

| 列 | 类型 | 取值/范围 | 默认 | 说明 |
|---|---|---|---|---|
| 耗项ID | string(PK) | {C4,C5,C6,C7} | — | 刚性耗四项标识 |
| 名称 | string | 弟子俸禄/建筑维护/修炼耗材/制式装备摊销 | — | 展示用 |
| 基数类型 | enum | {N, B} | — | N=弟子数；B=建筑数 |
| 单价 | float | >0，锚定值 {4.5, 3.0, 0.73, 0.375} | 见 ECON-02 §六 | C4=4.5 / C5=3.0 / C6=0.73 / C7=0.375 |
| 倍率键 | string | 空 / `身份倍率` | 空 | C4 按 Σ(身份倍率) 计倍；其余=1.0 |
| 标准局值 | float | 参考 {216,36,35,18} | — | 标准局(L4/N48/B12)校准值，审计用 |
| 备注 | string | 自由文本 | — | 公式说明 |

> **聚合 clamp**：四项合计须锁 `clamp(合计, 293.0, 318.0)`（ECON-01 刚性耗区间）。clamp 边界来源待确认：当前 GDD 伪代码硬编码 293/318；建议改为读取 `config/经济基线.csv` 的 `标准局月耗_下限`/`标准局月耗_上限`（见 §7-R5）。

#### 2.1.2 运行时消费者
- **接入节点**：`game_state.gd` 新增 `func _结算运维成本_S1() -> void`。插入位置 = `推演一月` 月循环 S1 区，紧接 `_结算俸禄_S1()`（**L1051**）之后、`_可能触发特殊登门_S1()`（L1052）之前（GDD §1.5「紧接 _结算俸禄_S1 之后」；已确认该桩在 `推演一月` 内被调用，见 §7-R4 核实）。
- **调用链路**：
  `推演一月`（L942）→ `_结算运维成本_S1()`（新增，L1051 后）→ `灵石 -= int(round(刚性耗))` → 影响全局 `灵石` → 期末 `结算()`（L1069）读 `灵石增量 = 灵石 - 年始灵石`（L1071）→ `周期评分.结算(门派等级, 快照)`（L1069）→ `period_settlement.结算()` → F2 `平衡(灵石增量)`（L128-129）→ 写回 `卡["明细"]["灵石增量"]`。
- **核心逻辑（伪代码）**：
```gdscript
# —— 新增 _结算运维成本_S1()（插入 推演一月 S1 区，紧接 _结算俸禄_S1() L1051 之后）——
func _结算运维成本_S1() -> void:
    var c4 = 0.0
    for d in 弟子列表:
        c4 += 4.5 * _身份俸禄倍率(d.身份)        # 普通1.0/执事1.5/长老2.0（倍率来自 宗门运维成本.csv 倍率键）
    var c5 = 3.0 * 建筑列表.size()
    var c6 = 0.73 * 弟子列表.size()
    var c7 = 0.375 * 弟子列表.size()
    var 刚性耗 = c4 + c5 + c6 + c7                 # 标准局 ≈ 216+36+35+18 = 305
    # F2 接线（方案B·实际 API）：global_cost_rate 由 period_settlement 结算最终节点 平衡() 统一施加；
    #   本消费者只产出「原始刚性耗」，不直接调 取系数()（该 API 方案B 已废弃，见 §7-R1）。
    # 守恒 clamp（边界来源待确认：硬编码 293/318 或读 经济基线.csv，见 §7-R5）：
    刚性耗 = clamp(刚性耗, 293.0, 318.0)
    灵石 -= int(round(刚性耗))                     # 进入 灵石增量，期末经 平衡() 走 F2
    # 欠俸/忠诚链路（F6 对冲）：刚性耗 实付 < 应发阈值 → 忠诚↓（引用 GDD-宗门经营 §五.1）
```

#### 2.1.3 F2 对接
- **对应系数**：`global_cost_rate`（即 `economy_balance.gd` 的 `全局消耗系数`/`运维系数`，二者同源）。
- **钳制阈值**：±15%（`economy_balance.gd` 常量 `红线=0.15`；`_取系数` 越界 `push_error` 并 clamp 到 [0.85,1.15]）。
- **开关名**：`config/经济阀门.csv` 的 `global_cost_rate` 行，**当前 `开关=1`（已开）**。D1 落地即生效，无需改开关，仅需实现真实消费者（当前 `_结算运维成本_S1` 尚未存在）。
- **注**：实际接线是 `period_settlement.gd` L128-129 的唯一 `平衡()` 调用；`global_cost_rate` 在该点按 `raw` 符号施加（见 §7-R2 语义 gap）。

#### 2.1.4 pre_f5 校验规则（第11闸落点）
- **Layer B（比值红线 + 特征卡位）**：`config/经济基线.csv` 已含 `标准局月耗_目标=305`/`下限=293`/`上限=318`；当 `F2_阀门_接线==1 且 F3_经营加成_封顶==0.30` 时，Layer B 比值红线升级为硬阻断，断言 `366 / 月耗 ∈ [1.15, 1.25]`（ECON-01 §4.2 / §4.6）。
- **Layer A（系数±15%）**：`宗门运维成本.csv` 单价与 ECON-02 §六锚定一致，偏差 >±15% 即 FAIL。
- **Layer C（F2 接线守）**：断言 `global_cost_rate` 由 `economy_balance.gd` 经 `config/经济阀门.csv` 读取（硬编码字面量 → FAIL）。
- **配置合法性**：断言 `宗门运维成本.csv` 主键唯一、`单价>0`、合计 clamp 区间 [293,318] 被代码执行（静态扫描 `clamp(..., 293.0, 318.0)` 或读配置）。

#### 2.1.5 数值基线与边界
- **基准（标准局 L4/N48/B12/BL2/经营+10%）**：C4=216 / C5=36 / C6=35 / C7=18；**合计=305** ✓。
- **常规波动**：刚性耗随 N/B/身份倍率缩放，落入 [293,318]；比值 366/305≈1.20 ∈ [1.15,1.25]。
- **极端上限**：刚性耗极端 = 318（比值 366/318≈1.151，贴 1.15 下沿）；>318 → 盈余<15% 告警；≥366 → 负盈余破产（clamp 拦截）。
- **身份倍率**：普通 1.0 / 执事 1.5 / 长老 2.0（GDD §1.3）。

### 2.2 坊市动态行情（D2 · ±10% 浮动 + 限购 + 事件联动）

#### 2.2.1 配置表结构：`坊市行情.csv`
> 仅呈 schema，不落实际文件。主键 `类别`（与 `game_state.gd` `_坊市商品类别()` 输出 {丹药/装备/功法/资源} 对齐）。

| 列 | 类型 | 取值/范围 | 默认 | 说明 |
|---|---|---|---|---|
| 类别 | string(PK) | {丹药,装备,功法,资源} | — | 商品类别（与 `_坊市商品类别()` 对齐） |
| 浮动下限 | float | ≥0.85（红线±15%下限） | 0.90 | 行情价格乘数下限（−10%） |
| 浮动上限 | float | ≤1.15（红线±15%上限） | 1.10 | 行情价格乘数上限（+10%） |
| 限购数量 | int | >0（防无限刷取通胀） | 按类别（建议 5~10） | 每类别每月限购；粒度待确认（类别级 vs 商品级，见 §7-R7） |
| 事件联动标记 | int{0,1} | 0 | 0 | 0=仅调价不发证灵石（守 <5% 事件渠道）；1=开启联动（须回算守 <5%） |
| 备注 | string | 自由文本 | — | — |

#### 2.2.2 运行时消费者
- **接入节点**：`game_state.gd` `坊市实价(原价)`（**L382**，返回折后价）→ 叠加行情浮动；`购买坊市物品(shop_id)`（**L397**，扣费 L422 `灵石 -= 折后`）→ 叠加限购校验。
- **调用链路**：玩家点击购买 → `购买坊市物品(shop_id)`（L397）→ `坊市实价(原价)`（L382，叠加声望折扣 × 行情浮动）→ 校验 `limit_daily/weekly`（L411-419，现有）+ 新增类别限购 → `灵石 -= 折后`（L422）。
- **核心逻辑（伪代码）**：
```gdscript
# —— 懒加载 坊市行情.csv（类别 → {浮动下限,浮动上限,限购数量,事件联动标记}）——
# —— 改写 坊市实价：原价 × 声望折扣 × 行情浮动系数 ——
func 坊市实价(原价: int, 类别: String) -> int:
    var 价 = ceil(原价 * 坊市折扣率())                 # 现有声望折扣
    var 行 = 坊市行情表.get(类别, null)
    var 下限 = 行["浮动下限"] if 行 else 0.90
    var 上限 = 行["浮动上限"] if 行 else 1.10
    var 浮动 = randf_range(下限, 上限)                 # 月度/每次摆动 ±10%
    价 = int(round(价 * 浮动))
    return 价

# —— 限购（购买时，类别级；与 xuanyu_shop.csv 的 limit_daily/weekly 关系待确认去重，见 §7-R7）——
func _坊市购买_类别限购(类别: String, 数量: int) -> bool:
    var 限额 = int(坊市行情表.get(类别, {}).get("限购数量", 0))
    if 限额 <= 0: return false                         # pre_f5 断言 限购数量>0，防 0/空无限刷取
    return (本月已购类别[类别] + 数量) <= 限额
```
- **F2 接线说明**：坊市 ±10% 浮动为**本地机制**（在 `坊市实价` 内），**不触宗门 `灵石增量` 基底**（坊市是玩家支出 `灵石 -= 折后`，宗门坊市收入未计入宗门 `灵石`，ECON-02 §2.1 确认中性）；F2 `trade_profit_rate` 旋钮经 `period_settlement` 唯一 `平衡()` 调用施加于**最终净盈余**（见 §7-R3 语义说明）。

#### 2.2.3 F2 对接
- **对应系数**：`trade_profit_rate`（即 `economy_balance.gd` 的 `坊市系数`）。
- **钳制阈值**：±15%（同 F2 全局红线）。
- **开关名**：`config/经济阀门.csv` 的 `trade_profit_rate` 行，**当前 `开关=0`（关）**；D2 接入时置 `1`。
- **注**：实际接线为 `period_settlement.gd` L128-129 唯一 `平衡()`；开启 `trade_profit_rate` 后，`平衡()` 在 `raw>=0`（净盈余）时乘 `坊市系数`（ECON-02 强约束：坊市须接线 `trade_profit_rate`）。本地 ±10% 浮动独立于该旋钮。

#### 2.2.4 pre_f5 校验规则（第11闸落点）
- **Layer A（系数±15%）**：断言 `坊市行情.csv` 每行 `浮动下限 ≥ 0.85 且 浮动上限 ≤ 1.15`（即 ≤±15% 红线）；超限 FAIL（ECON-01 Layer A）。
- **Layer A（配置合法性）**：断言 `限购数量 > 0`（防 0/空导致无限刷取 → 通胀 broken）。
- **Layer C（F2 接线守）**：断言 `trade_profit_rate` 由 `economy_balance.gd` 经 `config/经济阀门.csv` 读取（硬编码 → FAIL）。
- **Layer D（事件渠道<5%）**：断言 `事件联动标记` 默认 0（仅调价不发证灵石）；若置 1，须回算守 <5% 事件渠道，否则 broken 回退（§4.7）。
- **不进 Layer B 比值红线**：坊市不触宗门 `灵石增量` 基底，对闭环中性，不参与 366/月耗 比值计算。

#### 2.2.5 数值基线与边界
- **基准**：价格浮动系数带 `[0.90, 1.10]`（±10%），由 `_校准浮` 区间读取（非硬编码）。
- **常规波动**：±10% 系数 < ±15% 红线（ECON-01 Layer A），对闭环零影响。

```gdscript
# Σ(灵石冲击) ≤ 62 硬卡；超则截断最弱档 / 降强度，绝不转负盈余
```

## 3. 三功能叠加冲击测算

> 方法：D 类三项均经 `period_settlement.gd` L128-129 唯一 `平衡(灵石增量)` 出口；`平衡()` 内置熔断保证 `|final − raw| / |raw| ≤ 15%`（raw = 进入阀门前的净 `灵石增量`）。以下给原始净盘推导 + 阀门钳制后结果。

**基准**：标准局自动总产 P=366；运维刚性耗 R（常规 305 / 极端 318）；坊市不触宗门净盘（玩家支出，中性）；负面影响总灵石冲击封顶 62。

### 3.1 常规档叠加（运维 305 + 坊市中性 + 负面常规 −10%）
- 产出 = 366 × 0.90 = **329.4**（负面 −10%）
- 消耗 = **305**（运维常规）
- 进入 `平衡()` 的 raw 净 = 329.4 − 305 = **+24.4**
- `平衡()`：raw≥0 → ×全局产出系数(1.0) ×[坊市开关]×[负面开关]（默认全 1.0）→ **24.4**；熔断 `|24.4−24.4|/24.4 = 0%` → final = 24.4
- **盈余率** = 24.4 / 305 = **8.0%**（吃缓冲，不破产，与 ECON-02 §2.4 常规 −10% 盈余 8.0% 一致 ✓）
- **阀门诱发波动** = **0%**（系数全 1.0）≤ ±15% ✓

### 3.2 极端档叠加（运维 318 + 坊市中性 + 负面极端 −17% 且 Σ≤62 截断 + 额外消耗 30）
- 负面总冲击封顶 **62** = 产出削减 min(366×0.17, 62) ≈ 62（62.22 微超，见 §7-R8 处理）；额外消耗 30 已被 62 预算占用 → 管理器截断至 0（不叠加）。
- 产出 = 366 − 62 = **304**
- 消耗 = **318**（运维极端）
- 进入 `平衡()` 的 raw 净 = 304 − 318 = **−14**
- `平衡()`：raw<0 → ×全局消耗系数(1.0) ×[负面开关](1.0) → **−14**；熔断 0% → final = −14
- **盈余率** = −14 / 318 = **−4.4%**（轻微赤字，远优于 ECON-02 原 −35% 档的 −29% broken，已被锁死在近零）
- **最坏阀门情景**：若运营把 `负面系数` 调至上限 1.15 → final = −14 × 1.15 = −16.1，振幅 = 0.15（≤阈值，通过）；若 1.16 → 振幅 0.16 > 0.15 → `平衡()` 拉回 −14（熔断）。故 **final ∈ [−16.1, −14]**，**阀门诱发波动 ≤ ±15% ✓**

### 3.3 结论（满足 ECON-02 红线）
1. **比值红线**：运维锁 [293,318] → 比值 ∈ [366/318, 366/293] = **[1.151, 1.249]** ⊂ [1.15,1.25] ✓（极端运维 318→1.151；常规 305→1.20）。
2. **输出 ±15% 红线**：`平衡()` 熔断保证任意进入净盘的阀门诱发波动 ≤±15%；坊市 ±10%<15%、负面单档 −17%<15%、运维 lock 属比值红线（已证）。故**总盘波动 ≤ ±15%** ✓。
3. **事件渠道 <5%**：坊市事件联动标记=0（零灵石源）；负面影响非事件渠道（§4.7 守联动）✓。
4. **负面 Σ≤62**：常规 −10% 仅吃缓冲；极端 −17% + 截断使总冲击 ≤62，不转负盈余 ✓。
> **结论**：三功能任意常规/极端叠加，经 F2 钳制后总波动 ≤±15%、比值 ∈[1.15,1.25]、事件渠道 <5%、负面总冲击 ≤62，**满足 ECON-02 红线，红线不被击穿**。

- **阈值来源**：`ECON-01 §4.1`（单建筑产出效率 ≤+20%、全建筑 ≤+30%）。落地后把 `config/经济基线.csv` 的 `F3_经营加成_封顶` 由 `0` 置 `0.30` → 第11闸 C 层 F3 检查自动转为**硬阻断**，与 D1 形成双闸闭环。

### 6.4 pre_f5 挂 pre-commit / CI
- **目标**：从手动运行改为自动触发（impl 文档 §九.4）。
- **Git 钩本（.git/hooks/pre-commit）**：
  ```sh
  #!/bin/sh
  # pre-commit：跑 pre_f5 全闸，EXIT≠0 阻断提交
  python pre_f5_check.py
  if [ $? -ne 0 ]; then
    echo "❌ pre_f5_check 未通过（25 闸未全绿），提交被阻断。先修复红线问题。"

  fi
  exit 0
  ```
  （`chmod +x .git/hooks/pre-commit` 启用；注意 `.git` 不随仓库分发，团队需文档化或借 husky/lefthook 管理。）
- **CI 步骤（通用 YAML 示意，如 GitHub Actions）**：

  ```yaml
    # 退出码非 0 → CI 失败，阻断合并
  ```
- **说明**：`pre_f5_check.py` 已 `EXIT 0/1`，第11闸为其中一道 subprocess 闸；挂上即对所有提交/PR 自动守门，D 类每步接入后自动复跑校验。

## 7. 风险与缓解

| # | 风险 | 等级 | 缓解 |
|---|---|---|---|
| R1 | **F2 实际 API 与 GDD 伪代码不一致**：`economy_balance.gd` 仅暴露 `平衡(原始值)`/`系数合规()`，**无 public `取系数` getter**；GDD §1.5/2.5/3.5 逐消费者 `EconomyBalance.取系数(...)` 写法在方案B 已废弃。 | 高（落地必踩） | 本计划已按实际 API 改写消费者伪代码；落地时 engineering-lead 须以 `period_settlement.gd` L128-129 唯一 `平衡()` 为接线点；同步修订 GDD §1.5/2.5/3.5 伪代码，避免实现照抄废弃写法。 |
| R2 | **`global_cost_rate` 仅对净赤字生效**：标准局净 `灵石增量` = 366−305 = +61（>0），`平衡()` 走产出侧公式（×全局产出系数），**不乘 `global_cost_rate`（全局消耗系数/运维系数）**。故 GDD §1.3「刚性耗_实付 = 刚性耗_计算 × global_cost_rate」在净盈余局不生效。 | 中 | **待主理人/工程拍板**二选一：(i) 接受全局阀门语义——`global_cost_rate` 仅在宗门赤字时缩放消耗，运维刚性耗仍照扣（闭环成立），运维"接线"=启用该旋钮作赤字杠杆；(ii) 改 per-delta 接线——运维消费者对其原始 `−刚性耗` 单独调 `平衡()`（raw<0 → 消耗侧公式乘 global_cost_rate），使 GDD §1.3 字面成立。两者均安全，选(i)保持"单次调用"不变式。 |

| R4 | **`_结算*_S1` 桩调用链确认**：已确认 `_结算俸禄_S1`(L1051)/`_结算香火_S1`(L1053)/`_结算大阵耐久_S1`(L1056) 在 `推演一月` S1 区被调用（L1051-1056），且位于 `结算()`(L1069) 之前。 | 低（已核实） | `_结算运维成本_S1()` 插入 L1051 之后即可；确认 `年始灵石`(L220/L1071/L1084) 基准在结算前已设，运维扣费正确计入 `灵石增量`。 |
