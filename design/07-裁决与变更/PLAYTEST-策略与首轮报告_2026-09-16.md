# 《太玄宗门录》Playtest 策略与首轮报告

> 一句话结论：**自动化验收很扎实（6 门 + 64 页真实渲染 + 死键扫描），但它测的是"程序没坏"；本项目从未测过"新玩家愿不愿意玩"。本次以"新玩家第一次玩 30 分钟"的视角跑通路径，抓出 1 个 P0 阻断项（新手引导在新 UI 下原理性不可达）与 3 个 P1。**

- 判定：**CONCERNS**（可继续打磨；但 P0 阻断"新玩家能玩"这一验证前提，须先处置再进真人轮）
- Bug 分级：**P0 ×1 ｜ P1 ×3 ｜ P2 ×3**
- 质量门现状（实测 2026-09-16）：`gate_all.py` 门0–门5 **全绿 RC=0**；但门3 对"并行编辑"敏感，会短时假 FAIL（见 P2-1，实测 378→377）。

## 一、Playtest 策略（3 轮）

| 轮次 | 目标 | 自动化承担 | 必须真人 | 判据（退出线） |
|---|---|---|---|---|
| **R1 自动冒烟（已具备，常态跑）** | 防"程序坏了"回归 | ① `gate_all.py` 6 门；② `run_headless_chain.py`（import/compile/main_enter/ui_compile/ui_decouple/smoke 100 月推演）；③ `tests/ui_full_accept.tscn` 64 页真实渲染；④ `tests/_t_deadkey.gd` 死键扫描；⑤ `tests/_probe_perf` | 无 | ①②③ 全绿；③ `ISSUES n=0 / ACCEPT_ALL_DONE`；④ DEAD 收敛 ≤45 且无新增候选；⑤ 不劣于基线（FPS 70–80 / DrawCall 141 / texmem 77.4MB / 启动 2650ms）。**连续 2 次无 flaky** 才算过。 |
| **R2 真人首 30 分钟（本次建立）** | 验证"新玩家能不懵地跑通核心循环" | 仅帮跑 R1 与录屏/计时；引导可达性由 R1 静态取证 | ✅ 必须真人 | 见 §1.1 脚本"五个该出现时刻"全部出现；无 P0；P1 有处置计划。 |
| **R3 真人中期系统试玩（60–90min，老手视角）** | 验证"中盘系统值得玩" | 数值/经济/战斗断言供对照 | ✅ 必须真人 | 8 大系统"入口可达 / 有正反馈 / 无死循环 / 无死资源"逐项签收；P1 清零。 |

> 为何必须分轮：R1 能保证"不崩、不缺页"，**原理上查不出"引导是否讲清、数值是否好玩、AI 行为是否可感知"**——这正是本次 P0 能在 6 门全绿下长期存活的原因（见 §三）。

### 1.1 ★ 真人 30 分钟试玩脚本（新开档，单人，录屏 + 秒表）

**准备**：删 `user://save.json`（或标题屏「开新宗门」）；录屏；记录表：观察项 / 是·否 / 时间戳 / 截图。

| 时段 | 该看到什么 | 该被引导去做什么 | 该出现的正反馈 |
|---|---|---|---|
| **T0–2′ 首屏** | 标题屏：`太玄宗门录` + 副标 `开局接手太玄宗` + 标语"重振仙宗" + `[开新宗门]` | 点 `[开新宗门]` → 二次确认 → 宗门创建页（宗门名/宗主名/性别/外观） | 创建完成 → 进入主界面 |
| **T2–10′ 前 10 分钟** | 1）宗门首页（山水背景 + 顶部资源栏"太玄·Lv1 / 时间 / 灵石·灵草 / 人数"）；2）**常驻目标条"当前目标 · 第 1/5 步"**；3）高亮气泡指向当前该点的按钮；4）`临朝听政` 主按钮 + 周边快捷入口 | 按五步走：① 点顶部家底 → ② 看离线简报/等时辰（世界自转）→ ③ `开启接引大典` 招首徒 → ④ 弟子页点开一人 → ⑤ 看 `离山汇总`（岁末考评） | a) 招到首徒有测灵根过场 + 收录入册；b) 资源数字增长（灵石/灵草跳字）；c) 目标条步数前进；d) 弟子页出现首名弟子卡 |
| **T10–30′ 后 20 分钟** | 1）宗门自转（弟子修炼/突破、殿阁月产、纪事滚动）；2）**新手目标链红点**（newbie_001→007）；3）`宗门要务` 面板 | 再纳弟子、首遣历练、收日供、看纪事、把首弟子带到炼气三层/五层 | a) 目标达成弹奖（灵石/灵气 + 跳字 + 纪事一条）；b) `宗门要务` 红点亮起→领奖后消失；c) 弟子境界/战力数字上涨 |

**观察项清单（真人只需回答 是/否）**：① 第 1 分钟内我知不知道"下一步做什么"？② 我有没有点开过 ≥3 个系统且看得懂？③ 有没有某个按钮点了没反应（死键）？④ 红点亮了之后我点开，它消失了吗？刷新又回来吗？⑤ 有没有"数字变了但我不知道为什么"的时刻？⑥ 30 分钟里最强的一次正反馈是什么、第几分钟？⑦ 有没有想关掉游戏的时刻、第几分钟？

> ⚠️ **本轮前置阻断**：本报告 P0-1 表明——**在当前 `启用新UI` 构建里，上表"前 10 分钟"的引导列（目标条/气泡/灰锁/序章）与"后 20 分钟"的新手目标链红点，均为原理性缺席**。故 R2 应在 P0-1 处置后再执行；否则测的只是"无引导下的裸体验"。

## 二、首轮 Playtest 报告（Bug 分级 P0/P1/P2）

> 视角："新玩家第一次玩 30 分钟"。取证方式：读码定路径 + headless 探针 + 既有真实渲染截图 `accept_shots_full/`（未弹窗、未改动任何 `.gd`）。

### 🔴 P0-1｜新手引导体系（S0 FTUE）在新 UI 构建下**原理性不可达**（含连锁：新手目标链也未激活）

- **现象**：新档进游戏后**永远看不到**序章三屏、常驻目标条（"第 X/5 步"）、引导气泡、以及坊市/差事/历练的灰锁引导；新人直接落到宗门首页裸奔。
- **复现路径**：删档 → 标题屏 `[开新宗门]` → 确认 → 宗门创建页完成 → 进主界面 → **无任何目标条/气泡/序章**（`accept_shots_full/00_home.png` 可见：首页有红点、有数据带，但**无目标条**）。
- **根因（文件:行）**：
  - `main.gd:52` `const 启用新UI := true` ⇒ 恒走新 UI 分支。
  - `main.gd:3901-3913` `_进入主界面()` 的**新 UI 分支在 `新UI.refresh_all()` 后直接 `return`**，**越过了**紧跟其后的 `main.gd:3918 _入门指引_初始化()`（该调用只在 `else` 旧 UI 分支）。
  - 另两处 FTUE 初始化 `main.gd:1122` / `main.gd:1139` 均包在 `if not 启用新UI:` 内 ⇒ 同样不可达。
  - 全项目 `_入门指引_*` / `引导阶段` / `目标条` 仅存在于 `main.gd`，`ui/`（新 UI 全部页面）**零引用**（唯一相关仅 `ui/sect_home_page.gd:434` 的注释）。
  - **连锁**：`Game.激活新手目标链()`（`game_state.gd:9840`）**仅**由 FTUE 收尾/跳过触发（`main.gd:3352` / `main.gd:3360`）⇒ 引导阶段恒为 0 ⇒ 目标链永不激活 ⇒ `ui/sect_home_page.gd:436 Game.新手_有红点()` 恒 false ⇒ **新手红点也永不出现**（P0 目标链系统在实机等于未上线）。
- **影响面**：**100% 新玩家**。直接复现项目历史上被记录的"完全没有开场、没有指引、一头雾水、不像能玩的游戏"（见 `design/06-角色与UI/S0最小可玩体验_开场与首日引导设计.md` §0.1）。这是"能不能给真人测"的前置阻断。
- **建议**：二选一并 1 分钟实机确认——①（推荐）把 `_入门指引_初始化()` 提到 `_进入主界面()` 的 `return` 之前（对新 UI 也生效），并让目标条/气泡挂在 `新UI` 之上、Hook 指向新 UI 的真实控件；或 ② 明确"FTUE 退役"，改由新 UI 页面承接首日引导，并同步删除 `main.gd` 旧分支，避免"写了但永远不跑"的死代码继续骗门。

### 🟠 P1-1｜宗门页"19 入口按钮墙"，无分层解锁 ⇒ 认知过载

- **现象**：新玩家首屏（宗门页）一次面对 **19 个等权入口**：洞府/修炼/殿阁/坊市/差事/库藏/宗主管理/凡人王朝/拍卖行/传送阵/家族/法宝/科技/灵兽/灵钓/探遗迹/饲灵育兽/卜算星盘/商道。
- **复现路径**：进主界面 → 宗门页 → 3 列网格铺满 19 项。
- **根因（文件:行）**：`main.gd:487` `var 入口: Array = [...19 项...]` 全量铺网；仅 `main.gd:4997-4002 _功能解锁()` 对 **坊市/差事/历练** 三项做灰锁，其余 16 项首日全亮。
- **影响面**：新玩家首屏认知负荷；与设计红线直接冲突——`S0…开场与首日引导设计.md` §0.2（"首日仅暴露 2 个主操作…坊市/任务/历练/御兽 灰锁"）与 `design/03-系统设计/UX-新手引导.md` §六（认知过载 🔴 须防）。
- **建议**：接入既有 `config/unlock_order.csv`（洋葱表）做分层揭示；首日只亮 3–4 个，其余折叠进"更多"或按 `门派等级` 逐级点亮。

### 🟠 P1-2｜时间节奏：1 游戏日 = 4 真实分钟，长/短周期严重错配

- **现象**：新玩家 30 分钟内会看到"时间飞逝"，日常任务约每 4 分钟刷新、年结 24.3 小时、七载大典 7.1 天；而练气圆满 ≈ 3 真实天、仙阶圆满 ≈ 381 真实天。短反馈极快、长线目标几乎不可见。
- **复现路径**：进游戏挂机 8 分钟 → 观察日常刷新/时辰跳变；对照"下一境界还需多久"的文案。
- **根因（文件:行）**：`game_state.gd:57 const 现实秒每游戏日 := 240.0`（配合 `main.gd:3948-3968` 的 240s 心跳 `推演一月(1)`）。
- **影响面**：留存曲线（30 分钟体验的"正反馈密度 vs 长期目标可见性"失衡）。
- **建议**：R2/R3 真人重点记录"第几分钟最强正反馈 / 何时感到没目标"；数值节奏裁决交文策渊，QA 只提供真人观测数据（不与本报告口径冲突）。

### 🟠 P1-3｜红点/引导可信度：自动化原理上不可证，且死键扫描有指纹盲区

- **现象**：红点"是否可信"（点开→消失→刷新不复发）无法由现有自动化判定；死键扫描 375 次点击的 DEAD 收敛到 35–45，存在"选中态只改样式"的指纹盲区，结果须打折看。
- **复现路径**：`tests/_t_deadkey.gd` 全量点击扫描；对任一红点做"点开→返回→再进"三态观察。
- **根因（文件:行）**：`tests/_t_deadkey.gd:356`（"选中态不进 modulate、也不一定改 font_color ⇒ 不采则又是一批假死键"）——即"点了只改样式不改结构/文本"的按钮，扫描会漏或误判。
- **影响面**：红点系统（`red_dot_init.gd` / `ui/sect_home_page.gd:_refresh_red_dots`）的可信度无自动兜底；玩家可能遭遇"红点打不掉"或"该亮不亮"。
- **建议**：真人 R2 必答观察项 ④；并给死键扫描补一条"选中态数值通道"（读 `button_pressed`/主题态）以缩小盲区。

### 🟡 P2-1｜质量门稳定性：门3 死函数棘轮对"并行编辑"敏感，会短时假 FAIL

- **现象**：本次实测 `gate_all.py` 首跑 **门3 FAIL**（"死函数 378 / 新增 1：`ui_theme.gd:载入动效偏好`"），**约 30 秒后单跑 `pre_f5_check.py` 变 PASS**（"死函数 377 / 水位 396 / 已达目标"）。同一工作区、同一份代码，结论翻转。
- **复现路径**：在另一条线正在写 `ui_theme.gd` / 调用点时跑门。
- **根因（文件:行）**：`pre_f5_check.py:1112-1215` 的死函数闸以"基线名单外新增即 FAIL"为判据；`载入动效偏好`（`ui_theme.gd:1057`）的定义与其调用点（`ui/game_ui.gd:1071`）不在同一次落盘瞬间可见 ⇒ 扫描到"有定义无引用"的中间态。
- **影响面**：CI/门禁信号被污染（假 FAIL / 假绿）；且与铁律"并行编辑 game_state.gd"的现状叠加，风险升高。
- **建议**：门禁在**冻结点单线程**跑；或给死函数闸加"仅统计连续 N 次扫描均无引用才判死"的宽限；并把"结论翻转"记入 flaky 台账。

### 🟡 P2-2｜门禁/文档口径漂移：战斗断言"72 vs 93"

- **现象**：任务书与部分文档称"`tests/test_combat.gd` 72 条战斗断言"，实测该文件为 `tests/combat/test_combat.py`（Python），且 `pre_f5` 第 3 道报 **"通过 93 / 失败 0"**，第 30 道文案又写"72 断言"。
- **根因（文件:行）**：`tests/combat/test_combat.py`（红线的真实载体）；`pre_f5_check.py` 第 3 道 / 第 30 道口径不一致。
- **影响面**：红线守护"数不清自己守了几条"，易在重构中被误动。
- **建议**：统一为"93 条（`tests/combat/test_combat.py`）"，并在文档中改掉 `.gd` 的笔误。（红线本身**零改动**——本报告未触碰。）

### 🟡 P2-3｜`[PLACEHOLDER]` 未校准数值 34 处（新玩家可选路径上的"高阶不回本"）

- **现象**：`game_state.gd` 仍有 **34 处 `[PLACEHOLDER]`**；其中殿阁升级成本 `_升级消耗_灵石()`（`game_state.gd:22561`，指数增长）对高阶为负收益（历史评测：L2→3 ≈ 56 月、L3→4 ≈ 83 月回本）。
- **影响面**：新玩家一旦点进殿阁升级，会直观感到"升了更亏"，但自动化（数值断言）只覆盖战斗/命格/灵兽/增益等，**不覆盖"殿阁升级是否值得"**。
- **建议**：列进 R3 数值节奏观察项；由文策渊按既有数值裁决流程处置。

| 8 | **"像半成品"的死资源/死入口体感**（如顶栏胶囊恒为 0、入口点了无内容） | 门3 只判"函数有无引用"，不判"引用得对不对/玩家看不看得见" | R2/R3 真人：每个可见入口点一遍，记录"点了有没有内容" |

## 四、质量门判定与待拍板
