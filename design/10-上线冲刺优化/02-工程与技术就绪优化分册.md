## 三、崩溃稳定性与退出清理方案

### 3.1 崩溃风险清单与处置

- C-ARCH-1（弟子属性空字典）：disciple.gd:4111 `属性 = d.get("属性", {})` 仍写入空字典；但 from_dict(3957) 已接 算属性() 自愈（2669/3406 调用）。**当前状态：代码层已接自愈，但未实机回归**。方案：构造缺 属性 字段的旧档，确认 from_dict 重建 属性 且 加成评分/判定职业 不再 null 崩；若仍崩，则在 from_dict 缺键时显式调用 算属性() 重建。验收：旧档加载零崩溃（O7）。
- C-ARCH-2（存档损坏静默清空）：已部分解决——SAVE_VERSION=4 + _版本升级备份 + _迁移存档 + JSON.parse 失败走迁移而非归零。方案：补原子写（先写 .tmp 再 rename 覆盖）与 .bak 保留（最近 3 份），与 O8 自动存档协同。验收：写档中途杀进程后主档或 .bak 可恢复。
- C-ARCH-3（加权随机空字典越界）：item.gd:205 / beast.gd:162 `return 权重.keys()[0]`，空字典必 index error。方案：两处加 `if 权重.is_empty(): return ""` 前置守卫。验收：空字典传入返回 "" 不崩（O7）。
- C-ARCH-4（刷新无防抖）：main.gd 刷新每次 queue_free 全量重建，密集信号下重复建节点。方案：加 `_刷新中` 去重标志或差量更新。验收：密集信号下刷新不重复建（O7）。

### 3.2 退出清理方案

- 已加 `game_state.gd` / `game_ui.gd` 的 `_exit_tree()` 释放缓存页，退出泄漏从 CanvasItem 5863 / ShapedTextData 6172 / ObjectDB 13901 降到 490 / 281 / 1436（-90%~-95%）。
- 残余：ShapedTextData 281、ObjectDB 1436、Texture 82（实测值）。方案：系统核对各 Autoload（Game 及子系统单例）的释放路径，确认缓存页、文字整形缓存、Texture 引用统一释放；texmem 77.4→86.2MB 反向上升列为复测项（疑测量时点噪声）。
- 关键红线：**不改运行时缓存策略**（缓存页是切页速度的来源），只在退出时释放（O6）。

### 3.3 稳定性体检结论

正常新档可玩、不崩、短时流畅；最大隐患已从"必崩"降为"需回归验证的兼容边界"（C-ARCH-1/O26）。上线前必须用旧档（v1–v3）+ 缺字段存档 + 损坏存档三套用例实机回归（受当前约束，本批次只出方案，落地在专用会话）。

## 五、存档与版本兼容方案（新档/旧档迁移/跨版本字段兼容）

### 5.1 现状（实证）

- `game_state.gd:61` `const SAVE_VERSION := 4`；save_game 写入含 version 的大字典；load_game(25049) 检测 version 不符时调 `_版本升级备份` + `_迁移存档`(25096)，迁移后写回 version=SAVE_VERSION(25830)。
- 大量新字段注释为"不升 SAVE_VERSION，旧档缺键→默认零回归"（如邮件/消息/世界地图/外交/闭关嘱托/传讯/庆典/玄榜/碎片宝箱/辈分/正邪路线/功德业力/连锁/道友/日供/司职/引导/器殿赠宝/每日机缘/护道/渡劫/观礼/气运/周期评级/七载/先贤/祖师/飞升/化身/战令/图录/里程碑/成就/坊市/宗门任务榜/日常/周常/方针/奏折/随机事件冷却/新手/皮肤/历练/渡劫/炼丹/商队/灵钓/探秘/饲灵/卜算/药圃/论道/传送阵/朝报/贸易/领地/宣战/阵营战役/王朝/誓约/丹纹/丹方/符箓/符纹/拍卖/阵营任务/道友互动等）。
- 这是一种**向后兼容友好**的写法（新键旧档默认），但存在双刃剑：若误改既有字段语义/类型，旧档会静默错乱而非报错；且迁移函数仅在 version 不符时触发，version 不涨则新键靠默认。

### 5.2 字段兼容三原则（对齐 QUALITY_GATES G2/G4 §11.21）

- 只新增 + 默认值（兼容扩展）：纯新增可选字段，旧档缺键→默认，无需升版本（当前主流做法，保留）。
- 不修改：不改动既有字段名/语义/类型/主键 ID 生成规则/全局枚举顺序。
- 不删除：存档字段即使运行期无引用也不得删（区别于 O18 的运行期零引用字段清理）。

### 5.3 跨版本兼容策略固化（O26）

- 写《存档字段兼容规约》，明确分界：
  - **必须升 SAVE_VERSION 的破坏性改动**：改既有字段语义/类型、改主键/枚举顺序、删字段、改元数据头格式。触发 `_迁移存档` 对应版本分支。
  - **可默认零回归的兼容扩展**：纯新增可选字段（当前做法）。
- 补 `_迁移存档` 的版本分支（v1→v2→v3→v4 全链路）与集成测试：构造 v1/v2/v3 旧档，验证加载后核心数据（宗门等级/弟子/资源/建筑/关键系统状态）零丢失、零类型漂移。
- 自动存档（O8）接入原子写，确保写档中途中断可恢复（主档或 .bak）。
- 与 quality-lead 的 G4 发布门"三项用例"（旧档兼容/数据迁移/回退还原）对齐，迁移脚本与回退脚本随主版本交付。

### 5.4 账号兼容

- 当前为单人本地存档（user://save.json），无云端账号；若上线引入账号体系（云端存档/跨设备），需在 O26 之外补：账号绑定不破坏本地存档结构、云端存档版本号与本地一致、冲突时本地优先+云端合并策略。本分册仅预留技术钩子，具体内容待发行/账号方案定。

## 六、自动化验收闸门可持续化建议

### 6.1 当前闸门结构（实证）

### 6.2 可持续化要点（O19/O20）

- 编码假 FAIL 根因已修：`PYTHONUTF8=1` + PortableGit 进 PATH 注入子进程 env（门3 曾因 GBK 读 UTF-8 输出报 3 个假 FAIL）。**固化动作**：写入运行文档、各门 shebang 环境、CI 模板，杜绝复发。
- 并发 Godot 红线（最高优先级可持续化项）：同一机器**禁止并行 Godot/headless 会话**（争抢 .godot 缓存互相干扰，且本次主任务已明令另一会话占用项目）。闸门必须串行；建议加文件锁/任务队列，CI 同一 runner 不并行 Godot 任务。

## 七、本分册 Top 风险（5 条）

1. **并发 Godot 红线（最高风险）**：另一会话正占用项目，任何 Godot/headless 会争抢 .godot 缓存互相干扰。本分册所有落地动作（O1/O2/O3/O6/O7/O9 等）必须在专用空闲会话中**串行**执行，且禁止与占用会话同时跑。当前批次受约束只出方案。
2. **存档跨版本字段漂移**：当前大量字段"不升 SAVE_VERSION + 默认零回归"，若未来误改既有字段语义/类型，旧档静默错乱（不报错）；C-ARCH-1 仅代码层接自愈、未实机回归（受约束不能跑）。需在 O26 固化分界 + O7 旧档回归。

4. **包体/资源超限**：art 4.04GB + .git 3.28GB，首包若含全资源超商店限制；纹理未压缩（77MB 显存）在低端机有崩/掉帧风险。O14/O15/O9 必须落地且需 art-director 确认画质下限。
