## 二、移动端 UI/UX 铁律（多来源交叉验证，直接约束我们的排布）

| # | 铁律 | 来源 |
|---|---|---|
| 1 | **拇指热区**：高频操作放**屏幕下 1/3 + 主导侧**；**信息放顶部**（手不遮挡）；**导航放底部**。一拇指操作约占全部交互 70%+ | Epic《Designing for Mobile》、GameDesign.gg、run.world |
| 2 | 触控目标 ≥ **44×44pt**(iOS) / **48×48dp**(Android)，**游戏内建议 60–80px**；按钮间距 8–12px 防误触 | Apple HIG / Material、Sunstrike、designthegame |
| 3 | **扁平导航**：首页到核心功能 **1–2 tap**；菜单层级 ≤2 层（最多 3–4）；"每次上线都用"的功能必须在 2 步内 | GameDesign.gg、vrunik、gamineai |
| 4 | **一屏一主焦点**（one primary focus per screen, one primary action per moment） | Epic |
| 5 | 同屏活跃控件 **≤5–6 个** | Epic |
| 6 | 移动端信息密度 ≈ 同屏 PC 的 **50–60%**；"大数字、少图标、宽松间距" | Sunstrike |
| 7 | **视觉层级**用大小/色彩/对比/留白分层；最重要信息占最多像素 | NN/g、gamineai |
| 8 | 点击 **16ms 内**有视觉/音效反馈 | Sunstrike |
| 9 | **一致性**：同一视觉语言跨屏，前 10 分钟建立"语言" | Sunstrike |
| 10 | **渐进披露**：新手只给核心，复杂度逐步解锁 | run.world、gamineai |
| 11 | **安全区**：刘海/挖孔/圆角/Home 条 —— 交互元素必须锚在安全区内 | Epic、GameDesign.gg |
| 12 | **中断设计**：随时可被打断，自动暂停 + 频繁存档 | GameDesign.gg |

## 三、国风界面设计技法（可直接落到视觉层）

- **五正色**：青(东/木)、赤(南/火)、黄(中/土)、白(西/金)、黑(北/水)；"丹青"配色＝朱红×石青；渐变参考《千里江山图》青绿山水
- **"三远法"构图**：高远(主视觉) / 平远(功能区块) / 深远(背景层)；功能分区参照建筑"前庭-中堂-后苑"序列
- **留白"计白当黑"**；重要信息置**中轴线焦点**，次级信息分布**九宫格辅助线**
- **动效文化意象**：转场＝卷轴展开/屏风翻转；按钮反馈＝印章盖印/铜钱震动；进度条＝香炷燃烧
- **8pt 网格**保证间距一致（我们已有 `GRID` 体系）

## 四、竞品拆解（同类最直接对标）

### 4.1 寻道大千（竖屏放置修仙 · 最直接对标）

| 做得好 ✅ | 做得差 ❌ |
|---|---|
| **主界面一分为二**：一半砍树（主玩法/美术反馈），一半装备+战力面板 → "**一目了然，开门见山告诉玩家玩法是什么**" | 上方**充值图标太多且不能隐藏** → "点开十几个图标，玩家要每个去了解这是什么，并不易懂" |
| **下方玩法入口做了分类整合** → "比较好找又不会占界面" | 战斗跳过不便、爬塔重置不合理、界面偶卡顿 |
| 竖屏、挂机收益稳定、日常半小时 | 后期长草、流派固化 |

> **★ 关键取法**：主界面"一半玩法 + 一半系统面板"的分割，正是我们要补的"经营中枢"。

### 4.2 最强祖师（宗门经营 · 我们的直接竞品）

| 做得好 ✅ | 做得差 ❌ |
|---|---|
| 挂机产出、碎片时间友好、不逼氪 | ★★ **"各个系统面板过于繁杂，集成度不高，使得精力耗费严重，会觉得很累"** → 玩家**明确要求"出一个综合性的面板"** |
| **"资源收集点一个收全部，简洁方便"** | 建筑/生产要"点进去一个一个弄，超级麻烦" |
| 画风（水墨+Q 版）、弟子词条丰富 | 灵田/进驻要"一个个点进去看哪个弟子培植等级低，很麻烦" |

> **★ 关键取法**：玩家自己要"**综合面板**"+"**一键收取**" —— 这是首页重排的第一性需求。

### 4.3 一念逍遥

| 做得得好 ✅ | 做得差 ❌ |
|---|---|
| 主界面**按钮风格统一、UI 简洁明了**、水墨暖色调 | ★ **后期解锁玩法越多，界面"拥挤冗杂"**（与最强祖师同病） |
| 音乐/美术 | 放置却"**收不完的菜、点不完的红点**" |
|  | 战斗界面简陋（两个圆框） |

### 4.4 江南百景图（古风经营）

| 做得好 ✅ | 做得差 ❌ |
|---|---|
| 水墨画风、细节、"清明上河图"代入感 | ★★ **"不够人性化的 UI 设计"**：访问好友要从主画面**点 3 次**；**仓库功能不在主界面**，要点建筑、挪屏找 |
| 布局自由度高 | ★★ **"游戏模型感应范围太大"**：柳树/旗杆**整个模型都是触感区域** → 误触打开对话框（触控热区反面教材） |

### 4.5 了不起的修仙模拟器（★ 最大反面教材）

- ❌ **PC 界面直接搬到手机＝"灾难性的 UI，反直觉且操作繁琐"**、字体太小、数据太多
- ❌ 资源与格子**边界不明确**；大单位遮挡后方
- 玩家诉求：仓库**筛选全选**、**批量操作整合本体**、**一键切换**、点工作台**直接弹制作面板**

### 4.6 放置修仙通用病症（搜狐/GameRes 总结）

- ❌ "**挂机五分钟，点点点两小时**"｜"上线后**收不完的菜、点不完的红点**"
- ❌ "一个放置游戏，每天要花大量时间重复机械地点几百次，简直是一种**坐牢玩法**"
- ❌ 界面杂乱无章、红点遍地 → 对"想养老的放置玩家"是**极大劝退因素**

## 五、真实玩家反馈提炼

### 5.1 "好用"清单（要抄）

1. **主界面按钮/风格统一**（一念逍遥）
2. **一词分类整合，好找又不占界面**（寻道大千）
3. **一个收集点收全部 / 一键收取**（最强祖师）
4. **挂机产出 + 碎片时间友好**（寻道大千 / 最强祖师）
5. **画风/氛围**是留存第一动力（多款共识）
6. **开门见山告诉玩家"这游戏怎么玩"**（寻道大千）

### 5.2 "劝退"清单（要避）

1. **系统面板繁杂、集成度低、点进去一个个弄** → "**比上班还累**"（最强祖师，玩家高频吐槽）
2. **后期界面拥挤冗杂**（一念逍遥）
3. **收不完的菜、点不完的红点**（放置类通病）
4. **关键功能藏太深**（仓库要点建筑 / 好友点 3 次）（江南百景图）
5. **误触**：感应区过大（江南百景图）
6. **PC 思维直接移植手机**（了不起的修仙模拟器）
7. **字体太小 / 信息边界不清**（了不起的修仙模拟器）

## 六、行业趋势：**减负风**（2026 明确信号）

- 日常任务"**瘦身**"、**一键领取/扫荡/跳过** 成标配；取消断签惩罚；离线收益外溢到 RPG/模拟经营
- "**副游**"定位被更多厂商接受：随时拿起放下、不设强制在线
- ⚠ **反向教训**：一键领取有隐性成本 —— 实测误领概率 31.4%、玩家对道具**稀缺性感知下降**（原神至今不做全局一键领取）→ 我们应做"**一键 + 可选择性复核**"，而非全自动

## 八、方案 A：**宗门中枢 Dashboard**（推荐）

**核心思想**：把首页从"入口墙"改造为"**经营中枢**"—— 上半屏美术反馈，中部经营快照，下半屏高频操作簇，底部导航。**90% 复用 P0-1/P0-3 已有材质与组件**。

### 8.1 分区（1080×1920）

| 区 | Y 区间 | 内容 | 依据 |
|---|---|---|---|
| ① 顶栏 | 0–156 | 资源 + 历法（**信息置顶**，手不遮挡） | 铁律#1、#11 |
| ② 主视觉 | 156–700 | 宗门全景 + 气象带（美术反馈，占比降至 ~28%） | 国风"深远"、氛围留存 |
| ③ **经营快照带** | 700–980 | 横滑 4 卡：**弟子 / 月产 / 事务待办 / 宗门气运**（点卡直达） | 补空白 + 综合面板 |
| ④ **高频操作簇** | 980–1400 | 大按钮：**宗务 / 历练 / 日供 / 坊市**（**拇指热区**） | 铁律#1、#2 |
| ⑤ 侧栏入口 | 右列 | 天下 / 玄榜 / 宗门典藏 / 碎片宝箱 收为**右侧竖排小图标**（或并入"更多"） | 铁律#5 |
| ⑥ 底部 Tab | 1560–1920 | 宗门/弟子/殿阁/历练/纪事 | 铁律#1（导航放底） |

### 8.2 关键交互

1. **司职自动执行（★ 仿真铁律）**：宗门产出自**司职弟子**自动完成，首页**不设任何「收取」按钮** —— 月产卡只呈现「谁在管（如 丹堂·林清霜）+ 产出多少 + 运转状态」，宗主是**管理者**而非点收者。依据：`disciple.gd:655` 阶位轴（执事→堂主→长老→供奉）＋ `game_state.gd:186` 司职门槛映射 ＋ `offline_manager.gd` 离线管理。
2. **事务聚合**：快照带"事务待办"卡显示待批阅数，点击进聚合页 → 解决"点进去一个个弄"
3. **红点分级**：仅**强红点**（待办/可领取）出现在首页，弱红点收进"更多" → 解决红点遍地
4. **渐进披露**：未解锁的入口/卡不显示（沿用现 `SystemUnlock`）

### 8.3 优点 / 风险

- ✅ 直击"综合面板""一键收取""好找不占界面"三大玩家诉求；视线动线符合"上状态→中概览→下操作"
- ⚠ 快照带需真实数据支撑（弟子数/月产/待办要从 `Game` 只读取值，**遵守首页 S1 红线：只读 + 抛信号**）
- ⚠ 改动面最大，需 P0-5 分批（先做③④，再动侧栏）

## 九、方案 B：**双栏工作台**（信息密度优先）

**核心思想**：借鉴寻道大千"一半玩法 + 一半面板"，把下半屏做成**左右双栏工作台**，一眼看清宗门运转。

### 9.1 分区

| 区 | 内容 |
|---|---|
| ① 顶栏 | 同方案 A |
| ② 主视觉 | 宗门全景 + 气象带（占比 ~34%） |
| ③ **左栏：司职产出表** | 一行一司职（丹堂/灵田/矿脉/藏经阁/传功殿…）：**主理弟子署名** + 自动产出 + 运转状态；空缺司职行尾给「指派」→ 呈现「组织在运转」而非待领的菜（**无收取按钮**） |
| ④ **右栏：弟子请示** | 待批阅奏疏 / 待任命司职 / 历练见闻请示 / 护法请示 / 洞府营建请示，行尾「批阅·任命·裁决」→ 全部对齐 `game_state.gd` 实时传讯系统的真实类型 |
| ⑤ 底部 Tab | 同方案 A |

### 9.2 优点 / 风险

- ✅ 信息密度最高、"宗门真实运转"感最强；最贴近经营模拟玩家的期待
- ⚠ **拥挤风险**：一念逍遥/最强祖师都被"后期繁杂"反噬 → 必须配"**分类折叠 + 只显 TopN + 渐进披露**"
- ⚠ 双栏在 1080 宽下每栏仅 ~500px，字号与触控目标需重新校验（≥48dp）

## 十、两方案对比与建议

| 维度 | 方案 A 宗门中枢 | 方案 B 双栏工作台 |
|---|---|---|
| 视觉重心 | 美术为主（氛围） | 数据为主（经营感） |
| 信息密度 | 中 | 高 |
| 上手门槛 | 低（渐进披露友好） | 中（需折叠策略兜底） |
| 拥挤风险 | 低 | **高**（历史教训明确） |
| 改动面 | 大 | 很大 |
| 契合"放置+经营" | ✅ | ✅✅ |

**建议**：以 **A 为骨架**，把 B 的"一键全收 + 事务聚合"下沉进 A 的③④区 —— 即"**A 的布局 + B 的信息效率**"。先出 3 套候选稿（A / B / 混合），在 Ardot 上视觉确认后再动代码。
