# 《太玄宗门录》S1-P0 实施阶段总 GDD 与 CSV 模板

> **阶段定位**：路径乙（排雷优先）收口。ECON-01/02 已给数值锚并结论，用户已拍板全部决策。本稿把 **D类三项（进 S1）、A类三项（升级可落地）、B类三项（填数值）** 统一落为可评审、可实现的 GDD + CSV 模板。
> **铁律**：本稿仅出 GDD + CSV 模板（设计稿），**不写任何运行时代码**（`.gd`）。所有代码改动以「消费者接线点规格 / 伪代码级 light-code」落于各节，由 engineering-lead 在审计放行后落地。
> **三位一体强制**：每个新建/改动项必须同步交付 ① 配置表（CSV 草稿，见 `appendix-csv/`）+ ② 运行时消费者接线点（light-code 规格）→ ③ `pre_f5_check.py` 校验规则。三者缺一即摆设，禁止合入。
> **摆设 CSV 红线**：`personality_config.csv` / `negative_event.csv`（现状仅 csv_validator 注册）/ `resource_flow` / `sink_cost` / `output_daily` / `disciple_interact` 等**禁止当作已生效消费者复用**；本稿为 `negative_event.csv` **新建真实消费者**使其转正，`personality_config.csv`/`output_daily` 等**不复用**（弟子特质走新建 `弟子特质.csv`）。

## 一、D类1 · 宗门运维成本（刚性耗 C4-C7，强制进 S1）

### 1.1 定位
补 ECON-01 **F1 缺口**（刚性消耗全 STUB）与 **F6 缺口**（弟子津贴 N×2 无对冲）。引入后使 总产/总耗 比值从 ≈∞ 收敛到 1.20，建立零通胀闭环。是 ECON-02 唯一能补消耗闭环的功能，**强制进 S1**。

### 1.2 复用现状 · 诚实标注
- ⚠️ **需轻量代码 + 新建 CSV**：现有 `game_state.gd` 端口 `_结算俸禄_S1()`(L1174, STUB)、`_结算香火_S1()`(L1053, STUB)、`_结算大阵耐久_S1()`(L1056, STUB) 为零副作用桩；建筑维护(C5) 无实现（仅 `csv_validator` schema 提 `daily_maintain_cost`）。本稿新建 `宗门运维成本.csv` 配置四项系数，并在 `_结算俸禄_S1` 同位置新增 `_结算运维成本_S1()` 真接消费者。
- ✅ 系数口径复用 `GDD-宗门经营.md` §五 俸禄体系（每月初一发、职位倍率 ×2.0/×1.5/×1.0）。
- ❌ **不复用 `sink_cost.csv` / `output_daily.csv`**（摆设，零运行时消费者）；本稿为 C4~C7 新建真实消费者。

### 1.3 机制 / 数据 / 公式
- **月度刚性耗** = C4(俸禄) + C5(建筑维护) + C6(修炼耗材) + C7(制式装备摊销)，单位 灵石/月。
- **系数（初始校准值，落 `宗门运维成本.csv`）**：

| 耗项 | 计费基数 | 单价(灵石/月) | 计倍公式 | 标准局值(N48/B12) | 全量程 |
|---|---|---|---|---|---|
| C4 弟子俸禄 | 弟子数 N | 4.5（普通基数） | 俸禄基数 × Σ(身份倍率) | 48×4.5×1.0 = **216** | 身份倍率 普通1.0/执事1.5/长老2.0 |
| C5 建筑维护 | 建筑数 B | 3.0（flat/建筑） | 维护单价 × B | 12×3.0 = **36** | 不随 BL 缩放（可预测） |
| C6 修炼耗材 | 弟子数 N | 0.73 | 耗材单价 × N | 48×0.73 ≈ **35** | 随 N 缩放 |
| C7 制式装备摊销 | 弟子数 N | 0.375 | 制式单价 × N | 48×0.375 ≈ **18** | 随 N 缩放（入职包按月摊销） |

- **标准局合计** = 216 + 36 + 35 + 18 = **305** ✓（落入 [293,318]，比值 366/305≈1.20∈[1.15,1.25]）。
- **F2 接线（双兜底架构）**：`刚性耗_实付 = 刚性耗_计算 × global_cost_rate`（默认 1.0）。`global_cost_rate` 由 `economy_balance.gd` 经 `config/经济阀门.csv` 读取（默认 1.0，**运行时 ±15% 强制钳制**，非硬编码）；静态闸门 `check_resource_redline.py` 第11闸（pre_f5）静态守三旋钮键 + ±15% 硬范围。
- **比自稳定说明**：总产 ∝ N（P1+P2 主导），C4/C6/C7 亦 ∝ N，故 N 增长时比值自跟踪；当 N 大幅越界或职位倍率抬升使比值逼近 <1.15（盈余<15%）时，运营调 `global_cost_rate<1.0` 回拉；比值 >1.25（盈余>25% 囤积）时调 `global_cost_rate>1.0`。

### 1.4 红线 / 乘区登记
- **经济红线（本项即红线载体）**：刚性耗必须锁 **[293,318]**；月度盈余率守 **15%~25%**；不得 ≥366（负盈余破产）。
- **不引入增益**，无乘区登记（本项是消耗，反向于产出效率池/通用增益）。
- 对冲 F6：C4 俸禄是 P2 弟子津贴(N×2=96 纯产出) 的对冲项，使每弟子净贡献转负，消除「N 增长→灵石无界」。

### 1.5 需轻量代码（消费者接线点 · 伪代码级）

> **F2 双兜底架构（方案B·已落地）**：静态闸门（`pre_f5` → `check_resource_redline.py` 第11闸）做 **静态守**（校验 `economy_balance.gd` 引用 `经济阀门.csv` + 含三旋钮键 + ±15% 硬范围 + `period_settlement.gd` 调用 `平衡()`）；运行时由 `economy_balance.gd`（class_name `EconomyBalance`, extends RefCounted, 纯计算外挂中间层）从 `config/经济阀门.csv`（表头 `阀门,系数,开关,说明`）读取三旋钮 `global_cost_rate`/`trade_profit_rate`/`event_damage_rate`（默认 1.0，**熔断 ±15%**），在 `period_settlement.gd` 结算最终输出节点**单次调用 `EconomyBalance.平衡()`**，**核心结算逻辑零侵入**。

```gdscript
# —— 新增 _结算运维成本_S1()（紧接 _结算俸禄_S1 之后，推演一月月循环内）——
func _结算运维成本_S1() -> void:
    var 率 = EconomyBalance.取系数("global_cost_rate", 1.0)   # F2 阀门：economy_balance.gd 读 经济阀门.csv，运行时±15%钳制
    var c4 = 0.0
    for d in 弟子列表:
        c4 += 4.5 * _身份俸禄倍率(d.身份)               # 普通1.0/执事1.5/长老2.0
    var c5 = 3.0 * 建筑列表.size()
    var c6 = 0.73 * 弟子列表.size()
    var c7 = 0.375 * 弟子列表.size()
    var 刚性耗 = (c4 + c5 + c6 + c7) * 率
    # 守恒校验：293 ≤ 刚性耗 ≤ 318（超出则 clamp 并纪事告警，不破比值红线）
    刚性耗 = clamp(刚性耗, 293.0, 318.0)
    灵石 -= int(round(刚性耗))
    # 欠俸/忠诚链路（F6 对冲）：刚性耗 实付 < 应发阈值 → 忠诚↓（引用 GDD-宗门经营 §五.1）

# —— F2 阀门落位（方案B）：config/经济阀门.csv（表头 阀门,系数,开关,说明），由 economy_balance.gd 读取 ——
# 三旋钮（默认系数1.0，开关1=开，运行时熔断±15%）：
# global_cost_rate,1.0,1,宗门运维全局消耗系数(F2)
# trade_profit_rate,1.0,1,坊市收益总控系数(F2)
# event_damage_rate,1.0,1,负面事件伤害系数(F2，动态消耗阀门)
# period_settlement.gd 结算最终输出节点单次调用 EconomyBalance.平衡()，核心结算零侵入
```

### 1.6 pre_f5 校验（三位一体 ③）
- `check_resource_redline.py` Layer B 激活：断言 `标准局月耗_目标=305` ∈ [293,318]，比值 `366/月耗 ∈ [1.15,1.25]`。
- 闸门读取 `config/经济基线.csv`（ECON-01 已定义字段），`F2_阀门_接线==1` 且 `F3_经营加成_封顶==0.30` 时升级为硬阻断（见 ECON-01 §4.5/§4.6）。
- 硬约束：`global_cost_rate` 须由 `economy_balance.gd` 经 `config/经济阀门.csv` 读取（运行时 ±15% 钳制），硬编码字面量 → FAIL；pre_f5 第11闸静态校验 `经济阀门.csv` 含三旋钮键 + ±15% 硬范围。

### 1.7 边缘情况（≥3）
- **EC-1 旧档无刚性耗消费者**：当前全 STUB → 新消费者上线即建闭环；pre_f5 在 `F2_阀门_接线==1` 时阻断旧桩残留。
- **EC-2 职位倍率致刚性耗越 318**：clamp 至 318 并纪事告警（比值下限 1.15 不破）；同时建议运营调 `global_cost_rate`。
- **EC-3 N 暴涨致 刚性耗 逼近 293（盈余>25%）**：不强行 clamp 到 293（会锁盈余25% 囤积）；告警 + 动态消耗阀门（`event_damage_rate` 提升）吃冗余（§4.8）。
- **EC-4 建筑数 B 变动**：C5=3.0×B 自适应；B 增减平滑影响比值，无需特殊分支。

### 1.8 验收标准
刚性耗标准局=305、比值 1.20∈窗；`global_cost_rate` 配置化可调；对冲 F6（每弟子净贡献转负）；pre_f5 比值红线绿灯；旧桩清零。

## 二、D类2 · 坊市动态行情（±10% 浮动 + 限购 + 事件联动守 <5%）

### 2.1 定位
交易机制：价格 ±10% 浮动 + 限购规则 + 事件联动调价。**不触碰自动 366 基底**（ECON-02 §2.1：±10% 系数 < ±15% 红线，对闭环中性）。直接进 S1；限购规则反抑通胀。

### 2.2 复用现状 · 诚实标注
- ⚠️ **需轻量代码 + 新建 CSV**：现有 `xuanyu_shop.csv` 为坊市商品价（已有真实消费者 `game_state.gd` L422 坊市购买）；本稿新增 `坊市行情.csv` 定义**浮动系数带 + 限购规则**，由坊市定价管线乘算，接 `trade_profit_rate`。
- ✅ 复用 `xuanyu_shop.csv` 基础价，仅叠 ×行情系数；不另建商品表。
- ❌ **事件联动不新增灵石源**：联动仅调价（买/卖系数），不向玩家发放灵石，守 §4.7「机缘+秘境 <全渠道 5%」。

### 2.3 机制 / 数据 / 公式
- **成交价 = 基础价 × 行情浮动系数 × trade_profit_rate**。
- **行情浮动系数**：每商品类别在 `[0.90, 1.10]` 内按月摆动（±10%），由 `_校准浮` 区间读取，非硬编码。
- **限购规则**：每类别/每商品每月限购数量（反刷取通胀器），落 `坊市行情.csv` 的 `限购数量` 列。
- **事件联动**：事件可临时偏移某类别浮动系数，但**仅调价不发证灵石**；联动标记列 `事件联动标记=0`（本稿不开启"事件发灵石"模式）。

### 2.4 红线 / 乘区登记
- **红线**：浮动系数带 ≤ ±10% < ±15% 红线（ECON-01 Layer A）；限购规则须非空（防无限刷取）；事件联动灵石源 = 0（守 <5% 事件渠道）。
- **不引入增益**，无乘区登记。
- 接 `trade_profit_rate`(F2)：运营可一键下调（如 0.8）压制坊市收益溢出。

## 七、B类1 · 评级维度（四维 40/30/20/10，CSV 优先 + 三维兜底）

### 7.1 定位
将 `period_settlement.gd` 三维权重（经营0.30/收益0.35/弟子0.35）重构为**四维 CSV 驱动**（底蕴40/梯队30/盈余20/声望10）。用户拍板：CSV 优先、三维兜底；**初始配置须与原三维结算结果对齐无跳变**；新增声望维计数器。

### 7.2 复用现状 · 诚实标注
- ⚠️ **需轻量代码 + 新建 CSV**：`period_settlement.gd` 删 `const 权重`，改读 `评级维度.csv`；新增声望计数器（game_state `记声望增量`）。
- ✅ 子指标复用现有 `计数`/`快照` 字段 + `game_state.声望`（需新增声望增量计数器）。
- ❌ **不复用 `personality_config.csv`** 等摆设；四维为新建独立 CSV。

### 7.3 机制 / 数据 / 公式（数值已填）
- **权重（用户拍板）**：底蕴 40 / 梯队 30 / 盈余 20 / 声望 10（和=100）。
- **子指标构成（与三维原样，保证可审计）**：

| 维度 | 权重 | 组成子指标(子权) | 指标来源 | 归一化期望key |
|---|---|---|---|---|
| dundi 底蕴 | 40 | 资源产能(1.0) | 快照 | 资源产能 |
| tidui 梯队 | 30 | 总战力增量0.5;突破0.3;高品质新弟子0.2 | 快照/计数 | 总战力增量;突破;高品质新弟子 |
| yingyu 盈余 | 20 | 灵石增量0.5;稀有道具0.3;首通0.2 | 快照/计数 | 灵石增量;稀有道具;首通 |
| shengwang 声望 | 10 | 声望增量(1.0) | 声望系统 | 声望增量(新增key) |

- **计算**：`维度分 = 归一(子指标, 期望) × 权重 × 100`；`总分 = Σ维度分`；判级复用现有 `_判级(总分)`（评级阈值 D~SSS 不变）。
- **声望增量计数器**：game_state `_加声望` 处累加 `声望计数`，结算后清零；`_期望` 补 `声望增量` key（初始基准 = `20 × 门派等级`，tunable，使典型局声望分≈小，避免评级跳变）。

### 7.4 无跳变保证（设计约束）
1. **评级阈值不变**：`评级阈值` Dictionary(D~SSS) 与三维完全一致 → 玩家可见评级档位不因维度重组跳变。
2. **三维兜底**：`评级维度.csv` 缺失/解析失败/权重和≠100 → 回退三维硬编码路径（=现 `period_settlement.gd` const），绝对无跳变。
3. **声望初值≈0**：声望计数器刚接入、数据稀疏，声望维实得分≈0 → 四维净得 ≈ 三维的「资源产能↑/收益↓/弟子↓」重加权，阈值不变故仅极端偏斜玩家可能微调，标准局无跳变。
4. **校准备援**：若上线后评级档位可见偏移，临时将 `shengwang.是否启用=0`（权重归 0）即恢复三维等价，待声望计数稳定再启用。

### 7.5 红线 / 乘区登记
- **零经济触碰**：评级仅计分展示，不引入增益/产出；零乘区登记。总分不变 → 零通胀基线不受影响（仅维度重组）。
- 雷达 banding（`维度评级阈值` 列）为展示用，不影响评级判定。

### 7.6 需轻量代码（消费者接线点 · 伪代码级）
```gdscript
# —— period_settlement.gd 改读 CSV（删 const 权重）——
func _维度分(维度ID, 快照, 计数, 声望增量) -> float:
    var 行 = 维度表.get(维度ID, null)
    if 行 == null or int(行["是否启用"]) == 0: return 0.0
    var 子 = 行["组成子指标"].split(";"); var 子权 = _解析子权重(行["子指标权重"], 子.size())
    var 分 = 0.0
    for i in 子.size():
        分 += _归一(_取指标(子[i], 快照, 计数, 声望增量), _期望(门派等级)[子[i]]) * 子权[i]
    return 分 * float(行["权重"]) * 100.0
# 总分 = Σ(启用维度分)；_判级 复用；声望维 _期望 补 key

# —— game_state 声望计数器 ——
func 记声望增量(n): 声望计数 += n          # _加声望 处累加，结算清零
```

### 7.8 边缘情况（≥3）
