# 坊市商品图标 · 出图规格书（外批次）

> **文档号**：UI-ASSET-01 ｜ **日期**：2026-09-15 ｜ **批次**：`shop_icons_batch1`
> **数量**：20 张（`config/faction_shop.csv` 全量商品）
> **一句话**：给宗门坊市的 20 件灵石商品，各出一张**透明底裸器物图**，
> 文件名直接用商品的 `item_id`，落入 `art/icons/shop/`，代码自动寻址、无需任何登记。

---

## 一、为什么现在要这批图

坊市「收购」Tab（面向低阶弟子的**灵石**主渠道）目前**整屏没有图标** ——
`config/faction_shop.csv` 根本没有 `icon` 列，卡片回退到"首字"占位，
而同一页的仙缘阁（仙玉）商品图标 `104×104` 正常显示。

同屏一半有图一半是字，廉价感很强；且主理人刚提过"图标放大到跟框体一样大"，
方向正好相反。**这批图就是补这条链路。**

## 二、规格铁律（逐条都有工程原因，不是审美偏好）

| 项 | 要求 | 为什么 |
|---|---|---|
| **画布** | `1024 × 1024` | 项目全部高清图标统一 1024²（`equipment/` 160 张、`auction/` 6 张皆如此） |
| **格式** | **PNG / RGBA 透明背景** | ★ 商品卡的图标框内**已铺深色底**（`Color(0.122,0.169,0.192)`）。若出 RGB 方图，会出现"图自带方块底色 叠在 深色底上"的双层底色，边缘发脏 |
| **主体占比** | 外接半径 **0.72 ~ 0.82**（居中，四周留 9%~14% 透明边） | 上限：图标显示区 104×104 外面还有 **2px 品阶色描边**，主体顶到边会与描边"焊接"在一起；下限：留白过多就显得图标小 |
| **禁自带边框** | **不要**画外框 / 底座 / 圆形徽章底 / 描边圈 | 品阶语义（凡/灵/宝/王/圣 五档色）由**代码画的框色**承载。图标自带框会出现"**双环重影**"（项目此前踩过的事故） |
| **背景** | 完全透明，**不要**画地面/阴影底板 | 同上，避免与深色底叠加 |
| **风格** | 深色暗金国风；器物半写实 + 线性描边；统一光源（左上） | 全项目 UI 风格基线 |
| **阵营色系** | 同一阵营统一色温（见第五节） | 玩家一眼分辨派系，是坊市的**核心信息层级** |

## 三、命名与落盘（★ 关键：文件名 = 商品 id，零映射表）

```
落盘目录：E:\Xiuxian\taixuanzongmenlu\art\icons\shop\
文件命名：<item_id>_512.png
典型示例：shop_zhengdao_001_512.png
```

* `item_id` **直接抄 `config/faction_shop.csv` 第一列**，不要改写、不要翻译、不要加前缀。
* `_512` 是项目的**档位标记后缀**（沿用 `art/icons/equipment/artifact_huashen_fan_512.png`
  与 `art/icons/auction/auction_appraisal_512.png` 的既有一致写法），
  **不代表真实像素**，真实画布仍是 1024²。
* 好处：代码侧按 `item_id` **约定式寻址**，不需要任何映射表、不需要手改 CSV、
  不需要登记白名单 —— 新增商品时"丢图即有图"。

> **可以分批交付**：代码用 `ResourceLoader.exists()` 做了保护，缺图自动回退"首字"占位、
> **不会报错也不会崩**。先交 5 张就能先看到 5 张。

## 八、★ 交付验收记录（2026-09-15 23:5x 入库）

**结论：20/20 一次通过，零返工。** 豆包这批质量高于往批（往批高频出现「PNG 里装 JPEG」和「不透明方块」，本批零例）。

### 8.1 入库体检（两套独立判据，结论一致）

| 检查项 | 判据 | 结果 |
|---|---|---|
| 格式魔数 | 必须 `89504e47`（真 PNG） | 20/20 ✓ 无伪装 |
| 色彩模式 | 必须 `RGBA` | 20/20 ✓ |
| 四角透明 | 四角 16×16 patch 的 alpha 均值 | 20/20 全为 **0** ✓ |
| 不透明方块 | alpha>128 占比 < 0.95 | 最大 0.45 ✓ |
| 触边像素 | 外圈 6px 环带内 alpha>60 的计数 | 20/20 全为 **0** ✓ |
| 留白 / 填充 | 技能 `verify_icon_batch.py --profile icon` | **20/20 PASS，0 FAIL 0 WARN** |

### 8.2 实测到的观感数据（备查，非缺陷）

主体外沿半径 r99.5 分布：`min 0.406 / p50 0.795 / max 1.054`。
有 5 张 r99.5 > 0.85、3 张 r_max > 1.0（`shop_zhengdao_003` 正阳剑 1.113 / `shop_modao_003` 噬魂幡 1.043 / `shop_sanxiu_001` 手抄册 1.002）。

**实测判定：无需处理。** 依据有两条：

1. **零裁切（已量化）** —— 模拟实机 `TextureRect 104×104 + STRETCH_KEEP_ASPECT_CENTERED`：
   逐像素统计「alpha>128 且落在 104 框外」的像素数 ⇒ **全批合计 0 px**。
   原因是超界像素全在**对角方向**：最远可见半径 57.9px，而框的安全线是半对角线 73.5px。
   根因是「方形画布 + 方形贴图」⇒ contain 与 cover 等价，r_max 超 1.0 只是测量基准（以内切圆半宽 512 归一）所致，不代表逸出。
2. **斜构图显大属正常** —— 剑 / 幡 / 册本身就是长条物件。
   技能里的「双约束归一化」是为**入口图标**（叠圆形底座、需精确留白 12%）而设；
   坊市商品卡**自画品阶方框**、不叠底座，该约束不适用。
   且老大本轮明确倾向「图标更大」⇒ 反向缩小反而是逆意图。

### 8.3 导入规格统一（★ 这一项是真收益）

`.import` 初版是引擎默认值，与同族 `art/icons/auction/` 不一致，逐项对齐：

| 参数 | 初版 | 改为 | 理由 |
|---|---|---|---|
| `process/size_limit` | `0` | **`512`** | 源图 1024²，`0` = 不压尺寸 ⇒ 20×1024²×4B = **80MB 显存**；改 512 后 = **20MB**。显示区仅 104px，512 已有 4.9× 余量 |
| `detect_3d/compress_to` | `1` | **`0`** | `1` 会在纹理被用于 3D 时**自动重导入为 VRAM 压缩版**（行为突变）；auction 同族是 `0`，对齐 |

改参数后必须**删旧 ctex 重建**（参数进导入哈希）：`.godot/imported/shop_*.ctex` 删除后跑
`Godot --headless --import` ⇒ 20 个 ctex 全部重生成，合计 **2.6MB**（解压后显存 20MB）。

### 8.4 接入方式（约定式寻址，CSV 零改动）

`faction_shop.csv` 表头**没有 `icon` 列**，故不补列，改用**约定式寻址**：
`icon 路径 = res://art/icons/shop/<item_id>_512.png`。

落地在 `game_state.gd` 的 `_坊市表()`（**唯一入口，单点补键、零消费点改动**，与上一轮补
`shop_id`/`price_lingjing` 别名键同一处），并且**带 `ResourceLoader.exists()` 判定** ——
图不在时不写该键，消费点自动回退「首字」占位，**不会触发 `load()` 的 "Resource file not found"**。

> 缺图可分批补、不阻塞：`丢图即有图`。
