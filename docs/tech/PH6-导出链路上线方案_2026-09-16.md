## 2. Android 侧最小工具链方案

### 2.1 先核实任务书的判断：「非 gradle 构建、导出 APK」到底最少需要什么

**任务书判断**：只需要 `JDK 17` + `build-tools`（含 apksigner/zipalign）+ 可能 `cmdline-tools`，**不需要**完整 SDK Platform 与 Android Studio。

**核实结论：大方向正确，但有 1 处必须补、2 处可以砍。** 逐条对照 4.7 源码 `has_valid_export_configuration()`（`platform/android/export/export_plugin.cpp:3048-3120`）：

| 判断 | 核实 | 依据 |
|---|---|---|
| 需要 JDK 17 | ✅ 对 | 校验 `java_sdk_path/bin/java.exe` 存在（`:3049-3073`）；导出时 Godot 会把该路径写入 `JAVA_HOME` 与 `PATH`（`:2781-2788`）。apksigner 也依赖它。 |
| 需要 build-tools（apksigner） | ✅ 对 | 校验 `android_sdk_path/build-tools/<ver>/apksigner.bat` 存在（`:3100-3119`）。 |
| **需要 platform-tools（adb）** | ❌ **任务书漏了 —— 必装** | 校验 `android_sdk_path/platform-tools/` 目录**且** `adb.exe` 存在（`:3082-3097`）。**非 gradle 导出虽然不部署，但 `adb` 仍是硬校验项，缺了直接 `valid=false`**。 |
| 需要 zipalign | ❌ **不需要** | APK 对齐由 Godot **内部**用 libzip 以 raw 模式重写 zip 完成（`:4376-4461`，注释明确 "following ZipAlign.cpp"），**不调用 SDK 的 `zipalign`**。 |
| 需要完整 SDK Platform（`platforms/android-36`） | ❌ **不需要** | `has_valid_export_configuration()` 全程**没有**对 `platforms/` 的任何检查；非 gradle 直接用预编译模板 `android_release.apk`（`:4104-4106`）。 |
| 需要 Android Studio | ❌ **不需要** | 无任何依赖。 |
| 需要 cmdline-tools | ⚠️ **可选** | 仅用于 bootstrap 出 `sdkmanager`；若直接用官方独立 zip 手工摆放 `platform-tools` / `build-tools`，可完全不要 cmdline-tools。 |

> **修正后的最小集**：**JDK 17 + `platform-tools`(adb) + `build-tools`(apksigner)** —— 三件。
> 不需要 Android Studio、不需要 SDK Platform、不需要 zipalign、不需要 NDK、不需要 Emulator。

### 2.2 组件清单（发行版 / 版本 / 来源 / 体积）

> 体积为下载体积；安装后占用另计。**本轮不下载、不安装**，仅列方案。

| 组件 | 推荐发行版与版本 | 官方来源 | 体积（下载） |
|---|---|---|---|
| **JDK 17** | **Eclipse Temurin 17（LTS）**，当前 `17.0.20.1+1`（2026-08）。备选：Microsoft Build of OpenJDK 17。 | `https://adoptium.net/temurin/releases/?os=windows&arch=x64&package=jdk&version=17`（MSI 安装包，装完自带 `JAVA_HOME` 钩子） | **MSI ≈ 168 MB**（ZIP ≈ 190 MB；装后 ≈ 300 MB） |
| **platform-tools** | 最新 `37.0.1`（2026-07）/ `36.0.2`，含 `adb.exe` | `https://dl.google.com/android/repository/platform-tools-latest-windows.zip` | **≈ 8 MB** |
| **build-tools** | **`36.0.0`**（与 4.7 的 `DEFAULT_TARGET_SDK_VERSION = 36` 对齐；34/35 亦在 Godot 允许区间 28–36 内） | 路线 A：`sdkmanager "build-tools;36.0.0"`；路线 B 直下 `https://dl.google.com/android/repository/build-tools_r36_windows.zip` | **≈ 50–60 MB** |
| *(可选)* cmdline-tools | 最新 `commandlinetools-win-<ver>_latest.zip`（仅作 `sdkmanager` 引导） | `https://developer.android.com/studio#command-line-tools-only` | ≈ 150 MB |

**两种安装路线（推荐 A）：**

- **路线 A（推荐，最稳）**：下 `commandlinetools-win-*_latest.zip` → 解压到 `<SDK>\cmdline-tools\latest\` →
  `<SDK>\cmdline-tools\latest\bin\sdkmanager.bat --sdk_root=<SDK> "platform-tools" "build-tools;36.0.0"`。
  *好处：自动落到 `build-tools\36.0.0\` 的正确目录名、自动接受 license、无解压目录名坑。*
- **路线 B（最省）**：不要 cmdline-tools，直接下 §2.2 的 `platform-tools-latest-windows.zip` 与
  `build-tools_r36_windows.zip`，解压到同一 SDK 根目录，得到 `<SDK>\platform-tools\adb.exe` 与
  `<SDK>\build-tools\36.0.0\apksigner.bat`。
  ⚠️ **坑**：build-tools 的独立 zip 解压出来的目录名是代号（如 `android-16`），**必须手工改名为 `36.0.0`**，否则 Godot 按版本号扫描 build-tools 目录时会找不到。这是路线 A 更推荐的原因。

**总体积量级：约 230 MB 下载（JDK 168 + platform-tools 8 + build-tools ~55）/ 约 550–600 MB 磁盘。
若走 cmdline-tools 路线再 +150 MB。对比「Android Studio 全家桶 ≈ 2.3 GB」，省掉约 3/4。**

### 2.3 编辑器设置：需要填的键名（**已核实真实键名**）

编辑器中路径：**编辑器设置 → Export → Android**（*Editor Settings → Export → Android*）。三个字段：

| 编辑器设置键名（内部真实键） | 界面标签 | 填什么 |
|---|---|---|
| **`export/android/java_sdk_path`** | Java SDK Path | JDK 根目录（其下须有 `bin\java.exe`、`bin\keytool.exe`），例 `C:\Program Files\Eclipse Adoptium\jdk-17.0.20.1+1` |
| **`export/android/android_sdk_path`** | Android SDK Path | SDK 根目录（其下须有 `platform-tools\` 与 `build-tools\`），例 `C:\Users\Administrator\AppData\Local\Android\Sdk` |
| `export/android/debug_keystore` | Debug Keystore | **留空即可**，见 §2.4 自动生成。（附带 `export/android/debug_keystore_user` = `androiddebugkey`、`export/android/debug_keystore_pass` = `android`，均自动写入） |

**源码依据**：`get_java_path()` / `get_keytool_path()` 读 `EDITOR_GET("export/android/java_sdk_path")`（`export_plugin.cpp:2691, 2700`）；
`get_adb_path()` / `get_apksigner_path()` 读 `EDITOR_GET("export/android/android_sdk_path")`（`:2709, 2722`）；
报错文案亦直接点名键名（`:3784` "Java SDK path must be configured in Editor Settings at 'export/android/java_sdk_path'"、`:3791` 同 android_sdk_path）。

> ⚠️ **CLI 注意**：`--headless --export-*` 读的是**持久化的编辑器设置**（存于 `%APPDATA%\Godot\editor_settings-4*.tres`）。
> 所以正确顺序是：**先开一次编辑器 GUI 把两处路径填好 → 关掉 → 再走 CLI 导出**。
> （`JAVA_HOME` / `ANDROID_HOME` 环境变量可作为辅助，但 Godot 校验读的是编辑器设置，**以编辑器设置为准**。）

### 2.4 debug keystore 是否真能自动生成 —— **能**

- 机制：Godot 4.7 在 **editor 设置组 `export/android` 发生变化时**调用 `_create_editor_debug_keystore_if_needed()`（`export_plugin.cpp:918-921`）。
  只要 `java_sdk_path` 已填、且 `<java_sdk_path>\bin\keytool.exe` 存在、且目标 keystore 尚不存在，就**自动调用 keytool 生成**（`:927-985`）。
- 生成位置：`EditorPaths::get_debug_keystore_path()` = **数据目录 + `keystores\debug.keystore`**（`editor/editor_paths.cpp`），
  **Windows 实测路径即 `C:\Users\Administrator\AppData\Roaming\Godot\keystores\debug.keystore`**。
- 生成参数（源码内置，无需你输入）：alias `androiddebugkey`、keypass/storepass 均 `android`、RSA 2048、validity 10000、dname `cn=Godot, ou=Godot Engine, o=Stichting Godot, c=NL`（`:955-971`、`export_plugin.h:54-55`）。
- **触发时机**：填 `java_sdk_path` 时（`export/android` 组变化）即触发；生成后会自动回填 `export/android/debug_keystore`（`:981`）。

**兜底（若自动生成未触发，或你想自己掌控）：** 用 JDK 自带 keytool 手工生成：

```
& "<JDK>\bin\keytool.exe" -genkeypair -v -keystore "%APPDATA%\Godot\keystores\debug.keystore" ^
  -alias androiddebugkey -storepass android -keypass android ^
  -keyalg RSA -keysize 2048 -validity 10000 ^
  -dname "cn=Android Debug, ou=Android, o=Godot, c=NL"
```
生成后把它填进 `export/android/debug_keystore`（user=`androiddebugkey`，pass=`android`）。

### 2.5 ⚠️ 任务书之外的硬前置：ETC2/ASTC 项目设置（**本轮新发现，会让 Android 导出直接失败**）

**`has_valid_project_configuration()` 会检查项目的 ETC2/ASTC 导入开关，未开启则 `valid=false`**（`export_plugin.cpp:3148-3153`）。
而 **CLI 导出路径同样会走这个校验**：`editor_node.cpp:1400` → `EditorExportPlatform::can_export()` → `has_valid_project_configuration()`（`editor_export_platform.cpp:2550-2579`）。
**⇒ Android 的 `--export-release` / `--export-debug` 在 ETC2 未开启时会被直接拒绝。**

- 该设置键名：**`rendering/textures/vram_compression/import_etc2_astc`**，**默认值 = false**；
  且 `should_import_etc2_astc()` 在**非** ETC2 偏好主机（Windows 就是）上不会兜底为 true（`editor/import/resource_importer_texture_settings.cpp:47-54`）。
- 现盘实测：`project.godot` 中**没有**这一项 ⇒ 取默认 false ⇒ **当前状态下 Android 导出必被拦下**。
- **动作（属工程侧/项目设置，不是本任务能改的）**：在 项目设置 → 渲染 → 纹理 → VRAM 压缩 勾选 **Import ETC2 ASTC**。
  ⚠️ 开启后 **需重新导入全部纹理**（会在 `.godot/imported` 产出 `.etc2`/`.astc` 变体），
  这会显著拉长首次导出的耗时与磁盘占用。**这件事要单独排期，并知会工程侧。**

> 注：Windows 导出**不受**此项影响（`EditorExportPlatformPC::has_valid_project_configuration()` 恒返回 true）。

### 3.0 ⚠️ 引擎命令前置检查：显式携带 `APPDATA`（**规范条目，可直接抄**）

**所有 headless / 自动化 Godot 调用必须显式携带 `APPDATA`；缺失时 `user://` 会退化为工程内相对路径，把玩家存档落进仓库并可能进包。**

- 机理：`user://` = `[数据目录]/Godot/app_userdata/<项目名>/`；Windows 上数据目录 = `APPDATA`。`APPDATA` 为空 ⇒ 退化为相对路径 ⇒ 落进 `<工程根>/Godot/app_userdata/太玄宗门录/`。
- 现场证据：本仓库已出现 `Godot/app_userdata/太玄宗门录/`（`logs/godot.log`、`vulkan/*.cache`），即某次缺 `APPDATA` 的运行残留（详见 `.workbuddy/tmp/_rel_godot_appdata_audit.txt`）。
- 三层防护（已落地）：`Godot/.gdignore`（2026-09-16 建）+ 预设 `exclude_filter` 含 `Godot/*` + `.gitignore` 含 `Godot/`。
- 命令模板（PowerShell，导出前先固化 `APPDATA`）：
```powershell
$env:APPDATA = [Environment]::GetFolderPath('ApplicationData')   # 确保非空，杜绝 user:// 落进工程
& "<godot_console.exe>" --headless --path "E:\Xiuxian\taixuanzongmenlu" --export-release "Windows Desktop" "E:\Xiuxian\taixuanzongmenlu\build\windows\taixuanzongmenlu.exe"
```

### 3.3 导出命令 —— Android（**首次请用 `--export-debug`**）

```powershell
& "E:\Godot_v4.7-stable_win64.exe\Godot_v4.7-stable_win64_console.exe" `
  --headless --path "E:\Xiuxian\taixuanzongmenlu" `
  --export-debug "Android" "E:\Xiuxian\taixuanzongmenlu\build\android\taixuanzongmenlu.apk"
```

> ⚠️ **为什么首次用 `--export-debug` 而不是 `--export-release`**：
> 预设 `package/signed=true`，而 `keystore/release` 为空。**release 导出在签名阶段会因找不到 release keystore
> 直接失败**（`sign_apk()` 在 `:3343-3349` 报 "Could not find release keystore, unable to export." 并 `return ERR_FILE_CANT_OPEN`），
> 即使 APK 已写出，整体仍判定为导出失败。
> `--export-debug` 走**自动生成的 debug keystore**（§2.4），可零配置跑通。
> 待你备好 release keystore 后，再改跑：
> ```powershell
> & "<godot_console.exe>" --headless --path "E:\Xiuxian\taixuanzongmenlu" --export-release "Android" "E:\Xiuxian\taixuanzongmenlu\build\android\taixuanzongmenlu.apk"
> ```
> （或在预设置 `package/signed=false` 出未签名包 —— 但那样装机前仍需补签，不推荐。）

### 3.4 产物验证（三重校验，导出后立即做）

**Windows：**

**Android：**
```powershell
# ① 结构校验（zip 结构 + 关键条目）
Get-Item "E:\Xiuxian\taixuanzongmenlu\build\android\taixuanzongmenlu.apk" | Select-Object Name,Length
& "C:\Windows\System32\tar.exe" -tf "E:\Xiuxian\taixuanzongmenlu\build\android\taixuanzongmenlu.apk" | Select-String "AndroidManifest.xml|classes.dex|lib/arm64-v8a|assets/assets.sparsepck|META-INF/"
```

**判定标准**：文件存在 + 体积在合理量级 + Windows 能起进程 / APK 具备 `lib/arm64-v8a` 与签名 → **链路打通**。

## 4. 风险与阻塞

| 级别 | 项 | 说明 | 缓解 |
|---|---|---|---|
