## 一、为什么要一层「手感层」

老大验收标准是「达到真正的手游大厂水准」。大厂体感**不是靠页面各写各的动画堆出来的**，
而是靠**一处定义、全局生效**的基础层：任何按钮、任何页面、任何列表都自动获得同一套节奏。
本项目此前 60+ 页面各写各的 `Tween`，节奏参差（有的 0.1s、有的 0.6s，有的干脆硬切）。

**设计原则（三条）**

1. **零调用点优先**：能靠引擎钩子自动覆盖的，绝不在页面里让业务代码去调。
2. **不碰布局**：动画只动 `modulate` / `scale` / `position` 等**渲染态**；`Container` 托管的
   子节点 `position/size` 一律不碰（下一次 sort 就会覆写，必然打架）。
3. **可复现、可断言**：每个动效都要有**确定性**的起止值，能被 headless 探针量化断言，
   不能依赖「看起来差不多」。

### 2.1 列表错峰入场（本轮新增）

**语义定位**：页面里**第一个 `ScrollContainer` 的子 `VBoxContainer`** ＝ 货架 / 名录。
找不到就不做错峰（宁缺勿滥，不做「全树乱扫」。

**三段式行为**

| 区段 | 行为 | 理由 |
|---|---|---|
| `i < 10` | `alpha 0 → 1`，每条延迟 `i × 0.05s` | 人眼可读的「依次亮起」 |
| `i ≥ 10` | **直接置 `alpha = 1`** | 长列表（19 条以上）若全部错峰，末尾要等 1s+ 才可见 ⇒ 观感变「卡」 |
| 条目数 `< 3` | **整体不做** | 两三条错峰反而显拖沓 |

**为什么只做透明度、不做位移**
`VBoxContainer` 会托管子节点的 `position/size`。位移 tween 会在下一次 sort 时被覆写，
表现为「条目先滑出来又跳回去」。透明度是 `modulate` 相乘语义，与页面级淡入**天然叠加**、零冲突。

**抗「快速来回切页」卡半透明（★ 关键）**
错峰 tween 绑在条目自身（`create_tween().bind_node(c)`）。页面离树时 tween 会被**暂停**而非销毁，
条目可能停在半透明。故**每次入场的第一件事是先杀上一条 tween**，再重新写起始 `alpha`：

```gdscript
if c.has_meta(META_错峰TWEEN):        # 必须先 has_meta
    var 旧: Variant = c.get_meta(META_错峰TWEEN)
    if 旧 is Tween and (旧 as Tween).is_valid():
        (旧 as Tween).kill()
if i >= n:
    c.modulate.a = 1.0                # 上限之外无条件复位
    continue
c.modulate.a = 0.0
```

这条「每次入场都写下确定性起点」的写法，使**任意次数的连续重入都收敛到同一终态**——
探针用「连续两次入场 + 等足墙钟 ⇒ 全部 `alpha == 1`」来守这条。

## 三、实现纪律（踩过的坑，全是硬约束）

1. **`set_meta` 的键必须 ASCII**。中文键在 Godot 4 报 `Invalid metadata identifier` 且
   **静默失效**（返回 void，无从感知）⇒ 守卫可整条失效。故用 `_ui_press_hooked` / `_stagger_tw`。
2. **`get_meta(key, null)` 缺键时仍会刷 ERROR**。必须 `has_meta(key)` 先判。
3. **`Control.scale` 默认绕左上角**。播缩放动画前必须显式 `pivot_offset = size * 0.5`。
   （列表错峰故意**不做 scale**，就是为了绕开「入树当帧 `size` 还是 0、算不出轴心」的问题。）
4. **`resized` 只在已入树时生效**。`add_child` 之前设 `size` 不会触发 `resized`，
   需要 `tree_entered` 补一次。
5. **动画必须在 `refresh()` 之后播**。`refresh()` 会重排布局 / 改 `position`，
   先播就会被下一帧的重排打断（表现为动画只播了第一帧）。
6. **帧数 ≠ 时间**。动效是时间制 tween；`await process_frame` × n 在高帧率下只过去十几毫秒。
   验收探针必须用**墙钟**（`create_timer`）等待，否则会读到动画中途值。
7. **重页面首帧可能极慢**。实测 `page_shop` 构建 17 条列表后，前 2 帧耗时可达 ~175ms
   ⇒ 想读「入场瞬间」的起始值，必须**同步读**（函数体内已写入），不要等帧。

## 五、本层尚未覆盖（后续排期）

- **进度条缓动**：`ProgressBar.value` 是直赋值，**无法用 `node_added` 钩子拦截**（拦不到属性写入），
  需逐点接 `UITween` 或改走自定义控件。当前只在「升级/经验」这类玩家会盯着看的条上排期。
- **切页转场（缩放/翻页）**：当前是淡入 + 滑入；更「重」的转场需先确认手机端帧率预算。
- **`Window` 系弹窗（`Popup`）**：`Popup` 不是 `Control`，`scale/position` 语义不同，不能套本层；
  且 `apply_popup_font` 与 `apply_project_font` 口径不同，不可混用。
- **「减少动效」的 UI 落点**：`UITheme.动效强度` 已是统一开关，但项目当前**没有设置页**，
  暂作内部 API 使用（性能兜底 / 未来设置页接线）。

## 六、v1.1 增量：红点体系精修 + 弹窗/抽屉入场（2026-09-16 晚）

### 6.1 红点为什么「丑」——三个真因（都不是配色问题）

老大反馈「红点太丑」。逐层排查后配色/尺寸其实已达标（`RED_DOT_*` 单一来源、几何按像素尺寸自适应），
真正的三个问题全在**机制层**：

| # | 真因 | 后果 | 修法 |
|---|---|---|---|
| 1 | `RedDotBadge` 文件头写着「动画效果：出现时缩放动画，呼吸效果」，**一行都没实现** | 首页快捷栏 / 纪事 / 殿阁的红点全是**硬切**出现 | `_ready()` 里 `UITheme.挂红点动效(self)` |
| 2 | `RedDotManager._刷新节点显示` 用 `has_method("设置数量")` 探测，而工厂产出的是**裸 `Panel`、没有这个方法** | 数字角标**从创建那一刻起永不更新**（数字红点退化为装饰），且**全程无报错** | 管理器改为直改 `Num` 子 `Label` 文本 + 胶囊宽度 |
| 3 | `RedDotBadge.设置类型()` 在入树前被调用时已 `_build()` 一次，`_ready()` 又 `_build()` 一次 | **叠出两个圆点**、错位重叠 ⇒ 红点看起来「脏」「位置怪」 | `_ready()` 改 `if _圆点 == null: _build()` |

> 教训：**「注释里写了功能」不等于「功能存在」**。红点两套控件、注释都宣称有动效，实际两套都没有。
> 且 #2 是典型的**静默失效**（`has_method` 探测不到就跳过，无任何日志），只能靠「读代码 + 探针断言终值」抓出来。

### 6.2 红点动效三条语义（不可混用）

| 动效 | 触发 | 曲线 | 语义 |
|---|---|---|---|
| **弹入** | `visible` 翻转 false→true | `scale 0.35→1`，`0.26s`，`TRANS_BACK` | 「第一次出现」 |
| **呼吸** | 弹入结束后自动接上 | `1.0↔1.07`，`0.9s` 循环，`TRANS_SINE` | 持续提示（静息微动） |
| **脉冲** | 数量变化 | `1.0→1.18→1.0`，`0.12 + 0.14s` | 「又有新的了」 |

把脉冲做成「重播弹入」⇒ 玩家会误以为红点「消失后又重现」，故两者必须分开。

**呼吸幅度取 1.07 而非 1.12**：顶栏消息角标另有 `start_red_dot_breathe()` 在做 `modulate.a` 呼吸，
两轴叠加时缩放大一点就会显「跳」。

**呼吸计数只能减不能漏**：呼吸 tween 是 `set_loops()` 的、**永不 finish**，所以
「正在呼吸的红点数」只能在 `_红点_收()` 里减；漏了就会只增不减，攒到上限后**所有红点永久失去呼吸**
（同样是静默劣化，没有任何报错）。

### 6.3 ★ 显隐判据必须是 `visible`，不能是 `is_visible_in_tree()`

父级隐藏时 Godot 会把 `visibility_changed` **传播到整棵子树**，而子节点自身 `visible` 仍是 `true`。

- 用 `is_visible_in_tree()` ⇒ 每次切页（隐藏旧页 → 显示新页）都被判成「红点重新出现」，
  **整屏红点齐刷刷重播弹入**（观感像页面在抖）。
- 用 `visible` ⇒ 父级显隐被自动忽略，只有真正把红点显/隐时才播。

这条同时守住「切页不重播」与「显式显示必重播」两件事，探针 A2 / A5 / A7 就是守这三件事。

### 6.4 弹窗入场：为什么遮罩与面板要分两条 tween

面板若也做纯 `alpha` 淡入，会被遮罩的暗化「吃掉」半程 ⇒ 看成「糊出来」而不是「弹出来」。
拆分后：遮罩只动 `alpha` 且**先到位**（`0.7×时长`），面板动 `scale + alpha`
⇒ 玩家感受到「聚焦 → 弹现」。

**★ 绝不用 `position` 补间弹窗**：弹窗普遍走 `anchor/offset` 定位（居中弹窗 `anchor=0.5`、
全屏面板 `PRESET_FULL_RECT`），其 `position` 由 anchor 算出而非 `(0,0)` ——
补间到 `Vector2.ZERO` 会**直接把面板拖到左上角**。`scale` 不参与 anchor 计算，安全。

**准全屏面板（占屏 > ~70%）必须传 `缩放=false`**：做 `scale` 弹入会看到四边明显内缩再外撑，
观感是「画面被捏了一下」。

**轴心三级兜底**（`_弹窗轴心`）：面板刚 `add_child` 时 `size` 常为 `(0,0)`，
依次退到 `custom_minimum_size` → `get_combined_minimum_size()`，否则缩放会绕左上角（弹入像「从角上铺开」）。

### 6.5 抽屉入场：与弹窗入场的分工

抽屉面板是**绝对定位**（构造时直接给 `position/size`，如气象抽屉 `panel.position = …`）
⇒ 可以安全补间 `position`，实现「自底部升起」。

分工记法：**绝对定位用 `抽屉入场`；anchor/offset 定位用 `弹窗入场`。**

## 七、维护提示（写给下一个改这里的人）

1. **改红点配色请只改 `ui_theme.gd` 的 `RED_DOT_*` 常量**。此前 `red_dot_badge.gd` 与
   `ui_theme.make_red_dot*` 各写一份颜色，导致同屏两种红点观感不一致（已收敛）。
2. **新增红点必须走 `make_red_dot*` 或 `RedDotBadge`**，否则拿不到自驱动效。
3. **新增弹窗**：构造完面板后加一行 `UITheme.弹窗入场(...)`；全屏面板记得传 `false`。
4. **别在 anchor 定位的弹窗上补间 `position`**（除非改用 `抽屉入场` 且有绝对定位）。
   这是最容易踩且最难查的一类坑 —— 表现为「弹窗一闪就跑到左上角」，但**不会有任何报错**。
