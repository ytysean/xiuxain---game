## 0. 分诊结论速览

- 提案方向：**贴合现有架构**（双周期评级 / CSV 配置化 / 零通胀基线 / 放置经营内核），无脱离成本的空想设定，值得推进。
- 「纯配置 / 零新增开发量」标签**偏乐观**：实测发现提案自己点名引用的 `personality_config.csv`、`negative_event.csv` 当前均为**摆设型 CSV**（仅 `csv_validator` 注册、零运行时消费者）。因此「弟子特质」「负面影响」是 **B 类（需新建消费者）**，不是 A。
- 分类分布：**A 真接地 ~5** / **B 需 light-code ~7** / **C S2 预留 ~3** / **D 经济红线前置审计 ~3（含负面影响经济侧）**。
- 最高风险区：**坊市行情 + 运维成本 + 产业链功能 + 重度负面影响** —— 全部直接冲击 `零通胀` 总基线，必须「审计先行」。

## 3. 两个关键风险的落地标准

### 3.1 杜绝摆设型 CSV（三位一体交付标准）
1. **强制标准**：每个新建/改动项必须同时交付 **① 配置表 + ② 运行时消费者逻辑 + ③ pre_f5 校验规则**，三者缺一不可。
2. **禁止半吊子**：新建表必须同步写消费者，禁止「只建表不配逻辑」。
3. **批次过门**：每批次交付强制过 `pre_f5_check.py`，确保真实接入运行时链路。
4. **已中招预警**：`personality_config.csv` / `negative_event.csv` 当前即摆设 → 弟子特质、负面影响**必须新建消费者**，不得声称「复用」。

### 3.2 经济红线前置审计
1. **审计先行**：坊市行情 / 运维成本 / 产业链功能 / 重度负面影响 这类直接冲击经济总盘的功能，先算清 **产出增量 / 消耗增量 / 对零通胀基线的冲击幅度**，出具经济可行性报告。
2. **一票否决**：审计不通过 → 直接砍掉或降级，绝不先写功能再补平衡。
3. **闸门兜底**：`pre_f5` 新增「产耗 ±15% 红线」闸门（由 `engineering-lead` 设计），即使全负面触发，总收益波动也被锁在基准线 ±15% 内。
