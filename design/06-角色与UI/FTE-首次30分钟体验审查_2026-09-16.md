# 《太玄宗门录》FTE · 首次 30 分钟体验主线审查

> **一句话结论**：项目把「首日 30 分钟该教什么」设计得很完整（S0 文档 + 五步 + 序章 + 灰锁 + 7 条新手目标链），
> 但**这一整套在实机是死代码**——它挂在 `启用新UI := false` 的旧灰模 UI 分支上。
> 实机（`启用新UI := true`）首日玩家：**无开场、无目标条、无任何引导、底栏一半置灰、第一条正反馈回执（纪事）被锁**。
> 这不是"没设计"，是**设计没接上**。与 `PLAN-改进执行计划_v1.md:106-119` 已记录的同类事故（回合制战斗/30 关秘境「挂在已废弃旧 UI 上、实机不可达」）**是同一类，且更致命**。

### 1.5 首个「好玩时刻」定位：**30 分钟内大概率不出现**

「好玩」在本作的定义（S0 文档 §3.1）＝**第一次「我安排 → 有结果」的因果闭环**，即 S0 五步的 ②推演（可见产出）+ ④查看弟子（境界提升）。

实测链条：

| 环节 | 是否成立 | 证据 / 阻碍 |
|---|---|---|
| 招徒 | 路径成立，但**无引导** | 「接引决策」`page_disciple.gd:370`；旧 UI 的 `Button_开启接引大典` 名在新 UI 下不存在（`main.gd:3056` 找的是旧节点） |
| 派活 | 路径成立，但**无引导** | 「任免主事」`page_building.gd:2280`；未见任何首日提示指向 |
| 首推演可见产出 | **不成立** | 新档开机 FTUE 保底失效（A8），`累计游戏日` 停在 0；`_心跳_推演一日`（`main.gd:3965`）需 240 现实秒才推 1 日（`game_state.gd:57 现实秒每游戏日 := 240.0`） |
| 第一次境界突破 | **30 分钟内大概率不到** | 突破是**全自动**（`disciple.gd:3066 AI决定是否突破`），玩家不操作；但新弟子需可观游戏日才到练气三层（`quest_daily.csv:14` `disciple_realm_3` 判据 `练气 层数>=3`） |
| 首页 CTA 指向 | **不指向核心循环** | `sect_home_page.gd:866-887`：CTA 只会在「临朝听政·N件待裁决 / 领取供奉 / 临朝听政·宗门井然」三态间切换，**没有「去招徒/去派活」态** |

**结论**：30 分钟内玩家**没有被教会「好玩在哪」**。断点按严重度排序：

1. **断点 A（致命）** — 无开场 / 无目标条 / 无气泡 / 无序章（§1.2 全链）。
2. **断点 B（致命）** — 首屏唯一"主行动"是「临朝听政 / 领取供奉」，与「学核心循环」无关；首页 4 个可见入口里 3 个（玄榜 / 宗门典藏 / 碎片宝箱）属"收集与沉淀"，唯一的进度入口「宗务」被 `门派等级≥3` 滤掉。
3. **断点 C（重）** — 开机不推进游戏日 ⇒ 没有"我点了、宗门动了、资源涨了"的第一次正反馈。
4. **断点 D（重）** — 内容解锁断崖且链条不可见（详见 §3.3）：`炼丹/炼器` 需 门派等级≥2、`历练/宗务/商道/机缘` 需 ≥3，而首日可达上限 = **2**；`双周期评级启用 = true`（默认）下门派等级只在**七载大考（2555 游戏日 ≈ 7.1 现实日）**结算。

## 3. Q3 · 双周期是否对首日玩家讲清楚

### 3.1 结论：**说了，但没讲清；且三个日期边界口径不一致**

**已有的表达（保留）**：
- 游戏内周期：顶栏 `太玄 %d年 · %d月`（`top_bar.gd:628`）+ `%s · 宗门日程`（`:633`），12 时辰表（`:630`）。
- 真实时间周期：仅**局部、事后**出现 —— `page_auction.gd:915`「距下次拍卖还有%d游戏日（约%d现实分钟）」；`page_global_auction.gd:306`「大典每30游戏日开启一次（约2现实小时）」；`page_merchant.gd:229`「按现实日刷新」；`page_zongmen_battle.gd:954`「（现实7日重置）」。

### 3.2 ★ 口径不一致（必须拍板）

| 项 | 任务书/项目铁律口径 | **代码实现** | 证据 |
|---|---|---|---|
| 日常 / 周常刷新 | 每天 **08:00** | **凌晨 04:00** | `game_state.gd:2273` `重置点秒 = 4 * 3600  # 凌晨4点`；`:2272-2278` 日常；`:2281-2288` 周常；`:2250` 注释「现实每日凌晨4点后重置」 |
| 日供刷新 | 随每日 08:00 | **现实日历跨天（00:00）** | `game_state.gd:4013` `日供_今日可领() = 日供_最后领取现实日 != 获取现实日期()`（`:4011-4013`） |
| 坊市 / 商队等 | 真实时间日更 | 各自实现，未统一 | `page_merchant.gd:229`、`page_sect_manager.gd:1091-1094` |
| UI 呈现 | — | 「%d小时%d分后重置」（`game_state.gd:2279`） | 无「每日」字样、无「08:00」字样 |

⇒ **3 个不同的日期边界（00:00 / 04:00 / 设计 08:00）并存**。「每天 08:00 刷新」这条写进项目周期的口径，在实机**根本不存在**。

### 3.3 ★ 换算锚点缺失 + 解锁链全不可见

- **换算锚点**：全项目唯一解释「1 游戏日 = 多少现实时间」的地方是 `game_state.gd:57 现实秒每游戏日 := 240.0` 与 `page_auction.gd:914` 的代码注释 `1游戏日=4现实分钟`。**没有任何一处向玩家说明这个汇率**。首日玩家看到顶栏年月在走、产出来得慢，会误判成"卡住了"。
- **解锁链不可见**（断点 D 的细节）：

```
门派等级起点 1（game_state.gd:3619）
  ↑ 只能靠「举办晋升大典」(game_state.gd:23156) 提升
  ↑ 前置：可晋升等级 > 0（game_state.gd:23078-23081）
  ↑ 硬夹：等级上限 = min(灵脉上限, 大阵上限, 10)（game_state.gd:23075）
       灵脉上限：灵脉等级=1 ⇒ 3（game_state.gd:23055-23056）
       大阵上限：护山大阵=0 ⇒ 2（game_state.gd:23066-23067）
  ⇒ 首日可达上限 = 2
  ⇒ 要到 3（历练/宗务/商道/机缘）必须先 护山大阵≥2 且 灵脉≥3
  ⇒ 要到 4（坊市/家族/纪事）更远
另：双周期评级启用 = true（game_state.gd:4126）⇒ 门派等级不随年度自动升，
    只在七载大考（2555 游戏日 ≈ 2555×240s ≈ 170 现实小时 ≈ 7.1 现实日）结算
    （game_state.gd:23082-23094、:14505-14510）
```

UI 侧只给出**结果**提示（`system_unlock.gd:156-164` 回退语「宗门品级达 N 品后可入」/「门下弟子首次突破后可入」/「随宗门壮大自会显现」），**不解释 灵脉/大阵/综合评分/晋升大典/七载 这条链**，玩家拿到「宗品级达 3 品后可入」无从下手。

### 3.4 裁决

- **砍**：`04:00`（`game_state.gd:2273`）与「现实日期跨天」（`game_state.gd:4013`）两个口径，统一到**一个**。
- **改**：刷新时刻做成配置（`config/` 一行），UI 文案统一为「每日 <时刻> 更替」。
- **改**：首日补一处换算锚点（建议首页时令横幅 tooltip 或一次性事件引导）：「宗门一日，约当现实四分钟」。
- **改**：把「宗门品级达 N 品后可入」补成可行动提示（「须先修灵脉至 X 品、立护山大阵至 Y 品」），复用 `game_state.gd:23148-23151` 已算好的 `瓶颈` 字段（现已算、未被 UI 用）。
