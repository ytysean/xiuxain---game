## 三、三个分歧点（需要老大拍板）

### 分歧 1 🔴 宗主数据结构：Dictionary vs Disciple 实例

**豆包方案**：`var 宗主: Dictionary = {...}`，理由"单例、序列化简单、与 `方针`/`司职列表` 风格一致"。

**我的反对意见**：
- `disciple.gd` 有 **3297 行**成熟逻辑：修炼推进、突破成功率、渡劫、心魔、命格、瓶颈打磨、战力、寿命 …… 用 Dictionary 等于**这套全部要重写一遍**。
- 豆包自己也写了："`gongfa.gd` 参数从 `弟子` 改为 `角色对象`（支持 Dictionary 和 Disciple）"——这意味着 **3 个成熟系统要做双形态分支**，134 个 .gd 里凡是接触弟子的地方都可能被波及。
- 序列化根本不是问题：`Disciple` **已有 `to_dict()` / `from_dict()`**（存档在用），直接复用。

**建议方案**：
```gdscript
var 宗主: Disciple = Disciple.new()   # 复用全套成长逻辑，零改造
# 宗主专属字段（威望/精力/闭关状态/技艺等级）直接加在 Disciple 类里
# —— 加字段不影响弟子（弟子不用即为默认值），符合项目"不升 SAVE_VERSION"铁律
```
**工作量差异**：Dictionary 方案 ~5 个 Sprint（含 3 个系统改造）；Disciple 方案 ~2 个 Sprint。

### 分歧 2 🔴 P0 必须插入「P0-0：时间流引擎修复」

放在豆包 P0-1 之前。内容：

1. `game_state.gd:7939` `累计游戏日 += 1` → **`+= 月`**
   （离线 24h = 360 游戏日 → 循环 12 次 → 现在只加 12 天）
2. 约 30 处月度调用加**月边界门控**：`for _mi in range(int((累计游戏日 + 月)/30) - int(累计游戏日/30))`
   涉及：`_结算俸禄_S1()`、`月度家族结算()`、`兽潮月度触发检查()`、`阵营战争月度检查()`、`推进奇观建造_S34(1)`、`敌对势力月度行动()`、`势力兴衰月度检查()` 等
3. 统一同一函数内的口径矛盾：
   - 按「日」：`推进孵化(月)`、`(累计游戏日 + 月)/30`、`累计游戏日`
   - 按「月」：`_更新NPC状态(月 * 30)`、`_推进NPC任务进度(月 * 30)`
   - 修炼：本轮已统一为「日」（`d.推进修炼(float(月), ...)`）
4. 验收标准：`validate_all.py` + `pre_f5_check.py` 全绿，且**在线 24h 与离线 24h 的 `累计游戏日` 增量一致**（现在差 30 倍）

> ⚠️ 这一条我本轮已经查清机制但**主动停手没改**，因为豆包要 redesign 时间流，避免同函数并发冲突。谁来做都行，但**必须最先做、单独验收**。

## 四、数值校准（豆包方案的一处硬伤）

豆包 4.7.2 的"现实时间"列换算有误，差约 **2.5 倍**：

| 境界 | 寿元 | 豆包写的 | **正确值** |
|---|---|---|---|
| 练气 | 80 年 | 约 32 天 | **约 80 现实天** |
| 筑基 | 200 年 | 约 80 天 | **约 200 现实天** |
| 金丹 | 500 年 | 约 200 天 | **约 500 现实天（1.4 年）** |
| 元婴 | 1200 年 | 约 480 天 | **约 1200 现实天（3.3 年）** |

换算依据：`现实秒每游戏日 = 240` → 1 现实天 = 86400 / 240 = **360 游戏日 = 1 游戏年**（360 日）。

**结论不变但更乐观**：豆包说"金丹后绝大多数玩家不会玩到寿终"——正确值下这个结论**更成立**（金丹就能撑 1.4 年）。所以**不需要"掌门系数 0.3"这类人为缩短**，转世机制作为长线钩子足够。

## 六、建议补进豆包方案的两节（它没有）

1. **失败信号定义**（playtest 前先写，否则等于没做）：
   - A 玩家从不主动闭关 / 闭关后觉得亏 → 闭关收益不足
   - B 玩家闭关后再也不上线 → 在线理政内容不足
   - C 玩家从不更换副宗主 → 管理者能力影响不可感知
   - D 玩家对传位感到愤怒 → 传承惩罚过重
   - E 灵气永远不够 / 永远用不完 → 闭关消耗定价错误

2. **系统交互矩阵**（标 intended / acceptable / bug）：
   - 🔴 **宗主 × `弟子列表` = bug 风险**：宗主绝不能进 `弟子列表`，否则俸禄/差事/派遣/月例全乱
   - 🔴 **闭关 × 日常/周常 = bug 风险**：日常周常按**现实时间**刷新，闭关不得影响其节奏
   - 🟠 **传位 × 存档 = bug 风险**：旧档无宗主实体，必须懒迁移，**不升 SAVE_VERSION**
