### 2.3 最终抠图方案（按图标类型分三种）

#### A. 27 张标准图标（P1套装 + P2除3张功法 + P3）
- **方法**：纯白 flood（TH=232）+ 近白灰扩展（avg≥200, max-min≤10）+ 柔边
- **脚本**：`.workbuddy\_cut_white_batch.ps1`
- **状态**：已完成，质检通过

#### B. 3 张功法图（skill_dandao_02 / skill_daoxiu_01 / skill_daoxiu_04）
- **问题**：底部有浅色装饰（浅金/浅灰绿/纯灰），和四角白底颜色连通，被近白灰扩展误判为背景抠掉，导致底部边框缺失
- **最终方法**：纯白 flood（TH=232）+ **全圆半径保护 R=660**（原图 1024 下，r<660 不 flood 不柔边，只抠 r>660 的四角纯白背景）+ 柔边
- **脚本**：`.workbuddy\_fix_radius_protect.ps1`（当前 PROT_R=660，文件列表=daoxiu_01/daoxiu_04）
- **dandao_02**：徽章半径≈625，r=640 已在圆外，用 R=625 版本即可（当前成品是 R=625）
- **验证**：r=620–650 全部 100% 不透明，边框完整

#### C. 5 张入口图（entry_equipment_blueprint / herb_garden / library / pill_formula / puppet）
- **问题**：右下角背景是浅灰/浅棕渐变（亮度 160–231，色差较大），不是纯白，纯白 flood 和近白灰扩展都抠不掉；第一个 entry_activity 右下角是纯白所以一抠就干净
- **设计特征**：圆形徽章 + 四角云纹装饰，云纹在圆外但属于图案
- **最终方法**：**复用第一个 entry_activity 的 alpha 通道作为 mask**（6 张入口图是同一个模板，原始右下不透明像素完全一样 179,776，云纹位置形状完全相同）——mask 不透明的地方保留原图颜色，mask 透明的地方设为完全透明
- **脚本**：`.workbuddy\_fix_entry5_v3.ps1`
- **验证**：5 张图右下不透明像素都是 122,797（和第一个完全一致），云纹（左下+右下）都是 20,442（云纹保留），背景已完全抠透明
- **entry_activity（第一个）**：保持不变，它本身就是对的

### 2.4 抠图技术关键事实
- AI 文生/图生图无法输出带 Alpha 的透明 PNG，去白底必须程序化
- 真 PNG 头 `89 50 4E 47`、JPEG `FF D8 FF`
- System.Drawing LockBits+Marshal.Copy 字节序为 B,G,R,A（i+2=R, i+1=G, i=B, i+3=A）
- 从 24bpp 源图用 Format32bppArgb LockBits 写入 alpha 会被丢弃，必须先 Clone 为 Format32bppArgb 再操作
- 含中文 .ps1 必须先转 UTF-8 BOM 再跑

## 三、豆包客户端读图卡死问题（已诊断，用户暂缓修复）

### 3.1 现象
- Read 工具读取任何图片都会卡死几分钟，与图大小无关（121KB 小联系表也卡）
- 新会话只发一张截图也卡、重启电脑也卡
- 从某次豆包客户端更新后开始出现

### 3.2 诊断结论
- 根因：Chromium 147 内核 GPU 硬件加速在「Intel Arc B580 独显 + GameViewer 虚拟显示适配器」混合显卡下做图片解码/合成时挂起
- 已排除：截图文件正常、网络极快、无代理、磁盘不忙、内存充足、无 Godot 残留、腾讯电脑管家扫描≈0、无 Doubao 崩溃 dump

### 3.3 修复脚本（用户暂缓运行）
- 位置：`D:\桌面\一键修复豆包图片卡顿.bat` + `D:\桌面\fix_doubao_image.ps1`
- 源文件副本在 `.workbuddy\`
- 功能：退出豆包→关 hardware_acceleration_mode→清 GPUCache/Cache/Code Cache→自动重启，先备份 .bak 可回退
- ps1 已转 BOM、语法自检通过

### 3.4 处理图片任务时的规避方法
- **禁用 Read 读图**，改用 System.Drawing 做像素数值统计（只输出文本数字）
- 成品直接 present_files 发对话框供用户验收
- 已用 manage_preference 记录该环境故障
