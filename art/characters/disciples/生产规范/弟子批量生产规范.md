# 弟子批量生产规范（v1.2）

> 适用范围：太玄宗门录 · 弟子立绘 / 半身像 / 头像 / 战斗姿态 / 换装皮肤 统一生产链。
> 本规范锁定**一条标准生成链路**与**一套角色一致性控制表**，禁止后续混用多种出图方式（否则 90 张会风格漂移）。

---

## 一、标准生成链路（已锁定，禁止混用）

```text
① 角色原画 / 半身像参考图   → 固定每个弟子的脸型/发型/发色/气质基准
② OpenPose 姿态骨架         → 锁定站姿 / 战斗姿 / 半身姿，避免每图乱摆
③ Depth 深度图              → 锁定人体前后景深与构图，保证半身裁切一致
④ 人脸参考 / 角色一致性参考 → 锁定同一弟子多张图的脸一致（face ID / IP-Adapter）
⑤ 材质与服饰提示词          → 道袍/战甲/长裙的布料金属写实质感，主色锁定
⑥ 批量生成弟子立绘          → 按 disciple_manifest.csv 顺序跑，逐条验收
```

状态说明（诚实对照）：
- ② OpenPose：`batch_generate.py` / `gen_validation.py` 已支持 `--pose-dir`（ControlNet 姿态参考图目录），骨架已接入。
- ③ Depth：**已接入**。`gen_depth_refs.py` 复用 OpenPose 同源骨架坐标生成灰度深度代理图 `depth_{性格}_{性别}_{姿态}.png`（近白=近景、近黑=远景），绑 ControlNet **第二单元**（`depth_midas` / `control_v11f1p_sd15_depth`），权重 `DEPTH_STRENGTH=0.60`，锁定前后景深与半身构图一致。
- ④ 人脸/角色一致性（IP-Adapter）：**已接入**，采用**两遍式**——① stand 姿态先出图，自动人脸检测裁出 256 头像，存入 `reference/{role_id}_face_ref.png` 作为该弟子"基准脸"；② 同一弟子其余姿态 / 90 包同原型 `seq>=2` 变体，以该基准脸图作为 IP-Adapter 源（`ip-adapter` alwayson_script，`IP_ADAPTER_STRENGTH=0.50`），锁定多图脸一致，无需独立 face-embedding 模型。
- ⑤ 材质提示词：已锁定在 `build_prompt_package.py` 的 `QUALITY_CN/EN` + 构图锁（头顶留白 10%、头占图高 22–28%、无俯仰歪头、冠饰不遮眉眼）。
- ⑥ 批量出图：`batch_generate.py`（`--backend comfyui/a1111`，默认 `--crop-avatar` 走人脸检测动态裁切）。

### 5.1 OpenPose 姿态库（男女分版 + P0–P3 分层）

#### 男女分版原则
同性格底模 × 性别量化差异，**关节逻辑 / 文件格式 / 管线对接 100% 兼容**：

| 参数 | 男性基准 | 女性基准 | 对应关节点 |
|---|---|---|---|
| 肩宽 | +30 px（倒三角） | -24 px（收窄） | 2（画面左肩）、5（画面右肩）横向外扩/内收 |
| 胯宽 | -22 px（窄胯） | +22 px（梨形） | 8（画面左髋）、11（画面右髋）横向内收/外扩 |
| 腰节高度 | +14 px（腰线偏低） | -12 px（腰线偏高） | 髋线整体下移/上移 |
| 头身比 | head_r=158（头占比偏小） | head_r=192（头占比偏大） | 头圈半径 |
| 四肢 | limb=1.045，lw=20 | limb=0.955，lw=13 | 肘/腕/膝/踝从根关节等比缩放，线宽变化 |

> 参数固化在 `提示词包/gen_openpose_refs.py` 的 `GENDER_PARAMS`，直接决定 ControlNet 姿态参考图。`gen_validation.py` 自动从 `disciple_manifest.csv` 的 `gender` 字段匹配男/女骨架。

**命名规范**：`pose_{性格}_{性别}_{姿态}.png`
- 性格：`chen`=沉稳刚毅 · `gu`=清冷孤傲 · `wen`=温润亲和 · `bao`=暴躁 · `jiao`=狡黠 · `huo2`=活泼
- 性别：`男` / `女`（与 `disciple_manifest.csv` 的 `gender` 字段一致）
- 姿态：`stand` / `battle` / `halfbody`

✅ 正确：`pose_chen_男_battle.png`、`pose_gu_女_halfbody.png`  
❌ 禁止：只用 `pose_chen_male.png`（无法区分 stand/battle 多姿态，会撞名）

#### 半身姿与全身姿对齐铁律
- `halfbody` 与 `stand` 必须共用同一组**上身锚点**：鼻 0 / 颈 1 / 右肩 2 / 左肩 5 / 双眼 14-15 / 双耳 16-17；
- 这些点由 `gen_openpose_refs.py` 中的 `UPPER` 字典统一提供，`stand` 与 `halfbody` 各自合并下半身/臂节，绝不各自写死；
- 验证方法：脚本生成时自动校验 `gu`/`wen` 男女双版半身上身锚点与对应 `stand` 逐点完全一致；
- 产出价值：弟子详情页直接生成半身图，与「全身立绘裁切半身」的头像裁切坐标 100% 通用，避免男脸偏下/女脸偏上的裁切偏移。

#### 战斗姿女性力量保留
- 女性战斗姿默认收窄（shoulder -24 / hip +22）会削弱近战张力，因此对 `battle` + `女` 叠加**力量回调系数**：
  - shoulder 收窄回调至 **0.45 倍**（-24 → -11）
  - hip 外扩回调至 **0.5 倍**（+22 → +11）
- 仅 `battle` 姿态触发，远程/辅助性格仍走默认柔和体态，保证职业区分。

#### ControlNet 权重按性别微调
- 男性骨架：默认 **0.75** 锁姿力度足够，维持挺拔硬朗；
- 女性骨架：**0.70**，避免 AI 强行拉宽肩胯导致广袖长裙穿模/比例畸变；
- 由 `gen_validation.py` 在生成时自动读取 `gender` 字段传入 `backend.generate(..., controlnet_strength=...)`，产出清单 `validation_manifest.csv` 增加 `cn_strength` 列可追溯。

#### P0–P3 姿态分层

| 层级 | 准入标准 | 数量 | 当前状态 |
|---|---|---|---|
| **P0 核心基准** | 全游戏 90% 以上弟子复用，量产核心底座；强制统一头位/肩线/构图，保证头像裁切 100% 对齐 | 6 性格 × 2 性别 × 3 姿态 = 36 套 | **已生成 36 张（6 性格 × 2 性别 × 3 姿态）**，包含全部标准站姿 / 半身姿 / 战斗姿；验证组直接复用其中 6 张 |
| **P1 功能适配** | 核心系统必备展示，同类角色共用 | 通用半身像（已内嵌 P0）+ 战斗待机（已内嵌 P0）+ 通用施法姿 2 种 | P0 已覆盖 stand / battle / halfbody；扩 90 前补齐专属施法姿即可 |
| **P2 剧情表现** | 仅特定剧情 / 宗门事件使用，全游戏复用率 < 30% | 坐姿 / 跪姿 / 受击姿各 1–2 套通用版 | 未开始，功能开发到对应模块再补 |
| **P3 特殊定制** | 仅 VIP 顶级弟子 / 限定皮肤 / 专属剧情角色 | 单皮肤/角色 1 套 | 未开始，不提前囤 |

> 扩展铁律：每新增一类 pose，必须先做通用模板并确认能覆盖至少 3 个以上角色/场景，再纳入生产管线，禁止零散新增。

### 5.2 Depth 深度图约束（gen_depth_refs.py，已接入）

- **生成**：`gen_depth_refs.py` 复用 `gen_openpose_refs.py` 的 `BASE_POSES` / `build_kp` / `GENDER_PARAMS` / `POSE_PAIRS`，按**完全相同骨架坐标**绘制灰度深度代理图，保证与 OpenPose 姿态图 100% 对齐（不引入 XY/Z 偏移冲突）。
- **语义**：近=亮（白），远=暗（黑）。`SEG_DEPTH` 按肢体段赋灰阶——头/脸 235、躯干 220、前臂 175 / 上臂 150、小腿 155 / 大腿 115、背景 0；最后 `GaussianBlur(radius=22)` 软化过渡。
- **命名**：`depth_{性格}_{性别}_{姿态}.png`（与 `pose_*` 同键，36 张 = 6 性格 × 2 性别 × 3 姿态）。
- **管线接入**：`batch_generate.py` / `gen_validation.py` 在绑定 pose 的同时按 `personality_key` + `_gender_short(gender)` 解析 depth 路径；存在则追加 ControlNet 第二单元（A1111：`depth_midas` + `control_v11f1p_sd15_depth`，`weight=DEPTH_STRENGTH=0.60`；ComfyUI：workflow_metadata 记录 `depth`/`depth_weight`）。
- **权重说明**：0.60 偏柔，仅锁前后景深与半身裁切一致性，避免过强导致人物扁平。

### 5.3 IP-Adapter 人脸一致性两遍式（已接入）

- **两遍式流程**（同一 `role_id` / 同一 90 原型内）：
  1. **stand 先出图**：站姿为最完整正面姿态，作为"基准脸"来源；出图后人脸检测动态裁出 128/256/512 头像，将其 **256 头像复制到 `reference/{role_id}_face_ref.png`**。
  2. **其余姿态 / 变体复用**：同弟子 `battle` / `halfbody` 姿态、`seq>=2` 变体，以 `face_ref.png` 作为 `ip_adapter_image` 传入（`IP_ADAPTER_STRENGTH=0.50`），锁定脸一致。
- **A1111**：`alwayson_scripts["ip-adapter"]`（`ip-adapter_sd15`，weight=0.50）；**ComfyUI**：workflow_metadata 记录 `ip_adapter`/`ip_adapter_weight`；**DryRun**：`_dryrun_params.jsonl` 记录 `ip_adapter_image`/`ip_adapter_strength`，不调用模型。
- **清单溯源**：`disciple_asset_manifest.csv` / `validation_manifest.csv` 均新增 `ip_ref` / `ip_strength` 列，可直接追溯每张图是否用脸参考、用多重。
- **性别字段注**：90 包 `prompts_90.json` 的 `gender` 为 `男子`/`女子`，`batch_generate.py` 经 `_gender_short()` 归一为 `男`/`女` 再去拼 `pose_*` / `depth_*` 文件名；`disciple_manifest.csv` 的 gender 直接是 `男`/`女`，`gen_validation.py` 直接用。两者最终都落到 `男/女` 命名空间，互不冲突。

## 六、两层 Manifest 映射（避免混淆）

项目里存在**两层清单**，职责不同，不要混：

| 层 | 文件 | 职责 | 字段 |
|---|---|---|---|
| **身份层（本规范）** | `弟子立绘/disciple_manifest.csv` | 生产订单 + 角色一致性 + 状态跟踪 | role_id/name/gender/气质/脸型/发型/主色/武器/姿态/优先级/状态… |
| **产出层（脚本）** | `batch_generate.py` 输出的 `disciple_asset_manifest.csv` | 每条出图的物理产物追踪 | seq_id/file_path/avatar_paths/element/personality/aptitude/seed/**人脸检测动态坐标**/detect_method/backend/status… |

- 身份层回答"**要生产谁、长什么样、生产到哪了**"；
- 产出层回答"**这张图存在哪、头像怎么裁的、用的什么后端**"；
- 扩展 90 张时，由身份层逐条驱动产出层，产出后回填 `file_path` / 头像坐标到产出层。

## 十一、扩 90 执行节奏与质检（v1.2 新增）

### 11.1 分批量产节奏（建议 6 批 × 15 原型）

90 个正交原型（`prompts_90.json`）建议分 6 批、每批 15 个原型推进；每个原型默认出 3 张变体（`--variants-per-base`，hair/face/accessory 各随机 1 项），故每批实际为 **15 原型 × 3 ≈ 45 张立绘**。

- `--batch N`（1–6）按原型切片取第 N 批；`--batch-size` 默认 15（按原型计）。
- 每批跑完人工抽检「人脸一致性 + 姿态正确性 + 画风统一」后再进下一批，避免全量返工。
- 第 1 批同时承担定参任务（见 11.2）；第 2–5 批稳定量产；第 6 批收尾全量复核归档。

```bash
# 第 1 批（15 原型，含权重扫描定参）
python batch_generate.py --backend comfyui --url http://127.0.0.1:8188 --batch 1
# 第 2–6 批
python batch_generate.py --backend comfyui --url http://127.0.0.1:8188 --batch 2
python batch_generate.py --backend comfyui --url http://127.0.0.1:8188 --batch 3
# …… 直到 --batch 6
```

> 若某批只想出 15 张图（而非每原型 3 张），加 `--variants-per-base 1`。

### 11.2 首批权重梯度调优（定参）

初始权重（`batch_generate.py` 常量）：`DEPTH_STRENGTH=0.60` / `IP_ADAPTER_STRENGTH=0.50`。首批建议同步测三档，选最优值后写回常量或命令行固化：

| 控制 | 建议三档 | 过低风险 | 过高风险 |
|------|----------|----------|----------|
| IP-Adapter 权重 | 0.40 / 0.50 / 0.60 | 人脸一致性不足（换姿态就换脸） | 角色脸趋同、丧失个体差异 |
| Depth 权重 | 0.50 / 0.60 / 0.70 | 深度感不足、画面偏平 | 边缘生硬、人物与背景脱节 |

- 命令行覆盖：`--ip-weight 0.5 --depth-weight 0.6`（覆盖默认值，不影响其他逻辑）。
- **权重扫描模式 `--sweep`**：对目标原型先出「基准脸」（无 IP），再对 `Depth×IP` 网格各出一张并复用同一基准脸，产出于 `disciple_{id}_sweep_base.png` + `disciple_{id}_sweep_d{D}_i{I}.png`，清单逐张记录实际权重，便于横向对比定参。

```bash
# 对 2 个代表原型跑 3×3 权重网格（每原型 1 基准 + 9 组合 = 10 张）
python batch_generate.py --backend comfyui --url http://127.0.0.1:8188 \
    --sweep --id jin_chen_common --id jin_huo2_common
# 自定义网格
python batch_generate.py --backend comfyui --url http://127.0.0.1:8188 \
    --sweep --sweep-depth 0.5,0.6,0.7 --sweep-ip 0.4,0.5,0.6 --id <原型id>
```

> 定参后把最优值写回 `batch_generate.py` 的 `IP_ADAPTER_STRENGTH` / `DEPTH_STRENGTH`，或后续每批用 `--ip-weight/--depth-weight` 显式锁定，保证全量一致。

### 11.3 两项质检软检测（仅预警，不硬拦截）

新增 `提示词包/qc_lib.py`，复用 `crop_lib` 的 OpenCV DNN SSD 检测器（与裁切系统同源），对每张真实出图做两项软检测，结果写入清单 `qc_crop` / `qc_face` 列（格式 `level:reason`，level ∈ `ok`/`warn`/`fail`/`skip`）。

1. **`qc_crop_consistency`（头像裁切一致性）**：基于裁切元数据（脸中心归一化位置）判断头部是否偏出预期带（水平 0.30–0.70、垂直 0.10–0.35，与「构图锁」同源）；越带即预警，避免后续裁头像偏移/穿帮。
2. **`qc_face_integrity`（人脸完整性预警）**：检测 ① 无人脸（0 face → `fail`，疑似崩坏/无脸）② 多脸（>1 → `fail`，疑似残影/双脸）③ 主脸面积占比过小（< 6% → `fail`，疑似脸过小）④ 主脸中心偏离预期带（→ `warn`）。

两项均为 **软标记**：`fail` 不阻断产出，仅提示人工复核；dryrun 无图时列值为 `skip:dryrun`。

```bash
# 验证组试产（自动跑两项 QC，结果进 validation_manifest.csv 的 qc_crop / qc_face 列）
python gen_validation.py --backend comfyui --url http://127.0.0.1:8188

# 90 包量产（同样自动跑 QC，结果进 disciple_asset_manifest.csv）
python batch_generate.py --backend comfyui --url http://127.0.0.1:8188 --batch 1
```

### 11.4 首批验收三件事（实跑才可验证，DryRun 无法替代）

1. **IP-Adapter 人脸一致性**：同角色不同姿态五官/脸型是否统一，会不会「换姿态就换脸」；
2. **Depth 贴合度**：肢体与深度图是否匹配，会不会边缘崩坏/肢体扭曲；
3. **画风统一性**：三控叠加后整体美术风格是否与基准样一致，会不会质感割裂。

以上三项首批实产出图后人工确认，参数固化后再全量推进。

### 10.5 注意事项

- `gen_validation.py` 的 **英文提示词目前混用中文身份字段**（gender/age/temperament 等字段值取自 JSON，为中文）。项目主用中文 SD（ComfyUI/A1111 用中文 CLIP），不影响；若后续需走纯英文模型（如 Midjourney），在 JSON 中补 `*_en` 字段并在脚本里做映射。
- 真实后端运行时加 `--mark`（默认开启）会把 `disciple_manifest.csv` 中已跑弟子的 `status` 置为 `生成中`；`已验收` / `需重绘` 必须人工回填。
- ③ Depth + ④ IP-Adapter 人脸一致性已接入 `batch_generate.py` / `gen_validation.py`（机制见 §5.2 / §5.3），扩容 90 张前**无需再补一致性底层**，直接进入 §八 执行流程即可。
