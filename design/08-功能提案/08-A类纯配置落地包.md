## 一、事件分级与文案补充

### 1.1 定位
复用现有随机事件框架（`quest.gd` 已真接地 opt 选择），为事件池新增**分级维度** `触发周期`（日常 / 年度 / 七载），补充 35 条纯体验/文案向事件（20 日常 + 10 年度 + 5 七载），丰富世界氛围与节令仪式感。全部新事件**零经济触碰**（奖励仅用既有的社交/声望类轻量反馈，不引入灵石/产出/消耗）。

### 1.2 红线
- 不新增/修改任何 `灵石 / 产出 / 消耗` 数值；新事件 `is_counted_in_balance=false`（显式排除经济平衡核算）。
- `base_value / level_factor / min_value / max_value / display_level / weight_decay` 六列**留空占位**（非经济，无需填）。
- 不引 `personality_config.csv` / `negative_event.csv`；不分发任何"负面影响/特质"语义。
- 新增列 `触发周期` 必须置于 **header 末尾（第 29 列）**，不得插入中间，以保 `quest.gd` 固定索引解析安全。

### 1.3 复用现状 · 诚实标注
- ✅ **纯配置 + CSV**：`event_quest.csv` 现有 28 列全复用；opt 列已由 `quest.gd` 消费，新事件直接套用选择型结构（opt3 留空，与 R001 等同构）。
- ✅ **loader 兼容**：`DestinyDataLoader._read_csv` 按 header 对齐、容忍末尾列；新列追加末尾对旧行=补空、对新行=填充，零破坏。
- ⚠️ **需轻量代码（仅触发分发，非数值）**：`触发周期=年度/七载` 的事件需由对应弹窗钩子（岁末考评 `game_state` L1082 / 七载大典 `main.gd` L1162）按 `触发周期` 过滤读取并展示；随机池按 `trigger_type` 过滤（`yearly`/`sevenyear` 暂无随机池消费者 → 不会误入日常池）。本包**仅交付 CSV + 触发逻辑描述**，不含运行时实现。
- ⚠️ **奖励语义边界**：新事件 opt 奖励限定为既有社交/声望类轻量反馈（弟子好感± / 宗门声望小幅+），与现有 D/V 类事件（如 D002 好感+2、V004 人气）同口径，**不进入灵石经济**；若后续要加数值奖励，须走经济审计，不在 A类。

### 1.6 GDD 片段：触发逻辑（设计描述，非运行时代码）

- **日常（触发周期=日常）**：`trigger_type=monthly` → 进入现有随机事件池，由 `quest.gd` 现有分发路径真接地；玩家在「纪事 / 随机事件」中正常看到选择型事件。
- **年度（触发周期=年度）**：不进随机池（`trigger_type=yearly` 无随机消费者）。在**岁末考评**结算点（`game_state` L1082 附近）读取 `触发周期=年度` 的事件，于岁末考评卡片/弹窗内作为「当年风物」前置展示（纯文案 + 轻量选择反馈）。
- **七载（触发周期=七载）**：不进随机池（`trigger_type=sevenyear`）。在**七载大典**弹窗（`main.gd` L1162 `_弹七载大典`）读取 `触发周期=七载` 的事件，作为大典「盛事风物」模块展示。
- **回退**：`触发周期` 为空（旧档/未填行）→ 默认按 **日常** 处理（或仅入随机池），不影响现有事件展示。

1. **event_quest.csv 列冲突：无**。B类三项均为新建独立 CSV（评级维度.csv / 弟子特质.csv / 负面影响开关.csv），不向 `event_quest.csv` 追加列；A类第 28 列 `触发周期` 安全。B类负面效果走 `negative_event.csv`（独立文件，现状摆设，B类为其新建消费者），不碰 `event_quest.csv`；若未来 B类想让负面事件也吃「触发周期」节奏，约定**复用 A类已定义的 `触发周期` 语义**（日常/年度/七载），不另开列。
2. **七载大典弹窗模块顺序（已锁定）**：`〔灵石〕〔法宝〕〔晋升〕 → 〔本周期四维评分〕(B类预留槽位) → 〔本次解锁权益〕(A类)`。A类仅在末槽位渲染，不抢占评分明细槽位；B类后续按 `双周期评级体系.md` §5「评分→晋封→权益」叙事流填充分维明细（底蕴/梯队/盈余/声望）。
3. **数据流向（单向，无冲突）**：若 A类「品级权益映射.csv」需评级维度作门槛，方向为 B（评级维度.csv）→ A（权益映射）单向引用。B类 `评级维度.csv` 已定四个 stable key：**dundi(底蕴) / tidui(梯队) / yingyu(盈余) / shengwang(声望)**，待 A类权益映射需绑定四维门槛时，B类单向提供，A类按 key 引用，不反向写 B类表。
4. **补救通道（赏赐/修缮/扬威）**：属独立 UI 面板，不在七载弹窗内，与 A类模块无重叠。
5. **对齐纪律**：B类任何改弹窗/加列动作前先与 A类对齐；A类新增列一律置 `event_quest.csv` 末尾以保 `quest.gd` 固定索引兼容。

> **A类落地包结论**：三项均为零经济触碰的纯配置/纯文案项，可直接启动，不依赖经济审计结果；仅年度/七载事件与弹窗模块、纪事查询/面板需轻量代码（非数值），由 engineering-lead 在 S1 排期落地。跨团队（design-b-frame）已确认零冲突并锁定弹窗模块顺序与列占用纪律。
