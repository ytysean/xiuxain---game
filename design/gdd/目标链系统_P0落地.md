## 一、概述与定位

目标链系统 P0 是新手期「目标 → 反馈 → 下一步」闭环的核心承载，由三块构成：

1. **每日任务 UI 闭环**：既有 `daily_001~003` 接到目标面板，支持领取、数值跳字、底部 Tab 红点、前往按钮。
2. **新手阶梯目标 7 条**：混合主动 / 自动，上一条完成才解锁下一条；主动型配「前往」跳转，自动型检测到即自动完成发奖。
3. **指引收尾承接**：FTUE 最后一步（原 `_引导_收尾` 空白结算）替换为「宗门初立指南」文言弹窗，给 3 个一键跳转目标，解锁 `newbie_001`。

设计硬约束：不擅自改设计、不超范围、不碰底层数据字段 / 键 / 存档结构本身（仅增 UI 展示与配置行）、零死目标、`pre_f5_check.py` 必须 19/19 全绿 EXIT 0。

## 二、核心规则

### 2.1 混合方案（主动 + 自动）

- **主动型**（需玩家点击前往触发）：`newbie_001` 再纳弟子、`newbie_002` 首遣历练。UI 显示「前往处理」按钮，按 `jump_path` 跳转。
- **自动型**（事件 / 状态命中即自动完成发奖）：`newbie_003~007`。UI 显示「（自动达成中，静候机缘）」。

### 2.2 解锁链（顺序推进，零死目标）

`prev_quest_id` 推导解锁：上一条未完成则下一条不解锁；完成当前条后立即 `_新手_评估后续()` 预检并可能连续解锁多条状态型目标，避免「死目标」。

```
newbie_001 → newbie_002 → newbie_003 → newbie_004 → newbie_005 → newbie_006 → newbie_007
（prev 为空 = 链首，由 激活新手目标链() 直接解锁）
```

### 2.3 检测点分类

- **事件型**（钩子即证据，命中即完成）：`recruit_count` / `realm_first_enter` / `collect_income` / `event_first_trigger`。
- **状态型**（每次激活 / 月结预判当前状态）：`recruit_count_5` / `disciple_realm_3` / `disciple_realm_5`——由 `_新手_评估后续()` 依据 `弟子列表` 当前状态预判，无需玩家额外操作，杜绝「永远达不成」。

### 2.4 奖励与反馈

- 完成发灵石 / 灵气（`reward_lingjing` / `reward_lingqi` × `任务奖励系数()`），并抽 `pool_newbie`。
- 写入纪事（琐事分类），`新手目标更新` 信号驱动 UI 刷新（玉牌红点 + 底部 Tab 红点 + 数值跳字 + 面板实时刷新）。
- 抽池 P0 范围：仅结算可量化部分（气运 → 玄玉+1；其余 → 灵石+20），不向「宗门库房」（Item 实例数组）写入非 Item 字典，避免破坏 save/load。

## 四、交互 / UI 要点（main.gd）

- **玉牌入口**：`_建_玉牌()` 在 `_建_宗门页()` 中 `内容.add_child(_建_玉牌())`（L429）；主按钮样式「宗门要务」+ 朱砂红点 `ColorRect`。
- **宗门要务面板**：`_打开_宗门要务()` 弹窗遮罩（`弹窗遮罩` alpha）+ `_填_宗门要务()`——进行中标题 / 当前目标名 + 描 / 主动型「前往处理」按 `jump_path` → `_跳转()` / 自动型「静候机缘」/ 已完成列表 / 关闭。
- **底部 Tab 红点**：`_刷新_新手UI()` 以 `Named("新手红点")` 定位 Tab0 角标，亮起条件 = `新手_有红点() or _有未领日常()`。
- **数值跳字**：`_数值跳字(父, 文本, 色)` 用 `create_tween()` 上浮淡出；日常领取时跳 `灵石+N 灵气+M`（玉石绿），新手目标完成时跳 `宗门要务 第N项达成`。
- **跳转高亮**：`_跳转(路)` 按 `/` 拆分：宗门 / 弟子（二级 tab：接引=1、名录=0、详情=0）/ 历练 / 纪事 / 御兽 → `_on_主导航切换` + 二级页切换（宗门/收益栏 → 账册）。
- **FTUE 收尾承接**：`_引导_收尾()`（L2409）原空白结算替换为「宗门初立指南」文言弹窗（开坛接引 / 稽核收益 / 遣徒历练三策），「知道了」为次按钮，新增 3 个主按钮跳转（弟子/接引、宗门/收益栏、历练/秘境），点击先 `_引导_清除()` 再跳转；并在 `Game.引导阶段 = 6` 后调用 `Game.激活新手目标链()`（L2460）。
- **跳过路径兜底**：`_引导_跳过()`（L2466）同样在 `Game.引导阶段 = 6` 后调用 `Game.激活新手目标链()`（L2468，本会话补入）——确保跳过引导的玩家也不会落入「无目标」死局（`激活新手目标链()` 幂等，重复调用安全）。

> 全部按钮沿用 main.gd 顶部常量（主绿次棕、暗金、玉石绿、朱砂、弹窗遮罩、暗化），字号取自 `{22,17,18,16,15,13}`，背景 `BG_SCENE_ALPHA=0.30` / `弹窗遮罩` alpha=0.60；未新增 Tab（恒 5），通过 pre_f5 第 17/18/19 道闸。

## 八、遗留风险与决策记录

1. **跳过路径激活（决策）**：本会话补入 `_引导_跳过()` 调用 `激活新手目标链()`，以兑现「零死目标」硬约束；原补丁锚点仅命中 `_引导_收尾`。该调用幂等，若主理人认为跳过玩家不应获得新手引导，可移除 L2468 一行。
2. **gate 16 类型名 WARN（不阻断）**：存在 1 处未知类型名 WARN，经核查为预存项（`PanelContainer` / `Tween` 为 Godot 4 标准类型，本落地新增标注均为合法类型），不阻断 F5。
3. **抽池折算（已知简化）**：P0 不向库房写非 Item 字典，故材料 / 丹药落地为 +灵石，与「真实掉落物入库存」存在体验差，待 S1 库房结构化后闭环。
4. **临时补丁脚本**（非交付物）：`_patch_csv.py` / `_patch_gs.py` / `_patch_main.py` 仍留于项目根，可后续清理（不影响运行与 pre_f5）。
