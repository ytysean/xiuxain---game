## 0. 一句话结论

**推荐「方案 A′（改良 A）」：语义权威 + 渲染解耦。**

豆包的**大方向（保持 Control、分块渲染、迷雾按 chunk）是对的**，但它把两件必须分开的事**焊死在了一起**——「数据权威层」和「渲染层」：

- 它让 **噪声决定地形类型与区域归属** ⇒ 会拆掉现有的五域语义系统（灵钓档 / 灵兽品阶 / 化身桥接 / 风水 / 修炼加成全靠 `区域` 字段）；
- 它让 **地点/资源按 chunk 确定性生成** ⇒ 会拆掉 12 城镇手写固定坐标，与 `city_config.csv` 真源脱钩，连带废掉通商 / 朝贡 / 商情。

**正确做法**：世界（区域、城镇、资源、宗门）永远是**手工权威的有限世界**；噪声和分块**只做外观与渲染剔除**，不参与任何玩法判定。同时必须补一个豆包方案里**完全没有**、却是全局最关键的东西：**逻辑坐标 ↔ 视觉坐标解耦**。

另外方案 B（Node2D+TileMapLayer）与 C（SubViewport）**均不推荐**，理由见 §2.2。

## 1. 评审前置：三个必须先摆上桌的硬事实

评审任何"无限大地图"方案前，必须先看清现有系统的三个事实。豆包方案没有覆盖它们，而它们决定了方案的生死。

### 1.1 现有地图的"小"，是**内容密度**问题，不是**画布尺寸**问题

| 内容 | 实际坐标范围 | 现存画布 |
|---|---|---|
| 宗门坐标 | ±200 | 2000 × 2000 |
| 12 城镇坐标 | ±200（最大跨度 ~420） | 同上 |
| 其他宗门（模拟 15-20 家） | ±200 | 同上 |
| 资源点（初始化 8 个） | 宗门周边 50~300 | 同上 |
| 钓点（按区域生成） | 宗门心周边 220~420 | 同上 |

**全部玩法内容挤在中心 ±420 的方框里，只占 2000² 画布约 18% 的面积。** 换算到实机：默认缩放 0.6 时逻辑视口约 1800×3020，**已经能一眼看到整幅内容区**；最小缩放 0.3 时视口 3600×6040，**比整张 2000² 地图还大**——屏幕四周全是空白。

⇒ 老大感觉"地图小、不像天下"，**根因是内容只覆盖了一小块，不是画布不够大**。把画布扩到 8000² 或"无限"，只会让空白更多。

### 1.2 逻辑坐标是**语义载荷**，不能随意放大

坐标数值直接喂给这些公式（全部在 `world_map_system.gd`）：

```gdscript
计算运输时间(距离)  = ceil(距离 / 基础速度)         # 普通商队 15 / 精锐 30 / 距离单位·日
计算行军时间(距离)  = ceil(距离 / 25) * (跨域 × 1.5)
计算被劫风险(距离)  = clamp(距离 / 500, 0.05, 0.6)
资源距离衰减(距离)  = clamp(1 - 距离 / 1000, 0.5, 1.0)
```

现有坐标尺度下，宗门到最远城镇 ≈ 400 距离单位 → 运输 **~27 游戏日**（合理）。

**若把逻辑坐标扩到 10000²（豆包的"固定 100000×100000"尺度），距离变成 ~14000 → 运输时间 933 日、行军 560 日 ⇒ 商队与宗门战系统当场报废。**

⇒ **"无限坐标"绝对不能直接落到逻辑坐标上。** 无缝必须做在「逻辑坐标 → 视觉坐标」的映射层。

### 1.3 迷雾探索**当前根本没存档**（现存缺陷，正好一并修）

`_已探索网格` 是 `page_world_map_visual.gd` 的**页面局部变量**，而 `world_map_system.to_dict()` 里**没有迷雾字段**。地图页每次重新进入都会 `Control.new()` + `set_script()` 重建 → **迷雾进度每次清零**，只剩 `_ready()` 里 `_探索区域(中心, 300)` 的初始一小圈。

⇒ 也就是说，**"迷雾探索"这个玩法现在实际是不成立的**：玩家探索完一关页面就全白回来。任何"按 chunk 管理迷雾"的方案，**第一步都必须先修好存档**，否则 chunk 化只是把"会丢的迷雾"换了种丢法。

## 2. 五维评审

### 2.1 方案 A（Control 分块加载）可行性

**✔ 对的部分**：保持 Control 架构、不动现有 UI 体系、复用现有地点/事件/资源逻辑——判断正确，是低风险路线。

**✘ 逐条问题（具体，非泛评）**：

| # | 问题 | 依据 |
|---|---|---|
| A-1 | **Chunk 尺寸 500 + 加载半径 1 的估算错了 5~17 倍** | 豆包按"竖屏视口 400×700 @0.5"估算。真实 Godot 竖屏是 **1080×1920**，地图视口 Control = 1080 × 1812（顶栏 48 / 底栏 60 扣除）。逻辑可见范围 = 视口 ÷ 缩放：<br>• 缩放 0.6（`_定位到宗门` 默认值）→ 1800×3020 → `ceil(1800/500)×ceil(3020/500)` = **4×7 = 28 chunk**<br>• 缩放 0.3（最小）→ 3600×6040 → **8×13 = 104 chunk**<br>加半径 1 的常驻：0.6 时 ≈ 54、0.3 时 ≈ 150 chunk ⇒ 150×15 = **2250 节点，比现状 500 节点更重**。<br>⇒ 豆包"常驻 20 chunk / 2×3=6 可见"的假设与真实竖屏不符，**按此实现会做出一个比现状更卡的地图**。 |
| A-2 | **"节点数从 500 降到 300"不成立** | 现状实测 500 节点（400 迷雾 + ~50 地形 + ~50 标记）。按 §A-1 重算，chunk 化要么节点更多，要么必须换 chunk 尺寸。豆包的性能收益论证**建立在算术错误上**。 |
| A-3 | **FastNoiseLite 决定"地形类型 + 区域归属" ⇒ 破坏五域语义** | `区域` 字段是全工程语义主键：灵钓档（`区域灵渊档`）、灵兽品阶（`区域妖兽品阶`）、化身游历桥接（`化身游历桥接`）、风水（`区域风水`）、修炼加成（`区域特性`）、城镇归属、宗门战跨域判定——**全部读它**。噪声生成的区域边界不可能与这些手写映射对齐。 |
| A-4 | **地点/资源按 chunk 确定性生成 ⇒ 与 `city_config.csv` 真源冲突** | 12 城镇坐标是**手写常量**、且与 `city_config.csv` 的 12 个城镇一一对应；`获取城镇商情/获取货品城价/城镇通商/城镇朝贡` 全挂在它上面。改成"按 chunk 种子生成"会直接与真源脱钩，且无法保证"每个 chunk 恰好生成它该有的城镇"。 |
| A-5 | **完全没提"逻辑坐标 vs 视觉坐标"** | 见 §1.2。这是方案的**致命缺口**：不解决它，"放大世界"必然打爆商队/宗门战平衡；解决了它，chunk 的必要性又大幅下降。 |
| A-6 | **迷雾迁移没提存档** | 见 §1.3。迁移的前提是先让迷雾可持久化，方案未触及。 |
| A-7 | 噪声地形好不好看 | 豆包自己标了"P2 加纹理"，属于自知风险；但*"地形 6 类有速度/可通行字段却零消费方"*——现有 `地形类型` 的 `速度/可通行` 字段**没有任何寻路或移动消耗代码读它**（弟子探索是"字典记账 + 按日结算"，不做格子移动）。所以地形**当前纯粹是装饰**：噪声做装饰可以，但**不能**让它决定"区域"。 |

### 2.2 替代方案

**方案 B（Node2D + TileMapLayer）— 不推荐**

| 维度 | 判断 |
|---|---|
| 收益 | ≈ 0。当前 500 节点在 Godot Control 上拖动帧率已满（拖动只改 `position`/`scale`，不重建节点）。 |
| 成本 | 大。项目是**纯代码 UI + UITheme 主题体系**（55 个二级页、字体/颜色/9-patch 全走 `add_theme_*_override`），Node2D 子树不继承 Control theme 体系，需为地图单独造一套渲染与主题适配。 |
| 额外依赖 | TileMapLayer 需要 **tile 美术资产**（项目没有，也不打算做——见 §1.1 内容才是瓶颈）。 |
| 结论 | **投入产出比最差**，且会破坏"纯代码 UI"这一架构基线。 |

**方案 C（SubViewport + Node2D）— 不推荐**

- SubViewport 内的节点用子视口坐标系，**脱离现有 UITheme 主题系统**；且 `tests/ui_full_accept.gd` 里**已有"排除 SubViewport 内节点"的特判**（第 19 / 228 行注释），说明历史上已经踩过 SubViewport 与现有截图/布局校验体系不兼容的坑。
- 收益同样≈0，风险更高。

**方案 D（"只扩画布 + 视觉解耦"，不引入 chunk）— 推荐作为 MVP 基础**

若最终世界尺度不必超过 ~4000²，则 **chunk 本身就可以不做**：把逻辑↔视觉解耦 + 阴影/云雾柔化边界 + 内容扩充，就能拿到"无缝观感"。chunk 留作**节点数真正超阈值时**的按需优化（见 §3.4 触发条件）。

### 2.3 与现有系统的冲突点

| 系统 | 是否依赖坐标数值尺度 | 影响与适配 |
|---|---|---|
| `caravan_system.gd` | **是**（`计算宗门间距离`→运输时间；`城镇坐标表`→城镇区域） | 解耦后逻辑坐标不变 ⇒ **零影响** |

| `achievement_system.gd` / `xuan_rank_system.gd` | 否（读`获取探索进度`/`获取天下探索统计`） | 零影响 |
| 弟子派遣/行军 | 否（`探索中弟子` 字典独立记账，不写 `Disciple.状态`；坐标仅用于距离） | 零影响 |

⇒ **结论：只要坚持"逻辑坐标不动"，整个改造的爆炸半径极小，只有 2 个文件 + 1 个新字段。**

### 2.4 性能与移动端

| 项 | 实测/推算 | 判断 |
|---|---|---|
| 现状节点数 | 500（400 迷雾 + 50 地形 + 50 标记） | Godot Control 渲染千级节点在中端机（骁龙 6 系）**无压力** |
| 拖动帧率 | 拖动只改 `_地图层.position` / `.scale`，不重建节点 | **当前已是 60fps**，不是瓶颈 |
| 内存峰值 | 纯色 `ColorRect`/`StyleBoxFlat`，无纹理 | 几乎为 0，**不存在纹理显存问题** |

⇒ **性能不是本任务的驱动因素。** "无缝大地图"的价值在**体验**（大世界的沉浸感），不在帧率。任何以"性能"为由的架构大迁移（B/C）都缺乏依据。

## 3. 推荐方案 A′（完整设计）

### 3.1 核心思想：三层解耦

```
┌─────────────────────────────────────────────────────┐
│ ① 语义权威层（手工、有限、可存档）                    │
│    五域 / 12城镇 / 资源点锚点 / 其他宗门 / 宗门坐标     │
│    → 驱动全部玩法判定（灵钓·灵兽·化身·风水·商队·宗门战）│
│    → 逻辑坐标尺度【保持不变】(±200 域内)，存档零迁移     │
├─────────────────────────────────────────────────────┤
│ ② 外观生成层（程序化、装饰、无判定）                  │
│    FastNoiseLite 只决定【地形外观/云雾/远山/装饰纹理】   │
│    → 不参与任何区域/地点/资源判定                       │
├─────────────────────────────────────────────────────┤
│ ③ 渲染层（视觉坐标、可任意缩放、可分块剔除）            │
│    逻辑坐标 × 世界地图映射系数 = 视觉坐标                │
│    → 无缝平移缩放 / 边界柔化 / 按需 chunk 剔除           │
└─────────────────────────────────────────────────────┘
```

**一句话**：玩法看①，好看靠②，好滑靠③。三者互不越界。

### 3.2 坐标双轨（本方案的技术核心）

- **逻辑坐标**（`world_map_system.gd` 里所有 x/y）：**不变**。仍是 ±200 域内，仍是所有距离公式的输入，存档不迁移。
- **视觉坐标**（渲染层）：`视觉 = 逻辑 × K + 偏移`，`K = 世界地图缩放系数`（新增常量，唯一真源）。

收益：
1. 想"世界看起来更大"，只需调大 **视觉画布** 或 **K**，逻辑坐标与全部平衡公式**纹丝不动**；
2. 想加"无限"感，只需让视觉画布足够大 + 边界云雾柔化，**不需要真无限坐标**；
3. 存档、商队、宗门战、化身、灵钓**全部零适配**。

> 这也是为什么 §1.2 的"平衡耦合"不会成为障碍——**把尺度问题关在渲染层里**。

### 3.3 世界尺度定稿建议

| 层 | 建议值 | 理由 |
|---|---|---|
| 逻辑世界 | **维持现状**（域内 ±200，内容 ±420） | 保平衡、保存档 |
| 视觉画布 | **2000² → 3200²**（可调） | 给"天下"留白，让边界"在屏幕外"，消除"撞墙"感 |
| 内容密度 | **点位数 ~35 → ~150-200**（★真正的关键） | 把留白填成"远山/云雾/小聚落"，而不是空白 |

**★ 必须点明**：无缝大地图 60% 的工作量在**内容设计（策划）**——定义"天下"该有多少域、每域多少点位、点位怎么分布。技术层（②③）只是让这些内容"装得下、看得远、滑得顺"。**只做技术不做内容，地图照样空。**

### 3.4 渲染分块（条件启用，非默认）

**启用阈值**：可视节点数 > 800 时才启用（当前 500，未触发）。

若启用，按以下**修正后**的规则（**替换豆包 §2.1 的错误参数**）：

1. **chunk 尺寸按"目标可见数 ≤9"反推**，而非固定 500：
   - 缩放 0.6（默认）逻辑视口 1800×3020 → chunk ≈ **1024** ⇒ 2×3 = 6 可见；
   - 缩放 0.3（最小）→ 4×6 = 24 可见，仍在可控范围。
   - 或收紧缩放范围（如最小 0.4 而非 0.3）以压住极端情况。
2. **必须用对象池**，不能 `queue_free` 后重 `new`（`queue_free` 有帧末延迟 + 每帧分配会产生 GC 峰值）。chunk 节点出视口后 `hide()` + 复用。
3. **chunk 只承载"渲染物"**（地形色块 / 装饰 / 迷雾格 / 标记节点）；**地点数据永远在语义层全局持有**，chunk 只是它的一个"视图"。

### 3.5 迷雾持久化（P0 必做）

- 新增 `world_map_system` 字段：`已探索网格: Dictionary`（key `"cx_cy"` 复用 100 单位网格），写入 `to_dict/from_dict`；
- `page_world_map_visual.gd._已探索网格` 改为**读写 `Game.世界地图系统.已探索网格`**；
- 迷雾视觉层继续按网格渲染；chunk 化时迷雾格归属 chunk（§3.4）。
- **验收**：探索 → 关闭地图页 → 重开，探索区域**保持点亮**。

### 3.6 地形外观（噪声只做装饰）

- `FastNoiseLite` 允许使用，但**只允许决定**：地形色块的形状/密度、云雾分布、远山轮廓、装饰纹理。
- **禁止**用于：区域归属、地点生成、资源分布、可通行判定。
- 6 种地形的 `速度/可通行` 字段保持"预留"状态（当前零消费方），**不新增寻路玩法**（对齐 §11.10"零独立玩法"红线）。

### 3.7 边界柔化 = "无缝"观感的落地手法

"无缝"的体验本质 = **看不到边界、看不到加载、看不到接缝**。三招（纯渲染，零逻辑）：

1. **地图四边用云雾/渐变 alpha 淡出**（ColorRect + Gradient 或 `draw_` 渐晕），让"到边了"看起来像"云深处"；
2. **缩放极值保护**：最小缩放让整图刚好略小于视口，避免露出画布外的纯黑暗区；
3. **平移阻尼 + 惯性**（可选，Tween），拖动手感从"硬拖"变"顺滑"，主观"无缝"感大幅提升。

## 4. 与总纲 v2.30 §11.10 的口径裁决（需老大拍板）

**发现的口径张力**：

> `核心设定总览 §11.10` 明文：「全程点位式交互，**无自由行走 / 实时探索 / 大地图自由操控**等重度 MMO 功能」「§11.10.2 采用『区域划分 + 点位标记』轻量化形式……**无需实时操控移动**」

**但**现有 `page_world_map_visual.gd` 已实装**拖拽 + 缩放**的可视化地图（S58-P3），**已经超出**该 doc 的"分类列表"基线（§11.10.4 MVP 原定"用分类列表替代完整地图"）。

**我的建议（澄清而非推翻）**：在 §11.10.2 补一句界定——

> 「地图**视野**支持自由平移与缩放（无缝浏览），但**玩法交互仍为点位式**：所有玩法靠点击点位标记派遣，**不做人物自由行走 / 实时操控**。」

这样既**不违背"轻量化放置"红线**（红线针对的是"实时操控玩法"，不是"相机平移"），又给"无缝浏览"留出合法出口。**这条建议请老大定夺**（属设定文档变更，不宜由我单方拍板）。

## 5. MVP 范围建议

**MVP 目标**：拿到"无缝观感"，**不动逻辑坐标、不动玩法、不引入 chunk**。

| # | 交付 | 是否必做 |
|---|---|---|
| 1 | **坐标双轨**：新增"逻辑↔视觉映射"常量，渲染层统一走它 | ✔ 必做（地基） |
| 2 | **迷雾持久化**：`已探索网格` 入 `world_map_system` 存档 | ✔ 必做（修现存缺陷） |
| 3 | **边界柔化**：四边云雾/渐变淡出 + 缩放极值保护 | ✔ 必做（无缝观感核心） |
| 4 | **平移阻尼/惯性**（可选） | ○ 选做 |
| 5 | **视觉画布 2000² → 3200²** | ○ 选做（视内容而定） |
| 6 | 地形噪声装饰 | ✘ 后置（P2） |
| 7 | chunk 分块渲染 | ✘ 后置（节点 >800 才做） |

**MVP 明确不做**：无限坐标、噪声决定区域、按 chunk 生成地点、Node2D/TileMap/SubViewport 迁移。

## 10. 裁决记录（2026-09-14 老大拍板）

| 裁决项 | 结论 | 落地 |
|---|---|---|
| **① 世界尺度** | **有限放大**：画布 2000² → **4000²**；**不做真无限**（真无限列为远期选项，等内容密度撑满 4000² 再议） | 已落码：`page_world_map_visual.地图宽度/高度 = 4000.0` + `世界映射系数 = 2.4`（坐标双轨） |
| **② §11.10 澄清** | **采纳** | 已落盘：总纲 §11.10.2 补入「视野与操控的边界」+「坐标双轨（技术约定）」两段 |
| **③ 内容规模** | **分阶段**：MVP **80–100** 点位（关键城镇 / 资源点 / 秘境 / 钓点，优先填空白区）；完整版再扩 **150–200** | 本轮已做第一波：资源点 8 → **41**（宗门左近 6 + 五域各 7）+ 每域 2 秘境（共 10）+ 装饰填充（每域 14 块） |
| **④ MVP 开工** | **现在开**（含迷雾存档 bug 修复） | 已落码：迷雾持久化 / 坐标双轨 / 边界柔化 / 缩放极值保护 / 平移惯性 |

**据此定稿的解释口径**：
- 「世界更大」= 画布 ×2 + 视觉映射 ×2.4，**逻辑坐标一寸未动** ⇒ 商队运输（`距离/15~30`）、行军（`距离/25`）、被劫风险（`距离/500`）、资源衰减（`距离/1000`）全部零适配，**存档零迁移**。
- 范围约束：五域逻辑范围最大 ±700 → ×2.4 = ±1680（画布半宽 2000），**区域底板铺满画布中央 84%**，四边留 320 供内容继续长。
- chunk 分块渲染**仍未启用**（当前节点数 ≈ 550 < 800 阈值）——按 §3.4 触发条件后置。
- `已探索网格` 已入 `world_map_system.to_dict/from_dict`（键 `"列_行"`，4000/200 = 20×20 = 400 格）。
