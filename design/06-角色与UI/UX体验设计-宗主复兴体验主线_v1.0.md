# 《太玄宗门录》UX 体验设计 · 宗主复兴体验主线

> **一句话定位**：本项目已有「架构层」与「交互效率层」两层 UX，**唯独缺「体验层」**——这正是"作为玩家觉得还不够好、却说不上为什么"的根因。本文档补上这第三层，把游戏从「一个高效的宗门管理系统」升级为「一段让人沉浸的宗主复兴史诗」。

---

## 0. 定位：三层 UX，缺的是第三层

### 0.1 为什么"说不上为什么不够好"

因为此前所有 UX 工作是**工程视角的效率优化**，而非**玩家视角的体验设计**。两者关心的东西不同：

| 层 | 关心的问题 | 本项目现状 | 归属文档 |
| --- | --- | --- | --- |
| **① 架构层** | 东西**放哪**、怎么分组、何时解锁 | ✅ 已有（四套冲突已裁决） | `UX基线-信息架构裁决与冻结 v1.0` |
| **② 交互效率层** | **点几下**、怎么不累、怎么少操作 | ✅ 已有（一键化/托管/分层） | 核心设定 §11.22 |
| **③ 体验层** | **为什么想打开**、玩着爽不爽、关掉记不记得住 | ❌ **缺失** | **本文档** |

**关键诊断**：`§11.22` 的纲领是「新手 3 分钟看懂核心经营循环」「操作步数只减不增」「复杂逻辑后台化」——这全部是**把游戏当工具在优化**。工具优化的尽头是"好用但没有灵魂"。玩家不会因为"一键收菜"而爱上这款游戏，只会因为**"我的破宗门又活过来了一分"**而留下来。

> **结论**：老大作为玩家的"说不上为什么"，是因为我们一直在优化"怎么玩得更省事"，而没设计"玩起来是什么感觉"。**本章补的，就是"感觉"。**

### 0.2 三层不可互相替代

- 架构层做得再好，玩家也只是「找得到」；
- 效率层做得再好，玩家也只是「不累」；
- 只有体验层到位，玩家才会「想回来」。

三层同时成立，UX 才完整。本文档不推翻前两层，只在其之上补情感与节奏。

## 1. 全网调研 · 博采众长（可迁移洞察）

> 调研范围：国内外 UX 理论（Nielsen Norman Group「渐进披露」、认知负荷理论）、游戏 UI 专业资源库（**Game UI Database 2.0** 55,500+ 屏、**Interface In Game** 20+ 元素分类）、技术博主（**Game Maker's Toolkit** Mark Brown）、同类修仙/模拟经营竞品（了不起的修仙模拟器 / 一念逍遥 / 最强祖师 / 觅长生 / 鬼谷八荒）、PC 模拟标杆（RimWorld / Factorio / 星露谷 / 庄园领主）、放置赛道研究（GameAnalytics / Melior Games / 多篇 juice 专题）。

| # | 来源 | 核心洞察 | 对本作的启示 |
| --- | --- | --- | --- |
| 1 | 了不起的修仙模拟器（玩家自述） | "各阶段目标**一环套一环**，长期修仙之外有门派建设等中期目标、吃喝拉撒等短期目标，催促我勿要懈怠" | **目标牵引链**：短/中/长三层目标必须显式环环相扣，而非各管各的任务列表 |
| 2 | 同上（评测） | "被地图繁杂资源与乱跑 NPC 搞得晕头转向；**上手门槛极高**（类比欧陆风云）" | 复杂≠好。**信息层级**与**渐进披露**是护城河而非妥协 |
| 3 | RimWorld UI | 右上角**主动 alerts**（要疯/要救）；情境化 inspect pane 随选中对象变化；时间控制置于固定位 | **情境化主动信息**：系统主动"报忧"，而非等玩家去翻页找 |
| 4 | Factorio / 庄园领主 | 顶部资源栏 + 底部行动栏 + 中央世界，三层固定分区；信息密度高但**分区严格** | 首页/主界面**固定分区**，高频行动锚定拇指区 |
| 5 | 一念逍遥（评测） | "主界面按钮**风格统一**，UI 简洁；但后期解锁内容越多越**拥挤冗杂**" | 统一风格是优点，**拥挤是必然趋势**→必须靠分组+层级提前消化 |
| 6 | 最强祖师（DataEye 分析） | 弟子天赋/特质/属性**随机组合**、师傅互动、**弟子见闻各不相同** → 记忆点与传播点 | 把「弟子」做成**有故事的生命**，而非数值条目（本作已有自主 AI 与见闻，需在 UI 层放大） |
| 7 | 原神 / 哈利波特·魔法觉醒 | 主界面即**世界观入口**：动态场景、随现实时间变化的角色姿态；动态场景界面首启停留时长 **+37%** | **"活的宗门"**：首页背景承载环境叙事，而非静态贴图 |
| 8 | 第五人格 / 昆特牌 / 百闻牌 | **叙事化 UI**：起雾制造氛围、公告栏+火漆表达契约、猫咪引导 | 功能外壳**故事化**（签到→日诵、任务→法旨），契合本作修真化命名铁则 |
| 9 | Juice / Game Feel 专题 | 反馈放大（弹跳数字/粒子/屏震/音效）能让同一机制"活起来"；**建议最多花一半工时做 polish** | **高光时刻仪式化**：突破/奇遇/大典是全屏级事件，不是 toast |
| 10 | 放置赛道研究 | "5 分钟内必须出现**有意义决策**"；反面是 **spreadsheet syndrome**（数值表格糊脸）；离线收益应"有惊喜但不喧宾夺主" | 开局即给决策；数值**可视化**代替表格；离线收益要**有仪式地"领取"** |
| 11 | 会话设计（retention 专题） | 每次会话结束要有**可见的下一步**（倒计时/酝酿中/里程碑）；"失败不是留存杀手，失败周边的摩擦才是" | **回归钩子**：离开时永远有一个"正在发生、等你看结果"的事 |
| 12 | 视觉层级（strategy UI） | "**如果一切都重要，那就没有重要的**"；一屏一个主焦点，比周围大 20%+ | **单一主行动**：每页一个 Primary Action，其余退让 |
| 13 | NNG / 认知负荷理论 | 工作记忆容量有限；**渐进披露**优于一次性全给 | 与架构层 U2 一致，此处用于**情绪节奏**而非仅功能开关 |
| 14 | 不可能三角（功能全面/界面简洁/交互便捷） | 三者无法同时最大化，必须取舍 | 本作取舍：**保功能全面 + 交互便捷，牺牲"信息全显"**（靠分层收纳） |
| 15 | Game UI Database / Interface In Game | 按屏型/元素/主题检索真实商用案例，是布局与层级的事实标尺 | 列入 UI 布局重构的**参考工作流**（见附录 A） |

**调研总纲（一句话）**：**效率让人不累，体验让人不舍。** 本作前者已完成，后者待补。

## 2. 体验诊断：五处"失"

对照调研，本作作为「作品」而非「工具」的体验缺口如下：

| # | 症状（玩家感受） | 根因（设计层） | 对应支柱 |
| --- | --- | --- | --- |
| **D1 目标失锚** | "打开不知道现在该干嘛" | 无"当前该做的事"的显式锚点；无"复兴进度"的宏观可视化 | P1 目标牵引 |
| **D2 世界失活** | "像在填表格，不像在管一个宗门" | 首页是按钮墙；无天时流转、无人物活动、无异象——世界没有在"呼吸" | P2 世界存在感 |
| **D3 反馈失声** | "突破了也就弹个字" | 核心爽点（突破/奇遇/大典）未被仪式化放大，情绪曲线是平的 | P3 高光时刻 |
| **D4 视觉失焦** | "眼睛不知道看哪" | 所有入口等权、等大、等色 → 违反"若一切都重要则无重要" | P4 视觉焦点 |
| **D5 节律失拍** | "玩一会儿就没劲了，走了也不惦记" | 会话无起承转合；离开时没有"正在发生的事"拽你回来 | P5 节律与钩子 |

> 五处"失"合起来，就是那句"说不上为什么不够好"——**不是哪一处坏了，是这五处一起让游戏"没有情绪"。**

## 3. 体验设计框架：宗主复兴体验主线

> **主命题**：本作对外宣传名是《**开局接手太玄宗**》——这六个字本身就是一句**复兴史诗**。体验设计的全部工作，就是让 UI 成为这段"复兴叙事"的**载体**，而不是它的说明书。

### 3.1 体验主线：三把时间尺

把玩家体验锚定在三条真实存在的游戏时间尺上（均已在系统中存在，此处只做**体验化组织**）：

| 尺 | 时间跨度 | 玩家心智 | 体验目标 |
| --- | --- | --- | --- |
| **一日的宗门** | 分钟级（现实 1–10 分钟） | "今天宗门还好吗" | 进得来、看得懂、有收获 |
| **一年的道途** | 游戏月/年级（推演月、殿阁月产） | "我这个月要做成什么" | 有阶段目标、有可见进度 |
| **一世的传承** | 世代级（辈分、转生、飞升、七载大典） | "我的宗门会不会传下去" | 有史诗感、有代际接力 |

**设计含义**：任何界面只服务其中一把尺的**一个目标**（对齐架构层 U5 单页单目标），三把尺不得混塞一屏。玩家在任意时刻，心里应该清楚自己正处在哪把尺上。

### 3.2 支柱 P1 · 目标牵引链（治 D1）

**原则**：目标不是"任务列表"，是"牵引"。永远同时存在**三层目标**，且彼此关联——完成短的推进中的，完成中的逼近长的。

| 层 | 名称（修真化） | 形态 | 出现方式 | 示例 |
| --- | --- | --- | --- | --- |
| **短** | 宗门急务 | 情境化，一次 1–3 条 | **该出现时才出现**（不常驻列表） | "弟子{名}将破境，请宗主定夺" / "商队在{地}遇袭" |
| **中** | 宗门大计 | 1 条主线 + ≤2 支线，带进度条 | 常驻首页，可折叠 | "三月之内，重建丹霞殿（2/3）" |
| **长** | 大道之志 | 唯一，宏大，带复兴进度 | 首页一角，低调但恒在 | "重振太玄道统 · 宗门气象 37%" |

**关键机制（这是"牵引"区别于"任务"的地方）**：
1. **短目标的出现时机由世界状态驱动**（对齐 RimWorld 主动 alerts / 本作 §11.11 经营风险事件），不是固定列表催你做。
2. **每个短目标完成后，必须显式回指中目标**——toast 或结算卡上加一句"（宗门大计 +1）"。
3. **长目标要有可视化进度**，让"复兴"这件抽象的事持续被看见——这是全篇最重要的一条，直接把营销名落进 UI。

> **与 §11.22 的分工**：§11.22 管"任务系统的信息组织"，本支柱管"目标如何牵引情绪"。§11.14 宗门数据掌籍体系可作为长目标进度的**世界观化载体**（"掌籍载录宗门兴衰"）。

### 3.3 支柱 P2 · 世界存在感（治 D2）

**原则**：宗门必须"在呼吸"。用四类环境叙事要素，让首页从"按钮墙"变成"一个活的驻地"。（对齐 §11.10.1 宗门驻地内图，视觉载体已存在，此处定义**体验化用法**。）

| 要素 | 内容 | 体验目的 | 落地手段（低美术依赖优先） |
| --- | --- | --- | --- |
| **天时** | 四季轮转、昼夜、天候（雨/雪/雷/雾） | 时间"在流动" | 首页背景色调随游戏月插值；天气粒子层（纯代码可用 Tween + GPUParticles） |
| **人事** | 弟子在殿阁间走动、商队进出山门、炊烟袅袅 | 宗门"有人" | 少量动态精灵 + 路径缓动；**不必多，3–5 个活跃像素即够** |
| **物候** | 灵田长势、草木荣枯、聚灵阵灵光强弱 | 宗门"在生长" | 图元随值变化缩放/透明度 |
| **异象** | 突破天劫、灵气潮汐、妖兽出没、祥瑞 | 世界"有意外" | 环境级一次性特效 + 全局色调脉冲 |

**呼吸原则（借自"动态背景视觉工程学"）**：背景动效循环周期 **4–6 秒**、采用非线性缓动、运动频率低于玩家操作频率阈值（<0.8Hz）——**背景必须退到潜意识层，绝不能与前景交互抢注意力**。世界活着 ≠ 屏幕在动。

### 3.4 支柱 P3 · 高光时刻（治 D3）

**原则**：把三类核心爽点做成**有规格的全屏仪式**，而非文字提示。这是投入产出比最高的一环——它直接决定"记不记得住"。

| 高光时刻 | 情绪目标 | 仪式规格（时长/表现） | 反面（现状风险） |
| --- | --- | --- | --- |
| **境界突破** | 成就感、郑重感 | 1.5–3s 全屏演出：运镜推近 → 灵气汇聚 → 破境光爆 → 新境界名定格；配专属音效 | 弹一个 toast「突破成功」 |
| **奇遇事件** | 期待感、惊喜感 | **anticipation design**：翻牌/揭晓/渐显，0.5–1s 的"悬念延迟"；稀有度越高演出越长 | 直接显示结果文本 |
| **七载大典 / 测灵大典** | 盛典感、代际感 | 年度盛典：卷轴展开 → 逐年回溯 → 颁奖/名录定格；可回收再看的"纪念册" | 一个结算数字面板 |
| **飞升 / 转生** | 史诗感、闭环感 | 最高规格，允许做成短片式过场 | 与普通突破同款 |

**节制原则（对齐 juice 专题）**：奖励分频，**小奖励轻反馈、大奖励重演出**——若每个操作都放烟花，烟花就一文不值。演出强度必须与事件稀有度分级绑定。

### 3.5 支柱 P4 · 视觉焦点（治 D4）

**原则**：**一屏一个主角**。每页必须能回答"我现在最该点的是哪个"。

| 规则 | 说明 |
| --- | --- |
| **单一主行动** | 每页一个 Primary Action：比同级元素大 20%+，用高对比焦点色（本作已有 §4.4 状态色体系，扩展一个"焦点色"角色） |
| **主次降权** | 次要入口统一降饱和、降对比、缩小；禁止与主行动抢视觉权重 |
| **状态色即导航** | 已有的「正常绿 / 待处理黄 / 异常红 / 外出蓝」（§11.22.4）升级为**引导系统**：红黄点把玩家视线自然拉向"该处理的事" |
| **呼吸留白** | 核心操作区可紧凑，**边缘与辅助区必须大胆留白**；统一 8pt 网格间距，同类元素对齐/间距严格一致 |
| **动效即信号** | 默认界面**保持安静**；只有"需要玩家注意"的元素才动。若一切都动，则一切都不动 |

### 3.6 支柱 P5 · 节律与钩子（治 D5）

**原则**：每次会话要有**起承转合**，每次离开要有**再见的理由**。

**会话四拍（进入 → 决策 → 收获 → 展望）**：

| 拍 | 体验内容 | 设计要点 |
| --- | --- | --- |
| **进入** | 离线收获 + 今日简报 | 领取要有仪式（数字滚动/物件飞入），不是静默发放 |
| **决策** | 处理 1–3 条宗门急务 | 开局 5 分钟内必有一次**有意义决策**（放置赛道铁律） |
| **收获** | 完成大计节点 / 触发高光 | 回指中目标，触发一次高光时刻 |
| **展望** | 可见的下一步 | 倒计时（"聚灵大阵 3 日后成"）、酝酿中事件、未领奖励——**永远是"正在发生"的** |

**回归钩子三件套**：① 离线收益**具体化**（"挂机 X 小时 = 修为 +N 年"，借无极仙途做法，绝不"大量奖励"含糊）；② 进行中事务的**真实倒计时**；③ 一个"等你回来看结果"的事件（突破酝酿中/商队返程中）。

### 3.7 横切：叙事化外壳（功能 → 世界观映射）

> 直接服务于项目铁则 **U6 命名修真化**，同时是"世界存在感"最廉价的落地方式——**零美术成本，只改文案与图标壳**。

| 现代词（禁用） | 本作映射（已有一部分） | 状态 |
| --- | --- | --- |
| 新手引导 | 祖师遗训 / 掌门传承 | 待落地 |
| 任务 | 宗门法旨 | 部分 |

## 4. 与既有两层 UX 的关系（不推翻，只补位）

```
        ┌──────────────────────────────┐
        │  ③ 体验层（本文档·新增）      │  ← 为什么想打开 / 爽不爽 / 记不记得住
        │  情绪曲线 · 目标牵引 · 世界存在感 │
        ├──────────────────────────────┤
        │  ① 架构层（UX基线 v1.0）      │  ← 东西放哪 / 怎么分组 / 何时解锁
        ├──────────────────────────────┤
        │  ② 交互效率层（核心设定 §11.22）│  ← 点几下 / 怎么不累 / 怎么少操作
        └──────────────────────────────┘
```

- **架构层**定义结构 → 本文档定义**这个结构被玩家感受到的样子**。
- **效率层**减少操作 → 本文档定义**省下来的注意力用在什么情绪上**。
- 三者共同构成完整 UX。本文档的任何条款，**不得与架构层的容量/分组约束冲突**，也不得增加交互步数（效率层红线）。

## 5. 落地优先级

| 阶段 | 内容 | 依赖 | 理由 |
| --- | --- | --- | --- |
| **E1 先做（零美术/纯代码可落地）** | 目标牵引链 UI（P1）· 叙事化外壳（§3.7）· 状态色引导（P4）· 离线收益仪式化 + 回归钩子（P5） | 无（复用现有 UITheme 组件） | 投入最小、直接治"没目标/没钩子"，不依赖美术 |
| **E2 再做（低成本动态）** | "活的宗门"四要素（P2，先做天时+物候，纯代码 Tween/粒子）· 视觉焦点规则（P4 全量） | 首页布局定稿 | 视觉生命感的性价比最高处 |
| **E3 后做（依赖美术/演出）** | 高光时刻三件套全规格（P3）· 人事类动态精灵 | 豆包美术资源到位 + UI 布局定稿 | 演出质量依赖美术，排在 UX 冻结后 |

> **E1 可与 UI 布局重构并行**（因为它改的是"内容与节奏"，不依赖像素坐标）；**E3 必须在 UI 布局与美术确定后**。

## 6. MUST / MUST NOT 验收清单（体验层）

**【目标牵引 P1】**
- [ ] **MUST** 任一时刻同时可见短/中/长三层目标，且短目标完成时显式回指中目标。
- [ ] **MUST** 长目标（复兴进度）在首页恒常可见，且可量化（百分比或阶段）。
- [ ] **MUST NOT** 把短目标做成"一次列 10 条的常驻任务墙"（违反 U1/U3）。

**【世界存在感 P2】**
- [ ] **MUST** 首页具备天时/物候至少一类动态表现，随游戏时间变化。
- [ ] **MUST NOT** 背景动效干扰前景交互（循环周期 4–6s、频率 <0.8Hz、不抢焦点）。

**【高光时刻 P3】**
- [ ] **MUST** 境界突破、飞升为全屏级演出，规格与稀有度分级。
- [ ] **MUST NOT** 所有操作同级烟花（奖励分频，小奖励轻反馈）。

**【视觉焦点 P4】**
- [ ] **MUST** 每页有唯一 Primary Action（大 20%+、高对比焦点色）。
- [ ] **MUST** 默认界面保持安静，仅"需注意"元素动。

**【节律与钩子 P5】**
- [ ] **MUST** 开局 5 分钟内出现一次有意义决策。
- [ ] **MUST** 离线收益具体化数字 + 领取仪式；离开时存在"等待结果"的进行中事件。
- [ ] **MUST NOT** 出现"奖励发放无任何视觉确认"的静默结算。

**【叙事化外壳 §3.7】**
- [ ] **MUST** 功能名全部修真化（U6）；**MUST NOT** 出现「任务/签到/邮件/成就/设置」等现代词。

## 附录 A：UI 与美术工作的调研参考工作流

1. **Game UI Database 2.0**（gameuidatabase.com，免费，55,500+ 屏）：按**屏型（主界面/背包/结算/商店）+ 玩法类型 + 平台(mobile) + 色值**筛选对标案例；新版本带颜色盲模拟与网格工具，用于研究**信息分区与视觉层级**。
2. **Interface In Game**（interfaceingame.com，免费，20+ 元素分类）：按**元素类型（Menu/In-Game/Stats/Overlay/Inventory/Tutorial）+ 主题（Fantasy/Medieval）**检索；含从业者访谈与线框 PSD，适合本项目"修仙/古风"主题对标。
3. **Game Maker's Toolkit**（Mark Brown，YouTube）：设计分析，用于校验"机制是否服务于体验"。
4. 用法纪律：**参考结构，不抄皮肤**——避免与豆包在制美术撞风格（对齐架构层 §8 美术三类分层）。
