# ADR-001 装备穿戴数据模型与战力结算方案

> 状态：提案（系数已由 design-lead 裁决，见 design/gdd/DESIGN-RULINGS-P5.md 裁决①/②）｜ 作者：eng-lead（程基岩）｜ 阶段：Phase 4 收口
> 关联：数值体系细则.md §4.1/§4.2、太玄宗门录_核心设定总览.md §4/§8/§11.21、csv_validator.gd、tests/QUALITY_GATES.md（G3 装备出口门 E1~E4）
> 决策影响：首个冲刺（P5-1）= 装备穿戴；是奇遇 / 战斗 战力结算的前置依赖。

---

## 1. 背景与问题

**现状（代码）**：
- `item.gd` 已定义 `穿戴位`、`职业`、`战力加成`（= 基础战力表 + 词缀和×6×档倍 + 极品 flat），以及 9 个穿戴位名。
- `disciple.gd` 仅有 `物品: Array[Item]`（背包），**无任何槽位概念**。`总战力()` 对背包**全部物品**求和：
  ```gdscript
  func 总战力() -> int:
      var s := 战力
      for it in 物品: s += it.战力加成        # 背包所有物品都算，不区分穿/未穿
      if 灵兽 != null and not 灵兽.孵化中: s += 灵兽.战力贡献(战力)
      return s
  ```
- 结果：**「不穿也算战力」缺口**（QUALITY_GATES E1 反向用例），且为纯加性，与 §4.2 乘性公式不符（ARCHITECTURE §5.1）。

**目标**：建立「穿戴位→槽位」聚合，使战力按 §4.2 乘性公式结算，且装备词缀归入通用增益乘区（≤25%/硬30%），存档走 §11.21 三原则。

---

## 2. 决策（Decisions）

### D1 — 弟子持有模型：背包 + 槽位字典
在 `Disciple` 新增：
```gdscript
var 背包: Array[Item] = []            # 未穿戴物品（原 物品）
var 装备: Dictionary = {}             # 槽位 key -> Item；key 取规范槽位枚举
```
- 保留 `物品` 字段名向后兼容一次性迁移（见 §6），新代码统一用 `背包`/`装备`。
- 穿戴：`装备[槽位] = it` 并从 `背包` 移除；卸载：移回 `背包`，`装备.erase(槽位)`。
- **一个槽位仅一件**；换装先卸载再穿戴（悬空 equip_id 由 §11.21.5 自修复兜底）。

### D2 — 规范槽位枚举：采用 `csv_validator.EQUIP_SLOTS`（7 槽）
以配置为唯一真相源（GDD §11.23），**弃用 `item.gd.穿戴位名` 的 9 槽**：
- 映射：`衣袍→法袍`、`配饰→饰品`。
- 裁决项（待 design-strategist）：`长裤` 并入衣袍或弃用；`本命法宝` 作为**非 CSV 专属槽**保留（法宝类独占，不进 `EQUIP_SLOTS` 枚举但单列常量）。
- 后果：`item.gd` 生成时 `穿戴位` 必须落在 {武器,法袍,头盔,护腕,腰带,靴子,饰品}∪{本命法宝}。

### D3 — 战力结算：落地 §4.2 乘性公式（核心决策）
新增纯函数（建议置于 `disciple.gd` 或独立 `power.gd`）：
```gdscript
# 对齐 数值体系细则 §4.2
func 计算战力() -> int:
    var base   := 境界表[境界]["战力"]
    var 资质系数 := 资质系数表[资质]                     # 裁决①A：普通1.0/优秀1.15/顶级1.6（全档0.9~1.8）
    var 灵根系数 := 取灵根系数(灵根)                    # 裁决①B：普通1.0/天灵根1.08（⚠️ 取 §6.2 战力系数，勿用 §4.6 修炼速度1.2×，见 C6）
    var 职业系数 := 取职业系数(职业)                    # 裁决①C：单1.0/主辅1.7/三修2.1
    var 通用增益 := 聚合通用增益()                      # Σ 已穿装备词缀%（装备单源子帽≤8%）+ 其他；clamp_soft(0.25,0.30,0.2)
    var 道心增益 := 取道心增益()                        # 裁决①D：当前无道心系统=0.0（占位正确）
    var 主体 := int(base * 资质系数 * 灵根系数 * 职业系数 * (1+通用增益) * (1+道心增益))
    var 灵兽加成 := 灵兽契约战力()                      # (主宠战力*1.0 + 副宠战力*0.7) * 0.30
    return 主体 + 灵兽加成
```
- **`总战力()` 改为调用 `计算战力()`**（替换加性实现）。
- `聚合通用增益()`：遍历 `装备` 中每件物品的词缀，将「装备词缀」类百分比累加（同乘区内加算），再 `clamp_soft(0.25, 0.30, decay=0.2)`；其他通用增益源（功法/大阵/羁绊）后续并入同一池。

### D4 — item 字段对接
- `item.战力加成` 拆分为两部分语义：
  - **flat 基础**：`基础战力表[品阶] + (极品? +600/+1500 : 0)` → 仍作为 flat 并入？（见 §4 待裁决：设计 §4.2 无显式「物品基础战力」项，建议将 flat 并入 `base` 前的加性项或转译进通用增益，需 design 确认）
  - **词缀%**：`词缀` 中每条 `数值%` 作为通用增益源（与 §4.1「装备词缀属通用增益乘区」一致）。
- 本期**不改动 `item.算战力()` 的数值**，只在其上做聚合层；避免动既有随机生成逻辑。

### D5 — 存档兼容（§11.21 三原则）
- `to_dict()` 新增 `"装备": {槽位: item.to_dict()}`；`"物品"` 改名 `"背包"`（旧档 `物品` 在 `from_dict` 中以 `get("背包", get("物品",[]))` 兼容）。
- 新增字段均有默认值（`装备={}`），满足「只新增+默认值」；不删 `物品` 字段（保留读取兼容，标记 deprecated）。
- 存档外层须补 §11.21 元数据头（见 ARCHITECTURE §3.2 / TEST §4，属 H2 隐患，建议在首个冲刺一并补或在紧随的小迭代补）。

## 3. 备选方案（Alternatives Considered）

| 方案 | 描述 | 取舍 |
| --- | --- | --- |
| A（采纳） | 槽位字典 + §4.2 乘性公式 | 通过 QUALITY_GATES G3 E1；符合数值红线；代价：需 design 补系数 |
| B | 维持加性，仅把「背包全算」改为「仅穿算术」 | 改造成本最低，但**违反 G2**（装备加成线性加基础 → FAIL），且不通乘区红线 → 否决 |
| C | 仅重构槽位、战力仍加性但加 clamp | 部分修复缺口②感知，但 E4 乘区红线仍不破 → 不满足 E1 公式要求 → 否决 |

## 4. 已裁决系数（design-lead 裁决①/②，见 design/gdd/DESIGN-RULINGS-P5.md）

> 全部系数已由 design-lead 于 P5 裁决落地（含行号溯源），E4 现可判 PASS。数值以 **design 基线** 标记 `[DESIGN_BASELINE, 待实测/老大拍板]` 者为待校准项，不阻断 P5-1 跑通 E1~E4。

### 4.1 资质系数（基础乘区，无封顶）— 裁决①A
权威来源 §6.4 七档「初始属性总系数」（第 607–615 行）：

| 档位 | 系数 |
| --- | --- |
| 凡俗 | 0.9 |
| 平庸 | 1.0 |
| 优良 | 1.1 |
| 天才 | 1.25 |
| 妖孽 | 1.4 |
| 旷世 | 1.6 |
| 道胎 | 1.8 |

MVP 三档合并：**普通（凡俗/平庸）=1.0 / 优秀（优良/天才）=1.15 / 顶级（妖孽/旷世/道胎）=1.6**。

> ⚠️ **eng 对齐 TODO（非阻断 E4）**：本 ADR 原 D3 用 `资质系数 := 资质表[资质]["速度"] / 4.8`，与裁决表 0.9–1.8 标度不一致（那是修炼速度口径）。落地时改为**查 `资质系数表[资质]`**（源 §6.4 七档初始属性总系数），保证 `计算战力()` 落在设计量级。此对齐不影响 E4（E4 只卡通用增益 25%/30%）。

### 4.2 灵根系数（基础乘区，无封顶）— 裁决①B
权威来源 §6.2「灵根类型修正系数·初始总属性系数」（第 621–627 行）：

| 灵根类型 | 战力公式系数 | 备注 |
| --- | --- | --- |
| 杂灵根 | 0.95 | — |
| 普通单灵根 | 1.0 | MVP 基准 |
| 相生双灵根 | 1.03 | — |
| 天灵根 | **1.08** | ⚠️ 取 §6.2 初始总属性系数，勿用 §4.6 第305行「修炼速度分量 1.2×」 |
| 变异灵根 | 1.1 | — |

MVP 两档：**普通五行灵根=1.0 / 天灵根=1.08**。

> ⚠️ **小冲突 C6（待老大拍板）**：§4.6 第305行「天灵根 1.2×」是**修炼速度分量**，与 §6.2 战力公式灵根系数 1.08 口径不一致。本文按 §6.2 裁决（战力公式只能取 1.08），已记入待终审项。实现时务必用 1.08，防错用 1.2×。

### 4.3 职业综合系数（基础乘区，无封顶）— 裁决①C
权威来源 §4.2 第242行 + §4.1 第227行：
```
职业综合系数 = 主职业×1.0 + 辅修×0.7 + 三修×0.4
```
单=1.0 / 主+辅=1.7 / 主+辅+三=2.1。此系数对**整体战力**的乘子，与 §6.1.1 三职业分配结构（体修血防/法修攻速/道修均衡，第634–638行）**正交**——分配结构只改基础值构成，不改变总属性量；职业综合系数是多职业激活的额外乘子。两层都要落，勿二选一。

### 4.4 道心增益（道心独立乘区，≤0.10）— 裁决①D
权威来源 §4.1 红线第208行 + §4.2 第244行：道心增益独立乘区，总增益硬上限 10%，不占通用 25% 额度。
- 当前无道心系统 → `取道心增益() = 0.0`（占位正确）。
- 道心系统落地后：`道心增益 = Σ(道心标签 BUFF)`，单弟子总封顶 0.10（§6.9.1）。

### 4.5 性格系数（性格乘区 ±3%，分轴）— 裁决①E
权威来源 §4.6 第307行 + §6.6 十二性格修正。幅度严格 ±3% 以内，分属性轴微量修正（非单一标量）。MVP 阶段（第667行）明确**暂不加入性格属性修正**，故 `计算战力()` 取 **×1.00**；全量期再按 12 性格分轴表落（见 design 裁决表）。

### 4.6 装备单源子帽（通用增益乘区）— 裁决②
**口径铁则（§4.1 第233行 + §4.2 第247行）**：所有来源子类先各自边际乘算衰减收敛到单源子帽，再**加算**汇入「通用增益总和」喂 `(1+总和)`，最终卡软25%/硬30%（溢出20%衰减）；跨乘区独立乘算永不加算合并。

**design 基线 ≤ 8%**（全局等效，文档未给单值，由 design 设定）：理由——8% + 功法2% + 血脉1.5% + 家族2% + 自创2% + 灵兽~3% + 大阵/聚灵/先贤/常规≈6% ≈ 24.5%，精准贴合文档自述 23%~24.5% 总预算，不击穿 25%。

**收敛公式（落地 `聚合通用增益()` 的装备分支）**：
```
装备词缀池 =
  for 每个已穿戴槽位的 item:
    槽位内词缀% 先加算 → 槽位内边际衰减（同槽多条词缀收益递减）
  跨槽位再边际乘算收敛（槽位 n 贡献率 ×0.5^(n-1) 衰减）
装备子帽 = clamp(收敛值, 0, 0.08)        # 单源子帽 ≤8%
通用增益总和 += 装备子帽                     # 再进 25%/30% 池总帽
```
> ⚠️ 此 8% 为 `[DESIGN_BASELINE, 待实测校准]`（文档 [PLACEHOLDER] 惯例）。若实测偏松/偏紧，回调装备子帽即可，不影响机制正确性。E4 现可判 PASS。

### 4.7 `item.flat 基础` 去向（保留原处置，待 design 占坑）
§4.2 无显式「物品基础战力」项。`item.算战力()` 的 flat 基础（基础战力表[品阶] + 极品 flat）本期仍作 flat 加性项并入（base 前）；待 design 在 §4.6 乘区归属总表明确占坑，不阻断 P5-1。

**E4 PASS 结论**：QUALITY_GATES G3 出口 E4（任意装备组合 `聚合通用增益()` ≤ 硬上限 30%、软 25% 溢出按 20% 衰减、单源子帽生效）机制正确，**现可判 PASS**；仅 8% 子帽数值待实测校准（非阻断）。

## 5. 数据流（穿戴 → 战力 → 存档）

```
玩家/系统 调用 弟子.穿戴(槽位, it)
  ├─ 装备[槽位] = it; 背包.erase(it)
  ├─ 弟子.总战力() 重算（= 计算战力()）   # 触发 UI 战力刷新（缺口④感知修复）
  └─ Game.弟子变动.emit() → main.刷新()

Game.更新门派() / _判定成败() 读 弟子.总战力()   # 已用，自动受益
save_game(): data["dizi"].append(d.to_dict())    # 含 "装备" 分区（§11.21 扩展）
```

## 7. 验收标准（对应 QUALITY_GATES G3 装备出口门）

- **E1 穿戴后战力正确聚合**：穿戴装备后 `总战力()` 按 §4.2 变化（占位系数下至少「穿了比不穿高」），**不再对背包未穿物品计数**。
- **E2 卸载后战力回退**：卸下后 `总战力()` 回到穿戴前原值（epsilon 容差，无残留）。
- **E3 存档读档不丢装备**：save→load 后 `装备` 槽位绑定与 `背包` 持有完全一致；悬空 equip_id 由 §11.21.5 自修复（卸下归还），无空指针。
- **E4 乘区不破红线**：任意装备组合下 `聚合通用增益()` ≤ 硬上限 30%（软 25% 溢出按 20% 衰减）；装备单源子帽 ≤8% 生效（决议②基线）。**E4 现可判 PASS**（系数已裁决，机制正确；仅 8% 子帽数值待实测校准，非阻断）。

## 8. 风险与后续

- **R1**：§4.2 系数未定前，占位值会使战力绝对值偏离设计；须 design 尽快给基线（见 §4）。
- **R2**：`item.flat 基础` 去向若久拖，会导致「装备基础战力」无处安放；建议 design 在 §4.6 乘区归属总表明确占坑。
- **R3**：D2 槽位合并（衣袍→法袍等）会改变 `item.gd` 生成枚举，需同步更新 `item.gd.穿戴位名` 与 `槽显示` 映射，避免旧存档槽位名 mismatch。
