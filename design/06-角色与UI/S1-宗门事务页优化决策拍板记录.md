# S1 宗务页 · 优化决策拍板记录

## 0. 整体原则（拍板基线）
**S1 阶段优先保证页面可用、视觉完整、逻辑自洽，严格不碰数据层，预留扩展位，拒绝无效空壳开发。**

## 1. 主线 Tab：保持桥接周常（有内容）
- **结论**：不做空态占位，主线 Tab 继续承接周常内容。
- **理由**：S1 阶段不能让玩家进入页面后 4 个 Tab 里 3 个是空态，半成品感过强。主线先作为周常内容的承载入口，保证页面有可交互内容、玩家体验完整。后续主线真实数据落地后，直接替换 Tab 内的内容源即可，Tab 结构无需改动，开发成本最低，也不破坏现有架构。

## 2. 活跃度宝箱：先搭视觉脚手架 + 宝箱禁用态
- **结论**：保留 20/50/80/100 节点 + 宝箱视觉，宝箱统一置灰禁用，点击弹出轻提示「活跃度奖励筹备中」。
- **理由**：只做 UI 视觉占位，完全不触碰 GameState 数据层，不违反项目铁律；同时视觉完成度远高于光秃秃的进度条，符合大厂界面的完整感。玩家能清晰感知到「这是后续开放的功能」，不会当成 bug；等后续活跃度数据 + 档位奖励落地，直接解锁点击逻辑即可，扩展成本极低。

## 3. 卡片布局：接受偏离 05 屏定稿，启用新方案
- **结论**：采用「左侧类型色条 + 标题/描述分层 + 迷你资源图标奖励 + 右侧按钮」的 F-pattern 布局，同步更新 Ardot 定稿稿。
- **理由**：新布局的信息读取效率、视觉层级清晰度，都明显优于早期的「图标圆 + 进度条」方案，是手游任务系统的通用大厂标准。定稿的意义是指导落地，而非束缚体验优化；以实机最终体验为准，同步更新设计源文件，保证稿码一致即可。且迷你资源图标可直接复用现有资产，零额外美术成本，收益远大于死守旧定稿。

## 4. 背景方案 A：全二级页通用（除幻形），接受偏离 05 屏纯底色
- **结论**：所有列表型二级页（宗务、成就、背包等）统一采用「主背景复用 + 深青蒙层」方案，幻形页单独保留深色底。
- **理由**：纯深色底色的质感上限过低，方案 A 零额外美术成本、零额外性能开销，仅靠一层蒙层就能大幅提升界面氛围感和高级感，且和主界面风格完全统一，切换页面无割裂感，是性价比极高的优化。同步更新 Ardot 二级页背景规范，统一设计标准，不属于无依据的偏离。

## 5. 成就四子 Tab：只留 schema 预留，不建实体 Tab
- **结论**：当前成就页保持单页空态，代码层预留分类扩展位，不做实体子 Tab。
- **理由**：S1 阶段成就无任何真实数据，做 4 个实体 Tab 属于「空壳套空壳」，纯消耗开发量，且玩家点进去全是空态，体验反而更差。先保留单页空态的极简结构，等后续成就内容规划落地、有明确分类和数据后，再拆分实体子 Tab，避免做无效开发。

## 6. 补充落地对齐说明
- 以上决策全部落地后，宗务页会达到「S1 阶段可用、视觉完整、架构可扩展、严格不碰数据层」的标准，整体完成度对标中小厂仙侠手游上线水准，不会有明显的半成品感。
- `ui_theme.gd` 里的 Tab、空态、任务状态、按钮、背景蒙层等常量，建议同步整理归档，保证后续所有二级页都能直接复用这套规范。

## 7. 关联文件与扩展端口
- **实现层**：`ui/page_quest.gd`（宗务页）、`ui/sect_home_page.gd`、`ui_theme.gd`、各二级页 `ui/*.gd`。
- **设计源**：`Ardot 宗务页定稿稿`（背景规范、卡片 F-pattern 需同步更新）。
- **扩展端口**：主线内容源替换位、活跃度宝箱点击解锁位、成就分类 schema 预留位。
- **铁律约束**：所有样式走 `UITheme`，禁止硬编码颜色/尺寸；不触碰 `game_state.gd` 数据层；落地后 `pre_f5_check.py` 全绿（EXIT=0）。
