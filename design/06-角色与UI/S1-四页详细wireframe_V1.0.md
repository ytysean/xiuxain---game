# 《太玄宗门录》S1 UI 重构 · 四页详细 wireframe + 只读数据契约

> 本文档将 `S1-UX验收规格.md` 的 §3~§6（INTENT 段落）扩展为 **build-ready** 规格：每个页面含 ASCII wireframe（480×854，8px 栅格，标注模块尺寸）、只读数据契约表（每个字段 ← 精确 Game 访问器 + 缺失回退 "—" + 异常暗红条件）、复用组件、信号契约（全占位）、特殊行为、验收标准。
> 设计基线全部对齐 §0 / §2 / §7（详见 `S1-UX验收规格.md` 与 `UI交互规范_古风经营A版_V1.0.md`）。

## 0. 全局基线（对齐 §0 / §2.2）

- 基准分辨率 **480×854**（竖屏）；最小栅格 **8px**；所有边距/尺寸/间距为 8 的整数倍。
- 5-Tab 导航（权威）：**宗门 / 弟子 / 建筑 / 历练 / 纪事**。四页均复用「**TopBar(48) + 内容区 + BottomTabBar(64)**」骨架，仅替换内容区。
- **内容区可用高度** = 854 − TOPBAR_H(48) − TAB_H(64) = **742px**；可用宽度 = 480 − 2×MARGIN(16) = **448px**。
- 全局安全边距：左右 **MARGIN=16**。VBox 模块间距统一 **GRID×2 = 16**（与 `sect_home_page.gd` `_build` 的 `separation` 一致）。
- **UITheme 关键常量**（禁止硬编码）：`GRID=8` `MARGIN=16` `TOPBAR_H=48` `TAB_H=64` `OVERVIEW_H=120` `CORE_GRID_H=240` `SIZE_SM=48` `SIZE_MD=64` `SIZE_LG=120` `SIZE_XL=240` `BTN_H_PRIMARY=64` `BTN_H_SECONDARY=48` `FONT_TITLE=24` `FONT_VALUE=18` `FONT_BODY=16` `FONT_AUX=12`。
- **UITheme helper（一律经此调用）**：`apply_title_font` / `apply_value_font(label, abnormal)` / `apply_body_font` / `apply_aux_font` / `apply_panel_style(control, use_ink=true)` / `apply_tab_style(btn, selected)` / `make_divider_control()` / `load_icon(label)`。
- **ICON_BY_LABEL（现有 15）**：建筑→jianyu / 坊市→suanpan / 修炼→danhuo / 洞府→shandong / 任务→juanshu / 账册→boce / 宗门→zongmen / 弟子→dizi / 历练→lilian / 纪事→jishi / 灵石→lingshi / 灵气→lingqi / 时辰→shichen / 推演时日→rili / 折叠→chevron。
- **读数铁律（与 `sect_home_page.gd:refresh_overview` 对齐）**：所有 Game 读取先 `is_instance_valid(Game)`；方法访问先 `Game.has_method("X")`；字段访问用 `Game.get("prop")` 或属性访问配合 null-guard；缺失一律显示 **"—"**，绝不编造。
- **红线**：零战斗/数值/玩法触碰；所有按钮 `pressed` 仅 `emit` 占位信号，由宿主（engineering-lead 后续接线）决定行为；本批绝不写 `GameState`。

- **模块尺寸**：TopBar 48 / 列表头面板 56（内边距上下 8、左右 16）/ 弟子行 72（≥44 触摸，满足 ACCESSIBILITY §2）/ 接引决策区 固定 120~160（内边距 16）/ BottomTab 64。全局左右 MARGIN=16，模块间距 16。
- **信息层级**：弟子列表 + 接引决策区为 P0 首屏常驻（列表 expand，决策区固定底）；无 P2 折叠。
- **去重铁律（§3 验收）**：**弟子总数已在 TopBar 的「弟子」资源槽显示，本页内容区禁止再列「在岗弟子数」**；本页仅新增「总战力」聚合（TopBar 无此字段，不重复）。

### 1.2 数据契约表（只读 Game）

| 显示字段 | Game 访问器（只读） | 缺失回退 | 异常(暗红)条件 |
|---|---|---|---|
| 弟子总数（TopBar） | `Game.弟子列表.size()`（由宿主 `TopBar.set_resource("弟子", str(...))` 推送） | "—" | 否 |
| 总战力（列表头） | `Σ_{i} Game.弟子列表[i].战力`（遍历累加；或 `Game.弟子列表[i].总战力()`） | "—" | `战力 < 0`（防御性，正常不触发）→ 红 |
| 姓名（行） | `Game.弟子列表[i].姓名` | "—" | 否 |
| 境界/品阶（行） | `Game.弟子列表[i].境界`（如「炼气」「筑基」；即规格中的"品阶"呈现） | "—" | 否 |
| 战力（行） | `Game.弟子列表[i].战力` | "—" | `战力 < 0`（防御性）→ 红 |
| 状态（行·UI 派生，非 Game 字段） | 派生规则见 §1.5；读 `Game.弟子列表[i].堂口` / `.突破冷却剩余` / `.考核冷却剩余` | "—" | 否（aux 灰，非红） |
| 待抉择条目数（决策区） | `Game.待抉择.size()`（Array[Dictionary]） | "0" | 否 |
| 待抉择·弟子名 | `Game.待抉择[k]["弟子"].姓名`（Disciple 对象） | "—" | 否 |
| 待抉择·物品名 | `Game.待抉择[k]["物品"].名称`（Item 对象） | "—" | 否 |
| 待抉择·文案 | `Game.待抉择[k].get("文本", "")` | "" | 否 |

> 派生状态规则（UI 侧计算，零 Game 写）：
> - `堂口 == ""` → 「未入门」（aux 灰）
> - `elif 突破冷却剩余 > 0` → 「闭关养伤」（aux 灰）
> - `elif 考核冷却剩余 > 0` → 「考核冷却」（aux 灰）
> - `else` → 「在岗」（body 浅米 / 或 gold）
>
> 读数守卫：`is_instance_valid(Game)` → `Game.弟子列表 != null` → 下标 `i < Game.弟子列表.size()` → `d != null` 再取字段。

| 交互元素 | 发出信号 | 备注 |

### 1.5 特殊行为

- **弟子详情二级页（点行进入）**：保留 TopBar，底部 BottomTabBar 替换为「**返回 + 标题**」条（`Button` 套 `apply_secondary_button_style` 或 `apply_tab_style`；标题 `apply_title_font`）。结构（全只读，信号全占位）：
  - ① 基本信息：`姓名`/`道号`(`Game.弟子列表[i].道号`)、`身份`(`.身份`)、`阶位`(`.阶位`)、`来源`(`.来源`)、`备注`(`.备注`)
  - ② 资质灵根：`资质`(`.资质` → `Disciple.资质显示.get(资质)`)、`灵根`+`灵根品阶`(`.灵根`/`.灵根品阶`)、`命格`(`DestinyDataLoader.get_destiny(.destiny_id)["名称"]`)、`性格`(`.性格`)、`职业`(`.职业` 或「未入门」)
  - ③ 修炼状态：`境界`(`.境界`)、`层数`(`.层数`)、`修炼进度`(`int(.修炼进度*100)`%)、`寿元`(`.寿元`)、`年龄`(`%.0f岁` % `.年龄`)、`突破冷却剩余`/`瓶颈打磨值`/`稳固期剩余`/`丹毒`
  - ④ 任职：`堂口`(`.堂口`)、`阶位`(`.阶位`)、`考核冷却剩余`/`考核心得`
  - ⑤ 四维：`属性["攻"]`/`["防"]`/`["血"]`/`["速"]`（value18）
  - ⑥ 个人纪事：`Game.取弟子纪事(弟子ID, 姓名)` → 遍历条目取 `日`/`名称`/`文案`（同 §5 条目呈现）
  - 返回按钮 → `弟子详情返回()`（占位；宿主切回 弟子 Tab / 弹回一级内容区）。
- **接引决策区空态**：`Game.待抉择.size() == 0` 时，决策区显示 aux 灰「暂无待抉择」，不隐藏面板。
- **触摸目标**：所有行/按钮 ≥ 44×44（ACCESSIBILITY §2）。

### 1.6 验收标准（engineering-lead "done"）

- [ ] 内容区仅替换，TopBar/BottomTabBar 复用，5-Tab 选中态=弟子。
- [ ] 列表头显示「总战力」聚合值；**不重复显示弟子总数**（去重铁律达成）。
- [ ] 每行含 姓名/境界/战力/状态(派生)，行高 72，触摸 ≥44。
- [ ] `Game` 缺失（`is_instance_valid` 失败或下标越界）时所有字段显示 "—"，不报错/不崩。
- [ ] 接引决策区渲染 `Game.待抉择`；空态显示「暂无待抉择」；交宗/自留仅 emit 占位信号。
- [ ] 全部颜色/字号经 UITheme helper；无硬编码。
- [ ] 点行 emit `弟子详情请求(弟子ID)`；二级页保留 TopBar、底栏为返回条；返回 emit 占位信号。

- **模块尺寸**：TopBar 48 / 总览面板 56 / 堂口行 96（含名称+职能+等级+产出+主事+被动+升级按钮，满足 ≥44）/ 底部说明条 48 / BottomTab 64。左右 MARGIN=16，模块间距 16。

- **信息层级**：建筑总览 + 堂口列表 P0 首屏；底部说明条为全局被动摘要。

### 2.2 数据契约表（只读 Game）

> `Game.堂口列表` 为 `Dictionary{key: {key,名称,职能,产出,加成维度,负责人:Disciple|null,成员:Array,负责人锁定:bool,等级:int,政绩:int}}`（由 `重建堂口()` 自 `Lore.堂口定义` 生成，常驻 12 项）。

| 显示字段 | Game 访问器（只读） | 缺失回退 | 异常(暗红)条件 |
|---|---|---|---|
| 堂口数（总览） | `Game.堂口列表.size()`（恒 12） | "—" | 否 |
| 总等级（总览） | `Σ_{k} int(Game.堂口列表[k].get("等级",1))` | "—" | 否 |
| 名称（行） | `Game.堂口列表[key]["名称"]` | "—" | 否 |
| 职能（行） | `Game.堂口列表[key]["职能"]` | "—" | 否 |
| 等级（行） | `int(Game.堂口列表[key].get("等级", 1))`（1-based） | "—" | 否 |
| 主事（行） | `Game.堂口列表[key]["负责人"]` → `.姓名` if `!= null` else "缺" | "缺"（aux 灰） | 负责人==null → 显示「缺主事」(aux 灰，**非红**) |
| 成员数（行） | `(Game.堂口列表[key]["成员"] as Array).size()` | "0" | 否 |
| 产出（行） | `Game.堂口列表[key]["产出"]` | "—" | 否 |
| 加成维度（行） | `Game.堂口列表[key]["加成维度"]` | "—" | 否 |
| 被动/减免（底部条） | `Game.建筑被动_负面事件减免`（float，常驻；当前恒 0.0） | "0%" | 否（显示 `abs` 值 + "%"，aux） |

> 读数守卫：`is_instance_valid(Game)` → `Game.堂口列表 != null` → `Game.堂口列表.has(key)` 再取 `["字段"]`；`负责人` 取前先判 `!= null`。
> 注：单个堂口的「被动文案」（如接引堂+2%、功勋阁声望+10%）由 `game_state.gd` 的 `_接引堂测灵加()` / `_功勋阁声望乘区()` 等方法按 `堂口列表.has(key)` 推导；UI 属只读展示，建议 engineering-lead 将「加成维度 + 被动文案映射表」作为只读查表（不写 Game），或暂用 `加成维度` 文本占位，待 art/文案补全。
