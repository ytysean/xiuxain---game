## 0. 本规范要解决的"双源冗余"问题

S1 重架构已落地 P0 基础层：**设计令牌 v1.0 → `main_theme.tres`（基础 chrome）+ `ui_theme.gd`（字体/图标/动态色 helper）+ `UIThemeConfig.gd`（数据驱动色）+ 5 通用组件**。

但 5 个页面 + 相关手写 UI 模块是在 `main_theme.tres` 之前写好的，它们**逐实例调用 `UITheme.apply_panel_style` / `apply_*_button_style`** 来自行为自己生成"基础 chrome"。现在 `main_theme.tres` 已就位并绑定为项目默认主题，**基础 chrome 已由 `.tres` 统一提供**，页面里的这些调用就成了"双源并存"的冗余（且与 `.tres` 的 radius/边宽还可能不一致）。

**本规范目标**：把页面里"本应由 `main_theme.tres` 提供的基础 chrome 调用"移除，让 `.tres` 成为基础样式的唯一来源；把"能复用通用组件的业务结构"改走组件；保留 `ui_theme.gd` 的字体/图标/动态色 helper 与 `UIThemeConfig` 的数据色。实现"页面只拼结构 + 调 helper，不声明基础样式"。

## 1. 分层边界重申（强约束 · 迁移后必须成立）

| 层 | 责任方 | 放什么 | **不放什么（禁止反向）** |
|---|---|---|---|
| **`main_theme.tres`** | engineering-lead | 原生控件**基础样式**：`PanelContainer`/`Button`四态/`Label`默认色/`TabBar`/`ScrollBar`/`ProgressBar` 的 StyleBox 与默认字号/色（全部取自令牌） | 业务样式、品级/境界等业务色、动态色 |
| **`ui_theme.gd`** | design-strategist | 字体层级 helper（`apply_*_font`）、图标（`load_icon`/`load_icon_sized`）、**动态色 getter**（`color_value` 等）、分割线 helper（`make_divider_control`） | 基础 Panel/Button 的"重复"StyleBox 生成（收敛后由 `.tres` 接管）、硬编码 hex |
| **`UIThemeConfig.gd`** | design-strategist | **数据驱动色值表**：品级/境界/状态（以令牌 Token ID 为键），运行时读取、换皮 | StyleBox 实现、字体绑定 |
| **组件场景**（`components/`） | engineering-lead | 业务组件结构与**差异**覆盖（如 `ListItem` 行高亮、`ItemSlot` 品级染色） | 全局通用样式、跨组件业务色 |

**两条禁令（写进代码评审红线）：**
1. ❌ 禁止页面/组件在全局主题（`.tres` / `project.godot` theme_override）里塞业务样式。
2. ❌ 禁止动态色硬编码（`Color(#...)` / 魔法数字散落脚本）。动态色一律走 `UIThemeConfig`，静态基础色一律走 `main_theme.tres`，二者皆源自令牌。

**禁止反向 —— 本规范明确叫停的写法（迁移中必须消除）：**
- 页面里再手写 `PanelContainer` 的 `StyleBoxFlat` 边框 / 再调用 `UITheme.apply_panel_style` 重复声明基础面板 chrome → 改由 `main_theme.tres` 的 `PanelContainer/styles/panel` 默认提供。
- 页面里再手写 `Button` 四态 `StyleBoxFlat`（normal/pressed/disabled/hover）→ 改由 `main_theme.tres` 的 `Button/styles/*` 默认提供；或保留 `ui_theme.gd` 的 `apply_*_button_style`（见 §3 说明）。
- 页面里再硬编码 `#C9A865` / `#243439` 等 → 全部走 `UITheme`/`UIThemeConfig` 常量或 `.tres`。（**现状扫描：10 个页面/组件文件均无硬编码 hex，均已走 `UITheme` 常量，本项已合规，见 §2。）
