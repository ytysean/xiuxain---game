## 一、根因方法论（重要，后续沿用）
1. 用户贴的数百行错误绝大多数是**级联**：某文件自身 parse error → 依赖它的全部文件报「Could not parse global class Disciple / Could not resolve res://xxx.gd」。不按旧行号盲修，以本地 Godot headless 编译器为唯一权威，先解根因文件。
2. `--check-only --script 单文件`模式**不注册 autoload 全局名**，会对合法的 `Game.xxx`/`AlchemySystem.xxx` 误报 Identifier not found；只用于看文件内真实语法/类型行号。判断真伪必须用完整 `--headless --import`（脚本 `.workbuddy/_full_import.ps1`）。
3. check_lines 类脚本只扫根目录 *.gd，**不扫 ui/ 子目录**，UI 层错误一度被长期漏检；错误真实归属要看 _imp.err 里的 `at: GDScript::reload (res://文件:行)`，不能只看 SCRIPT ERROR 消息行（game_ui 报错的真实来源是它依赖的 ui/battle_scene.gd）。
4. 单文件 check-only 通过 ≠ 没问题：依赖失败时类型降级为 Variant，会让 `Vector2.inverse()`、强类型容器赋值等真实错误在单测里隐身，依赖恢复后完整 import 才暴露。
