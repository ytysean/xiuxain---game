## 三、设计决策与经验教训

### 3.1 私库自动使用的安全实现
- **问题**：遍历私库时同时修改私库（穿戴后移除、旧装备放回）可能导致数组遍历异常
- **解决方案**：先收集候选列表，再统一处理，最后统一移除。避免遍历中修改数组。
- **经验**：GDScript的Array遍历中修改数组是常见bug来源，必须用"先收集后处理"模式。

### 3.2 委托竞拍的灵石冻结机制
- **问题**：委托竞拍需要冻结灵石，防止出价后灵石不足
- **解决方案**：设置委托时立即扣除委托价金额，代出价时调整冻结金额（释放旧冻结+冻结新金额），结算时扣款或解冻。
- **经验**：经济系统必须有明确的资金流向，每一步都要有对应的扣减/返还，不能只在结算时一次性处理。

### 3.3 延时结算的时间换算
- **问题**：游戏时间（游戏日）和真实时间（秒）的换算，1游戏日=240真实秒=4分钟
- **解决方案**：延时窗口10真实秒 = 10/240 游戏日，最大延长240真实秒 = 1游戏日
- **经验**：涉及时间的配置必须明确单位，避免游戏时间和真实时间混淆。

### 3.4 声望等级的佣金率调整
- **问题**：原有佣金率是固定的5%，需要按等级调整
- **解决方案**：新增`_拍卖当前佣金率()`函数，替换原有`_拍卖配置浮("佣金率", 0.05)`调用。配置表中的佣金率保留作为基础值，实际使用按等级计算。
- **经验**：修改已有系统时，优先用新函数封装变化，而不是直接改原有逻辑，降低回归风险。
