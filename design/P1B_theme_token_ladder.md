#### A.2.1 关键论证：`4 → 6` 为什么不是视觉回退

Godot 4 `StyleBoxFlat` 在绘制时对圆角做**边长钳制**：同一条边上两个圆角之和超过该边长度时，按比例整体缩小。

- **ScrollBar**：`.tres` 注释明载「宽 8px：grabber/scroll 内容边距各 4 → 最小宽 8」。短边 = 8px，两角和 = 6+6 = 12 > 8 → 缩放系数 8/12，**实际渲染半径 = 4px**，与现状逐像素相同。
- **ProgressBar**：`sb_pbar_bg` / `sb_pbar_fill` 的实际高度由使用方决定，**本文无法静态判定**。若高度 ≤ 12px 则同样钳制回 4，零变化；若 > 12px 则圆角会真实变大 2px。

> ⚠️ **这是本轮唯一一处"论证不闭合"的地方**，已列入 §C 验收闸门：T6 必须对含 ProgressBar 的页面做像素比对。若实测有差异，**回退方案**：`sb_pbar_*` 单独保留 4 并在 `.tres` 注释标注「细长条钳制豁免」，或改走 `R1`=6 接受 2px 变化——由主理人届时定。**不要在未实测前就改。**

### A.3 圆形例外 `RC` 的必要性

`sb_avatar` 半径 18 + 边框 2，语义是**圆形头像框**。若强行归入 `R3`=10：

- 头像从「圆」变成「明显的圆角方块」，是**肉眼可见的视觉回退**，违背 P1-B「不改观感」前提；
- 且「头像=圆」是通用视觉语言，方形化会削弱人物识别性。

因此定义 `RC` 为**规则档而非数值档**：`corner_radius = min(width, height) / 2`。当前 36×36 头像 → 18，与现状完全一致。这样阶梯仍是封闭的（4 个数值档 + 1 条规则），不构成"零星半径"。

> 记入 `.tres` 注释：`; RC 圆形例外 — 半径=短边/2，仅限头像/圆形徽章，新增此类需走设计评审`。

## B. 字号 Token 阶梯

### B.1 语义档定义（对齐已锁集合，非新造）

锁定集 `{22, 17, 18, 16, 15, 13}`，语义出处 `太玄UI主题规范.md §2` + `UI硬性约束规范.md §3.3`：

| 档名 | 值(px) | 语义 | 典型场景 |
| --- | --- | --- | --- |
| `FS_TITLE` | **22** | 主标题 / 标题屏 | 门派名、弹窗主标题、启动页大标题 |
| `FS_SUBTITLE` | **18** | 区块标题（上限） | 面板标题、卡片组标题 |
| `FS_BUTTON` | **17** | 次级面板标题 / 按钮文字 | 按钮、页内小标题 |
| `FS_VALUE` | **16** | 数值 / 输入 | 资源数值、LineEdit |
| `FS_BODY` | **15** | **正文（下限，不可更低）** | 正文、资源行、列表项 |
| `FS_AUX` | **13** | 辅助 / 提示 | 说明、Toast、导航文字、角标 |

> 铁律：正文禁止 < 15px；辅助禁止 < 13px；禁止新增档位。

### B.2 Theme 配置方案

**设计原则**：`default_font_size` 取**出现频率最高**的档，让最多控件"什么都不写就对"；偏离默认的走**命名变体**（复用 M2/M3 机制①，与 StyleBox 收口同构，engineering 心智负担为零）。

统计：15px 覆盖 13/34 处内联，为最高频 → **`default_font_size = 15`**。

**即：约 68 处调用点正在绑定规范明令禁止的字号（30 / 14）。** 这是比 .tscn 内联严重得多的单源化漏洞。

`apply_title_font_sized`(16 处) / `apply_body_font_sized`(24 处) 由调用方传值，**须逐处审计**是否落在锁定集内。

> **建议**：单独立 **P1-D「运行时字号收口」**，范围 = 修正 4 个违规常量 + 审计 40 处 `*_sized` 传值 + 评估 helper 是否改为「只设字体不设字号、字号交 Theme」。
> **不建议塞进 P1-B**：① 涉及 112 个调用点，回归面远大于本轮；② 修 `FONT_TITLE` 30→22 是**真实观感变更**（缩小 8px），与本轮「像素等价」验收基线直接冲突，混做会导致两边都验不清。
