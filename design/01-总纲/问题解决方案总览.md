# 修仙宗门项目问题解决方案总览

以下按**设计规划、数值体系、UI 表现、叙事内容、玩法深度、商业化与留存**六大模块归类，对应 18 项问题给出可落地的解决方案，并标注首发 MVP 优先级，方便排期落地。

## 当前已识别问题清单（18 项）

- 系统密度过高：首发若同步开放 70% 以上系统，新手极易信息过载；部分系统（辈分礼制、凡人香火）沉浸感强但对核心循环增益有限，MVP 阶段优先级偏低。
- 功能边界有重叠：宗门日常任务、随机事件、奇遇触发三类内容在体验上有重复感，容易让玩家混淆「今天该做什么」。
- 大量数值仍为占位值：气运、功德、PVP 平衡、体力体系等核心参数均标`[PLACEHOLDER]`，缺乏实测校准，真实平衡度有待验证。
- 拓展系统数值接入偏表层：气运、功德等系统仅设计了系数接口，未完成全链路的数值影响测算，实际落地可能出现溢出或无效。
- 基础分辨率偏老旧：基准 480×854 的竖屏分辨率已落后于当前主流机型，高屏下 UI 精细度不足，适配工作量比预估更大。
- 信息层级偏深：系统数量多导致二级、三级页面嵌套深，部分功能入口隐蔽，新手找功能成本高。
- 纯代码 UI 有上限：经济看板、传承谱系、战斗详情等复杂信息的可视化表现力受限，纯代码实现易出现「数据全但看不懂」的问题。
- 剧情文本偏骨架化：核心节点只有示例文案，大量世界观信息靠奇遇碎片化补充，缺乏强冲击力的关键剧情演出。
- 阵营人设偏模板：正邪对立比较传统，人物标签化明显，缺少足够的反转与灰度，长期剧情吸引力不足。
- 多结局仅存框架：四个终局结局只有方向，没有具体分支路径与判定阈值，终局成就感偏弱。
- 部分系统技术方案偏概念：异步多人、大地图导航、跨服赛季等内容只有规则设计，缺少具体实现方案与性能评估。
- 缺少性能压测方案：弟子、建筑、事件数量提升后，离线推演与沙盘渲染的帧率风险未做前置评估。
- 付费点厚度不足：外观、便利类付费内容偏少，重氪用户的回收路径弱，付费天花板偏低。
- 社交留存拉力弱：异步弱社交的设计虽然稳妥，但也缺少强社交留存抓手，用户流失后召回难度高。
- 前期爽点密度不足：新手期以熟悉系统为主，正向反馈偏平缓，前 30 分钟的爽点设计偏少，首日留存风险偏高。
- 内容同质化偏高：丹药、功法、装备多数是纯数值堆砌，专属机制与特殊效果偏少，长期玩容易陷入数值疲劳。
- 策略深度偏优化：多数选择是「怎么搭配收益最高」的数值优化，缺少「选 A 就彻底失去 B」的重大路径抉择，策略重量不重质。
- 奇遇模板化明显：200 + 奇遇多数是「选项 1 稳妥低收益 / 选项 2 冒险高收益」的固定结构，重复体验后新鲜感下降快。

## 一、系统规划与 MVP 版本管控

对应问题：系统密度过高、功能边界重叠、部分系统技术方案偏概念

### 1. 系统密度过高：收敛首发内容，做梯度解锁

- **核心策略**：MVP 版本只保留 40% 核心系统，其余内容按赛季 / 宗门等级逐步释放，避免新手信息过载。
  1. **首发必留核心系统**：宗门建设、弟子招募培养、资源产出、基础历练、商店交易，仅支撑「建设 - 培养 - 产出 - 扩张」的核心循环。
  2. **降级为赛季更新内容**：辈分礼制、凡人香火等沉浸向、低增益系统，全部移出首发，放到 S1 赛季作为「宗门声望」线解锁，既保留长线更新空间，又不干扰新手体验。
  3. **渐隐式解锁规则**：所有系统绑定宗门等级，1 级仅开放建设 + 招募，2 级开历练，3 级开丹药 / 功法，每级仅解锁 1-2 个新系统，配合单步引导，避免一次性堆砌。

### 2. 功能边界重叠：明确三类内容的定位与触发规则

给日常任务、随机事件、奇遇做**分层定位 + 差异化触发 + 梯度奖励**，玩家自然形成认知区分：

| 内容类型 | 核心定位 | 触发方式 | 奖励梯度 | 入口位置 |
| --- | --- | --- | --- | --- |
| 日常任务 | 保底行为引导，塑造每日习惯 | 每日固定刷新，主动领取 | 稳定基础资源（灵石、材料） | 主界面侧边常驻入口 |
| 随机事件 | 操作附属反馈，增加日常变数 | 绑定收资源、弟子历练等操作，被动触发 | 小幅增益 / 减益，无大额奖励 | 操作后弹窗，无独立入口 |
| 奇遇 | 高稀有探索内容，彩蛋级体验 | 需满足前置条件（特定弟子 / 功法 / 声望），主动探索触发 | 稀有道具、专属剧情、特殊弟子 | 独立图鉴入口，解锁后可回看 |

### 3. 技术方案偏概念：降级首发需求，先验证再扩展

- 异步多人、大地图导航、跨服赛季全部移出首发 MVP，降级为远期规划。
  1. 异步多人简化为「单服排行榜 + 好友宗门拜访」，仅做数据展示与轻度互动，技术成本极低，可满足基础社交需求。
  2. 大地图导航替换为**2D 节点式平面地图**（类《三国志 11》城池节点），不用开放世界自由导航，大幅降低开发与性能压力。
  3. 跨服赛季延后至 S2 之后，首发先做单服赛季验证玩法闭环，再评估跨服实现方案。

## 二、数值体系与性能管控

对应问题：数值占位多、拓展系统数值表层化、缺少性能压测方案

### 1. 大量数值占位：分层校准，先跑通核心闭环

采用「从内到外、逐层填值」的策略，优先保障核心循环可用，边缘系统留接口迭代：

1. **P0 核心层（首发必做）**：先校准体力（宗门行动力）、基础资源产出消耗、弟子境界成长三条主线，用 Excel 模拟推演「筑基→金丹」的完整周期，定死核心数值，替换所有占位符。
2. **P1 增益层**：丹药、功法、装备的加成数值，首发给保守保底值，做成配置表可调参数，测试阶段根据数据迭代。
3. **P2 拓展层**：气运、功德、PVP 平衡等非核心数值，首发仅设基础区间与上下限，不追求绝对平衡，留足后续调优空间。

### 2. 拓展系统数值偏表层：补全链路，设置阈值防溢出

针对气运、功德等系统，明确**全链路生效点 + 计算公式 + 数值上下限**，避免无效或溢出：

- 示例：气运系统全链路定义
  1. 生效维度：弟子突破成功率、奇遇正向概率、资源产出暴击率、事件好结果概率
  2. 换算规则：每 100 点气运，对应各维度 + 3% 加成
  3. 阈值限制：单维度加成最高 ±20%，全局气运值设置上下限，杜绝极端数值
- 落地动作：给所有拓展属性增加数值埋点，测试阶段监控极值，超阈值自动告警；首发前完成一轮全链路数值模拟，验证无崩坏风险。

### 3. 缺少性能压测：定红线 + 分模块测试，首发控上限

1. **先定性能红线**：明确首发标准 —— 同屏 50 个单位时，沙盘渲染稳定 30 帧以上；离线推演 100 天运算耗时≤2 秒；安装包体≤500M。
2. **分模块压测**：
   - 离线推演：编写自动化脚本，模拟 100/200/500 名弟子推演 1/10/100 年的耗时，定位算法瓶颈，优先用「增量计算」替代全量重算优化。
   - 渲染模块：测试建筑、弟子数量上升后的帧率，针对 Godot 引擎做实例化渲染、远处模型降质等优化。
3. **首发控量**：首发版本限制弟子、建筑的数量上限在安全阈值内，后续版本随性能优化逐步放开。

## 三、UI/UX 与前端表现

对应问题：基础分辨率老旧、信息层级偏深、纯代码 UI 表现力不足

### 1. 分辨率老旧：升级基准，做自适应适配

- 直接将设计基准升级为**1080×1920（16:9）**，匹配当前主流竖屏机型，同时兼容 20:9 全面屏；原 480×854 仅作为最低兼容分辨率，不再作为设计基准。
- 落地方案：UI 布局统一使用锚点 + 自适应容器，素材全部采用高清图集或矢量资源；采用「一稿适配」工作流，主流机型自动缩放，小众机型仅做边缘兼容，控制适配工作量。

### 2. 信息层级偏深：扁平化改造 + 快捷入口

1. **页面层级收敛**：核心功能全部提升至一级页面，主界面仅保留「宗门、弟子、历练、背包、商店」5 个核心入口；二级页面仅做细分分类，砍掉不必要的三级页面 —— 例如丹药炼制直接在宗门建筑内弹出子面板，无需跳转新页面。
2. **全局快捷入口**：增加悬浮快捷按钮，覆盖资源收取、弟子突破等高频操作，无需往返主界面跳转。
3. **新手期入口隐藏**：未解锁的系统入口全部置灰 / 隐藏，避免界面信息过载，随宗门等级逐步暴露。

### 3. 纯代码 UI 上限：混合方案，优先解决可读性

采用「代码框架 + 可视化组件」的混合实现，不用纯硬编码，解决「数据全但看不懂」的问题：

1. 经济看板：接入图表插件，用折线图展示资源收支趋势、柱状图对比产出占比，关键数据用颜色高亮。
2. 传承谱系：做成可拖拽缩放的树状节点图，直观展示师承关系，替代纯文字列表。
3. 战斗详情：增加伤害占比饼图 + 关键事件高亮日志，胜负原因一目了然。

- MVP 阶段优先级：先保证核心看板的可视化可读性，美观度放在后续版本迭代。

## 四、剧情与世界观叙事

对应问题：剧情文本骨架化、阵营人设模板化、多结局仅存框架、奇遇模板化

### 1. 剧情骨架化：抓核心节点，做轻重结合

1. **重打造关键剧情点**：首发集中资源打磨 3-5 个核心里程碑 —— 宗门创立、首次宗门大劫、首位金丹弟子、宗门晋升三品，每个节点配完整文案 + 轻演出（立绘差分 + 特效 + 旁白），打造强记忆点。
2. **碎片化世界观补全**：其余世界观内容整合进「宗门典籍」「人物志」，作为玩家主动探索内容，不强制推送；同时将世界观信息植入奇遇文本，复用内容填充两个模块。

### 2. 阵营人设模板化：增加灰度，打破非黑即白

1. 阵营层面：正道宗门加入内部利益斗争设定（如打压新兴宗门、垄断灵脉），邪修阵营增加立场合理性（如被正道迫害、功法遭世人误解），双方都有正义与私利的两面性。
2. 人物层面：核心 NPC 全部设置「正反双标签」，例如正道掌门正直但古板守旧，邪修首领杀伐果断但对门徒重情重义，避免纯脸谱化。

### 3. 多结局框架化：先落地判定逻辑，再补全分支

1. 先明确四个结局的核心判定维度：正道结局（功德 + 宗门声望）、邪道结局（势力值 + 杀戮值）、隐世结局（传承代数 + 弟子总数）、覆灭结局（宗门崩坏值）。
2. 每个结局设置 3 个关键判定节点（宗门 3 级、5 级、渡劫期），玩家选择会累计对应维度数值，最终按最高值判定结局，首发先跑通判定逻辑与结局文案。
3. 支线分支路径放到后续版本逐步更新，保证首发终局有明确的成就感与闭环。

### 4. 奇遇模板化：多元结构 + 连锁设计，降低重复感

打破「稳妥低收益 / 冒险高收益」的固定结构，做三类差异化改造：

1. **无优劣选择**：选项只区分收益类型（如 A 加弟子好感、B 加资源），无高低收益之分，匹配不同发展路线。
2. **连锁奇遇链**：单个奇遇选择会触发后续连锁事件，例如救助一名修士后，后续会触发报恩 / 背叛的延伸剧情，形成完整小故事。
3. **条件专属奇遇**：仅特定灵根、功法、阵营的弟子可触发，奖励对应专属道具 / 剧情，提升稀有感。

- 落地比例：现有 200 + 奇遇中，30% 保留传统结构，40% 改为多元收益型，30% 改造为连锁 / 专属型。

## 五、玩法深度与策略性

对应问题：内容同质化偏高、策略深度偏数值优化

### 1. 内容同质化：给物品加专属机制，跳出纯数值堆砌

给丹药、功法、装备增加**场景化特性**，让每个物品有专属定位，而非单纯数值比拼：

- 丹药：除属性加成外，增加功能型效果 —— 辟谷丹降低体力消耗、转魄丹重置灵根、劫丹提升渡劫成功率但附带修为反噬，各有明确使用场景。
- 功法：划分发展方向 —— 种田型（提升资源产出）、战斗型（提升历练伤害）、突破型（提升突破成功率），部分功法附带代价（如修为增速快但走火入魔概率提升）。
- 装备：增加套装效果与特殊词条，区分战斗、种田、辅助等不同 build 方向。

### 2. 策略深度偏优化：增加不可逆抉择，强化选择重量

设计「选 A 即失去 B」的重大路径抉择，替代纯数值最优解计算：

1. **宗门路线抉择**：宗门 3 级时，选择正道 / 邪道发展路线。正道声望获取快、但资源获取受限；邪道资源效率高、但会触发正道讨伐，选定后无法轻易更改。
2. **弟子培养抉择**：高阶突破时，可选择「稳扎稳打」（成功率高、天赋上限普通）或「逆天改命」（成功率极低、成功后天赋暴涨），失败存在弟子报废风险。
3. **资源分配抉择**：核心资源（如灵脉、气运）设置总量上限，优先升级建筑 / 培养弟子 / 储备防灾，不同选择对应完全不同的发展节奏，无绝对最优解。

## 六、商业化、社交与留存

对应问题：付费点厚度不足、社交留存拉力弱、前期爽点密度不足

### 1. 前期爽点不足：高密度反馈，打造 30 分钟成长节奏

优化新手期体验，保证每 5 分钟一个正向反馈，30 分钟内有 3 个小高潮：

1. 前 10 分钟：快速完成「创宗→招首徒→建首座建筑→收第一波资源→首次突破」，每步都配特效与奖励弹窗，让玩家快速感知成长。
2. 30 分钟节点：设置「首位弟子筑基、首个奇遇解锁、宗门升 2 级」三个里程碑，配合大额奖励与升级动画，打造爽点峰值。
3. 福利辅助：新手期赠送 1 名高品质弟子 + 1 次高级招募，降低前期开荒门槛，提升首日留存意愿。

### 2. 付费厚度不足：搭建分层体系，兼顾平衡与天花板

构建「不破坏核心平衡」的分层付费体系，覆盖全付费层级：

- 微氪基本盘：月卡、宗门战令（成长手册），提供便利资源与限定外观，性价比最高，保证付费渗透率。
- 中氪持续项：限定弟子皮肤、建筑外观、加速礼包、功法礼包，定期更新，支撑长期付费。
- 重氪天花板：增加高价值个性化内容 —— 专属宗门皮肤、自定义功法名称、宗门领地装饰、专属称号、限定传奇弟子，抬升付费上限。

### 3. 社交留存弱：弱社交做深，增加召回抓手

保持异步弱社交的稳妥定位，从「互动、目标、召回」三个维度补全留存拉力：

1. 好友互动：开放宗门拜访、轻度互助加速、排行榜比拼，用轻度攀比提升活跃。
2. 赛季目标：开启单服宗门赛季（战力 / 资源 / 声望排行），配赛季专属奖励，给玩家长期上线目标。
3. 召回机制：增加好友召回奖励（双方均得资源）、回归专属礼包；搭配个性化推送（如「你的弟子即将突破金丹」），降低回流门槛。
