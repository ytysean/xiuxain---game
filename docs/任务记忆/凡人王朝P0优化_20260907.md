## 二、优化方案

### P0-1：标签页合并（10→5）+ 渐进式解锁

**合并方案**：

| 新标签页 | 合并内容 | 解锁条件 |
|---|---|---|
| 总览 | 王朝状态 + 今日朝报 + 今日要事 | 默认解锁 |
| 郡县 | 12郡列表 + 凡间差事榜 | 默认解锁 |
| 朝堂 | 派系 + 爵位 + 荐举 + 皇储 | 受封护国宗爵位后解锁 |
| 事件 | 诏令 + 朝廷委托 + 反制应对 | 触发第一个反制事件后解锁 |
| 信仰 | 香火庙 + 愿力 + 功德/业力 | 建立第一座香火庙后解锁 |

**旧标签页映射**：
- 天下 → 总览(王朝状态) + 郡县(郡县列表)
- 邸报 → 总览(今日朝报)
- 差事 → 郡县(差事榜)
- 朝堂 → 朝堂
- 册封 → 朝堂
- 皇嗣 → 朝堂
- 诏令 → 事件
- 委托 → 事件
- 国教 → 信仰
- 开国 → 特殊状态（王朝灭亡时弹窗）

### P0-2：今日要事提醒系统

**要事来源**（按优先级排序）：
1. 待批朝奏（最高优先级）
2. 王朝反制事件
3. 差事即将到期（剩余日≤3）
4. 爵位义务（荐举未履行）
5. 灾情预警（灾情>50）
6. 国祚危机（国祚≤30）
7. 民心危机（民心≤20）

**显示方式**：
- 总览页顶部显示最紧急的3项
- 每项显示：紧急程度（紧急/警告/提醒）+ 标题 + 描述 + 快捷跳转按钮
- 颜色编码：紧急=红色、警告=黄色、提醒=蓝色

### P0-3：数值可视化

**进度条组件**：
- 国祚/民心：0-100进度条
- 颜色编码：≥60绿色（健康）、30-60黄色（警告）、<30红色（危险）
- 显示数值：当前值/最大值

**状态颜色文本**：
- 对宗门关系：≥70绿色（亲近）、30-70黄色（中立）、<30红色（疏远）
- 郡县忠顺度/感恩度：同样的颜色编码

**郡县列表优化**：
- 每行显示：郡名（Lv等级）+ 忠顺度（颜色）+ 感恩度（颜色）+ 灾情标记

## 七、经验教训

1. **变量名必须先验证**：在使用Game.xxx变量之前，必须先在game_state.gd中搜索确认变量名是否正确，避免使用不存在的变量名。
2. **UITheme方法名要准确**：项目中UITheme是小写命名（ui_theme.gd），方法名如color_text_aux()，不是color_aux()。
3. **聚合函数优于重构**：对于大型UI重构，采用"保留原有函数+新增聚合函数"的方式，比直接重构原有函数风险小得多。
4. **渐进式解锁是新手友好的关键**：不要一次性把所有功能都暴露给玩家，按照游戏进度逐步解锁，能显著降低新手门槛。
5. **"今日要事"是减少玩家迷茫的有效手段**：玩家不知道做什么的时候，告诉他们"现在最紧急的3件事"，能显著提升游戏体验。
