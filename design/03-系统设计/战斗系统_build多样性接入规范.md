## 0. 为什么需要这份规范

用户（老大）明确：战斗是核心玩法，后期有宗门战、排行榜、秘境战，必须让深度玩家钻研**不同搭配、不同 build** 的可玩性。点名的 build 轴：装备、法宝、血脉羁绊、傀儡、毒、符箓、灵宠、本命法宝、战斗辅助道具、丹药、五行克制、功法克制。

**审计结论（已查实当前代码，非臆测）**：战斗引擎底层**已为 build 多样性备好**，**不需要重建**，缺的是「往漏斗里灌数据」。最关键的发现——`BattleCalculator._结算_1v1_增强`（支持 技能释放 / buff / dot 持续伤害 / 控制 / 灵力 全生命周期）因单位快照 `技能` 字段恒为 `[]` 而**现为死代码**。毒=dot、符箓=控制/buff、法宝/血脉/羁绊/丹药/称号=被动技能（常驻自增益），全部可经这条现成机制接入，**零碰红线**。

本规范定义：每个 build 轴归哪个乘区、走哪条 funnel、碰不碰红线、排哪个阶段。

## 2. 乘区归属三原则（funnel 模型）

所有 build 轴只能归到以下三类之一，禁止自创第四类乘区：

### 2.1 四维增量（flat 加法，经 `_聚合未来战力来源`）
- **适用**：效果本质是「属性加成」的系统（称号、血脉羁绊常驻、法宝被动、傀儡属性、丹药限时）。
- **机制**：在 `get_final_combat_attr` 的 `战斗属性` 上 flat 加法（境界倍率之后、外部加成之前已定结构：先 算属性 → ×境界倍率 → +装备映射 → +法阵/功法/灵兽/未来来源）。
- **红线**：零触碰。改动只在 `disciple.gd` 的聚合函数内加几行。
- **约束**：满足「战力映射铁律」——不新增独立乘区，避免「虚高战力实战裸属性」脱钩。

### 2.2 通用增益池（百分比乘区，经 `聚合通用增益`）
- **适用**：百分比类乘性加成（功法、大阵、血脉、家族、自创、灵兽——即 ADR-001 预算表内的来源）。
- **机制**：同池累加，软25%/硬30% 封顶（溢出按 20% 衰减）。
- **红线**：零触碰（改 `disciple.gd` 聚合函数）。
- **预算表（ADR-001）**：装备8% + 功法2% + 血脉1.5% + 家族2% + 自创2% + 灵兽~3% + 大阵/聚灵/先贤/常规≈6% ≈ 24.5%（精准贴合 23%~24.5% 总预算，不击穿 25%）。**新增来源必须在预算内分配额度，不得超池。**

### 2.3 技能数组（激活增强引擎，经 `技能` 字段）
- **适用**：主动/持续性效果（毒=dot、符箓=控制/buff、法宝主动、灵宠主动、功法主动技能）。
- **机制**：给单位快照 `技能` 数组填真实技能（来源 `config/skill.csv` / `skill_cultivation.csv`），`_结算_1v1_增强` 自动跑生命周期（进场被动→常驻自增益；每回合 dot 跳伤 / 控制跳过行动 / 增益减益重算属性）。
- **红线**：**填数据零触碰**；但 `_结算_1v1_增强` 内部逻辑若需扩展新 buff 类型，属 S2 扩展接口层（治理文档第三层），需过放开 Checklist。
- **价值**：这是把「死代码变活」的关键一步，也是 build 多样性体验落差最大的部分（dot/控制/连携）。

## 4. 增强引擎激活计划（把死代码变活）

`_结算_1v1_增强` 的 buff 分类已全（`_tick_buffs` 处理 dot/控制/增益减益/灵力；`_build_unit_state` 处理进场被动常驻自增益）。激活只需**给单位快照填 `技能` 数组**，映射关系：

| build 效果 | 技能/buff 形态 | 引擎处理 |
|---|---|---|
| 毒 | `技能` 带 `buff_type=dot`（每回合损血比例/flat） | `_tick_buffs` ① 持续伤害 |
| 符箓 | `技能` 带 `buff_type=控制`（跳过行动）/ `增益` | 控制标记 + 属性重算 |
| 法宝主动 | `技能` 带 `增益/减益`（攻防血速/暴击） | 属性重算 |
| 灵宠主动/被动 | `技能` 带 `被动天赋` → 进场常驻自增益 | `_build_unit_state` 174-182 |
| 功法主动 | `技能` 带释放/冷却（消耗灵力） | 完整技能生命周期 |

**激活前置**：`config/skill.csv` / `skill_cultivation.csv` 需补齐「效果类型 → buff 字典」的字段契约（当前 `已修功法` 默认 `[]`）。这是数据层工作，零红线。

**风险**：增强引擎从未在真机跑过（死代码），激活后须先过 Python 断言回归（dot/控制/灵力边界）+ 1v1/3v3 真机验收，再放开给全部入口。

## 6. 校验与测试

1. **pre_f5 扩展门**：在现有 8 闸门基础上，新增「build 多样性断言」子门——每个新接入的乘区须有对应 Python 断言（如 血脉羁绊常驻增益 ≤ 预算 1.5%；丹药限时 buff 到期后归零；多灵根纯度系数命中 `纯度克制/被克` 表）。
2. **蒙特卡洛胜率曲线**：沿用 `_s11_balance_sim.py` 范式，建 `_build_diversity_sim.py`——对每种 build 组合（如 毒道修+符箓+神兽血脉 vs 体修坦克）跑 400 局，输出胜率曲线，验证「搭配有差异、无必赢/必败垄断」。这是 build 多样性的核心验收指标。
3. **增强引擎回归**：激活 `_结算_1v1_增强` 后，Python 断言覆盖 dot 跳伤下限、控制跳过、灵力耗尽、被动常驻不消散；真机 3 用例（1v1 / 3v3 车轮 / 征伐联动）重跑。
4. **红线不破**：每次 build 接入 PR 必须 `pre_f5` EXIT=0，零战斗触碰 PASS。

## 8. 风险与开放问题

1. **增强引擎从未真机跑过**：激活 P2 前必须先在隔离环境跑通 Python 断言 + 真机 3 用例，避免「死代码变活即崩」。
2. **通用增益池超池风险**：血脉/家族/自创/灵兽 多个来源若同时满额会逼近 25% 软帽，新来源须严格按 ADR-001 预算分配，不得超池（pre_f5 加断言卡池总帽）。
3. **多灵根数据模型是 P1 纯度的前置阻塞**：五行多纯度「钩子」可 P1 就位，但「全档生效」依赖多灵根特性本身，需单独排期（H 分支）。
4. **功法克制 vs 近似**：若不想碰红线，可用「功法被动技能」近似功法克制（走 2.3），代价是克制不再是伤害公式内的独立乘区；是否接受近似待老大拍板。
5. **本次（S1 批次）不动红线**：本规范所有 P1 项须在新分支实施，不得混入今晚 F5 验收的 S1 批次（含 S1-1），避免验收污染。

## 9. 实施记录（S2 已落地部分）

> 用户授权「红线可碰、表现层也直接做」，以下已在当前批次（S1+S2）落地并通过 pre_f5（93 战斗断言 PASS、Godot3 残留 PASS、零战斗触碰转 S2 放开模式）。

### 9.1 P1 — 套装战斗接入（已完成）
- **根因**：原 `套装增益()` 仅按数量给统一 3/5/10% 灌入 `总战力()`，丢弃 `Item.套装库`(item.gd:170) 真实 2/3/5件战斗维度；`battle_util.gd` 套装减伤/闪避/抗性/暴击五参数全标「当前简化为0」。
- **落地**：
  1. `disciple.gd` 新增 `套装战斗加成()` + `_解析套装效果()`：读 `Item.套装库`，按各套装已达最高档位取该档效果、跨套装累加，仅取战斗维度（攻/防/血/速/暴击/反伤/穿透，%小数），非战斗维度（修炼速度/寿命/突破率）忽略。`to_float()` 对非数字返 0 → 五阴「突破成功率」安全跳过。
  2. `get_final_combat_attr()`：套装四维% 乘性叠入（与境界倍率/负责人buff 同范式），暴击率 += 套装暴击%；快照加 `反伤率`/`穿透率` 字段。

### 10.3 机制说明
- 解析器 `_解析套装效果` 支持单条多维度（按空格/、/， 拆分逐段），非战斗维度（修炼速度/寿命/突破率）经 `to_float` 宽容解析安全忽略。
- 减伤率（守方 def 快照，calc 内乘性叠加）、吸血率（攻方 actor 快照，原版/增强/技能三处消费，夹初始血量防过量）为新增快照字段，默认 0 → 72 断言不破。
- 特效族通过 `套装技能()` 注入快照 `技能` 数组 → 增强引擎按 `_skill_buff映射` 施放；无特效套装返回 [] → 走原版路径（零风险）。
