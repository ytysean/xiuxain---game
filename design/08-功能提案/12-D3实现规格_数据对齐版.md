**归类规则（澄清）**：punish_type 标注「被惩罚的维度」，事件主体决定「四类分闸归属」。本表用于 **① 无显式分类列时的兜底归类；② pre_f5 合法性校验（每个 punish_type 必须能在四分类找到归属）**。运行时以 `_punish类别()` 兜底 + 事件主体优先（见 §8）。

> **结论**：弟子属性向 6 类（心魔/修为/忠诚/心境/道心/气血）+ 灵石载体 → disciple；资源类（矿石/灵草/丹材）→ res_build；卖价 → reputation；无 → 仅总闸。声望/品级当前无属性型 punish_type，靠开关簇预留。

## 2. 固定值扣除模型 + Σ 单周期封顶（交付物 2）

### 2.1 模型切换
- **放弃蓝图「产出乘数惩罚」**（0.90/0.83 乘产）。改为：**每个负面事件直接扣固定 灵石 / 资源**（写入 `negative_event.csv` 行，双槽 punish_type/punish_value）。
- **双通道**：
  - **灵石通道**：直接扣 `灵石`；占用 Σ 单周期封顶。
  - **资源通道**：扣 `矿石`/`灵石` 存量；独立于灵石 Σ 封顶（材料经济池），受 `monthly_limit × 值` + 单事件 ≤50 约束（见 §6/§9）。

### 2.2 Σ 单周期封顶（灵石）= 62（固定值，取代蓝图 Σ≤62% 百分比）
- **数值**：`62` = `经济基线.csv` `冲击上限_灵石=62` = `floor(17% × 366)` = `floor(62.22)` = `62`（ECON-02 §2.4）。
- **论证（为何 62 不破红线）**：
  - 盈余缓冲 = 运维后净值 = `366 − 305 = 61` ≈ 62；在**极端运维(318)**下 `Σ=62` → 净 = `366 − 318 − 62 = −14`（轻赤，远未破产 −366）；**常规运维(305)**下 `Σ=62` → 净 = `−1`（近零）。**任何组合 Σ≤62 不转负盈余**。
  - 与 ±15% 红线**不冲突**：`62/366 = 16.9%` 是「功能影响上限」（ECON-02 §2.4 特性Δ），与 F2 旋钮「系数±15%红线」是**两道独立约束**。`Σ` 扣是固定值非系数，不触发 `平衡()` 熔断（熔断测系数摆动，`基准=含扣的 raw`，`负面系数=1.0` → 振幅=0）。
- **红线对齐**：
  - **常规档**：单事件灵石扣除锚定 **−10%**（366×10% = 36.6 ≈ 37；ne_008=37 即此锚）。
  - **极端档**：Σ 单周期封顶 **−17%**（62）；**取消蓝图 −35% 单档**。
  - ne_007（灵石 50，13.7%）为既有重单档，保留；其与新事件并发时由管理器截断至 62（见 §8）。

### 2.3 ne_007 的 50 如何计入 Σ
- ne_007 `灵石 50` 直接进入灵石通道，占用 Σ 封顶 `50/62 = 80.6%`。
- 单事件 50 < 62（封顶），自身合法；与 ne_008(37)/ne_009(25)/ne_010(30) 并发超过 62 时，管理器月末截断至 62（不转负盈余）。

## 4. P0 声望外部类预留（交付物 4 · 不做深度联动）

### 4.1 字段定义（punish_type = 卖价）
- 语义：`卖价` 惩罚值 = 坊市卖价乘数下限（如 `0.92` = 卖价 −8%）。

### 4.2 示例事件（2 条，P0 仅占位验证 schema）
```
ne_011,坊市压价,声望下滑且对手坊市倾轧,0.03,3,卖价,0.92,无,0,无,无,0,false
ne_012,商路断绝,战乱或天灾阻断商路,0.02,2,卖价,0.92,无,0,无,无,0,false
```

- 两行 punish_type_1=`卖价` / punish_value_1=`0.92`，punish_type_2=`无`/0。
- **明确标注「D3 不做深度联动」**：`neg_reputation=0` 时管理器跳过；坊市价差逻辑不实现于本批次。示例事件仅验证 punish_type 枚举 + 管理器分支解析可用。

## 7. 产耗冲击测算明细（交付物 7 · 供 pre_f5 Layer 校验移植）

基准值 = `标准局月产 366`（经济基线.csv）。Σ 封顶 = `冲击上限_灵石 62`。

| 事件 | 类别 | 基准值 | 灵石扣除 | 扣除% (÷366) | 资源扣除 | Σ 封顶占用(本事件) | 备注 |
|---|---|---|---|---|---|---|---|
| ne_007 偷窃资材 | disciple | 366 | 50 | 13.7% | — | 50/62=80.6% | 既有，保留 |
| ne_008 矿脉枯竭 | res_build | 366 | 37 | 10.1% | 矿石 40 | 37/62=59.7% | −10% 锚；受建筑被动减免 |
| ne_009 灵田歉收 | res_build | 366 | 25 | 6.8% | 灵草 30 | 25/62=40.3% | 折算机会成本 |
| ne_010 弟子卷资叛逃 | disciple | 366 | 30 | 8.2% | — | 30/62=48.4% | 永久流失 |
| ne_011 坊市压价 | reputation(预留) | 366 | 0（开关0） | 0% | 卖价 0.92 | 0 | D3 不深联动 |
| ne_012 商路断绝 | reputation(预留) | 366 | 0（开关0） | 0% | 卖价 0.92 | 0 | D3 不深联动 |

**最坏 Σ 测算（P0 全触发）**：`50 + 37 + 25 + 30 = 142` → 管理器月末截断至 **62**（≈−17%×366）→ 净 `366 − 318(极端运维) − 62 = −14`（轻赤，安全）。
**典型 Σ（1~2 事件触发）**：≤ 62 自然命中，无需截断。

**红线校验（pre_f5 可移植断言）**：
- 单事件灵石扣除 ∈ `[18.3, 62.2]`（= [5%, 17%]×366）→ ne_007/008/009/010 全部落入（50/37/25/30）。
- Σ 封顶 = 62 = `冲击上限_灵石`（ECON-02 §2.4）。
- 资源扣除 ≤ 50（单事件上限）。
- 卖价 ∈ `[0.85, 1.0]`（±15% 红线，0.92 合规）。

## 8. 运行时接线草图（交付物 8 · 伪代码级，非全量代码）

> 新增轻量代码（game_state.gd），**不重写框架**；复用 `period_settlement.gd` L128-129 单次 `平衡()` 出口 + `economy_balance.gd` 旋钮 + `建筑被动_负面事件减免`（DORMANT→消费）。

```gdscript
# ===== 负面事件管理器（新增，game_state.gd；D3 数据对齐版）=====
# 依赖：config/negative_event.csv（csv_validator 已校验结构，本管理器首次真实消费）
#       config/经济阀门.csv（neg_global/neg_res_build/neg_disciple/neg_reputation/neg_grade_perm + event_damage_rate）
#       game_state.建筑被动_负面事件减免（DORMANT→本管理器消费，仅 res_build）
#       economy_balance.gd.平衡()（period_settlement L128-129 单次调用，F2 钳制）

# —— 配置加载（懒加载）——
func _加载负面配置_S1():
    阀门表 = _读经济阀门表()                    # read_table_csv → {阀门:{系数,开关,说明}}
    neg_global    = _开关(阀门表, "neg_global",    1)
    neg_res_build = _开关(阀门表, "neg_res_build", 1)
    neg_disciple  = _开关(阀门表, "neg_disciple",  1)
    neg_reputation= _开关(阀门表, "neg_reputation",0)
    neg_grade_perm= _开关(阀门表, "neg_grade_perm",0)
    负面事件表 = _读负面事件表()                  # csv_validator 已注册

# —— 总闸优先判定 ——
func _负面类别生效(类别: String) -> bool:
    if not neg_global: return false              # 一键回退纯正向
    match 类别:
        "资源建筑": return neg_res_build
        "弟子人员": return neg_disciple
        "声望外部": return neg_reputation
        "品级权限": return neg_grade_perm
    return false

# —— punish_type → 类别（兜底归类）——
func _punish类别(pt: String) -> String:
    match pt:
        "矿石","灵草","丹材": return "资源建筑"
        "心魔","修为","忠诚","心境","道心","气血": return "弟子人员"
        "卖价": return "声望外部"
        "灵石": return "弟子人员"                # 货币载体，默认归弟子类
        _: return ""                             # 无类别：仅受总闸

# —— 月度结算接入点（推演一月 S1 区，紧接 _结算运维成本_S1 L1051 之后）——
func _结算负面事件_S1() -> void:
    if not neg_global: return
    本月灵石冲击 = 0.0
    for 行 in 负面事件表:
        if randf() >= float(行["base_prob"]): continue
        if _本月已触发次数(行["event_id"]) >= int(行["monthly_limit"]): continue
        _负面事件结算(行)

func _负面事件结算(行: Dictionary) -> void:
    for slot in ["1","2"]:
        类别 = _punish类别(行["punish_type_"+slot])
        if not _负面类别生效(类别): continue
        pt = 行["punish_type_"+slot]; pv = float(行["punish_value_"+slot])
        if pt == "无" or pv <= 0: continue
        match pt:
            "灵石":
                var 扣 = pv
                if 类别 == "资源建筑":                        # DORMANT 激活
                    扣 = max(0.0, 扣 * (1.0 + 建筑被动_负面事件减免))   # 减免∈[-0.30,0]
                本月灵石冲击 += 扣
            "矿石": 矿石存量 = max(0, 矿石存量 - int(pv))
            "灵草": 灵草存量 = max(0, 灵草存量 - int(pv))
            "卖价":
                if neg_reputation:                            # 仅开启时浅联动
                    _坊市卖价下限 = min(_坊市卖价下限, pv)    # 0.92
            "心魔","修为","忠诚","心境","道心","气血":
                _施加弟子属性惩罚(pt, int(pv))               # 纯属性，无经济副作用
    _本月已触发次数[行["event_id"]] += 1

# —— 月度总冲击卡位（月末，结算前；硬卡 Σ≤62，不转负盈余）——
func _负面总冲击卡位() -> void:
    var 上限 = 62.0                                  # = 经济基线.csv 冲击上限_灵石；镜像 pre_f5 Layer B3
    本月灵石冲击 = min(本月灵石冲击, 上限)           # 截断至封顶（超则降最弱档/整体截断）
    灵石 -= int(round(本月灵石冲击))                 # 进入 灵石增量 → period_settlement.平衡()
```

**F2 接线与钳制验证**（负面系数=1.0）：
- 极端运维(318) + 全 D3(Σ=62)：`灵石_delta = 366 − 318 − 62 = −14` → `平衡(−14)`：`负面系数=1.0` → 结果=−14，振幅=0，熔断不触发 → final=−14（安全）。
- 若误设 `负面系数=1.15`（上限）：`结果=−14×1.15=−16.1`，振幅=0.15=阈值，熔断不触发，final=−16.1（仅略差，F2 兜住）。**故 `负面系数≠1.0` 不破安全，但属双重惩罚冗余 → pre_f5 硬 FAIL（见 §9）**。

**DORMANT 激活点**：`建筑被动_负面事件减免`（L247）已由 `_建筑被动结算()` L1936 每期聚合（zhifa−15%/tanwei−5%/zhenfa−12%，封顶−30%），本管理器在 res_build 灵石扣除处乘 `(1+本值)` → 首次真实消费，零框架改写。
